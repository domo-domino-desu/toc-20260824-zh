The set of functions and the set of Turing machines are both
infinite so 
we must
understand how to compare the sizes of infinite sets. 
We will begin with two paradoxes, two examples that
dramatize the challenge to our intuition posed by 
comparing the sizes of infinite sets.

The first is 
\definend{Galileo's Paradox},\footnote{He did not invent this paradox but
he gave it prominence in his celebrated
\protect\textit{Discourses and Mathematical Demonstrations Relating to Two New Sciences}.}
comparing the size of the set of perfect squares with the size of the set of 
all natural numbers.
The set of squares is a proper subset of the set of all numbers,
so in a sense there are fewer squares than numbers.
However there are exactly as many squares as natural numbers in the sense that
the two sets can be made to correspond, 
to match element-to-element, as illustrated in the figure below.   
\begin{animatedfigure}{Correspondence $n\leftrightarrow n^2$ between the 
  natural numbers and the squares.}

\noindent We see the same thing in the children's game Musical Chairs. 
It starts with more children than chairs. 
Some music plays and the children walk around.
But then the music
stops and each tries to sit, and someone is left without a chair.
There is a child left over because between the set
of chairs and the set of children sitting is a correspondence. 
This correspondence demonstrates,
without counting, that the two sets have the same number of elements.

to compare the sizes of sets,

We want to

Consequently, we will see whether the sets correspond.

\begin{lemma} \label{lem:OneToOneOntoFiniteSets}
Suppose that finite sets have a map between them $\map{f}{D}{C}$.
If $f$ is onto then $D$ has at least as many elements as $C$.
If $f$ is one-to-one then $D$ has at most as many elements as $C$.
% Therefore, between two finite sets there is a correspondence 
% if and only if they have the same number of elements.
\end{lemma}

\begin{proof}
See \cref{exer:FiniteSetsSamSizeIffCorres}.
% asks for a proof of
% the statements about one-to-one and onto. 
% From those two, the final sentence is clear.
\end{proof}

\begin{definition} \label{def:Cardinality}
Two sets have the \citetext{same \definend{cardinality}}{Numbers 
have two natures.
First, in referring to the Pleiades as
the ``Seven Sisters'' we mean to take them as a set, not 
ordered in any way.
In contrast, second, in referring to the ``Seven Deadly Sins,'' well,
clearly some of them rate higher than others.
The first reference speaks to the cardinal nature of numbers 
and the second is their ordinal nature.
For finite numbers the two are bound together,
as \protect\cref{ex:SizeThreeSets} suggests,
but for infinite numbers they differ.} 
(or are \definend{equinumerous})
if there is a correspondence between them.  
That is, sets $S_0$ and $S_1$ have the same cardinality
if there is a 
one-to-one and onto function $\map{f}{S_0}{S_1}$.
If so, we write $\sizeof{S_0}=\sizeof{S_1}$.
\end{definition}

By the lemma, finite sets have the same cardinality just if they have
the same size, the same number of elements.
The definition's main interest is that it extends
this same-size relation to infinite sets.
We are familiar with the vertical bar notation for finite sets,
as in $\sizeof{\set{0,1,2}}=\sizeof{\set{1,2,3}}$, and the
definition extends it to apply to infinite sets.

\begin{example}  \label{ex:SizeThreeSets}
The set of numbers $S_0=\set{0,1,2}$ and set of
characters $S_1=\set{\str{a},\str{b},\str{c}}$ have the same cardinality,
$\sizeof{S_0}=\sizeof{S_1}$, as
witnessed by
the correspondence $0\mapsto\str{a}$, $1\mapsto\str{b}$, $2\mapsto\str{c}$.
This function is one-to-one because checking the three cases shows that
for each member of the codomain~$S_1$ there is at most one associated member
of the domain~$S_0$.
This function is onto because checking also shows that for each member
of~$S_1$ there is at least one member of~$S_0$ that maps to it.

That function is natural but not unique.
Another is $0\mapsto\str{b}$, $1\mapsto\str{a}$, $2\mapsto\str{c}$.
As with the prior paragraph, we can see that this is a correspondence 
by inspection.
\end{example}

\begin{example} \label{ex:PerfectSquaresCountable}
Galelio's Paradox is that the set of perfect squares 
$S=\set{n^2\suchthat n\in\N}$
has the same cardinality as the set $\N$, 
under the correspondence $\map{f}{\N}{S}$ given by $f(n)=n^2$.
This map is one-to-one because if 
$f(n_0)=f(n_1)$ so that $n_0^2=n_1^2$, then because these numbers are natural, 
and therefore non-negative, $n_0=n_1$.
It is onto because any element of the codomain $s\in S$
is the square $s=n^2=f(n)$ of some~$n\in\N$, by definition of~$S$.  
\end{example}

\begin{example} \label{ex:RealIntervalsCorrespond}
As Aristotle observed, with nonzero $r_0, r_1\in\R$,
the interval $I_0=\leftclosed{0}{2\pi r_0}$ has the 
same cardinality as the interval $I_1=\leftclosed{0}{2\pi r_1}$, 
because the map
$\map{g}{I_0}{I_1}$ given by $g(x)=x\cdot(2\pi r_1/2\pi r_0)$
is a correspondence. 
The verification is \cref{exer:VerifyAsParadox}. 
\end{example}

\begin{definition}
A set $S$ is \definend{finite} if $\sizeof{S}=\sizeof{\set{0,1,\ldots n-1}}$ 
for some $n\in\N$, or if $S=\emptyset$. 
Otherwise, it is \definend{infinite}.
\end{definition}

\margingraphic[l]{.225\textwidth}{background/pix/GeorgCantor.png}{\label{fig:cantor}\href{http://en.wikipedia.org/wiki/Georg_Cantor}{Georg Cantor 1845--\-1918, discoverer of the transfinite numbers}} % https://upload.wikimedia.org/wikipedia/commons/6/67/Georg_Cantor3.jpg
Using correspondences to compare the sizes of sets, even infinite sets, 
\citetext{was proposed by Cantor in the 1870's}{For spreading the word about his discoveries, Cantor was reviled by a very prominent mathematician and former professor, Leopold Kronecker, as a ``corrupter of youth.''  Of course, that was pre-Elvis.}. 
\Cref{lem:OneToOneOntoFiniteSets} shows that it takes an idea that is 
natural in the finite case and extends it to apply to all sets.
However, as the paradoxes above show, \cref{def:Cardinality} introduces 
a deep idea.
Besides observing that it
generalizes the finite case, we should convince ourselves that
it captures what we mean by two sets 
having the `same number' of elements.

As with Turing's definition of his machine, 
the strength of this definition
is that it is clear\Dash it is persuasive in itself.
G\"odel noted this, writing
``Whatever `number' as applied to infinite sets may mean, we certainly want it
to have the property that the number of objects belonging to some class does not change if,
leaving the objects the same, one changes in any way \ldots{}
e.g., their colors or their distribution in space \ldots{}\,.
From this, however, it follows at once that two sets will have the same
[cardinality] if their elements can be brought into one-to-one
correspondence, \citetext{which is Cantor's definition}{\autocite{Godel64}}.''

\citetext{the key example of an infinite set is $\N$}{%

\begin{definition}
A set with the same cardinality as $\N$ is \definend{countably infinite}.
If it is either finite or countably infinite then it is
\definend{countable}.\footnotemark[1]
\end{definition}\footnotetext[1]{%
  Some authors use `countable' where we say countably infinite,
  and use `countable or finite' where we say countable.}

We shall describe exhibiting a correspondence $\map{f}{\N}{S}$ as 
\definend{counting} or \definend{enumerating} that set.

\begin{example} \label{ex:MultiplesOfThreeCountable}
The set of multiples of three $\set{3k\suchthat k\in\N}$ is countable. 
The natural correspondence is $g(n)=3n$. 
\end{example}

\begin{example} \label{ex:NWithGapsCountable}
The set $\N-\set{2,5}=\set{0,1,3,4,6,7,\ldots}$ is countable.
This tabular display of a suitable function $\map{f}{\N}{\N-\set{2,5}}$
\begin{equation*}
  \begin{array}{r|ccccccc}
    n\in\N
      &0 &1 &2 &3 &4 &5 &\ldots \\ \cline{2-8}
    f(n)\in\N-\set{2,5}
      &0
      &1
      &3
      &4
      &6
      &7
      &\ldots
  \end{array}
\end{equation*}
gives the intuition that we just close up to fill the gaps.
The definition
\begin{equation*}
  f(n)=\begin{cases}
         n    &\case{if $n<2$}  \\
         n+1  &\case{if $n\in\set{2,3}$} \\
         n+2  &\case{if $n\geq 4$}
       \end{cases}
\end{equation*}
leads to an easy verification that $f$ both one-to-one and onto.
\end{example}

\begin{example} \label{ex:PrimesCountable}
The set of prime numbers is countable.
We won't give a 
formula for the correspondence.
Instead we can define the function as the input-output behavior of a 
program; just write one that reads in a natural number~$n$ and prints out 
the $n$-th prime
(taking the $0$-th prime to be~$2$, the $1$-th to be~$3$, etc.).
Showing that the function is a correspondence is straightforward.
\end{example}

\subsection{Cantor in code}
The definitions of cardinality and countability
do not require that the functions must be effective.
In this section we effectivize, 
exhibiting counting sets such aas 
$\set{0,1}\times\N$ and $\N\times\N$ 
using functions that are mechanically computable.
The most straightforward way to show that these functions can be computed is to 
exhibit code, so that is what we do.

\Cref{af:EnumerateNxN} does a breadth-first coverage
of the array by
\citetext{counting diagonally}{Some authors call this an anti-diagonal, 
taking the diagonal to be composed of the pairs $\sequence{n,n}$.}.
\begin{center}
  \includegraphics{background/asy/correspondences/correspondences3000.pdf}
\end{center}
For the idea behind the formula, consider the pair~$\sequence{1,2}$ in
the above figure.
The number of its diagonal, $3$, is the sum of its entries.
Also, before diagonal~$3$ are six pairs, 
so that on diagonal~$3$ the initial pair~$\sequence{0,3}$ 
gets counted as pair~$6$, and then
$\sequence{1,2}$ corresponds to~$7$.

Following that pattern, to get the number corresponding to~$\sequence{x,y}$
first observe that it lies on diagonal $d=x+y$.
Diagonal~$0$ has one entry, diagonal~$1$ has
two entries, diagonal~$2$ has three entries, etc.,
so the number of entries prior to diagonal~$x+y$ is $1+2+\cdots+d$.
This is an arithmetic series with total $d(d+1)/2$, 
called the $d$-th \definend{triangle number}.
Then, inside diagonal~$d$, the pair at the start is $\sequence{0,x+y}$,
next is~$\sequence{1,x+y-1}$, etc., and so
$\sequence{x,y}$ is the~$x$-th pair from $d$'s start.

\begin{definition}
\definend{Cantor's correspondence} $\map{\cantor}{\N^2}{\N}$
(or \definend{Cantor's unpairing function}, or
the \definend{diagonal} enumeration) is
\citetext{$\cantor(x,y)=(1/2)(x+y)(x+y+1)+x$}{The 
Fueter-P\'olya Theorem says that this is essentially the only 
quadratic function that serves as a pairing; see \autocite{Smorynski}.
No one knows whether there are pairing functions 
that are any other kind of polynomial.}.

\begin{example}  \label{ex:RationalsAreCountable}
The set of rational numbers $\Q$ is countable.
We already know how to alternate between positives and negatives, 
the problem reduces
to doing the nonnegatives $\map{f}{\N}{\Q^+\cup\set{0}}$.
A nonnegative rational is a numerator and denominator
$\sequence{n,d}\in\N\times \N^+$, except
that some pairs collapse; for instance, when the numerator is $4$ and the
denominator is~$2$ gives the same rational as does $n=2$, $d=1$.

As we did when counting the primes, we will count the nonnegative 
rationals not with a formula but instead with a program.
To avoid double counting~$4/2$ and~$2/1$ we 
\citetext{memoize}{%
  A memoized routine for computing a function
  saves the results of computing 
  that function on previously-seen inputs, and then can reuse those results. 
  For instance, if a memoized factorial function has been used to compute
  $5!=120$ and later is asked to compute $6!$, it can simply
  do $6\cdot 120$ instead of having to compute the $120$ all over again.
  (The term was invented by Donald Michie~\autocite{wiki:Michie}, 
  a coworker of Turing's in the World War~II effort to break the 
  German secret codes.)}. 
That is, to list the rational numbers
we generate the pairs $\sequence{a,b}$ in ascending order, 
\codeinline{(xy 0)}, \codeinline{(xy 1)}, etc.
For such a pair $\sequence{a,b}$, we reject it as the next rational
number to be listed if $b=0$, or if
the fraction $a/b$ is equivalent to a previously listed fraction.
Otherwise, we enumerate it as the next nonnegative rational.
\Cref{exer:CodeForRationalsCountable} asks for the Scheme code to compute
this function.
\end{example}

Verify \cref{ex:MultiplesOfThreeCountable}, that the function 
$\map{g}{\N}{\set{3k\suchthat k\in\N}}$ given by $n\mapsto 3n$ is
both one-to-one and onto.
\begin{answer}
To show that the map is one-to-one we will show that $g(n)=g(\hat{n})$ can only
happen if $n=\hat{n}$.
So let $g(n)=g(\hat{n})$, giving $3n=3\hat{n}$, and dividing by three 
yields $n=\hat{n}$, as required.

To show the map is onto we will show that every member of the codomain
$y\in\set{3k\suchthat k\in\N}$ is mapped-to by some member of the domain.
Because $y$ is a multiple of three, $y/3$ is a natural number.
Of course, $y=g(y/3)$, so $y$ is indeed the image of some member of the
domain.   
\end{answer}

\begin{answer}

and is the image of~$2^k\in P_2$.

The natural generalization is that for any two natural numbers 
$a,b>1$, the sets $P_a=\set{a^k\suchthat k\in\N}$ and 
$P_b=\set{b^k\suchthat k\in\N}$ have the same cardinality.
The argument is just as in the prior paragraph.

\begin{exercise}  \label{exer:StrictlyIncIMpliesOneToOne}
Let $E\subseteq\R$.

is \definend{strictly increasing} if $x<\hat{x}$ implies that
$f(x)<f(\hat{x})$.
Prove that any strictly increasing function 
is one-to-one;
it is therefore a correspondence between its domain and
its range.
(The same applies if the function is strictly decreasing.)
Does this hold for $E\subseteq\N$?
\begin{answer}
To get a contradiction suppose that $f$ is not one-to-one.
Then there are $x,\hat{x}\in E$ such that

suppose $x<\hat{x}$.
That gives $x<\hat{x}$ but $f(x)=f(\hat{x})$, which is the desired 
contradiction.  

Yes, the same argument works for $E\subseteq\N$.
\end{answer}

\end{exparts}

\begin{exercise} \label{exer:FiniteSetsSamSizeIffCorres}
We prove that for finite sets $D$ and~$C$, 
if there is a correspondence~$\map{f}{D}{C}$
then the two have the same number of elements.
Recall that $\sizeof{S}$, the cardinality of the set~$S$,
is the number of elements in~$S$.
\begin{exparts}
  \item Prove that if $f$ is one-to-one then $\sizeof{C} \geq \sizeof{D}$.
  \item Prove that if $f$ is onto then $\sizeof{C} \leq \sizeof{D}$.
\end{exparts}
\begin{answer}
\begin{exparts}
\item   Assume that $\map{f}{D}{C}$ is one-to-one.
  We will do induction on the number of elements in~$D$.
  The base step is that~$\sizeof{D}=0$.
  The codomain cannot have fewer elements than this
  so~$\sizeof{C} \geq \sizeof{D}$ holds in this case.

  For the inductive step assume that the statement is true when 
  $\sizeof{D}=0$, 
  \ldots, $\sizeof{D}=k$ and let~$D$ be a set with~$\sizeof{D}=k+1$.
  Pick some $d\in D$ and consider 
  $\hat{D}=D-\set{d}$ (because this is the $k+1$ case, there is at least
  one such element).
  The inductive hypothesis applies to $\hat{D}$ so that 
  the number of elements in the range of the restriction map 
  $\map{\hat{f}}{\hat{D}}{\range(\hat{f})}$
  is at least as great as the number of elements in the domain of that map
  $\sizeof{\range(\hat{f})} \geq \sizeof{\hat{D}}$.

  Now extend to~$D$ and the map~$\map{f}{D}{C}$.
  The set~$D$ has one element more than the set~$\hat{D}$.
  Because~$f$ is one-to-one, the value~$f(d)$ is not in 
  the range of the restriction map~$\range(\hat{f})$.
  Thus $\range(f)$ is one element larger than
  $\sizeof{\range(\hat{f})}$.
  Therefore $\sizeof{C} \geq \sizeof{D}$.      

\item   Assume that $\map{f}{D}{C}$ is onto.
  We do induction on the number of elements in
  the domain~$D$.
  The base step is that~$D$ has no elements, so $D=\emptyset$.
  The only function with an empty domain is the function whose graph is 
  empty. 
  This function is onto so the codomain~$C$ is also empty 
  (otherwise there would be an element of the codomain with no inverse
  image).

  For the inductive step assume that the statement is true when $\sizeof{D}=0$, 
  $\sizeof{D}=1$, \ldots, $\sizeof{D}=k$ and consider 
  the~$\sizeof{D}=k+1$ case.
  Pick some $d_0\in D$ and consider 
  $\hat{D}=D-\set{d_0}$ (because this is the $k+1$ case there is at least
  one such element in~$D$).

  There are two cases:
  whether the codomain element $f(d_0)$ is also the image of another domain
  element, some $d\in\hat{D}$, or else it is not.
  In the first case the restriction $\hat{f}$ is onto
  and so the inductive hypothesis applies, giving that 
  $\sizeof{C}\leq \sizeof{\hat{D}}<\sizeof{D}$.

  In the other case, that $d_0$ is the only element of~$D$ associated 
  by~$f$ with the codomain element~$f(d_0)$, let $\hat{C}=C-\set{f(d_0)}$.
  The restriction map~$\map{\hat{f}}{\hat{D}}{\hat{C}}$ is clearly onto,
  so the inductive hypothesis applies: $\sizeof{\hat{C}}\leq \sizeof{\hat{D}}$.
  Therefore $\sizeof{\hat{C}}+1=\sizeof{C}\leq \sizeof{D}=\sizeof{\hat{D}}+1$.
\end{exparts}
\end{answer}
\end{exercise}

\section{Diagonalization}
Cantor's definition of cardinality led us to produce  
correspondences.
We now introduce a powerful technique that can do the opposite, that
can show that no correspondence exists.
We will approach the first question that we will
address with this new technique by giving it
an evocative framing.


\subsection{Hilbert's Hotel} \label{subsection:HilbertsHotel}
The prior section describes how infinite 
sets can be equinumerous even though one may seem in some sense
smaller than the other.
These lessons are brought out in a memorable 
mathematical fable. 

\margingraphic{.18\textwidth}{background/pix/hotel.jpg}{\label{fig:hotel}\href{http://en.wikipedia.org/wiki/Ryugyong_Hotel}{A hotel with lots of empty rooms}}   % http://upload.wikimedia.org/wikipedia/commons/6/6b/Ryugyong_Hotel_-_August_27%2C_2011_%28Cropped%29.jpg
\citetext{Once unon a time}{The fable is due to 
David Hilbert in 1924.  
It was popularized by George Gamow in 
\textit{One, Two, Three \ldots{} Infinity}.  \autocite{Kragh}.}
there was an infinite hotel.  
The rooms were 
numbered $0$, $1$, \ldots, naturally.
One day, every room was occupied when 
someone new came. 
Could the hotel accomodate?
The desk clerk hit on the idea of moving each guest up a room, that is,
moving the guest in room~$n$ to room~$n+1$. 
With that, room~$0$ is empty.
So this hotel always had space for a new person, 
or any finite number of new people.

Next came a bus with infinitely many people $p_0, p_1,\ \ldots\ $.
Again the clerk had an idea:~move each guest to a room with twice the number, 
putting the guest from room~$n$ into room~$2n$.
Now the odd-numbered rooms are empty 
so everyone has a room.

Just then a convoy of buses pulled in, 
infinitely many of them,
each with infinitely many people.
\begin{equation*}
  B_0=\set{p_{0,0},\, p_{0,1},\, \ldots\,},
  \quad
  B_1=\set{p_{1,0},\, p_{1,1},\, \ldots\,},
  \quad
  \ldots
\end{equation*}
By now the spirit of the thing was clear:
move each guest to a new room with twice the number, and 
the new people go into the odd-numbered rooms, in the breadth-first order
$p_{0,0}$, $p_{1,0}$, $p_{0,1}$, $p_{2,0}$ \ldots{}
of \cref{exam:NCrossN}.  

After this experience the clerk could be forgiven for thinking
that there is always room in the infinite hotel\Dash
that with a sufficiently clever method it can fit any set of new guests at all.
The Hilbert's Hotel story makes natural the guess 
that all infinite sets have the same cardinality. 
Despite its naturalness, though, that guess is wrong.
We will next see that there are sets with so many members that they 
cannot all fit in the hotel.\footnote{Alas, 
the infinite hotel does not now exist.
The story goes that  
the guest in room~$0$ 
said that the guest from room~$1$ would cover both of their bills.
The guest from room~$1$ said yes, but in addition
the guest from room~$2$ had agreed 
to pay for all three rooms, $0$--$2$.
Room~$2$ said that room~$3$ would pay, etc.
So Hilbert's hotel made no money despite having infinitely many rooms,
or perhaps because of it.}





\subsection{Diagonalization}
One set so large that it is not countable, 
a set for which no correspondence exists with~$\N$,
is the set of real numbers~$\R$.

\begin{theorem}  \label{th:RealsNotCountable}
There is no onto map $\map{f}{\N}{\R}$. 
Hence, the set of reals is not countable.
\end{theorem}

This result is important but so is the technique we will use to prove it.
The proof is so short that a reader can miss the intuition behind it
so we pause to develop this intuition.
The table below illustrates a function $\map{f}{\N}{\R}$, 
listing some inputs and outputs,
with the outputs aligned on the decimal point. 
\begin{equation*} \setlength{\arraycolsep}{0.75\arraycolsep}
  \begin{array}{c|r@{\hspace*{.35em}.\hspace*{.35em}}ccccccc@{\hspace*{1em}\ldots\;}}
    \multicolumn{1}{c}{\text{\small $n$\hspace*{0.25em}}} 
    &\multicolumn{8}{c}{\text{\hspace*{-1.00em}\small\tabulartext{Decimal expansion of $f(n)$}\ }}  \\ 
   \cline{1-9}
   \rule{0em}{2.15ex}% bit more vertical room 
   0  &4   &3  &1  &2  &7  &7  &0  &4  \\  
   1  &12  &0  &1  &0  &0  &0  &0  &0  \\  
   2  &1   &4  &1  &4  &1  &5  &9  &2  \\  
   3  &-20  &9  &1  &9  &5  &9  &1  &9  \\  
   4  &  0 &1  &0  &1  &0  &0  &1  &0  \\
   5  &-0  &6   &2  &5  &5  &4  &1  &8  \\[-.5ex]
   \multicolumn{1}{c}{\vdotswithin{$0$}} 
    &\multicolumn{4}{c}{\vdotswithin{$1$}}  
  \end{array}
  \label{ex:DiagonalizationTable}
\end{equation*}
We will show that this function is not onto.
We will produce a number $z\in\R$ that does not equal 
any of the outputs, any of the $f(n)$'s.

Ignore what is to the left of the decimal point.
To its right, go down the diagonal:
take the digits $3$, $1$, $4$, $5$, $0$, $1$ \ldots\@
Construct~$z$ by making its first decimal place 
something other than~$3$, 
making its second decimal place something other than~$1$, etc.
To be specific: if the diagonal digit is a $1$ then~$z$ gets 
a~$2$ in that decimal place, and otherwise~$z$ gets a~$1$ there. 
Thus, in this example $z=0.121112\ldots$\@

By construction, $z$ differs from the number in the first row,
$z\neq f(0)$, because they differ in the first decimal place.
Similarly,~$z\neq f(1)$ because they differ in the second 
place.
In this way $z$ does not equal any of the~$f(n)$. 
Thus $f$ is not onto.

(In this argument we must skirt a technicality, that
some real numbers have two different decimal representations.
For instance, $1.0000\ldots=0.999\ldots$ 
because the two differ by less than $0.1$, less than~$0.01$, etc.
This is a potential snag because 
it means that showing $z$'s 
representation differs from the representation of a number on the list
does not show that~$z$ is unequal to that number.
However, this dual representation happens for decimals only when one of the 
representations ends in $0$'s while the other ends in~$9$'s.
That's why we build~$z$ using only $1$'s and $2$'s.)

\citetext{This technique}{%
  The argument just sketched is often called Cantor's 
  diagonal proof, although it was not Cantor's original argument for the
  result, 
  and although the argument style is not due to Cantor but instead to 
  Paul du~Bois-Reymond.  
  The fact that scientific results are often attributed to people who
  are not their 
  inventor is \protect\textit{Stigler's law of eponymy}, because it wasn't 
  invented by Stigler (who attributes it to Merton). 
  In mathematics this effect is called \protect\textit{Boyer's Law}, who 
  didn't invent it either. \autocite{wiki:StiglersLaw}}
is \definend{diagonalization}.
It is critical for our work.

\begin{proof}
We will show that no map $\map{f}{\N}{\R}$ is onto.

Write $f(i)[i]$ for the $i$-th decimal digit of $f(i)$ 
(if $f(i)$ is a number with two decimal representations then we use the 
one ending in $0$'s).
Let $g$ be the map on the decimal digits $\set{0,\ldots,9}$ given by:
$g(j)=2$ if $j$ is~$1$, and $g(j)=1$ otherwise.

Now let~$z$ be the real number that is~$0$ to the left of its decimal point
and that has the $i$-th decimal digit
$g(f(i)[i])$. 
Then $z\neq f(i)$ for all~$i$, because $z[i]\neq f(i)[i]$. 
So $f$ is not onto. 
\end{proof}

\begin{definition}
An infinite set that is not countable is \definend{uncountable}.  
\end{definition}

We next define when one set has more elements than another.
The intuition comes from trying 
to make a correspondence 
between the two finite sets such as $\set{0,1,2}$ and $\set{0,1,2,3}$. 
There are just too many elements in the codomain
for any map to cover them all.
The best we can do is 
something like this, which is one-to-one 
but not onto. 
\begin{center}
    \includegraphics{background/asy/maps/maps02.pdf}
\end{center}

\begin{definition}
The set $S$ has \definend{cardinality less than or equal to}
that of the set~$T$,    
denoted $\sizeof{S}\leq \sizeof{T}$,
if there is a one-to-one function from $S$ to~$T$.
\end{definition}

For example, there is a one-to-one function from $\N$ to $\R$,
namely the inclusion map that sends $n\in\N$ to itself,~$n\in\R$.
So $\sizeof{\N}\leq\sizeof{\R}$
(however, the two do not have equal cardinality by the theorem above).
Another example is that there is a one-to-one function from $\N$ to $\Z$,
namely $n\in\N\mapsto n\in\Z$, so $\sizeof{\N}\leq\sizeof{\Z}$.
But in this case \cref{ex:ZIsCountable} shows that
there is a one-to-one function that is also onto,
so they have the same cardinality.

The wording of that definition implies that if both 
$\sizeof{S}\leq \sizeof{T}$ and 
$\sizeof{T}\leq \sizeof{S}$ then $\sizeof{S}=\sizeof{T}$.
That is true, but the proof is beyond our scope;
see~\cref{exer:SchroderBernstein}. 

For the next result 
recall that a set's \definend{characteristic function} $\charfcn{S}$ 
is the Boolean function determining membership:
$\charfcn{S}(s)=1$ if $s\in S$ and $\charfcn{S}(s)=0$ if $s\notin S$.
Thus for the set of two letters $S=\set{\str{a},\str{c}}$,
the characteristic function 
with domain $\Sigma=\set{\str{a},\ldots, \str{z}}$ 
is
$\charfcn{S}(\str{a})=1$,
$\charfcn{S}(\str{b})=0$,
$\charfcn{S}(\str{c})=1$, 
$\charfcn{S}(\str{d})=0$,
$\ldots$\,
$\charfcn{S}(\str{z})=0$. 
Recall also that the \definend{power set}~$\powerset(S)$ 
is the collection of subsets of $S$.
For instance, if $S=\set{\str{a},\str{c}}$ then
$
  \powerset(S)=\set{\emptyset, \set{\str{a}}, \set{\str{c}},
                          \set{\str{a},\str{c}} }
$.

% \begin{example}
% Where $A=\set{1,2}\subset \N$ this is $\map{\chi_A}{\N}{\{0,1\}}$.
% \begin{center}\renewcommand{\arraystretch}{1.15}
%   \begin{tabular}{r|ccccccc}
%     $s$

%     \cline{2-7}

\begin{theorem}[Cantor's Theorem]
Each set's cardinality is strictly less than that of its power set.    
\end{theorem}

% Thus, given a set, 
% we can produce another one whose cardinality is strictly 
% greater\Dash there's always a
% bigger set.

Before stating the proof we first illustrate it.
The easy half is 
producing a function from a set $S$ to $\powerset(S)$ that is one-to-one:
just map $s\in S$ to the singleton set $\set{s}$.

The hard half is
showing that no map from $S$ to $\powerset(S)$ is onto.
We illustrate the proof's approach with the
set $S=\set{\str{a},\str{b},\str{c}}$ 
and the function $\map{f}{S}{\powerset(S)}$.
\begin{equation*}
  \str{a}\mapsunder{f}\set{\str{b},\str{c}} 
  \qquad
  \str{b}\mapsunder{f}\set{\str{b}}
  \qquad
  \str{c}\mapsunder{f}\set{\str{a},\str{b},\str{c}}
\end{equation*}
In the table below the three rows list the 
values of the three characteristic functions 
of the output sets
$\map{\charfcn{f(\str{a})}}{S}{\set{0,1}}$, 
$\map{\charfcn{f(\str{b})}}{S}{\set{0,1}}$, 
and $\map{\charfcn{f(\str{c})}}{S}{\set{0,1}}$.
%  of the
% three output sets $f(\str{a})$, $f(\str{b})$, $f(\str{c})$.
\begin{center}
  \begin{tabular}{c|c|ccc}
    \multicolumn{1}{c}{$s\in S$}
       &\multicolumn{1}{c}{$f(s)$}
       &$\charfcn{f(s)}(\str{a})$  
       &$\charfcn{f(s)}(\str{b})$   
       &$\charfcn{f(s)}(\str{c})$  
    \\[.5ex] \hline \rule{0em}{2ex}
    $\str{a}$ &$\set{\str{b},\str{c}}$          &$0$ &$1$ &$1$  \\ 
    $\str{b}$ &$\set{\str{b}}$                  &$0$ &$1$ &$0$  \\ 
    $\str{c}$ &$\set{\str{a},\str{b},\str{c}}$  &$1$ &$1$ &$1$  
  \end{tabular}
\end{center}
To produce a subset of~$S$ that is not one of the three shown above, 
diagonalize:  
go down the diagonal and flip the bits from $0$ to~$1$, and
from $1$ to~$0$.
The diagonal shown is \str{011}.
Flip to \str{100}.
That's the characteristic function of the set $R=\set{\str{a}}$.
This set is
not equal to $f(a)$ because it differs on the input~$\str{a}$, 
it is not $f(b)$ because it differs on~$\str{b}$,
and it is not $f(c)$ because it differs on~$\str{c}$.

\begin{proof}
One half is easy:
consider the map $\map{\iota}{S}{\powerset(S)}$
given by $\iota(s)=\{s\}$.
Clearly it
is one-to-one, so the cardinality of $S$
is less than or equal to the cardinality of $\powerset(S)$.

For the other half,
to show that no map from a set to its power set is onto, 
fix any~$\map{f}{S}{\powerset(S)}$ and consider 
this element of $\powerset(S)$ (this is where we flip the bits).
\begin{equation*}
  R=\set{s \suchthat s\notin f(s)}
  % \tag{$*$}
\end{equation*}
We will show that no member of the domain maps to~$R$,
and thus $f$ is not onto.

Suppose that there exists $\hat{s}\in S$ such that $f(\hat{s})=R$.
Consider whether $\hat{s}$ is an element of~$R$.
We have that $\hat{s}\in R$ if and only if 
$\hat{s}\in\set{s\suchthat s\notin f(s)}$.
By definition of membership, that holds if and only if
$\hat{s}\notin f(\hat{s})$, which 
holds if and only if $\hat{s}\notin R$.
This contradiction means that no such $\hat{s}$ exists.
\end{proof}

\begin{corollary} \label{cor:FcnsNNGreaterFcnsN}
The cardinality of the set~$\N$ is strictly less than the cardinality of 
the set of all natural number functions $\map{f}{\N}{\N}$.  
\end{corollary}

\begin{proof}
Let~$F$ be the set
of functions~$\map{f}{\N}{\N}$.
There is a natural one-to-one map from $\powerset(\N)$ to~$F$:
associate each subset $S\subseteq\N$ with its characteristic function 
$\map{\charfcn{S}}{\N}{\N}$.
Therefore~$\sizeof{\N}<\sizeof{\powerset(\N)}\leq\sizeof{F}$.
\end{proof}

This is like Musical Chairs,
with countably many chairs
$P_0,P_1,\ldots$\@
Think of all the functions $\map{f}{\N}{\N}$.
The prior result says that 
there are just too many functions to fit in the chairs;
when the music stops 
some function is \citetext{left without a chair}{%
This is a Pigeonhole Principle argument.}.

The next section show that there are countably many Turing machines.
With that, we will know that 
the cardinality of the set of functions $\map{f}{\N}{\N}$
is greater than the cardinality 
of the set of Turing machines;
some function
$\map{f}{\N}{\N}$ is without a Turing machine chair
$\TM_0,\TM_1,\ldots$\@

This is an epochal result:~in the light of Church's Thesis we see it
as the proof that there are functions not computed by
any program,
\citetext{there are jobs no computer can do}{%
  To a person with training in programming, 
  where all of the conversation is on getting the computer to do things,
  the existence of jobs that cannot be done can be a surprise, perhaps
  even a shock.
  One thing that it shows is that the topics introduced 
  here are nontrivial\Dash formalizing
  the definition of mechanical computation, and the results about
  infinity, leads to interesting conclusions.}.

\begin{exercise} \label{exer:SchroderBernstein}
The \definend{Schröder–Bernstein theorem} is that if
$\sizeof{S}\leq \sizeof{T}$ and $\sizeof{T}\leq \sizeof{S}$ 
then $\sizeof{S}=\sizeof{T}$.
That is, if there is a one-to-one function $\map{f}{S}{T}$ and a
one-to-one function $\map{g}{T}{S}$ then there is a correspondence, a function
$\map{h}{S}{T}$ that is both one-to-one and onto.
We prove this theorem.
The proof depends on finding chains of images:
for any $s\in S$ we form the associated chain 
by iterating application of the
two functions both to the right 
and to the left. 
\begin{equation*}
  \ldots,\,f^{-1}(g^{-1}(s)),\,g^{-1}(s),\,s,\,f(s),\,g(f(s)),\,f(g(f(s))),\, \ldots
  % \tag{$*$}
\end{equation*}
The chain associated with $t\in T$ is defined similarly. 
For instance, let $S=\set{0,1,2}$ and $T=\set{\str{a},\str{b},\str{c}}$
(where the elements of $T$ are characters, not variables).
Let these be $\map{f}{S}{T}$ and $\map{g}{T}{S}$.
\begin{center}
  \begin{tabular}{c|c}
    $s$    &\multicolumn{1}{c}{$f(s)$}  \\ \hline
    $0$    &$\str{b}$  \\
    $1$    &$\str{c}$  \\
    $2$    &$\str{a}$  
  \end{tabular}
  \qquad
  \vcenteredhbox{\includegraphics{background/asy/maps/maps03.pdf}}
  \qquad
  \begin{tabular}{c|c}
    $t$       &\multicolumn{1}{c}{$g(t)$}  \\ \hline
    $\str{a}$ &$0$   \\
    $\str{b}$ &$1$    \\
    $\str{c}$ &$2$     
  \end{tabular}
\end{center}
Then starting at $0\in S$ and iterating
shows that there is a single chain and it is cyclic:
$\,\cdots\,0\mapsto\str{b}\mapsto 1\mapsto\str{c}\mapsto 2\mapsto\str{a}\mapsto 0\,\cdots$\,.
\begin{exparts}
\item 
  Consider $S=\set{0,1,2,3}$ and $T=\set{\str{a},\str{b},\str{c},\str{d}}$.
  Let $f$ associate $0\mapsto\str{a}$, $1\mapsto\str{b}$, $2\mapsto\str{d}$
  and $3\mapsto\str{c}$.
  Let $g$ associate $\str{a}\mapsto 0$, $\str{b}\mapsto 1$, $\str{c}\mapsto 4$
  and $\str{d}\mapsto 3$.
  Check that these maps are one-to-one.
  List the chain associated with each element of $S$ and the 
  chain associated with each element of $T$.
\item For infinite sets a chain can have a first element or a last element.  
   Let $S$ be the even numbers and let $T$ be the odds.
   Let $\map{f}{S}{T}$ be $f(x)=x+1$ and let $\map{g}{T}{S}$ be $g(x)=x+1$.
   Show each map is one-to-one.
   Show there is a single chain and that it has a first element, an 
   element without any preimage.
\item For the same sets as in the prior item, produce maps leading to a 
   single chain, with a last element.
\item Assume $S$ and $T$ are disjoint and that $\map{f}{S}{T}$
  and $\map{g}{T}{S}$ are one-to-one.
  Show that every element of either set is in a unique chain, 
  and that each chain is of one of four kinds: (i)~those that
  repeat after some number of terms
  (ii)~those that continue infinitely in both directions
  (iii)~those that continue infinitely to the right but stop on the left
  at some element of~$S$, 
  and (iv)~those that continue infinitely to the right but stop on the left
  at some element of~$T$.
\item Show that for any chain the function below 
  is a correspondence between the 
  chain's elements from~$S$ and its elements from~$T$.
  \begin{equation*}
    h(s)=
    \begin{cases}
      f(s) &\case{if $s$ is in a sequence of type~(i), (ii), or~(iii)}  \\
      g^{-1}(s) &\case{if $s$ is in a sequence of type~(iv)}
    \end{cases}
  \end{equation*}
\item Show that we can assume without loss of generality that $S$ and
  $T$ are disjoint.
\end{exparts}

\end{exercise}

\begin{definition}
A \definend{numbering} is a function that assigns to each Turing machine
a natural number.  
For any Turing machine, the corresponding number is its
\definend{index number}, or \definend{G\"odel number}, 
or \definend{description number}.
For the machine with index~$e\in\N$ we write \definend{$\TM_e$}.
For the function computed by $\TM_e$ we write~\definend{$\phi_e$}. 

A numbering is \definend{acceptable} if
(1)~it is effective: there is a program that takes as input
the source of the Turing machine, the set of instructions,
and gives as output the associated number,
(2)~the set of numbers for which there is an associated machine is computable,
and (3)~there is an effective inverse that takes as input
a natural number and gives as output the associated Turing machine source. 
\end{definition}

Think of the machine's index as its designator, or name.
We will refer to it frequently, for instance as
``the $e$-th Turing machine.''

The exact numbering that we use 
\citetext{doesn't matter much}{For the precise meaning of ``much'' 
see \autocite{Rogers58}.} as long as it is acceptable, so 
for the rest of the book we will just fix one.
That is, we can take the numbering to be \codeinline{godel} and its
inverse to be \codeinline{machine},
although we won't ever need the details of those. 
The point is that because the numbering is acceptable, 
by conditions~(1) and~(3) the index is source-equivalent\Dash 
we can go effectively from the index to the machine source or
from the source to the machine index.

\begin{lemma}
Every computable function has infinitely many indices; 
if $f$ is computable then  
there are infinitely many distinct $e_i\in\N$ with
$f=\TMfcn_e=\TMfcn_{e_0}=\TMfcn_{e_1}=\cdots$\,.
\end{lemma}

\begin{proof}
Suppose that $f=\TMfcn_e$.
We will prove a bit more than the lemma says.
We will show that from $e$ we can construct a sequence of distinct indices.
Let $q_j$ be the highest-numbered state in the machine $\TM_e$.
For $k\in\N$ consider the Turing machine obtained from $\TM_e$ by
adding the instruction $\tminstruction{{j+k}}{B}{B}{{j+k}}$.
Because the instruction are different for each~$k$, this gives a
sequence of Turing machines $\TM_{e_0}$, $\TM_{e_1}$, \ldots\@
Because
this instruction is unreachable it does not change the behavior,
so $\TMfcn_{e_i}=\TMfcn_e=f$.
\end{proof}

In terms of ordinary programming, we can get infinitely many source codes with
the same compiled behavior by starting with one source and adding to the
bottom a comment line containing only the number~$k$.

Weaving by hand, as the loom operator on the left is doing,
is intricate and slow.
We can make a machine to reproduce her pattern.
But what if we want a different pattern; do we need another machine? 
In 1801 
\href{https://en.wikipedia.org/wiki/Jacquard_weaving}{J~Jacquard} 
built a loom like the one on the right, controlled by 
paper cards
(it weaves with hooks whose positions, raised or lowered, are determined by 
holes punched in the cards).
Getting a different pattern does not require a new loom, it only requires 
swapping cards.

Turing introduced the analog for computing devices.

\begin{theorem}[Turing, 1936]
There is a Turing machine that when
given the input $e,x$ will have the same   
output behavior as does $\TM_e$ on input~$x$.
\end{theorem}

An Extra section at the end of the first chaptes uses Scheme
to simulate Turing machines. 
This theorem asserts that a Turing machine can simulate Turing machines\Dash
there is a single 
Turing machine that can act like any Turing machine at all.
This is a \definend{Universal Turing Machine}.
We denote such a machine with~$\UTM$.

\margingraphic{0.2\textwidth}{background/pix/snake.png}{\label{fig:ouroboros}\href{https://commons.wikimedia.org/w/index.php?curid=36915535}{An ouroboros, a snake swallowing its own tail}}
A universal machine may seem to present a 
chicken and egg problem:~how can we give Turing machines as input to 
Turing machines?
In particular, the machine 
of the theorem has some index~$e$,
and the theorem seems to allow this machine possibly being 
given~$e,x$, or even $e,e$\Dash
won't giving a machine to itself lead to infinite regress?

\label{page:RepresentingTM}
We don't give a machine to itself.
Instead, the machine gets a representation of itself.
We run Turing machines by putting symbols on the tape as data
and pressing Start.
So if we show how to represent something with symbols on tape,
including representing a Turing machine on a tape, then 
we've shown how to get a machine to take that representation as input.

First, a technical point.
Turing machines have a tape alphabet.
So what we put on the tape has to be
input that the machine is defined as able to take.
But every Turing machine takes at 
least two symbols (one of which is a blank) so if we
figure out how to do a 
representation in binary then we are OK. 

Here is one way that we can represent a Turing machine on a tape.
(We use \str{1} for the machine's second symbol.)
Encode each four-tuple as a sequence of four blocks 
of \str{1}'s, separated by single~\str{B}'s.
The first block encodes the current-state number using the 
representation where the number~$n$ is represented by 
$n+1$-many \str{1}'s (use an extra \str{1} so that $0$'s representation is 
nonempty).
The second block encodes the current symbol, 
with \str{1} representing the blank
and \str{11} representing the one.
The third block gives the next-state number, represented in the way the
first block is represented.
For the fourth block, encode
writing a blank symbol as \str{1}, encode writing a one as~\str{11}, 
encode a move to the left~$L$ as \str{111}, and a move to the right~$R$ 
as \str{1111}.
To represent a complete machine,  
put tuples on the tape in any order, separated by two blanks~\str{BB}.
Finally, separate the description of the machine from 
the input with three blanks~\str{BBB}.
This encoding will suffice as input to any other machine,
provided the second one can accept \str{1}'s
(all Turing machines including blanks).

So, for any Turing machine, we could 
put its representation on the tape of another Turing machine 
(that accepts \str{1}'s),
or on its own tape (if it accepts \str{1}'s), and press \texttt{Start}.
If, say, the machine that we just started is an input doubler 
then the output may well not have any apparent 
sensible connection to the fact that the input represents a Turing machine.
Nonetheless, feeding a Turing machine as input to another Turing machine, 
or to itself, is perfectly possible.

Now that we know representation is possible, what remains is to see that 
there are 
universal machines, ones that can act like the thing that is represented.
With such a device, 
changing its behavior would only involve putting
new stuff on the tape\Dash this is like the punched cards, which
alter the behavior of the machine without any hardware patch chords.
In Turing's time, showing that $\UTM$'s exist required
a detailed analysis so that is what he did.
We instead appeal to the experience that we have from 
everyday computing experience.

\subsection{Uniformity}
We've argued that there are functions that no program can perform.
But why not?  Functions just output bit strings,
\str{0}'s and \str{1}'s.
Can't we just put out whatever \str{0}'s and \str{1}'s that we like?  
What's to stop us?

% \begin{example}
Consider this job:~given a real number $\leftclosed{0}{1}$,
write a program to produce its digits.
This asks for a family of programs,
a $\TM_r$ for each $r\in\leftclosed{0}{1}$,
such that when given input~$n\in\N$ the program returns the
$n$-th decimal digit of~$r$.
There are some $r$'s for which there is such a program, such as $r=1/3$.
For a more generic number, like $r=0.703\ldots$,
we might briefly think of brute-forcing it.
\begin{lstlisting}
read n
if n==0:
    print 7
elif n==1:
    print 0
...
\end{lstlisting}
But this won't work, obviously.
Programs have finite length.
The program code could have \codeinline{if .. else ..} exceptions for a few
of the digits but for all but finitely many of them it needs a uniform
approach.
At some point there must be code that handles all but finitely many
input~$n$'s.

By cardinality, we know that there is no such family of programs:
with finite-length objects we can describe countably many things.
But $\leftclosed{0}{1}$ has uncountably many members.
% \end{example}

% Of course, being able to print out the digits does not make a program
% able to print the digits of $\pi$.
% Willy-nilly versus uniform is the difference between scissors and surgery.

This requirement of uniformity can have unexpected ramifications.

\begin{example} \label{ex:NineInPi}
Consider this problem:~given a number $n$, 
decide whether somewhere in the decimal expansion of~$\pi=3.14159\ldots{}$ 
there is a sequence of 
\citetext{$n$~consecutive nines}{%
  At the $762$-nd decimal point there are 
  six nines in a row.  
  This is call the Feynman point; see 
  \protect\url{https://en.wikipedia.org/wiki/Feynman_point}.
  Most experts guess that for any~$n$ the decimal 
  expansion contains a sequence of 
  $n$ consecutive nines but no one has proved or disproved that.}.    
There are two possibilities.
Either for all numbers such a sequence exists, or else there is some
$n_0$ where the sequence exists for numbers less or equal to~$n_0$ and no such
sequence exists for numbers larger than that.

Thus, the problem is solvable by one of these two programs.
\begin{center}
\vspace*{-4ex}
\begin{minipage}[t]{0.4\linewidth}%
\begin{lstlisting}
read n
print 1
\end{lstlisting}%
\end{minipage}%
\hspace*{2em}
\begin{minipage}[t]{0.4\linewidth}%
\begin{lstlisting}
read n
if n < n0:
    print 1
else:
    print 0
\end{lstlisting}%
\end{minipage}%
\vspace*{-2ex}
\end{center}
Each of these solutions has the requisite uniformity so each is an acceptable
answer.
It is a little odd that neither has much to do with $\pi$, but
that was not part of the problem requirements.

One paradoxical aspect of this is that
although we have just shown this problem is mechanically solvable,
nonetheless we do not know what that solution is.
There is a difference between defining this function
\begin{equation*}
  f(n)=
  \begin{cases}
    1 &\case{if there are $n$ consecutive $9$'s}  \\
    0 &\case{otherwise}
  \end{cases}
\end{equation*}
and giving an algorithm to compute it.

This is reminiscent of the  
\citetext{Schr\"odinger's cat paradox}{See \protect\url{https://en.wikipedia.org/wiki/Schr\%C3\%B6dinger's_cat}.}. 
Only we had super powers to somehow take a peek 
then we'd see which one of the two is right, but as it stands
we just don't know.
Nevertheless, here one of the two is right,
and the problem is solvable.
\end{example}



\subsection{Parametrization}
% \subsection{$\mathbf{s}$-$\mathbf{m}$-$\mathbf{n}$ theorem}
% ====== S-m-n, uniformity
We can understand universality to be that there is a computable
function $\map{F}{\N^2}{\N}$ such that
$F(e,x)=\phi_e(x)$.
There, the letter~$e$ travels from the function's argument to an index.
We now generalize this observation.

Consider a two-input program $\TM_e(x,y)$.
Freezing the first argument, that is, locking $x=a$ for some $a\in\N$,
gives a one-input program $\TM{Q}_a(y)=\TM_e(a,y)$.
For example, starting with the program
\begin{lstlisting}
  P(x,y)
\end{lstlisting}
and fixing the first input at $a=7$ gives a one-input program.
\begin{lstlisting}
  Q_7(y)  
\end{lstlisting}
This is \definend{partial application}.
Obviously the second program is related to the first.
The next result is that the index of the second program is computable from the
first.

\begin{theorem}[Parameter theorem, or \smn{} theorem] \label{th:smn}
For every $m,n\in\N$
there is a computable function $\map{s}{\N^{1+m}}{\N}$ with this behavior:
where $m+n$-ary function computed by $\TM_e$ is
$\TMfcn_e(x_0,\ldots,x_{m-1},x_m,\ldots,x_{m+n-1})$,
freezing the initial $m$~variables at $a_0,\ldots,a_{m-1}\in\N$
gives the function computed by $\TM_{s(e,a_0,\ldots,a_{m-1})}$.
\end{theorem}

\begin{proof}
We must create $s$ to be effective, to input 
an index~$e$ and an $m$-tuple $x_0,\ldots,x_{m-1}$,
and to output the index of a machine~$\hat{\TM}$.
This machine~$\hat{\TM}$, when given the input $x_m,\ldots,x_{m+n-1}$,
will return
$\TMfcn_e(x_0,\ldots,x_{m-1},x_m,\ldots,x_{m+n-1})$.

Basically, $s$ constructs the instructions for~$\hat{\TM}$.
We know how to get from the instruction set to the index,
using Cantor's encoding, so then we are done.
The flowchart for $s$ is on the left below.
\begin{center}
  \vcenteredhbox{\includegraphics{background/asy/flowcharts/flowcharts00.pdf}}
  \hspace{3em}
  \vcenteredhbox{\includegraphics{background/asy/flowcharts/flowcharts01.pdf}}
\end{center}
The flowchart for $\hat{\TM}$, the Turing machine that $s$ constructs,
is on the right.
Before considering that, recall that we are being flexible about
the convention for Turing machines that take more than one input.
To be clear here, we assume for this argument that input
is encoded in unary, with the number~$k$ represented by
a string of $k$-many \str{1}'s, that
multiple inputs are separated with a single blank, and that
when the machine is started the head should be under the input's
left-most \str{1}.

With that, 
the machine $\hat{\TM}$ does not start by reading
its inputs $x_m,\ldots,x_{m+n-1}$.
Instead, it moves left and puts $x_0,\ldots,x_{m-1}$ on the tape,
in unary and separated by blanks.
Thus, 
when this phase is done the machine will have $x_0,\ldots,x_{m+n-1}$ on the
tape, in unary and separated by blanks.
Next move the I/O head until it is on the leftmost \str{1}
of the $x_0$.
Finally, turn control
over to Turing machine~$P_e$ (using universality),
which will run on that input list.
\end{proof}

The following Scheme code implements $s_{1,1}$.
(The \lstinline!gensym! function produces a symbol that does not appear
elsewhere in the program.)
% https://en.wikipedia.org/wiki/Smn_theorem
\begin{lstlisting}

   (let ((y (gensym)))
     (list 'lambda (list y) (list f x y))))
\end{lstlisting}
For example, in the addition function \lstinline!(lambda (x0 x1) (+ x0 x1))!
we can fix the first variable~\lstinline!x! to have the value~$3$ with 
the invocation \lstinline!(s_1_1 '(lambda (x0 x1) (+ x0 x1)) 3)!, which  
evaluates to the one-input function 
\lstinline!(lambda (g42) ((lambda (x0 x1) (+ x0 x1)) 3 g42))! that 
adds~$3$ to its argument.

\section{The \HP}
We've showed that
there are functions that are not mechanically computable.
We gave a counting argument, that there are countably many Turing machines but 
uncountably many functions and so there are functions without an
associated machine.
While knowing what's true is a step forward,
our taste is to prefer to construct a specific function rather than to just
know there is one.
We will now do that.



\subsection{Definition}
The natural approach is to go through 
Cantor's Theorem and effectivize it,
to see how much of the proof we can express as a construction.

Consider an illustrative table adapted from the discussion of
Cantor's Theorem on 
\cpageref{ex:DiagonalizationTable}.
This table's rows are the computable functions and 
its columns are the inputs.
For instance, this table imagines that $\phi_2(3)=5$.

Diagonalize.
That is, consider the program on the right
and note that its output is not any of the table's rows.
That contradicts the supposition that
the rows are all of the computable functions.

But we know that the Turing machines are enumerable.
So what's the resolution?
Its about halting\Dash among the computable functions 
there must be one that on some input does not converge.
In particular this must happen on the diagonal; there must be
an $e\in\N$ so that $\phi_e(e)\diverges$.
This makes the difficulty dissolve because for those input~$e$'s
in the flowchart, the program will never leave 
the middle box and so will never get to the contradictory output.
To prevent a contradiction,
in the above table some of the entries must be up arrows, $\uparrow$.

\begin{definition}
  $\definend{K}=\set{e \suchthat \text{$\TM_e$ halts on input~$e$}}$
\end{definition}

\begin{problem}[Halting Problem]  \label{prob:HaltingProblem}
Given~$e\in\N$ determine whether Turing machine~$\TM_e$ halts on input~$e$,
that is, whether $\TMfcn_e(e)\converges$.
\end{problem}

Certainly for any $e\in\N$, either $\TMfcn_e(e)\converges$ or
$\TMfcn_e(e)\diverges$.
Thus there is a function giving $1$ in the first case and $0$ in the second.
The \HP{} is to find a Turing machine whose behavior is that function.
That is, the \HP{} is to produce a program 
$\computablefunction{halt\_checker}$ that acts as the characteristic
function of $K$, returning $1$ if $\TM_e$ halts on input~$e$ and
returning~$0$ otherwise.


\begin{theorem}[Unsolvability of the \HP]
The \HP{} is mechanically unsolvable.
\end{theorem}

\begin{proof}
Assume otherwise, that there is a Turing machine whose behavior is this.
\begin{equation*}
  K(e)=
  \computablefunction{halt\_checker}(e)=
  \begin{cases}
  1  &\case{if $\TMfcn_e(e)\converges$}  \\
  0  &\case{if $\TMfcn_e(e)\diverges$} 
  \end{cases}
\end{equation*}
Then the function below is also mechanically computable.
The flowchart illustrates $f$'s construction;
it uses $\computablefunction{halt\_checker}$ for the branch.
\begin{center}
\begin{minipage}{0.3\textwidth}
  \begin{equation*}
  f(e)=
    \begin{cases}
    0    &\case{if $\TMfcn_e(e)\diverges$}  \\
    \uparrow  &\case{if $\TMfcn_e(e)\converges$}
    \end{cases}
  \end{equation*}
\end{minipage}
\hspace{2.5em}
\vcenteredhbox{\includegraphics{background/asy/flowcharts/flowcharts02.pdf}}
\end{center}
(In the function's first case it doesn't matter
that $f(e)$ outputs~$0$, just that it converges.)
Since $f$ is mechanically computable it has an index.
Let that index be~$\hat{e}$, so that
$f(x)=\TMfcn_{\hat{e}}(x)$ for all inputs~$x$.

Now feed $f$ its own index; consider $f(\hat{e})=\TMfcn_{\hat{e}}(\hat{e})$.
If it diverges then by the first clause in the definition of~$f$
we have $f(\hat{e})\converges$,
which contradicts that $f$~diverges.
If it converges then by $f$'s second clause 
we have $f(\hat{e})\diverges$, also impossible.
Since assuming that $f$ is constructed from mechanically computable
parts is contradictory,
the part from which $f$ is constructed,
$\computablefunction{halt\_checker}$,
is not mechanically computable.
\end{proof}

\noindent Instead, the unsolvability of the Halting Problem 
says that there is no single program that, for all~$e$, correctly computes 
in a finite time whether $\TM_e$ halts on input~$e$.

The ``finite time'' qualifier is there because we could just use a universal
Turing machine to simulate $\TM_e$ on~$e$, but if that machine failed to halt
then we would not find out in a finite time. 

The ``single program'' qualifier is there because for any index~$e$,
either $\TM_e$ halts on~$e$ or it does not.
That is, for any~$e$ one of these two programs
gives the right answer.
\begin{center}
% \vspace*{-4ex}
\vspace*{-\ht\strutbox}
\begin{minipage}[t]{0.4\linewidth}%
\begin{lstlisting}
read e
print 0
\end{lstlisting}%
\end{minipage}%
\hspace*{2em plus 0.5fil}
\begin{minipage}[t]{0.4\linewidth}%
\begin{lstlisting}
read e
print 1
\end{lstlisting}%
\end{minipage}%
% \vspace*{-2ex}
\end{center}
Thus, the unsolvability of the Halting Problem is about 
the non-existence of a single program that works across all
indices.
It speaks to uniformity,
or rather, the impossibility of uniformity.




\subsection{Significance}  \label{subsec:Significance}
A beginning programming class could leave the 
impression that if a program doesn't halt then
it just has a bug, something fixable.
So the \HP{} could seem to be not very interesting. 
That impression is wrong.

Imagine 
a utility for programmers, $\computablefunction{always\_halt}$,
to patch non-halting programs.
After writing a program~$\TM$ we run it through the utility, which
modifies the source so that for any input where $\TM$ fails to halt,
the modified program will halt (and output $0$) but the utility
does not change any outputs where $\TM$ does halt.
That would cause the list of all programs to give rise to a 
list of total functions like the one on \cpageref{ex:DiagonalizationTable}
and diagonalization gives a contradiction.

Thus, halting, or rather failure to halt, is central
to the nature of comptuation.
In any general computational scheme
there must be some computations that halt on all inputs, 
some that halt on no inputs, 
and some that \citetext{halt on some inputs but not on others}{A 
  Turing machine could fail to halt because it has an infinite loop.
  The Turing machine
  $\TM_0=\set{\tminstruction{0}{B}{B}{0},
    \tminstruction{0}{1}{1}{0}}$
  never halts, cycling forever in state $q_0$.
  We could patch this problem; we could write a program
  $\computablefunction{inf\_loop\_checker}$ that at each
  step checks whether a machine has ever before in this computation
  had the same configuration as it has now.
  This program will detect infinite loops like the prior one.
  
  However, note that there are machines that fail to halt but
  do not have loops, in the sense that they never repeat a configuration.
  One is $\TM_1=\set{\tminstruction{0}{B}{1}{1},
        \tminstruction{1}{1}{R}{0}}$
  which when started on a blank tape will endlessly move to the right,
  writing \str{1}'s.}.

That alone is enough to justify study of the \HP{} but we will give a 
second reason.
If $\computablefunction{halt\_checker}$ were a computable function
then we could solve many problems that we currently don't know how to solve. 
For instance, a natural number is \textit{perfect} if it is the 
sum of its proper positive divisors.
Thus $6$ is perfect because $6=1+2+3$.
Similarly, $28 = 1 + 2 + 4 + 7 + 14$ is perfect.
% and after that comes $496$ and~$8128$.
These were studied as far back as Euclid and
today we 
\citetext{understand the form of all even perfect numbers}{A 
number is an even perfect number if and only if it has the form 
$(2^p-1)\cdot 2^{p-1}$ where $2^p-1$ is prime.}.
But we do not know if there are any odd perfect numbers.

With a solution to the Halting Problem we could settle that question.
The
\margingraphicnomag*[l]{.425\textwidth}{background/asy/hp/hp00.pdf}
program shown here searches for an odd perfect number.\footnote{It takes an
input $x$ but ignores it; in this book we have a convention that 
all programs take an input, and all give an output.}
If it finds one then it halts.
If not then it does not halt.
So giving $\computablefunction{halt\_checker}$ the index of this program
would settle whether there exists an odd perfect number.
There are many open questions 
\citetext{involving an unbounded search}{%
A computer program that solved 
the Halting Problem, if one existed, could be very slow. 
So this might not be a feasible way to settle this question.  
But at the moment we are studying what can be done in principle.} 
that would fall to this approach.
 
Before moving on, we note the appearance here of the theme of unbounded search.
It does not just appear in looking for perfect numbers.
The obvious way to test whether $\phi_e(e)\converges$
is to run a brute force computation, an unbounded
search for a stage at which the computation halts.

\subsection{General unsolvabilty}
The \HP{} is part of a larger unsolvability phenomenon.

\begin{example} \label{ex:HaltOnThree}
Consider the problem of determining whether a given Turing machine halts 
on the input~$3$.
\begin{equation*}
  \computablefunction{halts\_on\_three\_checker}(x)=
  \begin{cases}
    1 &\case{if $\TM_x$ halts on input~$3$}  \\
    0 &\case{otherwise} 
  \end{cases}
\end{equation*}
We will show that this problem is mechanically unsolvable, that there is no
Turing machine whose input-output behavior is as above.
We will do that by showing 
that if $\computablefunction{halts\_on\_three\_checker}$ 
were a computable function then we could solve the \HP.
% \margingraphicnomag*[r]{.3\textwidth}{background/asy/hp/hp06.pdf}

Here is the idea.
Consider the program on the right below.
The middle box
simulates running $\TM_x$ on input~$x$.
If that simulation halts then the program as a whole halts
(it reads the input~$y$, ignores it, and gives a nominal output).
If that simulation does not halt then this program as a whole
does not halt, regardless of the input.
Thus, this program halts on input~$y=3$ if and only if 
$\TM_x$ halts on~$x$.
This flowchart shows that if we were able to answer questions about 
halting on~$3$ then we could leverage that to answer
questions about whether $\TM_x$ halts on~$x$.
\begin{center}
  \includegraphics{background/asy/hp/hp06.pdf}
  \hspace*{3em}
  \includegraphics{background/asy/hp/hp07.pdf}
\end{center}
But we don't want to only determine whether $\TM_x$ 
halts on~$x$ for a single~$x$.
We next bring in uniformity, using the program on the left.

Assume that $\computablefunction{halts\_on\_three\_checker}$ is a computable
function and consider this function.
\begin{equation*}
  \psi(x,y)=
  \begin{cases}
    0 &\case{if $\phi_x(x)\converges$} \\
    \uparrow &\case{otherwise}
  \end{cases}
\end{equation*}
It is computed by the flowchart on the left above, so by Church's Thesis
there is a Turing machine whose input-output behavior is $\psi$.
That Turing machine has some index~$e$, meaning that $\psi=\phi_e$.

Apply the \smn{} theorem to parametrize~$x$, giving $\phi_{s(e,x)}$.
This is a family of functions, parametrized by $x$,
illustrated by the flowchart on the right above.
As discussed, $\phi_x(x)\converges$ if and only if
$\computablefunction{halts\_on\_three\_checker}(s(e,x))=1$.
Therefore, 
the supposition that $\computablefunction{halts\_on\_three\_checker}$ is 
computable gives that the composition of the two functions
$\composed{\computablefunction{halts\_on\_three\_checker}}{s}$
is computable, which gives that the \HP{} is mechanically solvable, 
which is false.
The conclusion is that $\computablefunction{halts\_on\_three\_checker}$
is not mechanically computable.
\end{example}

demonstrating algorithmic unsolvability.

We closes with two comments.
The first is to reiterate that when we say that a problem is
unsolvable we mean that it is unsolvable
by a mechanism, that there  
is no Turing machine that can compute the solution to the problem.
There may well be a \citetext{function that solves it}{\autocite{wiki:ouija}}
but there is no computable function that solves it.

Out second comment is some intuition about which problems are unsolvable.
There certainly are problems that start with ``Given~$e$'' that we can solve.
Just to list one: given~$e$ decide if one instruction in $\TM_e$ is 
$\tminstruction{0}{B}{L}{1}$.
But that problem differs from the problems above.
Each of the above examples is about the behavior of the computed function\Dash
each is about $\phi_e$, rather than about the
internal details of $\TM_e$.

This echos the opening of the first chapter,
which says that we are more
interested in the input-output behavior of the machines than in their
implementation details. 
The next subsection expands. 




\subsection{Rice's Theorem}
The prior subsection shows a number of problems to be unsolvable.
The intuition from those examples is that
we cannot, given $e$, analyze the behavior of $\TM_e$ mechanically.
We now make that intuition precise.
We start with two definitions that formalize `behavior'.

\begin{definition}
Two computable functions
\definend{have the same behavior $\TMfcn_{e}\samebehavior\TMfcn_{\hat{e}}$}
if they converge on the same inputs~$x\in\N$
and, when they do converge, they have the same outputs. 
\end{definition}

\begin{definition}
A set $\mathcal{I}$ of natural numbers is an \definend{index set} if for all 
indices~$e,\hat{e}\in\N$,
if $e\in\mathcal{I}$ and $\TMfcn_e\samebehavior\TMfcn_{\hat{e}}$ 
then also~$\hat{e}\in\mathcal{I}$. 
\end{definition}

\begin{example}
This set of indices
$\mathcal{I}=\set{e\in\N\suchthat \text{$\phi_e(x)=2x$ for all $x$}}$
is an index set. 
Suppose that $e\in\mathcal{I}$ and that $\hat{e}\in\N$ is such that 
$\phi_e\samebehavior \phi_{\hat{e}}$. 
Then the behavior of $\phi_{\hat{e}}$ is also to double its input: 
$\phi_{\hat{e}}(x)=2x$ for all~$x$.
Thus $\hat{e}\in\mathcal{I}$ also.
\end{example}

\begin{example}
The set
$\mathcal{J}=\set{e\in\N\suchthat
      \text{$\phi_e(x)=3x$ for all $x$, or $\phi_e(x)=x^3$ for all~$x$}}
$
is an index set.
For, suppose that $e\in\mathcal{J}$ and that  
$\phi_e\samebehavior \phi_{\hat{e}}$  where $\hat{e}\in\N$.
Because $e\in\mathcal{J}$, either 
$\phi_e(x)=3x$ for all $x$ or $\phi_e(x)=x^3$ for all~$x$.
Because $\phi_e\samebehavior \phi_{\hat{e}}$ we know that
either $\phi_e(x)=3x$ for all $x$ or $\phi_e(x)=x^3$ for all~$x$, and  
thus $\hat{e}\in\mathcal{J}$.
\end{example}

\begin{example} \label{ex:NotIndexSet}
The set $\set{e\in\N\suchthat
      \text{$\TM_e$ contains an instruction starting with $q_1$}}$ 
is not an index set.
We can easily produce two Turing machines with the same behavior,
such as giving a constant output of $0$,
where one machine contains such an instruction while the other does not.
\end{example}


\begin{theorem}[Rice's Theorem]   \label{thm:RicesThm}
Every index set that is nontrivial, that is not empty and not 
all of $\N$, is not computable.
\end{theorem}

\begin{proof}
Let $\mathcal{I}$ be an index set.
Choose an~$e_0\in\N$ so that $\phi_{e_0}(y)\diverges$ for all~$y$.
Then either $e_0\in\mathcal{I}$ or $e_0\notin\mathcal{I}$.
We shall show that in the second case $\mathcal{I}$ is not computable. 
The first case is similar and is \cref{exer:OtherHalfRicesThm}.

So assume $e_0\notin\mathcal{I}$.
Since $\mathcal{I}$ is not empty there is an index~$e_1\in\mathcal{I}$.
Because $\mathcal{I}$ is an index set $\phi_{e_0}\not\simeq\phi_{e_1}$
and there is an input~$y$ such that $\phi_{e_1}(y)\converges$.

Consider the flowchart on the left below.
(Note that $e_1$ is not an input, it is hard-coded into the source.)
By Church's Thesis there is a Turing machine with that behavior,
let it be~$\TM_e$.
Apply the \smn{} theorem to paramatrize~$x$,
resulting in the uniformily computable 
family of functions $\phi_{s(e,x)}$, whose behavior is 
charted on the right.
\begin{center}
  \vcenteredhbox{\includegraphics{background/asy/hp/hp12.pdf}}
  \hspace{2em plus 0.5fil}
  \vcenteredhbox{\includegraphics{background/asy/hp/hp13.pdf}}
\end{center}
We've constructed the functions on the right so that if 
$\phi_x(x)\diverges$ then $\phi_{s(e,x)}\samebehavior\phi_{e_0}$
and thus $s(e,x)\notin\mathcal{I}$, and so that
if $\phi_x(x)\converges$ then $\phi_{s(e,x)}\samebehavior\phi_{e_1}$
and thus $s(e,x)\in\mathcal{I}$.
Therefore being able to check whether an index $s(e,x)$
is an element of~$\mathcal{I}$
would allow us to solve the \HP.
\end{proof}


\begin{example}
Show using Rice's Theorem that this problem is unsolvable: 
given $e$, decide if $\phi_e(3)\converges$.    

Consider the set
$
  \mathcal{I}=\set{e\in\N \suchthat \phi_e(3)\converges}
$.
To apply Rice's Theorem we must show that it is not empty, that 
it is not all of~$\N$, and that it is an index set.
This set is not empty because we can write a Turing machine that 
acts as the identity function $\phi(x)=x$, and if $e_0$ is the index of that 
Turing Machine then $e_0\in\mathcal{I}$.
The set is not all of $\N$ because, 
where $e_1$ is the index of a Turing Machine that never halts then
$e_1\notin\mathcal{I}$.

To show that~$\mathcal{I}$ is an index set, assume that
$e\in\mathcal{I}$ and 
that $\hat{e}\in\N$ is such that $\phi_e\samebehavior\phi_{\hat{e}}$.
Then $e\in\mathcal{I}$ gives that  $\phi_e(3)\converges$ and 
$\phi_e\samebehavior\phi_{\hat{e}}$ gives that
$\phi_{\hat{e}}(3)\converges$ also.
Hence $\hat{e}\in\mathcal{I}$, and it is an index set.  
\end{example}

\begin{example}
Show that this problem is unsolvable:
given $e$, decide if $\phi_e(x)=7$ for some~$x$.    

We will show that
$\mathcal{I}=\set{e\in\N \suchthat \text{$\phi_e(x)=7$ for some $x$}}$
is a nontrivial index set.
It is not empty because where $e_0$ is the index of a 
Turing Machine that acts as the identity function $\phi_{e_0}(x)=x$
then the input $x=7$ produces the output~$7$
so $e_0\in\mathcal{I}$.
It is not all of $\N$ because, 
where $e_1$ is the index of a Turing Machine that never halts, 
$e_i\notin\mathcal{I}$.
So this set is nontrivial.

Showing that $\mathcal{I}$ is an index set is straightforward.
Assume that $e\in\mathcal{I}$ and that $\hat{e}\in\N$ is such that
$\phi_e\samebehavior\phi_{\hat{e}}$.
Byt the first assumption, $\phi_e(x_0)=7$ for some input~$x_0$.
By the second,
$\phi_{\hat{e}}(x_0)=7$ also. 
Consequently, $\hat{e}\in\mathcal{I}$.
\end{example}

To recap, 
Rice's Theorem speaks to the behavior of the machines.
It addresses the properties of the functions
associated with the machines, rather than the properties of the machines
themselves.
For an example from everyday programming:~the set of functions
computed by C~programs whose $100$-th character
is a `k' would not be an index set. 

We saw by a counting argument that there are unsolvable problems.
The Halting Problem shows us that there some interesting problems 
that are unsolvable.
Rice's Theorem in a sense tells us that \emph{every} interesting problem
is unsolvable.
That sense is that a problem is `interesting' if it encapsulates some behavior,
if it gives rise to 
a nontrivial index set.

\section{Computably enumerable sets}
% Required for the section on oracles, which in turn is required
% for the seciton on barriers to solving P=NP.
The natural way to attack the \HP{} is to 
use universailty to simulate running $\TM_0$ on input~$0$ for a few
steps, and then simulate $\TM_1$ on input~$1$ for a few steps.
Then run $\TM_0$ on~$0$ for a few more steps,
followed by $\TM_1$ on~$1$ for a few more,
and then $\TM_2$ on~$2$ for a few steps.
Keep cycling among the $\TM_e$ on~$e$ simulations,
running each for a few mopre steps before going on.
Over time some of these calculations will halt and so
the elements of $K$ will fill in.
(This interleaving the computations is
  \definend{dovetailing}.)

Of course the problem is with the complement.
For those indices~$e$ where $e\notin K$, the computation never halts.
You just wait, forever.

\begin{definition}
A set is \definend{computably enumerable} (or \definend{recursively enumerable},
or \definend{c.e.}, or \definend{r.e.})
if it is effectively listable, that is, if it is
the set of outputs of some computable function
\definend{$W_e=\set{k\suchthat \text{$k=\TMfcn_e(i)$ for some $i\in\N$}}$}.
\end{definition}

The term `enumerable' comes from picturing a stream of output
$f(0)$, $f(1)$, $f(2)$, \ldots{} that fills out the set.
A computably enumerable set can be empty, if
$\TMfcn_e$ never halts.

\begin{lemma}
\begin{thmparts}
\item \label{lem:SetComputableThenSetCE}
  If a set is computable then it is computably enumerable.
\item \label{lem:SetComputableIffSetAndCompCE}
  A set is computable if and only if both it and its
  complement are computably enumerable.
\end{thmparts}
\end{lemma}

\begin{proof}
For \cref{lem:SetComputableThenSetCE} let the set~$S\subseteq\N$ be computable
and we will produce an effective enumeration~$\map{f}{\N}{\N}$.
We take two cases.
If $S$ is finite then take $f(0)=s_0$, $f(1)=s_1$, \ldots
$f(n-1)=s_{n-1}$, and for any larger input $m>n$, define $f(m)\diverges$.
The other case is that $S$ is infinite.
For~$f(0)$, find the smallest element of~$S$ 
by trying $S(0)$, $S(1)$, \ldots\@ 
This unbounded search is effective because~$S$ is computable
and it must halt because $S$ is infinite.
Similarly, define $f(k)$ to be the $k$-th smallest element in~$S$.

For \cref{lem:SetComputableIffSetAndCompCE} first
suppose that $S$ is computable.
Then the prior item shows that it is computably enumerable.
And, since the complement of a computable set is also computable,
the prior item also
gives that $\setcomp{S}$ is computably enumerable.

For the other direction of \cref{lem:SetComputableIffSetAndCompCE},
suppose that both $S$ and $\setcomp{S}$ are computably enumerable
and that $S$ is enumerated by~$f_S$ while $\setcomp{S}$ is
enumerated by $f_{\setcomp{S}}$.
Given an input~$x\in\N$,
effectively determine which of the two sets contains~$x$ by
dovetailing their enumerations.
That is, first run the computation of $f_{S}(0)$ for a step.
Then run the computation of $f_{S}(0)$ for a second step and
$f_{\setcomp{S}}(0)$ for a step.
Next run the computation of $f_{S}(0)$ for still another step and
$f_{\setcomp{S}}(0)$ for another step, and $f_{S}(0)$ for a step.
The sets are complements so eventually $x$ is enumerated into one or the other.
\end{proof}

\begin{lemma} \label{lem:CEIffDomainOfComputableFcn}
A set is computably enumerable if and only if it is the domain of a
partial computable function.
\end{lemma}

\begin{proof}
Assume first that $S$ is computably enumerable, so it 
is the range of a computable function~$f$.
We produce an effective~$\map{g}{\N}{\N}$ that converges if and only
if the input is an element of~$S$.
Given the input $x\in\N$,
enumerate the outputs $f(0)$, $f(1)$, \ldots, and wait for~$x$ to appear.
If it does appear then halt and return some nominal value.
If it never appears then this procedure~$g$ never halts.

The implication in the other direction is more involved.
Assume that $S$ is the domain of the partial computable function~$g$.
If $S$ is empty then it is computably enumerable by definition.
So assume that~$S$ is not empty and fix some $\hat{s}\in S$. 
We will produce a computable function~$f$ whose range is~$S$. 
Given input $n\in \N$, run the computations of 
$g(0)$, $g(1)$, \ldots\,$g(n)$ for $n$-many steps each.
Possibly some of these computations halt.
Define $f(n)$ to be the least $k$ so $g(k)$ halts within~$n$ steps and such
that $k\notin\set{f(0),f(1),\ldots f(n-1)}$.
If no such $k$ exists then define $f(n)=\hat{s}$.

If $s\in S$ then eventually $g(s)$ must converge,
in some number~$n_s$ of steps.
At that point the number~$s$ is queued for output by~$f$, in the sense that
it will be enumerated by~$f$ as, at most, $f(n_s+s)$. 
\end{proof}

\begin{lemma}
The \HP{} set $K$ is computably enumerable.
Its complement $\setcomp{K}$ is not.
\end{lemma}

\begin{proof}
The set $K$ is the domain of the partial computable function~$\TMfcn_e$.
If the complement~$\setcomp{K}$ were computably enumerable then 
$K$ would be computable, but by unsolvability of the
\HP{} it is not.
\end{proof}

We close with a different way to look at computably enumerable sets that
relates to later chapters.
A set of natural numbers
is \definend{decidable}
(or \definend{computable}) if its
characteristic function is computable.
So a set is computable if and only if there is a
Turing machine that, given an input number,
will decide `yes' or `no' whether the input is a member of the set.
In contrast,
with computably enumerable sets there is a Turing machine that,
given an input number, will decide `yes' if that number is in the set;
see \cref{ex:TuringRecognizers}.
But there is no requirement that there be a machine to decide `no'.
(If there is a machine to decide `no' then the computably enumerable
set is computable.)

Restated, a set is computable if there is a Turing machine that acts
as a decider on the question of membership or non-membership.
A set is computably enumerable if there is a Turing machine that
recognizes members.
For this reason, the computably enumerable sets are also called 
\definend{semidecidable}.

\section{Oracles} \label{sec:Oracles}
The \HP{} is unsolvable.
Does that make it the absolutely hardest problem
or are there ones that are even harder?

What does it mean to say that one problem is harder than another?
When we considered the problem of whether
a Turing machine halts on input~$3$,
we proved that if we could solve it then we could solve the \HP.
That is, we proved that the halts-on-$3$ problem is at least as hard as the \HP.
So we have already encountered relative computability.
% the idea of ranking problems by:~a first problem is harder than a second one
% when a solution to the first would also give us a solution to the 
% second.

Under Church's Thesis we interpret the unsolvability of the \HP{} to
say that no mechanism can answer all questions about
membership in~$K$.
So if we want to think about answering questions about such sets, 
we must look for the answers to be supplied in some way
that
\citetext{won't be a physically-realizable discrete and deterministic
mechanism}{%
  Turing introduced oracles in his PhD thesis.
  He said, ``We shall not go any further into the nature of this oracle
  apart from saying that it cannot be a machine.''
  \autocite{TuringThesis}}.

\margingraphic{0.2\textwidth}{background/pix/delphi.png}{\label{fig:yogi}\href{https://en.wikipedia.org/wiki/Pythia}{The oracle at Delphi}}
Consequently, we posit that to the Turing machine CPU we attach a device,
an \definend{oracle},
that acts as the characteristic function of a set. 
To see what could be computed if only we could solve
the \HP{} we can attach a $K$-oracle,
answering questions of the form,
``Is $x\in K$; does $\TMfcn_{x}(x)\converges$?''
This is a black box, meaning that we don't open it to see how it
works.\footnote{%
  That would
  let out the \citetext{magic smoke}{See \autocite{wiki:MagicSmoke}.}.}

One way to define an oracle computation
extending that of Turing machines is:~to the action
symbols \str{L} and~\str{R}, add one more, \str{O}.
When this symbol applies, where the read/write head is pointing to the
leftmost \str{1} of a sequence of $n$-many \str{1}'s,
that sequence is replaced
by either a single~\str{1} followed by $n$-many \str{0}'s if $n\in A$,
or entirely by $n$-many \str{0}'s if $n\notin A$.

\begin{center}
  \includegraphics{asy/share/machine01.pdf}
\end{center}

This is \definend{computation relative to the oracle}.
For a full treatment see \autocite{Rogers}.
In this section, instead of working with the details of the
definition, including the low-level details of Turing machine computations,
we will use Church's Thesis and
discuss introducing into a programming language 
a Boolean function \codeinline{oracle(x)}.
% \begin{lstlisting}
% (if oracle(x)
%     #t  ;; How you write True in Scheme
%     #f)
% \end{lstlisting}
    
Here, as when we defined computation in the first chapter,
we have a family of programs, like programs we have considered earlier
except that they may contain the \codeinline{oracle(x)} call.
Each of these new program is a string and
we can list them effectively, for instance in ascending alphabetical order,
so each program has an index.
The index is source-equivalent:~from an index we can compute the
source associated with that index,
and from a source we can find the index.

In the setup pictured above, programs do not
change if we change the oracle\Dash
if we have an $A$ oracle box plugged in, and then unplug it and replace
it with a~$B$ oracle box, 
the source code is unchanged.
Of course, the values returned by \codeinline{oracle(x)} may change,
resulting in changes to the outcome of running that source code.
But the source itself stays the same.

Thus,
to specify the outcome of a relative computation, in addition to specifying
which program we are using, and which inputs,
we must also specify 
an oracle set.
That explains all the parameters in the notations for the
\definend{oracle Turing machine $\TM_e^A$}
and for the outcome of the
\definend{function computed relative to an oracle $\TMfcn^A_e(x)$}.

\begin{definition}
If the function computed from~$A$ is the characteristic function
of a set~$B$ then we say that \definend{$B$ is $A$-computable} or that
$B$ is \definend{Turing reducible} to~$A$,
denoted \definend{$B\leq_T A$}.\footnotemark[2]
\end{definition}\footnotetext[2]{The terminology
  ``$B$ is Turing-reducible to $A$''
  can at first seem reversed.
  The idea is that we can solve problem~$B$ by
  using a solution to~$A$.
  We use this phrase in other areas of Mathematics.
  For instance, we may say that the problem of finding the area under a
  curve reduces to the problem of antidifferentiation.}

Think of the set $B$ as being simpler, or at least no harder, than~$A$.

\begin{theorem}
\begin{thmparts}
\item A set is computable if and only if it is computable
relative to the empty set, or relative to any computable set.
\item \textsc{(Reflexivity)} Every set is computable from itself, $A\leq_T A$.
\item \textsc{(Transitivity)} If $A\leq_T B$ and $B\leq_T C$ then $A\leq_T C$.
\end{thmparts}
\end{theorem}

\begin{proof}
For the first, a set is computable if its characteristic function is computable.
Clearly if the characteristic function is computable without reference to an
oracle, then it can be computed by an oracle machine, simply by ignoring the
oracle.
For the other direction, suppose that a characteristic function can be computed
by reference to the empty set oracle (or any other computable oracle).
Then it can be computed without reference to an oracle by replacing
the oracle calls with computations.

The second item is clear.
For the third, suppose that $\TM_e^B$ computes the characteristic
function of~$A$ and that
$\TM_{\hat{e}}^C$ computes the characteristic function of~$B$.
Then in the computation of $A$ from $B$ we can replace the
$B$-oracle calls with calls to $\TM_{\hat{e}}^C$.
That gives a routine that computes the characteristic function of $A$
directly from~$C$.
\end{proof}

\begin{example}
Consider the problem of determining, given~$e$, whether $\TM_e$ halts
on input~$3$.
This problem asks for a program that acts as the
characteristic function of the set
$A=\set{e\suchthat \text{$\TM_e$ halts on~$3$}}$.
We will show that $K\leq_T A$.

This is a reprise of \cref{ex:HaltOnThree}.
Consider the function $\map{\psi}{\N^2}{N}$
that returns $0$ if $\TMfcn_x(x)\converges$ and that diverges otherwise.
By Church's Thesis
there is a Turing machine whose input-output behavior is $\psi$.
Let that machine have index~$e$, so that $\psi=\TMfcn_e$.
Apply the \smn{} theorem to parametrize~$x$, giving $\TMfcn_{s(e,x)}$.
Observe that $\TMfcn_x(x)\converges$ if and only if
$A(s(e,x))=1$.
That computes $K$ from an $A$~oracle.
\end{example}

Consider again the \HP, which is
to decide the characteristic function of the set
$\set{e\suchthat \text{$\TM_e$ halts on input~$e$}}$.
That may seem odd; 
surely the more natural question is whether $\TM_e$ halts on input~$x$?

\begin{definition}
  $\definend{K_0}=\set{\sequence{e,x} \suchthat \text{$\TM_e$ halts on input~$x$}}$
\end{definition}

We will argue that the problems of computing~$K$ and of computing~$K_0$
are equivalent, 
are inter-solvable, meaning that if you can solve the one then
you can solve the other and so the choice of problem is a 
matter of convenience and convention.
% \footnote{%  
%   For the definition we go with $K$ 
%   because it is the standard usage and because it has some technical advantages,
%   including that it falls out of the diagonalization development done
%   at the start of this subsection.}

\begin{definition}
Two sets $A,B$ are \definend{$T$-equivalent, $A\equiv_T B$} if $A\leq_T B$
and $B\leq_T A$.
For any set~$A$, the collection of sets $T$-equivalent to $A$ is the
\definend{Turing degree} of~$A$.
The Turing degree of~$A$ is denoted using boldface, as~\definend{$\textbf{a}$}.
\end{definition}

Showing that two sets are $T$-equivalent
shows that two seemingly-different problems are actually versions
of the same problem.

\begin{theorem}
$K\equiv_T K_0$.
\end{theorem}

\begin{proof}
For $K\leq_T K_0$ suppose that we have access to a $K_0$-oracle.
Since it can say whether $\TM_e$ halts on~$x$ for any input~$x$,
it can clearly say whether $\TM_e$ halts on~$e$.

For the $K_0\leq_T K$ half, suppose that we have access to a $K$~oracle.
The problem we must solve is:~given a pair $\sequence{e,x}\in\N^2$,
determine whether $\TM_e$ halts on input~$x$.
Consider the program sketched on the left below;
obviously it halts for all input triples exactly if $\sequence{e,x}\in K_0$.
By Church's Thesis there is a Turing machine implementing
it; let it be machine~$\TM_{\hat{e}}$.
\begin{center}
  \includegraphics{background/asy/hp/hp03.pdf}
  \hspace{2em plus 0.5fil}
  \includegraphics{background/asy/hp/hp04.pdf}
\end{center}
Get the 
flowchart on the right by applying the \smn{} theorem
to parametrize $e$ and~$x$. 
That flowchart represents a family of programs
with infinitely many
members, one for each pair $\protect\sequence{e,x}$.

Now suppose that we are given a pair $\sequence{e,x}$ and consider the 
right-side flowchart $\TM_{s(\hat{e},e,x)}$ associated with that pair.
It either halts on all inputs~$y$ 
or fails to halt on all inputs, depending on whether $\phi_e(x)\converges$.
In particular, taking the input to be the number of this machine
$y=s(\hat{e},e,x)$, we have that
$\TM_{s(\hat{e},e,x)}$ halts on input $s(\hat{e},e,x)$
if and only if $\phi_e(x)\converges$.
So with a $K$-oracle, we can solve the $K_0$~problem.  
\end{proof}

\begin{corollary}
The \HP{} is at least as hard as any computably enumerable
problem:~$W_e\leq_T K$ for all~$e\in\N$. 
\end{corollary}

\begin{proof}
By \cref{lem:CEIffDomainOfComputableFcn}
the computably enumerable sets are the columns of $K_0$.
\begin{equation*}
  \set{y\suchthat \TMfcn_e(y)\converges}
  =\set{\sequence{e,y}\in K_0 \suchthat y\in\N}
\end{equation*}
So $W_e\leq_T K_0\equiv_T K$.
\end{proof}


\begin{theorem}
The Relativized \HP{},
the problem of determining the characteristic function of 
$K^K=\set{x\suchthat \TMfcn_x(x)\converges}$,
is not computable from a $K$ oracle.
That is, there is no index~$e\in\N$ such that $\TMfcn_e^K=K^K$.
\end{theorem}

\begin{proof}
We adaptat the proof that the \HP{} is unsolvable.
Assume otherwise, that there is a mechanical computation relative to a
$K$~oracle with this behavior.
\begin{equation*}
  K^K(e)=
  \begin{cases}
  1  &\case{if $\TMfcn^K_e(e)\converges$}  \\
  0  &\case{if $\TMfcn^K_e(e)\diverges$} 
  \end{cases}
  \tag{$*$}
\end{equation*}
Then the function below is also computable relative to a $K$~oracle.
The flowchart illustrates $f$'s construction;
it uses the above function for the branch.
\begin{center}
\begin{minipage}{0.3\textwidth}
  \begin{equation*}
  f(e)=
    \begin{cases}
    0    &\case{if $\TMfcn^K_e(e)\diverges$}  \\
    \uparrow  &\case{if $\TMfcn^K_e(e)\converges$}
    \end{cases}
  \end{equation*}
\end{minipage}
\hspace{2.5em}
\vcenteredhbox{\includegraphics{background/asy/flowcharts/flowcharts03.pdf}}
\end{center}
Since $f$ is an oracle-computable function, it has an index.
Let that index be~$\hat{e}$, so that
$f(x)=\TMfcn^K_{\hat{e}}(x)$ for all~$x$.

Now feed $f$ its own index\Dash consider
$f(\hat{e})=\TMfcn^K_{\hat{e}}(\hat{e})$.
If it diverges then the first clause in the definition of~$f$
gives that $f(\hat{e})\converges$,
which contradicts that $f$~diverges.
If it converges then $f$'s second clause 
gives $f(\hat{e})\diverges$, which is also impossible.
So assuming that $f$ is computable relative to a $K$~oracle leads to
a contradiction.
We constructed~$f$ by assuming only that 
the characteristic function of $K^K$ is $K$-computable,
so that also is not true.
\end{proof}

\begin{theorem}
Any set~$S$ is reducible to its relativized \HP{}, $S\leq_T K^S$.
\end{theorem}

\begin{proof}
The flowchart on the left sketches a function that is intuitively
mechanically computable, relative to an oracle.
So Church's Thesis gives that there is an oracle Turing machine that
computes it, $\TM_e^X$ for some index~$e$.
Apply the \smn{} theorem to parametrize~$x$, giving the
uniformily computable family of
machines $\TM_{s(e,x)}^X$ charted on the right.
\begin{center}
\vcenteredhbox{\includegraphics{background/asy/flowcharts/flowcharts04.pdf}}
\hspace{3em}
\vcenteredhbox{\includegraphics{background/asy/flowcharts/flowcharts05.pdf}}
\end{center}
The computations on the right do not use the input~$y$, so that
$\TMfcn_{s(e,x)}^X(y)\converges$ if and only if $x\in X$.
Then taking the oracle to be~$S$ and the input to be $s(e,x)$ gives that
$x\in A$ if and only if $\TMfcn_{s(e,x)}^A(s(e,x))\converges$,
which holds if and only if $s(e,x)\in K^A$.
\end{proof}


\begin{corollary}
The set $K$ is computable from $K^K$, that is, $K\leq_T K^K$, but
$K^K\not\leq_T K$. 
\end{corollary}

\begin{proof}
This follows from the prior two results.
\end{proof}

There are problems strictly harder than the \HP.
One is the relativized \HP, that of computing the characteristic function
of $K^K$.

\subsection{When diagonalization fails}
But what if the transformed diagonal is a row? 
Then the member of the array where the diagonal crosses that row is
unchanged by the transformation; if $z=d_{n_0}$ then 
$d_{n_0,n_0}=t(d_{n_0,n_0})$.
Conclusion:~if the diagonalization fails then the transformation has
a fixed point.

We will apply this to sequences of
computable functions,
$\TMfcn_{i_0},\TMfcn_{i_1},\TMfcn_{i_2},\ldots$\@
We are interested in effectiveness so we don't consider just
arbitrary sequences of indices but instead take the indices to be computable,
$i_0,i_1,i_2\ldots=\TMfcn_e(0),\TMfcn_e(1),\TMfcn_e(2)\ldots$
for some~$e$, so we are considering sequence of this form.
\begin{equation*}
  \TMfcn_{\phi_e(0)},\,\TMfcn_{\phi_e(1)},\,\TMfcn_{\phi_e(2)}\,\ldots
\end{equation*}
This table lists all effective sequences of effective functions.
\begin{center}\small \renewcommand{\arraystretch}{1.25}
  \begin{tabular}{rr|ccccc}
    &\multicolumn{1}{c}{\ }
    &\multicolumn{4}{c}{\tabulartext{Sequence term~$\TMfcn_{\TMfcn_e(n)}$}}  \\
    &\multicolumn{1}{c}{\ }
      &$0$ &$1$ &$2$ &$3$ &\ldots \\  \cline{3-7}
   \multirow{5}{*}{\tabulartext{Sequence~$e$}}
    &$0$ &$\phi_{\phi_0(0)}$ &$\phi_{\phi_0(1)}$ &$\phi_{\phi_0(2)}$ &$\phi_{\phi_0(3)}$  &\ldots \\
    &$1$ &$\phi_{\phi_1(0)}$ &$\phi_{\phi_1(1)}$ &$\phi_{\phi_1(2)}$ &$\phi_{\phi_1(3)}$  &\ldots \\
    &$2$ &$\phi_{\phi_2(0)}$ &$\phi_{\phi_2(1)}$ &$\phi_{\phi_2(2)}$ &$\phi_{\phi_2(3)}$  &\ldots \\
    &$3$ &$\phi_{\phi_3(0)}$ &$\phi_{\phi_3(1)}$ &$\phi_{\phi_3(2)}$ &$\phi_{\phi_3(3)}$  &    \\[-.5ex]
    &$\mathrel{\makebox[\widthof{3}]{\vdots}}$
      &$\mathrel{\makebox[\widthof{=}]{\vdots}}$
      &$\mathrel{\makebox[\widthof{=}]{\vdots}}$
  \end{tabular}
\end{center}
The natural transformation uses a computable function~$f$. 
\begin{equation*}
  \TMfcn_e\mapsunder{t_f}\TMfcn_{f(e)}
\end{equation*}
Diagonalization fails under this transformation, the next result shows,
because the transformed diagonal is
a computable sequence of computable functions.
Thus the transformation~$t_f$ has a fixed point.

\begin{theorem}[Fixed Point Theorem, Kleene 1938]\hspace*{-0.5em}\footnotemark[1]  \label{th:FixedPointThm}
For any total computable function~$f$
there is an index~$e$ such that $\TMfcn_e=\TMfcn_{f(e)}$.
\end{theorem}\footnotetext[1]{%
  This is often known as the Recursion Theorem
  but there is another widely used result of that name.
  Besides, this name is more descriptive, so we will use it in this book.}

\begin{proof}
In the array the diagonal is
$\TMfcn_{\TMfcn_0(0)},\,\TMfcn_{\TMfcn_1(1)},\,\TMfcn_{\TMfcn_2(2)}\,\ldots$\@
The flowcharts below sketch the computation of these functions. 
On the left is an effective computation.
Church's Thesis says that some Turing machine computes it; let that
machine have index~$e_0$.
Apply the \smn{} theorem to get the right chart, which describes a family of 
machines parametrized by~$n$ that compute $d_n$,
the $n$-th function on the diagonal.
\begin{equation*}
  \vcenteredhbox{\includegraphics{background/asy/flowcharts/flowcharts06.pdf}}
  \hspace{1em}
  \vcenteredhbox{\includegraphics{background/asy/flowcharts/flowcharts07.pdf}}
  \hspace{2em}
  d_n(x)=
  \begin{cases}
    \TMfcn_{\TMfcn_n(n)}(x)  &\case{if $\TMfcn_n(n)\converges$} \\
    \uparrow                &\case{otherwise}
  \end{cases}
\end{equation*}
The index~$e_0$ is fixed so $s(e_0,x)$ is a function of one variable.
Let $g(n)=s(e_0,n)$, so the diagonal functions are $\TMfcn_{g(n)}=d_n$.
Then $g$ is computable and total.

Under~$t_f$ those functions are transformed to
$\TMfcn_{f\TMfcn_0(0)},\,\TMfcn_{f\TMfcn_1(1)},\,\TMfcn_{f\TMfcn_2(2)},\>\ldots$\@
\begin{equation*}
  t_f(d_n)\;(x)=
  \begin{cases}
    \TMfcn_{f\TMfcn_n(n)}(x)   &\case{if $\TMfcn_n(n)\converges$}     \\
    \uparrow                 &\case{otherwise}
  \end{cases}
  \hspace{2em}
  \vcenteredhbox{\includegraphics{background/asy/flowcharts/flowcharts08.pdf}}
\end{equation*}
As the flowchart indicates, this is a computable sequence of
computable functions.
Hence it is one of the table's rows.
Let it be row~$v$, so that $\TMfcn_{fg(n)}=\TMfcn_{\TMfcn_{v}(n)}$.
Consider where the diagonal sequence $\TMfcn_{g(n)}$ intersescts that row.
\begin{equation*}
  \TMfcn_{g(v)}=\TMfcn_{\TMfcn_v(v)}=\TMfcn_{fg(v)}
\end{equation*}
The desired fixed point for $f$ is $g(v)$.
\end{proof}

The power of this result is that it
applies to any total computable function.

\begin{corollary} \label{cor:ExistsPhiNWithRanN}
There is an index~$e$ so that $W_e=\set{e}$.
\end{corollary}

\begin{proof}
Consider the program described by the flowchart on the left.
By Church's Thesis it can be done with a Turing machine
$\TM_{e_0}$.
Parametrize to get the program on the right,
$\TM_{s(e_0,m)}$.
\begin{equation*}
  \vcenteredhbox{\includegraphics{background/asy/flowcharts/flowcharts09.pdf}}
  \hspace{1em}
  \vcenteredhbox{\includegraphics{background/asy/flowcharts/flowcharts10.pdf}}
  \hspace{1em}
  \TMfcn_{s(e_o,m)}(x)=
  \begin{cases}
  0         &\case{if $x=m$}  \\
  \uparrow  &\case{otherwise}
  \end{cases}
\end{equation*}
Since $e_0$ is fixed (it is just the index of the left-hand program),
we have a total computable function~$f$ of one variable
$f(m)=s(e_0,m)$ such that $W_{f(x)}=\set{x}$ for all $x$.
The Fixed Point Theorem gives a fixed point~$m=e$, so
$W_e=W_{f(e)}=\set{e}$.
\end{proof}

Restated, this result says that there is a Turing machine that halts
only on one input, its index.
That is,
\citetext{its name is its behavior}{%
  \definend{Nominative determinism}
  is the theory that a person's name has some influence over what they do
  with their life.
  Examples are: the sprinter Usain Bolt,
  the US weatherman Storm Fields,
  the baseball player Prince Fielder.
  and the Lord Chief Justice of England and Wales named Igor Judge,
  I~Judge.}.

Of course, every Turing machine has some index number, but why 
must there be a machine numbered in a way related to its behavior?
It seems to be an accident of the numbering.
But it isn't,
the theorem says that it must happen(as long as the numbering is acceptable).
These are deep results, showing very  surprising and interesting behaviors

\begin{corollary}
There is an $m\in\N$ such that  
$\TMfcn_m(x)=m$ for all inputs~$x$.
\end{corollary}

\begin{proof}
As in the prior corollary,
use Church's Thesis and the \smn{} theorem to construct this
family of computable functions, parametrized by~$m$. 
\begin{equation*}

  \uparrow  &\case{otherwise}
  \end{cases}
\end{equation*}
The function~$f$ with action $m\mapsto s(e_0,m)$ is computable
and total so it
has a fixed point~$e$,
giving $\TMfcn_e(x)=\TMfcn_{f(e)}(x)=e$ for all~$x$.
\end{proof}

\subsection{Discussion}
The Fixed Point Theorem and its proof are often 
\citetext{considered mysterious}{%
  For example, ``The recursion theorem \ldots{} has one of the most
  unintuitive proofs where I cannot explain why it works, only that it
  does.'' \autocite{blog:ComputationalComplexityRecursionThm}},
  or at any rate obscure.
One aspect of the theorem that needs explication is how it employs
the use-mention distinction.  

Compare the sentence \textit{Atlantis is a mythical city}  
to 
\textit{There are  two a's in ``Atlantis''}.
In the first `Atlantis' refers to something.
We say that the word Atlantis is \definend{used}. 
In the second sentence `Atlantis' is not used to refer to something, this 
sentence is about the word itself.
We say that `Atlantis' is \definend{mentioned}.
This difference is the reason for the second sentence's
quotation marks.\footnote{%
  This distinction comes up in programming books.
  In the sentence, ``Set the value of \texttt{boxes} to initialize
  the number of boxes''
  the first `boxes' is computer code while the second refers to the actual
  boxes.
  Quoting everything would be awkward and ugly so standard practice is to
  put the computer code in a typewriter font.
  We have done something like the same thing with
  the paragraph's single-quoted ``\,`Atlantis'\,'' mentions. 
  (That is quoted because it mentions a mention.)}

We see a version of the use-mention distinction in computer programming,
with pointers.
The C language program below illustrates.
The asterisk means that both \codeinline{x} and~\codeinline{y} are pointers.
% That is, we are not interested in the contents of these,
% so much as we are interested in the contents of the memory cells that they name.
The compiler associates
\codeinline{x} and \codeinline{y} with memory cells, 
each of which has room for an integer.
The first diagram
imagines that the compiler associates~\codeinline{x}
with memory address~$123$ and~\codeinline{y} with $124$.
It also imagines that the contents of address~$123$ is the number~$901$
and the contents of address~$124$ is~$902$.
We say that \codeinline{x} points to $901$ and \codeinline{y} points to~$902$.

The second diagram in the sequence shows the code running.
The code puts $42$ where \codeinline{x} points.\footnote{%
  Using the \codeinline{*} operator to access the value stored at a pointer
  is called dereferencing that pointer.
  There is a matching referencing operator, \codeinline{&},
  that gives the address of an existing variable.
  Both allow a programmer to control the indirection that pointers provide.}
The key here:~it does not put $42$ in location~$123$, rather it
puts $42$ in the location referred to by the contents of~$123$.  
Then the code sets \codeinline{y} to point to the same
address as~\codeinline{x}, address~$901$.
Finally, it puts $13$ where \codeinline{y} points, which is at this moment
the same cell to which~\codeinline{x} points.
\begin{animatedfigure}{Pointers in a C program.}
\vcenteredhbox{\animategraphics[poster=last]{1}{background/asy/memory/memory}{00}{04}}
\end{animatedfigure}
\noindent The variables \codeinline{x} and~\codeinline{y} are being
considered at different levels of meaning.
On one level,
listing \codeinline{x} refers to the contents of $123$,
while on another level it is about the contents of those contents,
what's in address~$901$.

As to the role played by the use-mention distinction in the
Fixed Point Theorem, 
the proof starts by taking 
$g(n)$ to be the name of this procedure.\footnote{%
  Here, `name' is an evocative equivalent of `index'.}
\begin{equation*}
  \TMfcn_{g(n)}=
  \begin{cases}
    \TMfcn_{\TMfcn_n(n)}(x)  &\case{if $\TMfcn_n(n)\converges$}  \\
    \uparrow                &\case{otherwise}
  \end{cases}
\end{equation*}
Regardless of whether we can compute the function, regardless of whether 
$\TM_n(n)\converges$, we can nonetheless compute the index~$g(n)$,
and from it the instructions for the function.
This is like Atlantis\Dash despite that the referred-to
city doesn't exist we
can still assert things about its name.
  
Informally, what $g(i)$ names is,
``Given input~$n$, run $\TM_n(n)$ and if it halts with
output~$w$ then run $\TM_w$.''
Shorter:~``Produce $\TM_n(n)$ and then do $\TM_n(n)$.''

Next, from~$f$ we consider the composition and give it a name
$\composed{f}{g}=\TMfcn_v$.
Then $g(v)$ names, ``Compute $\TMfcn_v(v)$ and then do $\TMfcn_v(v)$.''
That's the same as
``Compute $\composed{f}{g}(v)$ and then do $\composed{f}{g}(v)$.''
Note the self-reference; it may appear that to compute $g(v)$ we need $g(v)$,
that the instructions for $g(v)$ paradoxically
contains itself as a subpart.

Then $g(v)$ first computes the name of $\composed{f}{g}(v)$ and after that
runs the machine numbered $\composed{f}{g}(v)$.
So $g(v)$ and $\composed{f}{g}(v)$ are names for machines that
compute the same function.
So $g(v)$ does not contain itself; more precisely, the set of instructions for
computing $g(v)$ does not contain itself.
Instead, it contains a name for the instructions for computing itself.

\extra{The \HP{} in Wider Intellectual Culture}
The \HP{} and related results are about limits.
Given Church's Thesis, they say that there are things that we can never do.
To understand their impact, in the intellectual world
outside mathematics as well as inside,
we must place them in their historical setting.

\margingraphic{0.35\textwidth}{background/pix/crystalpalace.jpg}{\label{fig:crystalpalace}\href{https://upload.wikimedia.org/wikipedia/commons/6/61/Crystal_Palace_-_Queen_Victoria_opens_the_Great_Exhibition.jpg}{Queen Victoria opens the Great Exhibition of the Works of Industry of All Nations, 1851}}
With 
\citetext{Napoleon's downfall in the early 1800's}{See 
\autocite{wiki:AubreyMaturin}.}, 
many people in Europe felt a swing back to
a sense of order and optimism, fueled by progress.\footnote{These
statements are in the context of European general intellectual culture,
which is the context in which early Theory of Computation results
appeared and is the context in which this book is written.
A broader view is outside our scope.}
For example, in England, Queen Victoria's reign from 1837 to~1901
seemed to many commentators to be an extented 
\citetext{period of prosperity and peace}{See \autocite{wiki:PaxBritannica}.}.
Across wider Europe, people perceived that the natural world 
was being tamed with science and
engineering:~witness the introduction of steam railways in 1825, 
the opening of the Suez Canal in 1869, the invention of the electric light in
1879.\footnote{This is not to  % , and construction of the Eiffel Tower in 1889
say that this perception is without exception, is sensible, or is justified.
Disease and poverty were rampant, colonialism and imperialism 
were ruining the lives of millions, 
for much of the period the horrors of industrial slavery in the US south
went unchecked, and Europe was hardly an oasis of calm and
refinement, with for instance the revolutions of 1848. 
Nontheless the zeitgeist included a sense of progress, of winning.}  

In science this same sense was expressed by 
\citetext{A~A~Michelson, who wrote in 1899,
``The more important fundamental laws and facts of physical science have 
all been discovered, and these are now so firmly established that the 
possibility of their ever being supplanted in consequence of new 
discoveries is exceedingly remote.''}{%
  Michaelson was not a minor figure
  who was expressing a minority view.
  From 1901 to~1903 he was president of the American Physical Society. 
  In 1910--1911 he was president of the American Association for the 
  Advancement of Science and from 1923--1927 he was president of the 
  National Academy of Sciences. In 1907 he received the Copley Medal from 
  the Royal Society in London, and the Nobel Prize.  
  He is 
  still well-known today for the Michelson–Morley experiment that
  tried to find the presence of aether, the hypothesized medium through with 
  light waves travel.}
Many researchers felt this way, 
that the nature of the universe was largely understood
and what remained was only to work out the messier details.

The Physicist R~Feynman famously likened science to
\citetext{working out the rules of a game by watching it being played}{%
  See \url{https://www.youtube.com/watch?v=o1dgrvlWML4}}.
``to try to understand nature is to imagine that the gods are playing some
great game like chess. \ldots{}
And you don't know the rules of the game, but you're allowed to look at the
board from time to time, in a little corner, perhaps.
And from these observations, you try to figure out what the rules are of the
game.''
People in this period thought that they had basically figured out
the rules, but there was a thing or two like castling, that would be
worked out soon enough.

In Mathematics, the view from the turn of the
century was typified in Hilbert's 1930 
address,\footnote{Hilbert grew up in the 1800's and here is speaking in reaction to the changes; this is from his retirement address.}
``We must not believe those, who today, with philosophical bearing and 
deliberative tone, prophesy the fall of culture and accept the 
\textit{ignorabimus}. 
For us there is no \textit{ignorabimus}, and in my opinion none whatever 
in natural science.

In opposition to the foolish ignorabimus our slogan shall be:~Wir 
m\"ussen wissen — wir werden wissen.'' 
(The final phrase translates as, ``We must know\Dash we will know.''
`\textit{Ignorabimus}' means `that which we must be forever ignorant of'
or `that thing we will never fully penetrate'.)
Of course there was a range of opinion but the general sense was that
people had done so much and were moving steadily forward that
no doubt any question would be settled eventually.

But with the new century, with the 1900's, that sense changed.

\margingraphic{0.3\textwidth}{background/pix/wwi.jpg}{\label{fig:germandead}\href{https://en.wikipedia.org/wiki/Western_Front_(World_War_I)}{World War I German dead in a trench}}

Although the terrible effects of the modern mastery 
of mechanisms on warfare became generally understood with World War~I,
1914--1918.

In science, Michaelson's assertion that 
physics was essentially a solved probblem
was destroyed by the discovery of radiation in 1896.
This changed everything by bringing in quantum theory, 
that places at the
heart of its approach that there are events that are completely random,
that included Heisenberg’s uncertainty principle, and that

With Einstein we see most

After experiments during a solar eclipse in 1919 provided strong support for

\citetext{``everything is relative.''}{%

His work showed that the universe has absolute limits and that
everyday 
perceptions break down: nothing
can travel faster than light,  
time bends, and even the commonsense idea of 
two things happening at the same instant falls apart.  

In the general culture there were many reflections 
of this sense of loss of certainty.
For example, 
the generation of writers and artists who came of age in World War~I 
became known as the  Lost Generation.
In literature they expressed their experience through themes of alienation, 
isolation, and dismay at the corruption they saw around them.
Famous writers in this group included 
Eliot, Fitzgerald, Hemingway, Pound, and Stein.
In music, composers such as Debussy, Mahler, and
\margingraphic{0.3\textwidth}{background/pix/thepersistenceofmemory.jpg}{\label{fig:persistenceofmemory}\href{https://en.wikipedia.org/wiki/The_Persistence_of_Memory}{Salvadore Dali's 1931 \textit{Persistence of Memory}. Depicts relativity's warping of a pillar of reality, time itself.}}

As for art, the painting here dramatically shows that visual artists 
also picked up on these themes.

\margingraphic[l]{0.3\textwidth}{background/pix/einsteingodel.jpg}{\label{fig:einsteingodel}\href{http://www.newyorker.com/magazine/2005/02/28/time-bandits-2}{G\"odel and his best friend}}
In mathematics, much the same inversion of the standing order
happened in 1930 with K~G\"odel's announcement of the
First Incompleteness Theorem.\footnote{The announcement was made
at the same meeting as the one where Hilbert gave his retirement address.} 
The Incompleteness Theorem says that if we fix a 
(sufficiently strong) formal system such as the elementary number theory
of $\N$ with addition and multiplication, then there are  
statements that, while true in that system, 
cannot be proved in that system.
% We say more elsewhere, \cref{extra:Godel}, but 
% even without elaboration
The theorem is clearly about what cannot be done\Dash
there are true things, correct things, and
we shall never prove them.
This statement of basic limits
seemed to many observers to be especially striking in the field of 
mathematics.

G\"odel's Theorem is closely related to the \HP.
In a mathematical proof, each step must be verifiable as a deduction
that is valid from the prior steps or as an axiom.
So proving a mathematical theorem is a kind of computation.\footnote{%
  This implies that you could start with all of the axioms and
  apply all of the logic rules to get a set of all of the
  first-rank theorems.
  Then, application of all of the logic rules to those will give
  all the second-rank theorems, etc.
  In this way, from the axioms you can computably enumerate all of Mathematics.}
Thus, G\"odel's Theorem and other uncomputability results are in the same vein. 
To people at the time these results were deeply shocking,
revolutionary.
Today we work in an intellectual culture that has absorbed this shock,
that is part of the background of what we all have come to expect,
but we should recognize them as a bedrock.

\subsection{Paley's watch}
In 1802,

based on evidence in the natural world.

In crossing a heath, \ldots{}
suppose I had found a watch upon the ground
\ldots{}
[W]hen we come to inspect the watch we perceive \ldots{}
that its several parts are framed and put together for a purpose, e.g., that 
they are so formed and adjusted as to produce motion, and that motion so 
regulated as to point out the hour of the day 
\ldots{} the inference we think is inevitable, that 
the watch must have a maker\Dash that there must have existed, at some
time and at some place or other, an artificer or artificers who
formed it for the purpose which we find it actually to answer, 
who comprehended its construction and designed its use.

The marks of design are too strong to be got over.
Design must have had a designer.
That designer must have been a person.
That person is GOD.
\end{quotation}

\subsection{Quines}
A \citetext{\definend{quine}}{%
  Named for the philosopher Willard Van Orman Quine.}
is a program that outputs its own source code.\footnote{%
  The easiest such program finds its source file on the disk and prints it. 
  That is cheating.}
% http://www.madore.org/~david/computers/quine.html

% http://cs.brown.edu/courses/gs019/asgn/hw3.sol.pdf
% http://cs.brown.edu/courses/gs019/lectures/recursion.pdf
The Fixed Point Theorem shows that there is a number~$m$ such that 
$\TMfcn_m(x)=m$ for all inputs.
Think of~$m$ as the name of the function.
This function outputs its name.
Since we can go effectively from the index~$m$ to the machine source,
this function knows its source, in a sense.
Said another way, $\TM_m$ is a program whose name
\emph{is} its behavior.
This is \citetext{self-reference}{%
  `Self-reference' describes something that refers to itself.
  The classic example is the \definend{Liar paradox},
  the statement attributed to the Cretian Epimenides,
  ``All Cretans are liars.''
  Because he is Cretian we take the statement to be an utterance about
  utterances by him, that it to be about itself.
  Further, if we suppose the statement is true then it asserts that
  anything he says is false, so the statement is false.
  But if we suppose it is false then we take that
  he is saying the truth, that all his statements are false. 
  Its a paradox, meaning that the reasoning seems locally sound but
  it leads to a global impossibility.
  
  This is related to Russell's paradox, which lies
  at the heart of the diagonalization technique, that
  if we define the collection of sets $R=\set{S\suchthat S\notin S}$
  then $R\in R$ holds if and only if $R\notin R$ holds.
  
  Self-reference is obviously related to recurrence.
  You see it sometimes pictured as an infinite recurrence, as here on the
  front of a chocolate product.
  \begin{center}
    \includegraphics[height=1in]{background/pix/droste.jpg}
  \end{center}

  Besides the Liar paradox there are many others.
  One is Quine's paradox, a sentence that asserts its own falshood. 
  \begin{center}
    ``Yields falsehood when preceded by its quotation'' \\
    \quad yields falsehood when preceded by its quotation.
  \end{center}
  If this sentence were false then it would be saying something that is true.
  If this sentence were true then what it says
  would hold and it would be not true.

  A wonderful popular book exploring these topics and many others is
  \autocite{Hofstadter}.}; machine~$m$ names itself.

To make this more concrete we will step through the nitty-gritty of making a
quine.  
We will use the C language since it is low-level.

A first try might include the source as a string within itself.
\begin{lstlisting}
main() {
  printf("main(){\n ... }");
}    
\end{lstlisting}
But is obviously naive; it has infinite regress since included
in the string would be another strings, etc.
This is the same problem the homoculus theory had.

A less naive approach, one that employs the thinking behind our
discussion of the Fixed Point Theorem, is to mention the code before use.
\begin{lstlisting}
char *e="main(){printf(e);}"
main(){printf(e);};
\end{lstlisting}
Here is the printout.
\begin{lstlisting}
main(){printf(e);};  
\end{lstlisting}
This idea is summarized by the sentence ``quine `quine'''.
Here, the verb to quine (invented by Douglas Hofstadter) means
``to write a sentence fragment a first time, and then to write it a second time, but with quotation marks around it''
For example, if we quine `say' then we get ``say `say'''.
Thus, if we quine `quine', we get ``quine `quine',''
so that the sentence ``quine `quine''' is a quine…
In this linguistic analogy, the verb ``to quine,'' plays the role of the code
and ``quine'' in quotation marks plays the role of the data.
% http://www.madore.org/~david/computers/quine.html

We are closer but not quite there yet.
Ratcheting up this approach gives the next try.
\begin{lstlisting}
char *e="main(){printf("char*e="");printf(e); printf("";\n");printf(e);"
main(){printf("char *e="");printf(e); printf("";\n");printf(e);}
\end{lstlisting}
It is very close.
To get a quine just escape some newlines and quotation marks.\footnote{%
  Note that $10$ is the ASCII encoding for newline and
  34 is ASCII for a double quotation mark.}   
This works.
\begin{lstlisting}
char *e="char*e="%c %s %c; %c main() {printf(e,34,e,34,10,10);}%c";
main(){printf(e,34,e,34,10,10);}
\end{lstlisting}

A quine is a fixed point of an execution environment, 
when the execution environment is viewed as a function.
They are possible in any complete model of 
computation; the exercises ask for them in a few languages.
(In some languages
an empty source file is 
a valid program that produces no output but typically
quine contests disallow that.)

K~Thompson is one of the two main creators of the UNIX operating system.
For this and other accomplishments he won the Turing Award,
the highest honor in computer science.
He began his acceptance address with this.
\begin{quotation}
In college, before video games, we would amuse ourselves by posing
programming exercises.
One of the favorites was to write the shortest self-reproducing program.
Since this is an exercise divorced from reality,
the usual vehicle was FORTRAN.
Actually, FORTRAN was the language of choice for the same reason that

\end{quotation}

\extra{Busy Beaver}
% See also: https://johncarlosbaez.wordpress.com/2016/05/21/the-busy-beaver-game/
% We compute things all the time so noncomputability is 
% counterintuitive.
% Here we see one easily-understood way
% that a function can fail to be computable.  
Consider this attempt to solve the \HP: ``For
any~$n\in\N$ the set
of Turing machines having $n$~many tuples or fewer is finite.
For some members of the set
$\TM_e(e)$ halts and for some it does not but because the set is finite,
the information
on which Turing machines halt must also be finite.
Finite sets are computable.
So to solve the \HP, given a Turing Machine~$\TM$, 
find how many four-tuples it has,
just compute the associated finite halting information set.''
The problem is uniformity, or rather lack of it.
We can indeed compute any one of the finite sets.
But there is no single computable function that does them all.
% \Dash
% no computable function that accepts inputs~$\sequence{n,e}$ and that 
% outputs~$1$ if there is a $n$-tuple machine such that $\TM_e(e)$ halts,
% or~$0$ otherwise.

Another natural attack on the \HP, this time a uniform one,
is to start all of the machines in $T_n$,
and run them in a breadth-first way until no more of them will ever converge.

That is, consider this function $\map{D}{\N}{\N}$, where
$D(n)$ is the minimal number of steps 
                   after which all of the $n$-instruction machines 
                   that will ever converge have done so.
% \begin{equation*}
%   D(n)= \text{\begin{minipage}[t]{0.7\textwidth}
%                  \begin{hangingpar}
%                    minimal number of steps 
%                    after which all of the $n$-instruction machines 
%                    that will ever converge have done so
%                  \end{hangingpar}
%                \end{minipage}} 
% \end{equation*}
We can prove that $D$ is not computable.
Assume otherwise.
Then to compute whether $\TM_e$ halts on input~$e$, 
find how many instructions~$n$ are in the machine $\TM_e$, compute $D(n)$,
and run $\TM_{e}(e)$ for $D(n)$-many steps.
If $\TM_{e}(e)$ has not halted by then, it never will.
Of course, this contradicts the unsolvability of the \HP.

So far this seems like another uncomputable function; why is it
especially enlightening? 
Observe that if a function $\hat{D}$ has values larger than $D$\Dash
if $\hat{D}(n)\geq D(n)$ for all sufficiently large~$n$\Dash
then $\hat{D}$ is also not computable.
This tells us that one way that functions can fail to be computable is that 
they grow too fast.\footnote{%
  Note the connection with the Ackermann function: in an Extra section
  we showed that it is not primitive recursive because it grows
  faster than any primitive recursive function.}

\subsection{Busy Beaver is unsolvable}
% \urldef{\radourl}{\url{https://math.osu.edu/about-us/history/tibor-rad%C3%B3}}
\margingraphic{0.2\textwidth}{background/pix/rado.jpg}{\label{fig:rado}\href{}{Tibor Rad\'o 1895--1965}} % https://math.osu.edu/about-us/history/tibor-rad%C3%B3
Write \definend{$\Sigma(n)$} for the largest number of $1$'s that any 
$n$~state machine, when started on a blank tape, 
leaves on the tape after halting.
Write \definend{$S(n)$} for the most moves, that is, transitions.

Why isn't $\Sigma$ computable?
The obvious thing is to do a breadth-first search:~there 
are finitely many $n$-state machines,
start them all on a blank tape,
and await developments.

That won't work because some of the machines won't halt.
At any moment you have some machines that have halted and you can see
how many $1$'s are on each such tape, so you know the longest so far.
But as to the not-yet-halted ones, who knows?
You can by-hand see that this one or that one will never halt
and so you can figure out the answer for $n=1$ or~$n=2$.
But there is no algorithm to decide the question for an arbitrary
number of states. 

\begin{theorem}[Rad\'o, 1962]
The function $\Sigma$ is not computable.  
\end{theorem}

\begin{proof}
Let $\map{f}{\N}{\N}$ be computable.
We will show that $\Sigma\neq f$ by showing that
$\Sigma(n)>f(n)$ for infinitely many~$n$.

First note that there is a Turing Machine $\TM[M]_j$
having $j$~many states that writes $j$-many $1$'s to a blank tape.
For instance, here is $\TM[M]_4$.
\begin{center}
  \includegraphics{background/asy/busybeaver/busybeaver00.pdf}
\end{center}
Also note that we can compose two Turing machines.
The illustration below shows two machines on the left.
On the right, we have combined the final states 
of the first machine with the start state of the second.
\begin{center}
  \vcenteredhbox{\includegraphics{background/asy/busybeaver/busybeaver01.pdf}}
  \hspace{2.5em}
  \vcenteredhbox{\includegraphics{background/asy/busybeaver/busybeaver02.pdf}}
\end{center}

Let $\map{F}{\N}{\N}$ be this function.
\begin{equation*}
  F(m) % = \sum_{0\leq i< m+1} f(i)+i^2  % using \Sigma so omit summation 
       = (f(0)+0^2)+(f(1)+1^2)+(f(2)+2^2)+\cdots+(f(m)+m^2)
\end{equation*}
It has the properties:~if $0<m$ then $f(m)<F(m)$,
and $m^2\leq F(m)$,
and $F(m)<F(m+1)$.
It is intuitively computable so Church's Thesis says there is a 
Turing machine $\TM[M]_F$ that computes it.
Let that machine have $n_F$~many states.

Now consider the Turing machine $\TM$
that performs $\TM[M]_j$ and follows that with the machine 
$\TM[M]_F$, and then follows that with another copy of the machine 
$\TM[M]_F$. 
If started on a blank tape this machine will first produce $j$-many $1$'s,
then produce $F(j)$-many $1$'s, and finally will leave the tape with 
$F(F(j))$-many $1$'s.
Thus its productivity is 
$F(F(j))$.
It has $j+2n_F$ many states.

Compare that with the $j+2n_F$-state Busy Beaver machine.
By definition
$F(F(j))\leq \Sigma(j+2n_F)$.
Because $n_F$ is constant (it is the number of states in
the machine $\TM[M]_F$), the relation $j+2n_F\leq j^2< F(j)$
holds for sufficiently large~$j$.
Since $F$ is strictly increasing, $F(j+2n_F)<F(F(j))$.
Combining gives
$
   f(j+2n_F) <
   F(j+2n_F) <
   F(F(j))
   \leq \Sigma(j+2n_F)$,
as required.
\end{proof}

\begin{remark}
Not only are Busy Beaver numbers very hard to compute, at some
point they become impossible.
In 2016, A~Yedida and S~Aaronson obtained an~$n$ for which
\citetext{$\Sigma(n)$ is unknowable}{%
  See \autocite{Aaronson16}}.

Briefly, they created a programming language that lets you write programs
that compile down to small Turing machines.
They then took an arithmetic statement that's equivalent to the consistency
of the axioms.
With it they constructed a $7918$-state Turing machine whose behavior,
halting or not,
cannot be proven in the usual foundation for mathematics (the axioms of
Zermelo–Fraenkel set theory with choice, 
under the hypothesis of the Stationary Ramsey Property)

Since the axiom system can’t prove its own consistency (this is G\"odel's Second
Incompleteness Theorem), the machine will halt only if the
axioms are inconsistent.
Since most set theorists believe the axioms are consistent,
this machine probably doesn’t halt.
But we cannot prove this using the axioms.
\end{remark}

So one way for a function to fail to be computable is if it grows faster than
any computable function.
Note, however, that this is not the only way.  
There are functions that grow slower than some computable function but
are nonetheless not computable.
