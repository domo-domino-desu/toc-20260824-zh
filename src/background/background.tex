We have defined mechanical computation.
Here we will develop the ideas in that definition.
We will see several results that are a theme throughout the subject.

One point we made in the prior chapter is that we are extensional:
we are interested in the 
things that are computed more than in the means to compute them.
In particular, we are interested in the functions $\map{f}{\N}{\N}$
that are effective, 
that are computed by Turing machines.
The major result of the chapter, the major result of the 
book, is that there are functions for which there is no Turing machine
to compute them.
There are functions that are uncomputable;
there are jobs that no machine can do.





\section{Infinity}

In the children's game Musical Chairs, there are more people than there are
chairs so when the music stops some  person is left without a chair.
Our first look at the major result follows this idea: we will show that there 
are more functions than 
Turing machines and that therefore some function has no associated machine.

The set of functions and the set of Turing machines are both
infinite so 
we need to
understand how to compare the sizes of infinite sets. 
We will begin with two paradoxes of the infinite, two examples that
dramatize the challenge to our intuition posed by 
comparing the sizes of infinite sets.

The first is 
\definend{Galileo's Paradox},\footnote{He did not invent this paradox but
he gave it prominence in his 
\protect\textit{Discourses and Mathematical Demonstrations Relating to Two New Sciences}.}
comparing the size of the set of perfect squares with that of the set of 
all natural numbers.
There are fewer perfect squares than natural numbers in the sense that
the first set is a proper subset of the second\Dash there are some numbers that
are not square.
However, there are exactly as many squares as natural numbers in the sense that
we can see the elements of the two sets as in a correspondence, 
illustrated the figure below.   
\begin{animatedfigure}{Correspondence $n\leftrightarrow n^2$ between the 
  natural numbers and the perfect squares.} 
\animategraphics{3}{background/asy/galileo/galileo}{000}{012}
\end{animatedfigure}
\noindent This is the situation in Musical Chairs 
after the music has stopped, where there is a correspondence between the set
of available chairs and the set of people sitting.
This correspondence demonstrates,
without any need to count, that the two sets have the same number of elements.

Second is \definend{Aristotle's Paradox}.
Everyone knows that a smaller circle has a smaller circumference.
But if the two are put together, like a wheel on a railroad train, then

The key idea from these examples is that 
to compare the number of elements in two sets,
such as when we compare the number of elements in the
set of functions from $\N$ to~$\N$
with the number of elements in the set of Turing machines,
we must see whether there is a way for
their elements to correspond.

\begin{definition}
Two sets have the same \definend{cardinality} (or are \definend{equinumerous})
if there is a correspondence between them.  
That is, sets $S_0$ and $S_1$ have the same cardinality
if there is a 
one-to-one and onto function $\map{f}{S_0}{S_1}$.
We denote this with $|S_0|=|S_1|$.
\end{definition}

\begin{example}
This set of numbers $S_0=\set{0,1,2}$ and set of
letters $S_1=\set{\alpha,\beta,\gamma}$ have the same cardinality, namely~$3$,
under the correspondence $0\mapsto\alpha$, $1\mapsto\beta$, $2\mapsto\gamma$.
\end{example}

Generalizing that example, 
finite sets are equinumerous if and only if they have 
the same number of elements.
So using correspondences to compare the sizes of sets, 
first proposed by Cantor in the 1870's, 
takes an idea that is natural in the finite case and
extends it to apply to all sets, including infinite sets.

\begin{remark}
One strength of Cantor's definition, as with Turing's, is that it is 
persuasive in itself.
G\"odel noted this, writing,
``Whatever `number' as applied to infinite sets may mean, we certainly want it
to have the property that the number of objects belonging to some class does not change if,
leaving the objects the same, one changes in any way \ldots{}
e.g., their colors or their distribution in space \ldots{}\,.
From this, however, it follows at once that two sets will have the same
[cardinality] if their elements can be brought into one-to-one
correspondence, \citetext{which is Cantor's definition}{\autocite{Godel64}}.''
% ``[Cantor's] is the right definition.
% Whatever we mean by equinumerous, it encompasses fixture under such things
% as changes in color or spatial arrangement.
% But the definition goes no further than that.''
\end{remark}

\begin{example} \label{ex:PerfectSquaresCountable}
The set of perfect squares $S=\set{n^2\suchthat n\in\N}$
has the same cardinality as the set $\N$. 
One correspondence
is the map $\map{f}{\N}{S}$ given by $f(n)=n^2$.

The verification that $f$ is a correspondence is straightforward.
It is one-to-one because if we have an output with two associated inputs 
$f(n_0)=f(n_1)$ then $n_0^2=n_1^2$, which for
natural numbers implies that $n_0=n_1$, so the two inputs are the same.
It is onto because any element of the codomain $s\in S$
is the square $s=n^2$ of some~$n\in\N$, by defininition of~$S$, 
and so $s$ is the output associated with some input, namely $s=f(n)$.  
\end{example}

\begin{example} \label{ex:RealIntervalsCorrespond}
With $r_0, r_1\in\R$ nonzero,
the interval $I_0=\leftclosed{0}{2\pi r_0}$ has the same cardinality
as the interval $I_1=\leftclosed{0}{2\pi r_1}$, 
under the 
correspondence $\map{g}{I_0}{I_1}$ given by $g(x)=x\cdot(2\pi r_1/2\pi r_0)$.  
\end{example}

For our work the key model of  
\citetext{an infinite set is $\N$}{This is the Axiom of Infinity, one of the standard axioms of Mathematics, the Zermelo-Frankel axioms.}.

\begin{definition}
A set~$S$ is \definend{infinite} if for every number~$n\in\N$ 
there is a subset of~$S$ whose cardinality is that number.
A set with the same cardinality as $\N$ is \definend{countable}
or \definend{countably infinite}.
We shall call exhibiting a correspondence $\map{f}{\N}{S}$ 
\definend{counting} or \definend{enumerating} that set.
\end{definition}

\begin{example}
The set $\N-\set{2,5}=\set{0,1,3,4,6,7,\ldots}$ is countable.
This tabular display of a suitable function $\map{f}{\N}{\N-\set{2,5}}$
\begin{equation*}
  \begin{array}{r|ccccccc}
    n\in\N
      &0 &1 &2 &3 &4 &5 &\ldots \\ \cline{2-8}
    f(n)\in\N-\set{2,5}
      &0
      &1
      &3
      &4
      &6
      &7
      &\ldots
  \end{array}
\end{equation*}
is intuitive, but the formula 
\begin{equation*}
  f(n)=\begin{cases}
         n    &\case{if $n<2$}  \\
         n+1  &\case{if $2\leq n<4$} \\
         n+2  &\case{if $4\leq n$}
       \end{cases}
\end{equation*}
lets us easily show that $f$ both one-to-one and onto.
\end{example}

\begin{example} \label{ex:OddNumbersCountable}
The set of odd numbers $\set{2n+1\suchthat n\in\N}$ is countable. 
The function given by $g(n)=2n+1$ is a correspondence between  
the set of natural numbers and the set of odd numbers.
\end{example}

\begin{example}
The set~$\mathcal{P}$ of prime numbers is countable.
Here the correspondence $\map{f}{\N}{\mathcal{P}}$ isn't given by an 
easy to produce formula.
But we can draw on our experience writing programs: we could
write one that inputs a natural number~$n$ and outputs the $n$-th prime
(taking the $0$-th prime to be~$2$, the $1$-th to be~$3$, etc.).
The function that is the input-output behavior of this program 
is by construction a correspondence: it 
is one-to-one because the $n$-th prime is only output
when the input is~$n$, and it is onto because every prime is for some~$n$
the $n$-th prime. 
\end{example}

\begin{example}
Consider the alphabet $\Sigma=\set{\str{a},\ldots,\str{z}}$.
Also consider the set of finite-length strings made of 
characters from $\Sigma$, denoted $\kleenestar{\Sigma}$.
It contains for instance \str{abc}, \str{xyz}, and~\str{abba}.
The set $\kleenestar{\Sigma}$ is countable.
As in the prior example we won't give a formula but this tabular presentation
of the function makes clear that we get a correspondence by 
taking the strings in the 
ascending dictionary order.
\begin{center}
  \begin{tabular}{r|cccccccc}
    $n\in\N$  &$0$    &$1$   &$2$ &$\ldots$  &$26$  &$27$ &$28$ &$\ldots$   
   \\ \cline{2-9}
    $f(n)\in\kleenestar{\Sigma}$  &$\emptystring$  &\str{a} &\str{b} &$\ldots$ 
    &\str{z} &\str{aa} &\str{ab}  &$\ldots$
  \end{tabular}
\end{center}
(The first one on the bottom is the empty string, 
$\emptystring=\text{`\,'}$.)
The argument that the function suggested by that tabular presentation 
is a correspondence, that it is one-to-one and onto, is 
like that in the prior example.
\end{example}

The definitions here do not require that the functions be in any way
effective, that is, mechanically computable.

effectivize them.

In counting it, the mistake to avoid
is to try first exhausting one copy:~$f(0)=\sequence{0,0}$,

\begin{example}
The set integers~$\Z$ is a strict superset of $\N$,
so in that sense it is a bigger set.
But $\Z$ is equinumerous with $\N$ because it is like the 
prior example; it is, except for~$0$,  
two copies of $\N$, a $+$~copy and a $-$~copy. 
\begin{equation*}
  \begin{array}{r|cccccccc}
    n\in\N  &0    &1   &$2$ &3  &4  &5  &6 &\ldots   
   \\ \cline{2-9}
    f(n)\in\Z  &0  &+1 &-1 &+2  &-2 &+3 &-3 &\ldots 
  \end{array}
\end{equation*}
\end{example}

That method easily extends to showing the
countability of
$\set{0,1,2}\times\N$, and of $\set{0,1,2,3}\times\N$, etc.

\begin{example} \label{exam:NCrossN}
The obvious next set to tackle is $\N\times\N$.
\begin{equation*}
  \begin{array}{cccccc}
    \vdots          &\vdots         &\vdots                  \\
    \sequence{0,3}  &\sequence{1,3} &\sequence{2,3} &\sequence{3,3} &\cdots  \\
    \sequence{0,2}  &\sequence{1,2} &\sequence{2,2} &\sequence{3,2} &\cdots  \\ 
    \sequence{0,1}  &\sequence{1,1} &\sequence{2,1} &\sequence{3,1} &\cdots  \\ 
    \sequence{0,0}  &\sequence{1,0} &\sequence{2,0} &\sequence{3,0} &\cdots
  \end{array}
\end{equation*}
The method of \cref{exam:NMatchesTwoN} doesn't apply here
because it depends on the finiteness of the first set: if we try 
to exhaust the bottom row $f(0)=\sequence{0,0}$, $f(1)=\sequence{1,0}$, 
$f(2)=\sequence{2,0}$, \ldots{} then we would never get to the row 
above it.  
Instead,  
we first enumerate the $\sequence{0,0}$ in the lower left, 
then we do the pairs that are one~away from
the lower left, $\sequence{1,0}$ and~$\sequence{0,1}$,
then those that are two away, etc.  

\begin{animatedfigure}{The order in which we enumerate $\N\times\N$.} 
\animategraphics[poster=first]{2}{background/asy/correspondences/correspondences2}{000}{009}
\end{animatedfigure}
\noindent Here is the tabular presentation of the correspondence.
\begin{equation*}
  \begin{array}{r|cccccccc}
    n\in\N  &0    &1   &$2$ &3  &4  &5  &6 &\ldots   
   \\ \cline{2-9}
    f(n)\in\Z  &\sequence{0,0}  
               &\sequence{0,1} 
               &\sequence{1,0} 
               &\sequence{0,2}  
               &\sequence{1,1} 
               &\sequence{2,0} 
               &\sequence{0,3} 
               &\ldots 
  \end{array}
  \tag{$*$}
\end{equation*}
\end{example}

That there is a correspondence between $\N\times\N$ and~$\N$
is a fact that we will frequently use.
In principle the details of the correspondence don't matter much but
the one above has a formula that is too nice to rush past
so we will have a look.

The formula is based on the way the correspondence 
uses the left-to-right diagonals. 
Consider the pair~$\sequence{1,2}$.
It is in diagonal~$3$.
The prior diagonals have a total of six pairs 
so on $\sequence{1,2}$'s diagonal the first pair is 
counted with~$6$
(our counting is $0$-offset, that is, it starts at~$0$, so the seventh thing
counted is assigned number~$6$).
Then $\sequence{1,2}$ is number~$7$.

To find the number associated with $\sequence{x,y}$ 
we will first find how many pairs have been enumerated 
before its diagonal, and then add the place this pair holds in its diagonal.
For the first step, note that pair~$\sequence{x,y}$ is on diagonal $x+y$.
Then observe that
diagonal~$0$ has one entry, diagonal~$1$ has
two entries, diagonal~$2$ has three entries, etc.
So the number of entries prior to diagonal~$x+y$ is $1+2+\cdots+(x+y)$.
That's a geometric series, with total $(1/2)(x+y+1)(x+y)$.
For the second step, the starting pair on the diagonal is $\sequence{0,x+y}$,
the next is~$\sequence{1,x+y-1}$, etc., 
so the pair $\sequence{x,y}$ is~$x$-th from the start.

% Thus, the number assocated with $\sequence{x,y}$ is $(1/2)(x+y+1)(x+y)+x$.

\begin{definition}
The \definend{breadth-first} enumeration of $\N\times\N$ is the function
that associates $\sequence{x,y}$ with $(1/2)(x+y+1)(x+y)+x$.
We write $\godelnum{\sequence{x,y}}$ for that natural number.
\end{definition}

This correspondence is the inverse of \cref{exam:NCrossN}'s $f$.
For example, $\godelnum{\sequence{2,0}}=5$.
Its name comes from the approach to counting the infinite array by
avoiding trying to first do the full depth of a column or row.

\begin{example}  \label{ex:RationalsAreCountable}
The set of rationals $\Q$ is countable.
We already know how to alternate between positives and negatives 
so that reduces the problem to just doing
the nonnegatives.
A nonnegative rational is, roughly,
an ordered pair 
$\sequence{\text{numerator},\text{denominator}}$
(with a nonzero denominator), except
that some pairs collapse: $4/2$ equals~$2/1$.
To counter that we memoize: to enumerate the $n$-th rational
we remember the previously-enumerated 
rationals, and as we do a breadth-first listing of the pairs 
we check each against the cached rationals, and only enumerate 
it if it is not a repeat.
\end{example}


\subsection{Hilbert's Hotel}
Mathematicians tell a fable about infinite sets 
that makes memorable the point of the above examples.

\citetext{Once there was an infinite hotel}{The fable is due to 
David Hilbert in 1924.  
It was popularized by George Gamow in 
\textit{One, Two, Three \ldots{} Infinity}.  \autocite{Kragh}.},
with rooms 
numbered $0$, $1$, \ldots\,.
One day, every room was occupied (it was a paradise of a hotel) when 
someone new came. 
Could the hotel accomodate them?
The desk clerk hit on the idea of moving each guest up a room, that is,
moving the guest in room~$n$ to room~$n+1$. 
With that, room~$0$ is empty.
So this hotel always had space for a new person, 
or any finite number of new people.

Next a bus came with infinitely many people $p_0, p_1,\ \ldots\ $.
Again the clerk had the idea to
move each guest to a room with twice the number, that is, 
to move the guest from room~$n$ to room~$2n$.
With that, the odd-numbered rooms were empty. 
So everyone had a room.

That's when the clerk spotted a convoy of buses pulling in, 
infinitely many of them,
each with infinitely many people.
\begin{equation*}
  B_0=\set{p_{0,0},\, p_{0,1},\, \ldots\,},
  \quad
  B_1=\set{p_{1,0},\, p_{1,1},\, \ldots\,},
  \quad
  \ldots
\end{equation*}
But the clerk had the spirit of the thing now.
As before, 
move each guest to a new room with twice the number.
The new people go into the odd-numbered rooms, in the breadth-first order
$p_{0,0}$, $p_{1,0}$, $p_{0,1}$, $p_{2,0}$ \ldots{}
from \cref{exam:NCrossN}'s table~($*$).  

The clerk could be forgiven, after this experience, for thinking that
there is always room in the infinite hotel,
that with a sufficiently clever method,  
the hotel can fit any number of people.
The above examples make natural the guess 
that all infinite sets have the same cardinality. 
That guess is wrong.
We will next see a set with so many members that they cannot
all be counted.\footnote{Sadly, the infinite hotel no longer exists. 
The guest agreed among themselves on a scheme where the one in room~$0$ 
told the clerk that the guest from room~$1$ was covering both their bills.
The guest in room~$1$ said yes, but said that in the meantime
the guest in room~$2$ had agreed 
to pay the tabs for all three rooms $0$--$2$.
Room~$2$ said that the room~$3$ person would pay for rooms~$0$--$3$, etc.
So in the end this hotel made no money, despite having infinitely many rooms,
or perhaps because of it.}


\subsection{Diagonalization}
The prior subsection promises a set with so many members that 
it cannot be counted.
One such set is~$\R$.
(Recall again that we do not mean that $\R$ has more members than $\N$ 
because $\R$ is a superset;
the set of integers is a superset of the set of natural numbers but it is 
countable.)

\begin{lemma}  \label{lem:UnitIntUncountable}
There is no onto map $\map{f}{\N}{\leftclosed{0}{1}}$. 
\end{lemma}

Consequently, the interval $\leftclosed{0}{1}$ is
not equinumerous with $\N$, is not countable.

To motivate the proof, picture a map $\map{f}{\N}{\leftclosed{0}{1}}$

   f(5)  &6  &2  &5  &5  &4  &1  &8  \\[-.5ex]
   \multicolumn{1}{c}{\vdotswithin{f(0)\ }} 
    &\multicolumn{4}{c}{\vdotswithin{1}}  
  \end{array}
\end{equation*}
(The argument uses the interval $\leftclosed{0}{1}$ because in this table the 
decimal line up nicely.)
The right side seems to list all the numbers 
in $\leftclosed{0}{1}$:
some of the output numbers seem to be rational and
some seem to be irrational, 
they don't all have the same first decimal place, etc.
Nonetheless, we will 
build a number $z\in\leftclosed{0}{1}$ that does not equal 
the right side of any row.

Go down the table's diagonal, taking the digits 
$3$, $5$, $1$, $1$, $0$, $1$ \ldots{}\,.
Construct~$z$ by making its first digit something other than a~$3$, 
making its second digit something other than a~$5$, etc.
Specifically, if the diagonal digit is a $1$ then~$z$ gets 
a~$2$ in that decimal place, while if the diagonal digit is not a~$1$ 
then~$z$ gets a~$1$ there. 
Following the illustration above, $z=0.112212\ldots$\,.

The point of that construction is that $z$ is not the number in the first row,
$z\neq f(0)$, because they differ in the first decimal place.
Similarly,~$z\neq f(1)$ because they differ in the second decimal 
place.In this way $z$ does not equal any of the~$f(n)$, so the function is not onto.

(We must 
take care to not be snagged by a technicality in representations:
some numbers have two different decimal representations.
For instance, $0.5000\ldots=0.499\ldots$, 
because the two differ by less than $0.1$, less than~$0.01$, etc.
Thus, 
two numbers having different representation does not 
necessarily mean that they are different numbers.
But this happens only if one of the two 
decimal representations ends in $0$'s and the other ends in~$9$'s.
For just this reason, our~$z$ avoids $0$'s and $9$'s.)

This technique is called \definend{diagonalization}.
It is critical for our work.

\begin{proof}
Consider a map $\map{f}{\N}{\leftclosed{0}{1}}$.
We will show that $f$ is not onto.

Write $f(i)[i]$ for the $i$-th decimal digit of $f(i)$ (if $f(i)$ is a number with two decimal representations then we use the one ending in $0$'s).
Let $g$ be the map on the decimal digits $\set{0,\ldots,9}$ given by:
$g(j)=2$ if $j$ is~$1$, and $g(j)=1$ otherwise.

Now let the number~$z$ have the $i$-th decimal digit
$g(f(i)[i])$. 
Clearly $z\in\leftclosed{0}{1}$, and $z\neq f(i)$ for all~$i$, 
so $f$ is not onto. 
\end{proof}

\begin{theorem} \label{th:RealsNotCountable}
The set of real numbers is not countable.  
\end{theorem}

\begin{proof}
If $\R$ were countable then there would be a correspondence $\map{f}{\N}{\R}$.
We will show that the existence of such a map leads to a contradiction.

The tangent function is a correspondence from $\open{-\pi/2}{\pi/2}$ to~$\R$
so its inverse, arctangent, is a correspondence in the other direction.
Thus, $g(x)=(\arctan(x)+(\pi/2))/\pi$ gives a correspondence from $\R$ to 
$\open{0}{1}$.
\begin{center}
  \includegraphics{background/asy/arctan/arctan.pdf}
\end{center}
If $f$ exists then
composing would give an onto map $\map{g\circ f}{\N}{\open{0}{1}}$. 
Producing from that a map $\map{h}{\N}{\leftclosed{0}{1}}$ that is onto the
half-closed interval is easy:
as in the Infinite Hotel, move all the existing output values up by one so that
$h(i)=g\circ f(i-1)$ if $i$ is not~$0$, and slip the new value in so that 
$h(0)=0$.  
However \cref{lem:UnitIntUncountable} says that no such $h$ exists, 
and so no such~$f$ exists.
\end{proof}

\begin{definition}
An infinite set that is not countable is \definend{uncountable}.  
\end{definition}

We next define when one set has fewer members than the other.
For the intuition, consider trying 
to make a correspondence 
between $S=\set{0,1,2}$ and $T=\set{0,1,2,3,4}$. 
We can try to stretch~$S$ to make it cover as much 
of $T$ as possible, say with $0\mapsto 0$, $1\mapsto 1$, and~$2\mapsto 2$.
This stretching map is one-to-one but 
it is not a correspondence because it is not onto. 

\begin{definition}
The set $S$ has \definend{cardinality less than or equal to}
that of the set~$T$,    
denoted $|S|\leq |T|$,
if there is a one-to-one function from $S$ to~$T$.
\end{definition}

For example, there is a one-to-one function from $\N$ to $\R$,
namely the inclusion map that sends $n\in\N$ to itself~$n\in\R$.
What \cref{th:RealsNotCountable} says 
is that no function from $\N$ to~$\R$ is onto.

The preceeding defintion allows us to show that, given a set, 
we can produce another set of larger cardinality\Dash there's always a
bigger set.
For that, recall that a set's \definend{characteristic function} $\charfcn{S}$ 
is the boolean function determining membership:
$\charfcn{S}(s)=1$ if $s\in S$, and $\charfcn{S}(s)=0$ if $s\notin S$.
Recall also that the \definend{power set}~$\powerset(S)$ 
is the collection of subsets of $S$.
Thus, for the set $S=\set{\str{a},\str{b},\str{c}}$ of three letters,
the characteristic function 
(with domain $\Sigma=\set{\str{a},\ldots, \str{z}}$) 
is
\begin{equation*}
  \charfcn{S}(\str{a})=1
  \quad
  \charfcn{S}(\str{b})=1
  \quad
  \charfcn{S}(\str{c})=1
  \quad
  \charfcn{S}(\str{d})=0
  \quad
  \ldots
\end{equation*}
and its power set is
$
  \powerset(S)=\set{\emptyset, \set{\str{a}}, \set{\str{b}}, \set{\str{c}},
                          \set{\str{a},\str{b}}, 
                          \set{\str{a},\str{c}}, 
                          \set{\str{b},\str{c}}, 
                          \set{\str{a},\str{b},\str{c}} }
$.

\begin{theorem}[Cantor's Theorem]
Every set has cardinality strictly less than that of its power set.    
\end{theorem}

First we illustrate the proof.
% The easy part is 
% producing a one-to-one function from $S$ to $\powerset(S)$.
% Just map $s\in S$ to the singleton set $\set{s}$.
% That is clearly one-to-one.
The hard half will be 
showing that no map from $S$ to $\powerset(S)$ is onto.
Consider the set $S=\set{\str{a},\str{b},\str{c}}$ 
and the example function $\map{f}{S}{\powerset(S)}$.
\begin{equation*}
  \str{a}\mapsunder{f}\set{\str{b},\str{c}} 
  \qquad
  \str{b}\mapsunder{f}\set{\str{b}}
  \qquad
  \str{c}\mapsunder{f}\set{\str{a},\str{b},\str{c}}
\end{equation*}
The table below gives the characteristic functions 
$\map{\charfcn{f(s)}}{S}{\set{0,1}}$ of the
three output sets $f(\str{a})$, $f(\str{b})$, $f(\str{c})$.
\begin{center}
  \begin{tabular}{c|c|ccc}
    \multicolumn{1}{c}{$s\in S$}
       &\multicolumn{1}{c}{$f(s)$}
       &$\charfcn{f(s)}(\str{a})$  
       &$\charfcn{f(s)}(\str{b})$   
       &$\charfcn{f(s)}(\str{c})$  
    \\[.5ex] \hline \rule{0em}{2ex}
    $\str{a}$ &$\set{\str{b},\str{c}}$          &$0$ &$1$ &$1$  \\ 
    $\str{b}$ &$\set{\str{b}}$                  &$0$ &$1$ &$0$  \\ 
    $\str{c}$ &$\set{\str{a},\str{b},\str{c}}$  &$1$ &$1$ &$1$  
  \end{tabular}
\end{center}
Diagonalize.  
That is, go down the diagonal on the right and flip the bits from $0$ to~$1$
and from $1$ to~$0$.
The result is the characteristic function of a set, 
$R=\set{\str{a}}$,
which is not one of the mapped-to sets in the second column.
It is not the first mapped-to set because it differs on~$\str{a}$, 
it is not the second mapped-to set because it differs on~$\str{b}$,
and it is not the third mapped-to set because it differs on~$\str{c}$.

\begin{proof}
One half is easy:
the map $\map{\iota}{S}{\powerset(S)}$
given by $\iota(s)=\{s\}$
is one-to-one, so the cardinality of $S$
is less than or equal to the cardinality of $\powerset(S)$.

For the other direction,
to show that no map from a set to its power set is onto, 
fix any~$\map{f}{S}{\powerset(S)}$ and consider 
this element of $\powerset(S)$.
\begin{equation*}
  R=\set{s \suchthat s\not\in f(s)}
  % \tag{$*$}
\end{equation*}
(This is where we flip the bits.)
We will show that $f$ is not onto because no member of the domain maps to~$R$.

For that, suppose that $\hat{s}\in S$ is such that $f(\hat{s})=R$.
We will show that both $\hat{s}\in R$ and $\hat{s}\not\in R$ give 
contradictions.
First, assuming that $\hat{s}\in R$ leads, by
the definition of $R$, to the conclusion that $\hat{s}\not\in f(\hat{s})$, 
but in this case $f(\hat{s})=R$ so $\hat{s}\not\in R$, which is a contradiction.
Alternatively, assuming that $\hat{s}\not\in R$ leads, because
$R=f(\hat{s})$, to
$\hat{s}\not\in f(\hat{s})$, so $\hat{s}\in R$, which is also a contradiction.
\end{proof}

\begin{theorem}
The cardinality of the set of functions $\map{f}{\N}{\N}$ is 
strictly greater than the cardinality of the set of Turing machines.  
\end{theorem}

\begin{proof}
The set of Turing machines is countable because we can 
enumerate all the one-instructions machines, then all the two-instruction
machines, etc.
See \cref{exer:EnumerateTMachines}.
So by the prior result, the cardinality of the set of Turing machines
is strictly less than the cardinality of $\powerset(\N)$.

That, in turn, is
less than or equal to the cardinality of the set~$F$
of functions~$\map{f}{\N}{\N}$.
There is a natural one-to-one map from $\powerset(\N)$ to~$F$:
associate each subset $S\subseteq\N$ with its characteristic function 
$\map{\charfcn{S}}{\N}{\N}$.
Therefore~$\sizeof{\N}<\sizeof{\powerset(\N)}\leq\sizeof{F}$.
\end{proof}

As in the child's game of Musical Chairs, we have here countably many places, 
the Turing machines $\TM_0$, $\TM_1$, \ldots{}\,,
and 
there are just too many functions $\map{f}{\N}{\N}$ 
to have each fit into a solo place.
It is a pigeonhole argument.

In the light of Church's Thesis, we can leave the strictly technical realm of 
computational models and number-theoretic functions 
in which this theorem is stated 
to say something more, 
something very interesting, very essential, about the nature
of mechanical computation: there are functions for which there is no
program that computes them. 
There are jobs that no computer can do.

$\map{g}{\N}{\set{2n+1\suchthat n\in\N}}$ is
both one-to-one and onto.
\begin{answer}
To verify that $g$ is one-to-one, assume $g(n_0)=g(n_1)$,

Subtract~$1$ and divide by~$2$ to conclude that

To verify that $g$ is onto we need to start with an element of the codomain
$y\in\set{2n+1\suchthat n\in\N}$, the odd natural numbers.
Observe that because $y$ is odd, $y$ has the form $y=2n+1$ for some
natural number~$n$.
Thus there is a natural number that maps under~$g$ to~$y$, 
namely~$n$, and so~$g$ is onto.  
\end{answer}

\begin{exercise}
We prove that for finite sets $D$ and~$C$, 
if there is a correspondence~$\map{f}{D}{C}$
then the two have the same number of elements.
Recall that $\sizeof{S}$, the cardinality of the set~$S$,
is the number of elements in~$S$.
\begin{exparts}
  \item Prove that if $f$ is one-to-one then $\sizeof{C} \geq \sizeof{D}$.
  \item Prove that if $f$ is onto then $\sizeof{C} \leq \sizeof{D}$.
\end{exparts}
\begin{answer}
\begin{exparts}
\item   Assume that $\map{f}{D}{C}$ is one-to-one.
  We will do induction on the number of elements in~$D$.
  The base step is that~$\sizeof{D}=0$.
  The codomain cannot have fewer elements than this
  so~$\sizeof{C} \geq \sizeof{D}$ holds in this case.

  For the inductive step assume that the statement is true when 
  $\sizeof{D}=0$, 
  \ldots, $\sizeof{D}=k$ and let~$D$ be a set with~$\sizeof{D}=k+1$.
  Pick some $d\in D$ and consider 
  $\hat{D}=D-\set{d}$ (because this is the $k+1$ case, there is at least
  one such element).
  The inductive hypothesis applies to $\hat{D}$ so that 
  the number of elements in the range of the restriction map 
  $\map{\hat{f}}{\hat{D}}{\range(\hat{f})}$
  is at least as great as the number of elements in the domain of that map
  $\sizeof{\range(\hat{f})} \geq \sizeof{\hat{D}}$.

  Now extend to~$D$ and the map~$\map{f}{D}{C}$.
  The set~$D$ has one element more than the set~$\hat{D}$.
  Because~$f$ is one-to-one, the value~$f(d)$ is not in 
  the range of the restriction map~$\range(\hat{f})$.
  Thus $\range(f)$ is one element larger than
  $\sizeof{\range(\hat{f})}$.
  Therefore $\sizeof{C} \geq \sizeof{D}$.      

\item   Assume that $\map{f}{D}{C}$ is onto.
  We do induction on the number of elements in
  the domain~$D$.
  The base step is that~$D$ has no elements, so $D=\emptyset$.
  The only function with an empty domain is the function whose graph is 
  empty. 
  This function is onto so the codomain~$C$ is also empty 
  (otherwise there would be an element of the codomain with no inverse
  image).

  For the inductive step assume that the statement is true when $|D|=0$, 
  $|D|=1$, \ldots, $|D|=k$ and consider the~$|D|=k+1$ case.
  Pick some $d_0\in D$ and consider 
  $\hat{D}=D-\set{d_0}$ (because this is the $k+1$ case there is at least
  one such element in~$D$).

  There are two cases:
  whether the codomain element $f(d_0)$ is also the image of another domain
  element, some $d\in\hat{D}$, or else it is not.
  In the first case the restriction $\hat{f}$ is onto
  and so the inductive hypothesis applies, giving that 
  $|C|\leq |\hat{D}|<|D|$.

  In the other case, that $d_0$ is the only element of~$D$ associated 
  by~$f$ with the codomain element~$f(d_0)$, let $\hat{C}=C-\set{f(d_0)}$.
  The restriction map~$\map{\hat{f}}{\hat{D}}{\hat{C}}$ is clearly onto,
  so the inductive hypothesis applies: $|\hat{C}|\leq |\hat{D}|$.
  Therefore $|\hat{C}|+1=|C|\leq |D|=|\hat{D}|+1$.
\end{exparts}
\end{answer}
\end{exercise}

\subsection{Primitive recursion}
In the development of the definition of a Turing machine we discussed
that multiplication can be done with repeated addition, and that addition
in turn can be done with a repeated successor operation, a plus-one
operation.

How to do that?
In grade school we learn these operations as mildly complicated 
algorithms (``carry the one'').
In 1861 a much prettier definition was given by Grassman
(and in 1888 Dedekind used the definition to give a first rigorous 
proof of the laws of elementary school arithmetic).
Here is addition, which is based on
successor $\map{\successor}{\N}{\N}$ given by $\successor(n)=n+1$.
\begin{equation*}
  \plus (x,y) =\begin{cases}
                x                 &\case{if $y=0$}  \\
                \successor(\plus(x,z)) &\case{if $y=\successor(z)$ for $z\in\N$}
               \end{cases}
\end{equation*}
This is \definend{recursive} since `$\plus$' recurs within
its own definition.
That is, recursion is a discrete form of feedback.

A natural first reaction to a recursive definition is to wonder 
whether it is logically problematic\Dash isn't defining
something in terms of itself a fallacy?
But the above does not define things in terms of themselves;
for instance $\plus(3,2)$ is defined 
in terms of $\plus(3,1)$.
And $\plus(3,1)$ is defined in terms of $\plus(3,0)$, whose definition
is clearly not a problem.

\begin{example}
We can trace the expansion of $\plus(3,2)$.
\begin{align*}
  \plus(3,2) &= \successor(\plus(3,1)) \\
             &= \successor(\successor(\plus(3,0))) \\
             &= \successor(\successor(3))=5 
\end{align*}
The second equality comes from expanding $\plus(3,1)$ 
to $\successor(\plus(3,0))$, so the left-hand $\successor$ is just 
carried down from the prior line.
\end{example}

One beautiful thing about this approach is that multiplication follows the
same form.
\begin{equation*}
  \product (x,y) =\begin{cases}
                0                 &\case{if $y=0$}  \\
                \plus(\product(x,z),x) &\case{if $y=\successor(z)$}
               \end{cases}
\end{equation*}
\begin{example}
The expansion of $\product(2,3)$
reduces to a sum of three $2$'s.
\begin{align*}
  \product(2,3) &=\plus(\product(2,2),2)     \\
                &=\plus(\plus(\product(2,1),2),2)  \\
                &=\plus(\plus(\plus(\product(2,0),2),2),2) \\
                &=\plus(\plus(\plus(0,2),2),2)
\end{align*}
\end{example}

The derivation of exponentiation also follows that form.
\begin{equation*}

                1                 &\case{if $y=0$}  \\
                \product(\power(x,z),x) &\case{if $y=\successor(z)$}
               \end{cases}
\end{equation*}

\begin{definition}  \label{def:PrimitiveRecursion}
A function~$f$ is defined by the schema\footnotemark[2] 
of \definend{primitive recursion}
from the functions $g$ and~$h$ if it has this form.
\begin{equation*}
  f(x_0,\ldots,x_{n-1},y)=
  \begin{cases}
    g(x_0,\ldots,x_{n-1}) &\case{if $y=0$}   \\
    h(f(x_0,\ldots,x_{n-1},z),\,x_0,\,\ldots,\,x_{n-1},\,z)
      &\case{if $y=\successor(z)$}
  \end{cases}
\end{equation*}
\end{definition}
\footnotetext[2]{A schema is an underlying organizational pattern or structure.}

The bookkeeping is that the number of inputs to~$f$ is 
one more than the number of 
inputs to~$g$, and one less than the number of inputs to~$h$.

\begin{example}
The function $\plus$ is defined by primitive recursion from 
$g(a)=a$ and $h(a,b,c)=\successor(a)$.
The function~$\product$ is defined by primitive recursion from
$g(a)=0$ and $h(a,b,c)=\plus(a,b)$.   
The function~$\power$ is defined by primitive recursion from
$g(a)=1$ and $h(a,b,c)=\product(a,b)$.   
\end{example}

Primitive recursion suffices to define many familiar functions. 

\begin{example}
The predecessor function on the natural numbers is:
$\pred(y)$ equals
$y-1$ if $y$ is positive, and equals~$0$ if $y$ is zero.
Here is a derivation.  
\begin{equation*}
  \pred(y)=\begin{cases}
              0  &\case{if $y=0$}  \\
              z  &\case{if $y=\successor(z)$}
            \end{cases}
\end{equation*}
In the notation of \cref{def:PrimitiveRecursion},
$\pred$ has no $x$'s. 
So, $g$ is a function of no inputs 
(and must therefore be a constant function) $g(\,)=0$,
while $h$ has two inputs~$h(a,b)=b$. 
\end{example}

\begin{example}
We can use primitive recursion to 
produce \definend{proper subtraction}, often denoted $x\dotminus y$,
which gives $x-y$ if that value is nonnegative, and gives $0$ otherwise.   
\begin{equation*}
  \operatorname{propersub}(x,y)
               =\begin{cases}
                 x    &\case{if $y=0$}  \\
                 \pred(\operatorname{propersub}(x,z))  &\case{if $x\geq y$}
               \end{cases}
\end{equation*}
This fits the schema with $g(a)=a$ 
and $h(a,b,c)=\pred(a)$.
\end{example}

These examples underline that the function~$f$ is produced from, or
comes after, the functions~$g$ and~$h$.
The code examples also dramatize that if $g$ 
and~$h$ are intuitively mechanically computable then so is~$f$.
So we will have a system of computable functions if we start with 
some suitable list of effective initial functions.

\begin{definition} \label{def:PrimitiveRecursive}
A function is 
\definend{primitive recursive}\footnotemark[1]
if it can be derived by a finite number of applications of 
function composition and the scheme of primitive recursion
from the initial operations of 
the \definend{zero} function~$\zero(x)=0$,
the \definend{successor} function~$\successor(x)=x+1$,
and the \definend{projection} 
functions~$\projection_i(x_0,\ldots,x_i\ldots,x_{n-1})=x_i$ 
\end{definition}
\footnotetext[1]{`Primitive'  
distinguishes these from another set of functions that we will see soon.}
\noindent 
Observe that there are infinitely many projections, one for each 
$n,i\in\N$.
We use the symbol $\projection$ for projection because it is a generalization
of the identity function.

Are all intuitively mechanically computable functions primitive recursive?
We have already seen some mechanically computable functions 
that are partial, that fail to have an output for some inputs.
But all primitive recursive functions are total.
So we have seen some functions not derivable as above.

We could speculate that perhaps 
this is a matter of making a minor adjustment,
perhaps something like:~for any $f$ that is intuitively mechanically
computable there is a primitive recursive~$g$ such that 
if $f$ converges on input~$x$ then $g(x)=f(x)+1$ and if $f$ does not converge
on~$x$ then $g(x)=0$.
However, this speculation is wrong;
the next subsection gives a function that is intuitively mechanically computable
but that is not primitive recursive.







\subsection{Ackermann functions}
Addition is repeated successor.
\begin{equation*}
  x+y=\underbrace{\successor(\,\successor(\,\cdots \successor(x)))}_{\text{$y$ many}}
  \qquad
  \text{e.g., $x+2=\successor(\successor(x))$}
\end{equation*}
Multiplication is repeated addition.
\begin{equation*}
  x\cdot y=\underbrace{x+x+\,\cdots\, +x}_{\text{$y$ many}}
  \qquad
  \text{e.g., $x\cdot 2=x+x$}
\end{equation*}
Exponentiation is repeated multiplication.
\begin{equation*}
  x^y=\underbrace{x\cdot x\cdot \,\cdots\, \cdot x}_{\text{$y$ many}}
  \qquad
  \text{e.g., $x^2=x\cdot x$}
\end{equation*}
This is a compelling pattern.
We can, for instance, ask what operation comes next.

We start with successor.
Using that operation, 
addition has the recursive definition $\plus(x,y)=\successor(\plus(x,y-1))$.
Multiplication's recursion is $\product(x,y)=\plus(x,\product(x,y-1))$.
Exponentiation's is $\power(x,y)=\product(x,\power(x,y-1))$. 
We have this sequence of operations, where $\hyperoperation_0=\successor$. 
\begin{align*}
  \plus(x,y)=
  \hyperoperation_1(x,y)&=\begin{cases}
             x                             &\case{if $y=0$}  \\
             \hyperoperation_0(x,\hyperoperation_1(x,y-1))    &\case{otherwise}
           \end{cases}                                                \\[1ex]
  \product(x,y)=
  \hyperoperation_2(x,y)&=\begin{cases}
             0                                  &\case{if $y=0$}  \\
             \hyperoperation_1(x,\hyperoperation_2(x,y-1))    &\case{otherwise}
           \end{cases}                                               \\[1ex]
  \power(x,y)=
  \hyperoperation_3(x,y)&=\begin{cases}
             1   &\case{if $y=0$}  \\
             \hyperoperation_2(x,\hyperoperation_3(x,y-1))    &\case{otherwise}
           \end{cases}
\end{align*}

\begin{definition}
The \definend{hyperoperation} $\map{\hyperoperation}{\N^3}{\N}$ is given
by this.
\begin{equation*}
  \hyperoperation(n,x,y)=
  \begin{cases}
    y+1  &\case{if $n=0$}             \\
    x    &\case{if $n=1$ and $y=0$}   \\
    0    &\case{if $n=2$ and $y=0$}   \\
    1    &\case{if $n>2$ and $y=0$}   \\
    \hyperoperation(n-1, x, \hyperoperation(n, x, y-1)) &\case{otherwise}
  \end{cases}
\end{equation*}
In place of $\hyperoperation(n,x,y)$
we often write $\hyperoperation_n(x,y)$, 
and describe this two-input function as \definend{level~$n$} 
of~$\hyperoperation$. 
\end{definition}

\begin{lemma}
$\hyperoperation_0(x,y)=y+1$,
$\hyperoperation_1(x,y)=x+y$,
$\hyperoperation_2(x,y)=x\cdot y$,
$\hyperoperation_3(x,y)=x^y$.
\end{lemma}

\begin{proof}
The level~$0$ statement $\hyperoperation_0(x,y)=y+1$ is in the definition of
$\hyperoperation$.

With that, we prove the level~$1$ statement $\hyperoperation_1(x,y)=x+y$ by 
induction on the second variable,~$y$.
For the $y=0$ base step, the definition 
gives that $\hyperoperation(1,x,0)=x$, which equals $x+0=x+y$.
For the inductive step, assume the statement holds for $y=0$, \ldots, $y=k$
and consider the $y=k+1$ case.
The definition is
$\hyperoperation_1(x,k+1)=\hyperoperation_0(x,\hyperoperation_1(x,k))$.
Apply the inductive hypothesis to get
$\hyperoperation_0(x,x+k)$.
By the prior paragraph this equals the successor of the second argument
$x+k+1=x+y$, as required.

The other two, $\hyperoperation_2$ and~$\hyperoperation_3$, are similar, 
and are left for the exercises.
\end{proof}

\begin{remark}
The next level, \definend{tetration} $\hyperoperation_4$,
is the natural answer to the question of what comes after the
elementary school operations of addition, multiplication, and exponentiation.
Here are two values.
\begin{equation*}
  \hyperoperation_4(2,2)=2^2=4
  \quad
  \hyperoperation_4(2,3)=2^{2^2}=2^4=16
\end{equation*}
Similarly, $\hyperoperation_4(2,4)$ has four $2$'s stacked up.
This is sometimes called a power tower.
Recall that the order in which we perform exponentiations is significant.
\begin{equation*}
  (3^3)^3=27^3=3^9
  \quad\text{does not equal}\quad
  3^{(3^3)}=3^{27}
\end{equation*}
Tetration associates the powers in the second way, 
so the one on the right is $\hyperoperation_4(3,3)$.
Incidentally, $\hyperoperation_4(3,3)=7\,625\,597\,484\,987$.
The rapid growth of the output values is a striking aspect of tetration, and
of the hyperoperation in general.
\end{remark}

Observe that $\hyperoperation$ is intuitively mechanically computable.
From the definition, producing the Scheme code
hardly needs any adaptation at all.
\begin{lstlisting}
(define (H n x y)
  (cond
   ((= n 0) (+ y 1))
   ((and (= n 1) (= y 0)) x)
   ((and (= n 2) (= y 0)) 0)
   ((= y 0) 1)
   (else (H (- n 1) x (H n x (- y 1))))))  
\end{lstlisting}

\begin{wrapfigure}{L}{0.2\textwidth}
\centering
\includegraphics[width=0.2\textwidth]{background/ackermann.jpg} % http://upload.wikimedia.org/wikipedia/commons/4/48/Galilee.jpg
\caption{\label{fig:ackermann}\href{https://en.wikipedia.org/wiki/Wilhelm_Ackermann}{Wilhelm Ackermann 1896--1962}}
\end{wrapfigure}
Hyperoperation is one of a family of functions with the same recursion,
the same last line in the above code.
We refer to them all as \definend{Ackermann functions} after 
the mathematician who first showed that a member of the family, while
intuitively mechanically computable, is not primitive recursive.

For that argument, note that the recursion 
$
  \hyperoperation(n,x,y)=
  \hyperoperation(n-1, x, \hyperoperation(n, x, y-1))
$
is not in the form for the definition of a primitive recursive function,
\cref{def:PrimitiveRecursive},  
$f(x_0,\ldots,x_{n-1},y)= h(f(x_0,\ldots,x_{n-1},y-1),x_0,\ldots,x_{n-1},y-1)$.
The problem is not that $\hyperoperation$'s 
arguments are stated in a different order; 
that is cosmetic.
The problem is that the definition requires that
$h$ be a function for which we already have a derivation as 
primitive recursive.

Of course, just because~$\hyperoperation$'s definition is not stated in the 
form for \cref{def:PrimitiveRecursive} doesn't mean that
it cannot be put into that form.
The proof that it cannot is an
\hyperref[sec:ComputableFunctionNotPrimitiveRecursive]{Extra Section}
but briefly: 
we have already observed that $\hyperoperation_1$
grows arithmetically, that $\hyperoperation_2$ grows geometrically, 
and that $\hyperoperation_3$ grows exponentially.
Each primitive recursive function~$f$ 
has a derivation from initial functions via a sequence of 
compositions and primitive recursions.
The proof
shows that
each initial function grows slower some level~$\hyperoperation_k$, that
each composition bumps the level of the resulting function up by~$2$,
and that each primitive recursion bumps the level up by~$3$.
Then, as the function~$\hyperoperation$ as a whole grows faster 
than any of its levels, it cannot be primitive recursive.

Finally, a comment: not only is the hyperoperation an
example of an intuitively computable function that is not
primitive recursive, but also
it is particularly interesting since it arises in the wild\Dash it is not
a contrived example but a quite natural one.




\subsection{\protect\(\ \mathbf{\mu} \protect\) recursion}
Using the schema of primitive recursion is a productive step towards  
defining the functions that are mechanically computable because it is
natural and because many 
familiar functions are primitive recursive.
But the prior subsection shows that the class is not wide enough
to contain all of the mechanically computable functions.
So we wiill define a broader class. 

The proof that hyperoperation is not primitive recursive shows that 
all primitive recursive functions fall into a level.
To expand expand to a class larger than that of primitive recursive functions 
we look for a way that cuts
across levels: if what we want isn't on level~$i$ then
move to level~$i+1$.
Consequently, to the combining operations of composition and
primitive recusion we add unbounded search.
% As witnessed by the result that
% a function is primitive recursive if and only if it can be computed 
% using for loops alone, we think to add the ability to 
% do \codeinline!while! loops\Dash unbounded searches.  

\begin{definition} \label{def:MuRecursion}
Where $\map{g}{\N^2}{\N}$, we say 
$\map{f}{\N}{\N}$ is 
defined by \definend{unbounded minimization} from $g$
if $f(x)=y$ where~$y$ is the least number such that $g(x,y)$  equals~$0$
(and is defined).
We write $\mu$ for `the least', giving this notation.
\begin{equation*}
  f(x)=\mu y\,\big[ g(x,y)=0 \big] % =(\mu g)(x)
\end{equation*}
\end{definition}

Intuitively, we've added the capacity to do unbounded search: to 
look at $g(x,0)$, then $g(x,1)$, etc., until we get the output of~$0$.

\begin{example}
Let $g(x,y)=\ceiling{(x+1)/(y+1)-1}$, and let $f(x)=\mu\,y[g(x,y)=0]$.
In general, $f(x)=x$.
For instance, the first few values of $g(5,y)$ show that $f(5)=5$.
\begin{equation*}
  \begin{tabular}{r|rrrrrr}
    \tabulartext{input $y$} 
      &\multicolumn{1}{c}{$0$}
      &\multicolumn{1}{c}{$1$}
      &\multicolumn{1}{c}{$2$}
      &\multicolumn{1}{c}{$3$}
      &\multicolumn{1}{c}{$4$}
      &\multicolumn{1}{c}{$5$} \\ \hline
   \tabulartext{$g(5,y)$}
      &$5$ &$2$ &$1$ &$1$ &$1$ &$0$
  \end{tabular}
\end{equation*}
\end{example}

In the definition, the parenthetical comment  ``and is defined'' is there
because using the minimization operator  we can get functions whose output 
value is undefined for some inputs.

\begin{example}
Let $g(x,y)=1$ for all~$x,y\in\N$.  
Then $f(x)=\mu\,y[g(x,y)=0]$ is undefined for all~$x$.
\end{example}

That some functions are undefined for some inputs is an awkward aspect of 
this definition.
Of course, on a computer we do see that for some programs there are inputs
with no associated output, so it just is part of the landscape. 

\begin{definition} \label{def:Recursive}
A function is 
\definend{recursive} (or \definend{general recursive})
if it can be derived from the initial operations of 
the \definend{zero} function~$\zero(x)=0$,
the \definend{successor} function~$\successor(x)=x+1$,
and the \definend{projection} 
functions~$\projection_i(x_0,\ldots,x_i\ldots,x_{n-1})=x_i$ 
by a finite number of applications of 
function composition, the schema of primitive recursion,
and minimization.
\end{definition}

Kleene showed that the set of functions satisfying this definition is
the same as the set of 
functions that can be computed by a Turing machine, 
or by Church's $\lambda$-calculus.

\begin{answer}
\autocite{Davis}  
Suppose that if two functions $\map{f,\hat{f}}{\N^{n+1}}{\N}$ both    
satisfy \cref{def:PrimitiveRecursion}.
We will show that for all $\sequence{x_0,\ldots,x_{n-1},y}\in\N^{n+1}$
the two are equal $f(x_0,\ldots,x_{n-1},y)=\hat{f}(x_0,\ldots,x_{n-1},y)$,

they are equal when $y=0$ because they both equal $g(x_0,\ldots,x_{n-1})$.

the $y=k+1$ case.

  &=g(\hat{f}(x_0,\ldots,x_{n-1},k),\,x_0,\ldots,x_{n-1},\,k)
   =\hat{f}(x_0,\ldots,x_{n-1},k+1)
\end{align*}
The second equality follows from the induction hypothesis.
\end{answer}

\section{Universal Turing Machine}

We have seen many Turing machines:
one whose behavior is that the output is 
twice the input, 
one that adds three \str{1}'s to the input, etc.
These are single-purpose devices.
From what we have seen so far, to get different input-output behavior
requires a new machine, new hardware.

The early electronic computer below illustrates.
The programmers change the machine's behavior by 
changing the circuits, using the patch cords that hang down from 
the panels.

a screwdriver and a soldering gun, but still inconvenient.
This is as though your laptop required that, 
to change from running a browser to running a spreadsheet, you had to 
pull the browser chip and replace it with the spreadsheet chip. 

A pattern in technology is for jobs done in hardware to migrate to software.
One early example is in the weaving of cloth.
On the left below is a loom operator.
\begin{center}

  \includegraphics[width=.33\textwidth]{background/loom.jpg}

Weaving by hand to get a beautiful pattern like hers is intricate and slow.

built a loom with hooks whose position, raised or lowered, is controlled by 
holes punched in paper cards, shown on the right.
Reconfiguring the loom means only

and then take them out again next year.

Turing introduced the analog for computing devices, to
move the reconfiguration from hardware to software so that, 
along with its input, the machine
also reads its configuration from the tape.

\begin{theorem}[Turing, 1936]
There is a Turing machine whose
output behavior on the input $\sequence{e,x}$ is 
the same as the output behavior of $\TM_e$ on input~$x$.
\end{theorem}

This is a \definend{Universal Turing Machine}.
We denote such a machine with~$\UTM$.
It is universal in that it is one machine that can be made to
act as any machine at all.

At first glance, building a universal machine may seem to be a 
chicken and egg problem:~how can we give Turing machines as input to 
Turing machines?
In particular, the machine of the theorem has some number,
and the theorem seems to allow this machine possibly being 
given~$\sequence{e,x}$ where~$e$ is   
its own number\Dash
won't that give infinite regress?

Here is a way to represent a Turing machine on a machine tape.
Encode each four-tuple as a sequence of four blocks 
of \str{1}'s, separated by single~\str{B}'s.
The first block encodes the current-state number using the unary 
representation, where the number~$n$ is represented by 
$n+1$-many \str{1}'s (use an extra \str{1} so that $0$'s representation is 
nonempty).
The second block encodes the current symbol, 
with \str{1} representing the symbol blank
and \str{11} representing the symbol one.
The third block gives the next-state number, also in unary.
The fourth block represents the action performed: encode
writing a blank symbol as \str{1}, encode writing a one as~\str{11}, 
encode a move to the left~$L$ as \str{111}, and a move to the right~$R$ 
as \str{1111}.
Now to encode a complete machine, a set of four-tuples, 
put tuples on the tape in any order but separated by two blanks~\str{BB}.
Finally, separate the description of the machine from 
the input with three blanks~\str{BBB}.

For any Turing machine, we could 
put its representation on the tape of another Turing machine,
or on its own tape, and press \texttt{Start}.
If, say, the machine that we just started is an input doubler 
then the output will not have any apparent 
sensible connection to the fact that the input represents a Turing machine.
Nonetheless, feeding a Turing machine as input to another Turing machine, 
or to itself, is perfectly possible.

Now that we know representation is possible, what remains is to see that 
there are 
universal machines, ones that can become what is represenated.
With such a device, 
changing its behavior would only involve putting
new stuff on the tape\Dash this is like the punched cards, which
alter the behavior of the machine with no hardware patch chords.
In Turing's time, showing that $\UTM$'s exist required
a detailed analysis so he exhibited such a machine.
Today, we can start by  
appealing to the intuition that we all have from 
everyday computing experience, that is,
by using Church's Thesis.

\section{Halting Problem}
We've shown there are problems that no computer can solve.
We did this by arguing that there are countably many programs but 
uncountably many functions and so there are functions not computed
by a program.

That argument does not, as it stands, 
give us a specific unsolvable problem.
In this subject, our taste is that while a proof that something exists is
better than nothing, we prefer an argument that constructs an object
with the properties of interest.
In this section we will give a problem, the Halting Problem, and show
that it cannot be mechanically solved.

In our everyday experience,
a program that gets stuck or does not halt is a glitch.
Our thought is reach for source code, to eliminate 
whatever is the problem.
From this our sense may be that programs failing to halt is 
an abberation, something that we can patch up. 

However, that sense is mistaken.
Imagine that we could arrange so that all Turing machines 
produce output on all inputs.
We'd have a table like this.

\subsection{Definition}
That motivation shows that 
we are interested in these sets.

\begin{definition}
  $\definend{K}=\set{e \suchthat \text{$\TM_e(e)$ halts}}$
\end{definition}

\begin{definition}
  $\definend{K_0}=\set{\sequence{e,x} \suchthat \text{$\TM_e(x)$ halts}}$
\end{definition}

Finding the characteristic function of the first is our touchstone
unsolvable problem.

\begin{problem}[Halting Problem]
Determine if a Turing machine halts.
\probleminput~integer $e$.
\problemoutput~$0$ if $\TM_e(e)$ does not halt and $1$ if it does.
\end{problem}

There are Turing machines that halt on all inputs, 
Turing machines that halt on no inputs, 
and ones that halt on some inputs but not others.

The statement of the problem may seem unnatural.
Surely the more natural question is whether $\TM_e$ halts on input~$x$?

We will observe that the two problems are essentially the same problem 
(we go with the above statement because it has some technical advantages).
For, if we can solve the problem of determining whether any $\TM_e$ halts on
any input~$x$ then clearly we can answer whether $\TM_e$ halts on~$e$.
Conversely, suppose that we can answer the question of whether $\TM_e$ halts on
input~$e$.
Consider this program.

\end{center}
By Church's Thesis there is a Turing machine implementing that chart.
Let it be machine~$\TM_{f(\hat{e},x)}$. 
Observe that the machine either halts on all inputs, or fails to halt on
all inputs, depending on wheyter

\begin{theorem}[Unsolvability of the Halting Problem]
There is no machine that solves the Halting Problem.
\end{theorem}

\begin{proof}
Suppose that a Turing Machine exists that solves the Halting Problem,
that enables us to test for any~$e$ whether $\TM_e$ halts on input~$e$.
Consider the program charted here.
\begin{center}

Suppose that it has index~$e_0$, so it is~$\TM_{e_0}$.
Give it~$e_0$ as input.
% We are feeding $e_0$ to $\TM_{e_0}$ so the test applies.

If $\TM_{e_0}$ halts on $e_0$ then the test would 
take the right-hand branch, which results in $\TM_{e_0}$ not halting
on~$e_0$.
If $\TM_{e_0}$ fails to halt on $e_0$ then the test would 
go left, which leads to $\TM_{e_0}$ halting on~$e_0$.
This contradiction means that
no Turing Machine exists that solves the Halting Problem.
\end{proof}

The unsolvability of the Halting Problem says that there is no

in a finite time whether $\TM_e$ halts on input~$x$.

The ``finite time'' qualifier is there because we could just use a universal
Turing machine to simulate $\TM_e$ on~$x$, but if it failed to halt we 
would not find that out in a finite time. 

The ``single program'' qualifier is there because of the subtlety 
illuminiated by the next example.

\begin{example}
Consider the problem of, given a number $n$, 
deciding whether somewhere in the decimal expansion of~$\pi=3.14159\ldots{}$ 
there is a sequence of 
\citetext{$n$~consecutive nines.}{At the $762$-nd decimal point there are 
$6$ nines in a row.  
This is call the Feynman point; see 
\protect\url{https://en.wikipedia.org/wiki/Feynman_point}.
Most experts guess that for any~$n$ there is in the decimal 
expansion a sequence of 
$n$ consecutive nines but no one has proved it, or disproved it either.}    

There are two possibilities:
either for all numbers such a sequence exists, or else there is some
$n_0$ where the sequence exists for numbers less or equal to~$n_0$ and no such
sequence exists for numbers larger than that.

Thus, the problem is solvable by one of these two programs.
\begin{center}
\vspace*{-4ex}
\begin{minipage}[t]{0.4\linewidth}%

\end{lstlisting}%
\end{minipage}%
\hspace*{2em}

\end{lstlisting}%
\end{minipage}%
\vspace*{-2ex}

indices~$e$ and inputs~$x$\Dash this results speaks about uniformity,
or rather, the impossibility of uniformity.

yield an intuitively computable function not on that list?


The resolution of the paradox 
is that there are numbers~$n$ for which the computation
$\TM_n$ on input~$n$ never halts, that is,
$f_n(n)\diverges$.

At that core of the notion of computability is that there are
some indices and some inputs for which the computation never halts.

  \ackermann(4,2)=2^{65536}-3
  \qquad
  \ackermann(4,3)=2^{(2^{65536})}-3
\end{equation*}
Those are big numbers.

% We have already discussed the core idea: level~$1$ grows arithmetically, 
% level~$2$ grows geometrically, 
% level~$3$ grows exponentially, etc., and 
% each primitive recursive function
% grows slower than some level $\hyperoperation_n$.
% Specifically, given the derivation of a 
% primitive recursive function, each step in that derivation increases
% the level by some maximum amount.
% For example, composition bumps the level up by~$2$
% and primitive recursion bumps the level up by~$3$.


% \crefalias{enumi}{extratheorem}
\begin{extralemma} \label{lem:GrowthOfAckermann}
\begin{thmparts}
  \item \label{lem:AckermannLargerThanSecondArg}
    $\ackermann(k,y)>y$
  \item  \label{lem:AckermannMonotoneInSecondArg}
     $\ackermann(k,y+1)>\ackermann(k,y)$, and in general
     if $\hat{y}>y$ then $\ackermann(k,\hat{y})>\ackermann(k,y)$
  \item \label{lem:AckermannCrossArg}
    $\ackermann(k+1,y)\geq\ackermann(k,y+1)$  
  \item \label{lem:AckermannLargerThanFirstArg}
    $\ackermann(k,y)>k$ 
  \item \label{lem:AckermannMonotoneInFirstArg}
    $\ackermann(k+1,y)>\ackermann(k,y)$ and in general
    if $\hat{k}> k$ then $\ackermann(\hat{k},y)>\ackermann(k,y)$ 
  \item  \label{lem:AckermannFirstArgMoreImportant}
    $\ackermann(k+2,y)>\ackermann(k,2y)$
\end{thmparts}
\end{extralemma}

\begin{proof}
We will verify the first item here and leave the 
the others as exercises.
They all proceed the same way, with 
an induction inside of an induction.

Formally stated, this is the first item.
\begin{equation*}
  \forall k\,\forall y\,\big[\ackermann(k,y)>y\big]
  \tag{$*$}
\end{equation*}
We will prove it by induction on~$k$.
The $k=0$ base step is $\ackermann(0,y)=y+1>y$.
For the inductive step, assume that statement~($*$) 
holds for $k=0$, \ldots, $k=n$ and consider the $k=n+1$ case.

We now must verify this statement, 
\begin{equation*}
  \forall\,y\,\big[\ackermann(n+1,y)>y\big]
  \tag{$**$} 
\end{equation*}
which we will do by induction on~$y$.
In the $y=0$ base step of this inside induction, the definition gives 
$\ackermann(n+1,0)=\ackermann(n,1)$ and by the inductive hypothesis that 
statement~($*$) is true when $k=n$ we have that
$\ackermann(n,1)>1>y=0$.

Finally, in the inductive step of the inside induction, assume that
statement~($**$) holds for $y=0$, \ldots, $y=m$ and consider $y=m+1$.
The definition gives
$\ackermann(n+1,m+1)=\ackermann(n,\ackermann(n+1,m))$.
By ($**$)'s inductive hypothesis, $\ackermann(n+1,m)>m$.
By ($*$)'s inductive hypothesis, when $\ackermann(n,\ackermann(n+1,m))$ 
has a second argument greater than~$m$ then it's result is greater than~$m$, 
as required.
\end{proof}

Some notation will help these arguments: 
we will abbreviate the function input list $x_0,\ldots,x_{n-1}$ 
by the vector~$\vec{x}$.
And we will write the maximum of the vector $\max(\vec{x})$ to mean the
maximum of its components 
$\max(\set{x_0,\ldots,x_{n-1}})$.

\begin{extradefinition}
A function~$s$ is \definend{level}~$k$, where $k\in\N$, if 
$\ackermann(k,\max(\vec{x}))>s(\vec{x})$ for all~$\vec{x}$.
\end{extradefinition}

By \cref{lem:GrowthOfAckermann}.\ref{lem:AckermannMonotoneInFirstArg}, if 
a function is level~$k$ then it is also level~$\hat{k}$ for any $\hat{k}>k$.
% define dominated?

\begin{extralemma} \label{lem:CompositionLevelKIsLevelKPlusTwo}
If for some $k\in\N$ each function $g_0,\ldots,g_{m-1},h$ is level~$k$,  
and if the function~$f$ is obtained by composition as
$f(\vec{x})=h(g_0(\vec{x}),\ldots,g_{m-1}(\vec{x}))$,
then $f$ is level~$k+2$.
\end{extralemma}

\begin{proof}
Apply \cref{lem:GrowthOfAckermann}'s \cref{lem:AckermannCrossArg}, 
and then the definition of~$\ackermann$.
\begin{equation*}
  \ackermann(k+2,\max(\vec{x})) 
    \geq \ackermann(k+1,\max(\vec{x})+1)             
    = \ackermann(k,\ackermann(k+1,\max(\vec{x})))
  \tag{$*$}
\end{equation*}
Focusing on the second argument of the right-hand expression,
use \cref{lem:GrowthOfAckermann}.\ref{lem:AckermannMonotoneInFirstArg} 
and the assumption that each function $g_0,\ldots,g_{m-1}$ is level~$k$ to get
that for each index $i\in\set{1,\ldots,m-1}$
we have $
  \ackermann(k+1,\max(\vec{x})) 
    > \ackermann(k,\max(\vec{x}))  
    > g_i(\vec{x})
$.
Thus
$
  \ackermann(k+1,\max(\vec{x})) 
    > \max(\set{\,g_1(\vec{x}),\ldots,\,g_{m-1}(\vec{x})\,})
$.

\Cref{lem:GrowthOfAckermann}.\ref{lem:AckermannMonotoneInSecondArg} 
says that $\ackermann$ is monotone in the
second argument, so returning to equation~($*$) and swapping out
$\ackermann(k+1,\max(\vec{x}))$ gives the first inequality here
\begin{align*}
  \ackermann(k+2,\max(\vec{x}))
  &> \ackermann(k,\max(\,\set{ g_1(\vec{x}), \ldots, g_{m-1}(\vec{x})}\,))  \\
  &> h(g_0({\vec{x}}),\ldots,g_{m-1}(\vec{x}))
  = f(\vec{x})
\end{align*}
and the second holds because
the function~$h$ is level~$k$.
\end{proof}

\begin{extralemma}  \label{lem:PrimRecOfLevelKIsLevelKPlusThree}
If for some $k\in\N$ the functions $g$ and~$h$ are level~$k$,  
and if the function~$f$ is obtained by the schema of primitive recursion as
\begin{equation*}
  f(\vec{x},y)=
  \begin{cases}
    g(\vec{x})  &\case{if $y=0$}  \\
    h(f(\vec{x},z),\,\vec{x},\,z)  &\case{if $y=\successor(z)$}
  \end{cases}
\end{equation*}
then $f$ is level~$k+3$.
\end{extralemma}

\begin{proof}
Let $n$ be such that $\map{f}{\N^{n+1}}{\N}$, so that
$\map{g}{\N^{n}}{\N}$ and $\map{h}{\N^{n+2}}{\N}$.
The core of the argument is to show that this statement holds.
\begin{equation*}
  \forall k\,\big[ \ackermann(k,\max(\vec{x})+y)>f(\vec{x},y)\big]
  \tag{$*$}
\end{equation*}
% (for any first argument~$k$).
We show this by induction on~$y$.
The $y=0$ base step is that 
$\ackermann(k,\max(\vec{x})+0)=\ackermann(k,\max(\vec{x}))$ is 
greater than
$f(\vec{x},0)=g(\vec{x})$ because $g$ is level~$k$.

For the inductive step assume that~($*$) holds for 
$y=0$, \ldots, $y=z$ and consider the $y=z+1$ case.
The definition is that
$\ackermann(k+1,\max(\vec{x})+z+1)
  =\ackermann(k,\,\ackermann(k+1,\max(\vec{x})+z))$.
The second argument
$\ackermann(k+1,\,\max(\vec{x})+z)$ is larger than $\max(\vec{x})+z$ 
by \cref{lem:GrowthOfAckermann}.\ref{lem:AckermannLargerThanSecondArg},
and so
is larger than any~$x_i$ and larger than~$z$,
and is larger than $f(\vec{x},z)$ by the inductive hypothesis. 
\begin{equation*}
  \ackermann(k+1,\max(\vec{x})+z)
  > \max(\set{f(\vec{x},z),\,x_0,\ldots,x_{n-1},\,z})
\end{equation*}
Use 
\cref{lem:GrowthOfAckermann}.\ref{lem:AckermannMonotoneInSecondArg},
monotonicity of~$\ackermann$ in the second argument,
and the fact that~$h$ is a level~$k$ function.
\begin{align*}
  \ackermann(k+1,\max(\vec{x})+z+1)
    &=\ackermann(k,\,\ackermann(k+1,\max(\vec{x})+z))  \\
    &> \ackermann(k,\,\max(\set{f(\vec{x},z),\,x_0,\ldots,x_{n-1},\,z})) \\
    &> h(f(\vec{x},z),\vec{x},z)  
    = f(\vec{x},z+1) 
\end{align*}
That finishes the inductive verification of statement~($*$).

To finish the argument, 
\cref{lem:GrowthOfAckermann}.\ref{lem:AckermannFirstArgMoreImportant}
gives that for all $x_0,\ldots,x_{n-1},y$
\begin{align*}
  \ackermann(k+3,\,\max(\set{x_0,\ldots,y}))
    &> \ackermann(k+1,\,2\cdot\max(\set{x_0,\ldots,y}))  \\
    &\geq \ackermann(k+1,\,\max(\vec{x})+y)    
\end{align*}
(the latter holds because $2\cdot\max(\vec{x},y)\geq \max(\vec{x})+y$
and because of 
\cref{lem:GrowthOfAckermann}.\ref{lem:AckermannMonotoneInSecondArg}).
In turn, by the first part of this proof, that is greater than
$f(\vec{x},y)$.
\end{proof}

\begin{extratheorem}[Ackermann, 1925]
For each primitive recursive function~$f$ there is a~$k\in\N$ 
such that $f$ is level~$k$.  
\end{extratheorem}

\begin{proof}
The definition of primitive recursive functions \cref{def:PrimitiveRecursive}
specifies that each~$f$ is
built from a set of initial function by the operations of
composition and primitive recursion.
With \cref{lem:CompositionLevelKIsLevelKPlusTwo} 
and \cref{lem:PrimRecOfLevelKIsLevelKPlusThree} we need only show that
each initial operation is of some level.

The zero function $\zero(x)=0$ is level~$0$ since $\ackermann(0,x)=x+1>0$.
The successor function $\successor(x)=x+1$ is level~$1$
since $\ackermann(1,x)>\ackermann(0,x)=x+1$ by 
\cref{lem:GrowthOfAckermann}.\ref{lem:AckermannMonotoneInFirstArg}.
Each projection function $\projection_i(x_0,\ldots,x_i\ldots,x_{n-1})=x_i$ is
level~$0$ since $\ackermann(0,\max(\vec{x}))=\max(\vec{x})+1$ is greater than
$\max(\vec{x})$, which is greater than or equal to~$x_i$.
\end{proof}

\begin{extracorollary}
The function~$\ackermann$ is not primitive recursive.  
\end{extracorollary}

\begin{proof}
If $\ackermann$ were primitive recursive then it would be of some level,~$k_0$,
so $\ackermann(k_0,\max(\set{x,y}))>\ackermann(x,y)$ for all~$x,y$.
Taking $x$ and~$y$ to be $k_0$ gives a contradiction.  
\end{proof}

\extra{Ritchie's lemma}
The simplest looping constructs are 
\codeinline!for! and \codeinline!while!.
In a \codeinline!for! loop you know in advance the number of times 
you will pass through the loop.
In contrast, a \codeinline!while! loop can go 
an unbounded number of times.

A function is primitive recursive if and only if it can be computed 
using for loops alone.

\extra{Busy Beaver}

We compute things all the time so noncomputability is 
counterintuitive.
Here we see one way that a function can fail to be computable.  

Consider this attempt to solve the Halting Problem:
Turing machines are made of four-tuples.
For any~$n\in\N$ the set $T_n=\setbuilder{e}{|\TM_e|\leq n}$ 
of machines with $n$~many tuples or fewer is finite.
For some members of the set
$\TM_e(e)$ halts and for some it does not, but because the set if finite,
certainly the information
on which of the set's member machines halt must also be finite.
We can compute finite sets.
So to solve the Halting Problem, given a Turing Machine~$\TM$, 
find how many four-tuples it has,
compute the associated finite halting information set, 
and then we know whether $\TM$ halts.
What's the problem with that?

The problem is uniformity.
We can compute any one of the finite sets.
But there is no single computable function that does them all\Dash
no computable function that accepts inputs~$\sequence{n,e}$ and that 
outputs~$1$ if there is a $n$-tuple machine such that $\TM_e(e)$ halts,
or~$0$ otherwise.

The natural uniform attack along these lines is to start all of the 
$n$-tuple machines,
all the $\TM_e(e)$ for $e\in T_n$
and run them in a bredth-first way until no more of them will ever converge.
So let the function $\map{D}{\N}{\N}$ be that $D(n)$ is the minimal number of 
transitions, that is, 
steps, after which all of the $n$-tuple machines that will ever converge have 
done so. 
Now to tell if $\TM_e(e)$ halts, find how many tuples $\TM_e$ has~$n$,
and let $\TM_{e_0}(e_0)$ run for $D(e_0)$-many transitions.
If it has not halted by then, it never will.

Of course, a computable solution to the Halting Problem is impossible.
So instead, this argument shows that $D$ is not computable.

Observe that if a function $\hat{D}$ has values larger than $D$\Dash
if $\hat{D}(n)\geq D(n)$ for all sufficiently large~$n$\Dash
then $\hat{D}$ is also not computable.
So one way that functions could be not computable is that 
they could grow too fast.
(Note Ackermann link.)

\extrasubsection{Busy Beaver is unsolvable}
Why isn't $\Sigma$ computable?
You may guess that you can do a bredth-first search for this computation:
there are finitely many $n$-state machines,
start them all on a blank tape,
and await developments. 

That won't work because some of the machines won't halt.
At any moment you have some machines that have halted and you can see
how many $1$'s are on each such tape, so you know the longest so far.
But as to the not-yet-halted ones, who knows?
You can by-hand see that this one or that one will never halt
and so you can figure out the answer for $n=1$ or~$n=2$.
But there is no algorithm to decide whether an arbitrary
calculation halts.

The function $\Sigma$ is not computable.  
\end{extratheorem}

and $F(m)<F(m+1)$.
This function is intuitively computable so Church's Thesis says there is a 
Turing machine $\TM_F$ that computes it.
Let it have $n_F$~many states.

Consider the Turing machine $\TM$
which performs $\TM_j$ and then follows it with 
$\TM_F$, and in turn follows that with 
$\TM_F$. 
If started on a blank tape this machine will first produce $j$-many $1$'s,
then produce $F(j)$-many $1$'s, and finally will leave the tape with 
$F(F(j))$-many $1$'s.
Thus its productivity is 
$F(F(j))$, and it has $j+2n_F$ many states.

Finally, consider the $j+2n_F$-state Busy Beaver machine.
\begin{equation*}
  F(F(j))\leq \Sigma(j+2n_F)
\end{equation*}
Because $n_F$ is constant (it is the number of states in
the machine $\TM_F$), for large $j$ we have
$j+2n_F\leq j^2< F(j)$.
Since $F$ is strictly increasing, $F(j+2n_F)<F(F(j))$.
Combining gives this.
\begin{equation*}
   f(j+2n_F) <
   F(j+2n_F) <
   F(F(j))
   \leq \Sigma(j+2n_F)
\end{equation*}
Since $f$ is any computable function, $\Sigma$ is not computable.
\end{proof}

So one way for a function to fail to be computable is if it grows faster than
any computable function.
(This is not the only way.  
There are functions that grow slower than some computable function but
are nonetheless not computable.  Counting?)
