\section{Languages}\index{language|(} % see for more: http://jeffe.cs.illinois.edu/teaching/algorithms/all-models.pdf
Our machines input and output strings of symbols.
We take 
a \definend{symbol}\index{symbol}, 
sometimes called a \definend{token},\index{token} 
to be an atomic unit that a machine can read and write.\footnote{%
  We can imagine Turing's clerk 
  calculating without reading and writing symbols, 
  for instance by keeping track of information by 
  \protect\citetext{having elephants move 
  to the left side of a road or to the right}{% 
    Less fancifully, we could be making
    a Turing machine out of LEGO's and want to keep track by sliding a block
    from one side of a column to the other.
    Or, we could use an abacus.}.
  But 
  \protect\citetext{we could translate any such procedure}{%
    While a 
    person may quite sensibly worry that elephants could be not just on
    the left side or the right, but in any of the continuum of points
    in between, we will make this 
    assertion without more philosophical analysis than by just referring
    to the discrete nature of our mechanisms
    (as Turing basically did).
    That is, we take it as an axiom.} 
  into one using marks that our mechanism's read/write head can handle.
  So readability and writeability are not essential
  but we require them in the definition of symbols 
  as a convenience; after all,
  elephants \emph{are }inconvenient.}
On everyday binary computers the symbols are the bits \str{0} and~\str{1}.
An \definend{alphabet}\index{alphabet} 
is a nonempty and finite set of symbols.
We usually denote an alphabet with the upper case Greek letter~$\Sigma$,
although an exception is the alphabet of bits, 
\definend{$\B=\set{\str{0},\str{1}}$}.
A \definend{string}\index{string} 
over an alphabet 
is a sequence of symbols from that alphabet.
We  denote strings with lower case Greek letters such as $\sigma$ and~$\tau$.  
We use $\emptystring$ to denote the empty string, the length zero sequence
of symbols.
The set of all strings over $\Sigma$ is 
\index{Kleene star}$\kleenestar{\Sigma}$.\footnote{%
  More on strings is in Appendix~\ref{sec:Strings}.}

%<*def:Lang>
\begin{definition}
A \definend{language~$\lang$ over an alphabet~$\Sigma$}\index{language}
is a set of strings drawn from that alphabet. 
That is, $\lang\subseteq\kleenestar{\Sigma}\!$.  
\end{definition}
%</def:Lang>

\begin{example}
The set of bitstrings
that begin with \str{1} is 
$\lang=\set{\str{1},\,\str{10},\,\str{11},\,\str{100},\,\ldots}$.   
\end{example}

\begin{example}
Another language over $\B$
is the \citetext{finite set $\set{\str{1000001},\str{1100001}}$}{%
  Although it looks like two strings plucked from the air, the language is not 
  without sense. 
  The bitstring \str{1000001} represents capital A in the 
  ASCII encoding, while \str{1100001} is lower case a.
  The American Standard Code for Information Interchange, ASCII,
  is a widely used, albeit quite old, 
  way of encoding character information in computers.  
  The most common modern character encoding is UTF-8, 
  which extends ASCII.
  For the history see 
  \url{https://www.cl.cam.ac.uk/~mgk25/ucs/utf-8-history.txt}.}.
\end{example}

\begin{example}
Let $\Sigma=\set{\str{a}, \str{b}}$.
The language consisting of strings where the number of \str{a}'s is twice 
the number of \str{b}'s is
$\lang=\set{\emptystring,\str{aab},\str{aba},\str{baa},
               \str{aaaabb}, \,\ldots}$.  
\end{example}

\begin{example}
Let $\Sigma=\set{\str{a},\, \str{b},\, \str{c}}$.
The language of length-two strings over that alphabet is
$\lang_2=\Sigma^2=\set{\str{aa},\,\str{ab},\,\str{ba}\,\dots,\,\str{cc}}$.
Over the same alphabet, 
this language consists of length-three strings whose 
characters are in ascending order.
\begin{equation*}
  \lang_3=
  \set{\str{aaa},\,\str{bbb},\, \str{ccc},\, \str{aab},\, \str{aac},\, \str{abb},\, \str{abc},
    \str{acc},\,\str{bbc},\, \str{bcc}}
\end{equation*}
\end{example}

\begin{definition}\index{palindrome} \label{def:palindrome}
A
\citetext{\definend{palindrome}}{%
  Sometimes people call Psychology
  the study of college freshmen because so many studies start, roughly,
  ``we put a bunch of college freshmen in a room, lied to them
  about what we were doing, and \ldots\sentencespace''
  In the same way, Theory of Computing can sometimes seem like
  the study of palindromes.}
is a string that reads the same forwards as backwards.
\end{definition}

Some 
\citetext{palindromes in English}{%
  Some people like to move beyond single word palindromes to 
  make sentence-length palindromes that make some sense.
  Some of the more famous are:~(1)~supposedly the first sentence ever uttered, 
  ``Madam, I'm Adam''
  (2)~Napoleon's lament, ``Able was I ere I saw Elba''
  and (3)~``A man, a plan, a canal: Panama'', about Theodore Roosevelt.
  See also \url{http://norvig.com/palindrome.html}.}
are \str{kayak}, \str{noon}, and~\str{racecar}.

\begin{example}  
The language of palindromes over $\Sigma=\set{\str{a},\str{b}}$ is
$\lang=\set{\sigma\in\kleenestar{\Sigma}\suchthat \sigma=\reversal{\sigma}}$.
A few members are \str{abba}, \str{aaabaaa}, \str{a}, and $\varepsilon$.
\end{example}

\begin{example}
Let $\Sigma=\set{\str{a}, \str{b}, \str{c}}$.
Recall that a Pythagorean triple of integers has the sum of the squares
of the first two equal to the square of the third,
as with $3$, $4$, and $5$, 
or $5$, $12$, and $13$.
One way to describe Pythagorean triples
is with the language

$.
Some members are $\str{aaabbbbccccc}=\str{a}^3\str{b}^4\str{c}^5\!$,
            and $\str{a}^5\str{b}^{12}\str{c}^{13}\!$, and
            $\str{a}^8\str{b}^{15}\str{c}^{17}\!$.

\begin{example}
  The empty set is a language $\lang=\set{}$ over any alphabet.
  So is the set whose single element is the empty string
  $\hat{\lang}=\set{\emptystring}$.
  These two languages are different because the first has no members
  while the second has one.
\end{example}

The motivation for taking `language' to be a set of strings
is that we can imagine that
$\Sigma$ is the set of words in a dictionary and a sentence is a 
string of words.
However, this 
allows a language to be any string of words at all,
while a natural language such as English we must follow rules.
The next section studies rules for languages, grammars.

%<*def:class>
\begin{definition}
A collection of languages is a \definend{class}.\index{class}\index{language!class}
\end{definition}
%</def:class>

\begin{example}
For any alphabet,
the collection of all finite languages over
that alphabet is a class.
\end{example}

% One member of this class is the finite language

\begin{example}
Let $\TM_e$ be a Turing machine using the input alphabet
$\Sigma=\set{\str{B},\str{1}}$.
The set of strings
$
W_e=\set{\sigma\in\kleenestar{\Sigma}\suchthat
  \text{$\TM_e$ halts on input $\sigma$}}
$  is a language.
The collection of all such languages, of the $W_e$ for all~$e\in\N$,
is the class of computably enumerable languages over~$\Sigma$.
\end{example}

These are the natural operations on languages.

%<*def:LangOps>
\begin{definition}[Operations on languages]\index{language!operations on}  \label{def:LangOps}
The
\definend{concatenation of languages, $\lang_0\concat\lang_1$} 
or \definend{$\lang_0\lang_1$},\index{concatenation of languages}\index{language!concatenation}
is the language of concatenations,
$\set{\sigma_0\concat\sigma_1\suchthat \text{$\sigma_0\in\lang_0$ and $\sigma_1\in\lang_1$}}$.

For any language $\lang$, when $k>0$ the 
\definend{power $\smash{\lang^k}$}\index{power of a language}\index{language!power} 
is the language consisting of the
concatenation of $k$-many members,
$\smash{\lang^k}=
\set{\sigma_0\concat\cdots\concat\sigma_{k-1}\suchthat \sigma_i\in\lang}$.\footnotemark[1]
We take 
$\smash{\lang^0}=\set{\emptystring}$.\footnotemark[2]
The 
\definend{Kleene star of a language $\smash{\kleenestar{\lang}}$}\index{Kleene star}\index{language!Kleene star}
is the 
language consisting of the concatenation of any number of strings.
\begin{equation*}
\kleenestar{\lang}
  =\set{\sigma_0\concat\cdots\concat\sigma_{k-1}\suchthat \text{$k\in\N$ and $\sigma_0,\ldots,\sigma_{k-1}\in\lang$}}
  =\lang^0\cup\lang^1\cup\lang^2\cup\cdots
\end{equation*}
This includes the concatenation of $0$-many strings, 
so $\emptystring\in\kleenestar{\lang}$.\footnotemark[3] 
The 
\definend{reversal}\index{reversal of a language}\index{language!reversal} 
of a language is 
the language of reversals,
$\smash{\reversal{\lang}}=\set{\smash{\reversal{\sigma}}\suchthat \sigma\in\lang}$.
\end{definition}\footnotetext[1]{%
  Don't confuse this with the Cartesian product operation for sets.
}%
\footnotetext[2]{%
  % We take $\lang^0=\set{\emptystring}$ even when
  % $\lang=\emptyset$.
  We take $\sigma^0=\emptystring$ since
  $\emptystring$ is the identity element for string concatenation.
  (We saw the same reasoning 
  when we defined the sum of
  zero-many numbers to be~$0$ and the product of zero-many numbers to be~$1$,
  on page~\pageref{page:PrimitiveRecursion}.)
  % Also see \zcref{exer:WhyEmptysetZeroPowerNotEmpty}.
}%
\footnotetext[3]{%
   This holds even if $\lang=\emptyset$.
}

%</def:LangOps>

As described in \zcref{sec:Strings},
we extend the star notation beyond languages to alphabets~$\Sigma$,
\citetext{defining $\kleenestar{\Sigma}$
to be the set of strings
of characters from that alphabet}{%
  That is, we won't be careful
  to distinguish between the symbols of the alphabet and the
  single-character strings consisting of just those characters.}.\index{Kleene star}\index{alphabet!Kleene star}

\begin{example}
Where the language 
is the set of bitstrings $\lang=\set{\str{1000001},\str{1100001}}$ 
then the reversal is $\reversal{\lang}=\set{\str{1000001},\str{10000011}}$.
\end{example}

%<*ex:KleeneStar>
\begin{example}
If the language $\lang$ consists of two strings $\set{\str{a},\,\str{bc}}$
then its second power is
$\lang^2=\set{\str{aa},\,\str{abc},\,\str{bca},\,\str{bcbc}}$.
Its Kleene star is the union of the powers.
\begin{equation*}
  \kleenestar{\lang}=\set{\emptystring,\,\str{a},\,\str{bc},\,\str{aa},\,\str{abc},\,\str{bca},\,\str{bcbc},\,\str{aaa},\,\ldots}  
\end{equation*}
\end{example}
%</ex:KleeneStar>

\begin{remark}
For the above definition of the operation  $\lang^k$ of
repeatedly choosing strings,
there are two ways that we could go.
We could choose a string~$\sigma$ and then repeat it,
and so get the set of all $\sigma^k\!$.
Or we could repeatedly choose strings, getting the set of all
$\sigma_0\concat\sigma_1\concat\cdots\concat\sigma_{k-1}$.
The second is more useful so that's what we do.
\end{remark}

\label{discuss:LanguageDecidesRecognizes}
We finish by describing two ways that a machine can relate to a 
language.\footnote{%
  We discussed these in Definition~I.\protect\ref{df:TMDecidesLanguage} 
  for sets in general
  but here we reiterate for the special case of languages.}
%<*discussion:DecidingVsRecognizing>
\begin{definition} \label{def:MachineDecidesLanguage}
A machine 
\definend{decides a language}\index{decide a language}\index{language!decide}
if it computes whether or not a given input is a member of that language.
A machine 
\definend{recognizes}\index{recognize a language}\index{language!recognize}
% (or \definend{accepts},\index{accept a language}\index{language!accept} 
or \definend{semidecides}\index{semidecide a language}
a language when if the input is in the language then
it computes that in a finite time,
and if the input is not in
the language then the machine will never 
incorrectly report that it is an element.
\end{definition}

Thus, if a language~$\lang$ is not computable 
then there is no machine that decides it.
But if $\lang$ is computably enumerable then
there is a machine that recognizes it.
If an input is in $\lang$ then this machine can 
compute that in a finite time,
but no machine can determine non-membership in a finite time.
There might be a machine that correctly reports on some non-members,
but it must fail on others.
% because this language is not computable,
% no machine can determine on one hundred percent of inputs both
% membership and non-membership.
%</discussion:DecidingVsRecognizing>

In short, `deciding' means that on any input the machine
correctly computes all yes and no answers,
while `recognizing' is the weaker condition that it correctly 
computes all yes answers.

\begin{exercise}
List five of the shortest strings in each language, if there are five.
\begin{exparts}
\item $\set{\sigma\in\kleenestar{\B}\suchthat
                    \text{the number of \str{0}'s plus the number of \str{1}'s equals $3$}}$
\item $\set{\sigma\in\kleenestar{\B}\suchthat

\end{exparts}

\begin{exparts}
\item Five are \str{000}, \str{001}, \str{010}, \str{011}, and~\str{100}.
\item These five work: \str{0}, \str{1}, \str{00}, \str{11},
  and~\str{000}.
  (Is the empty string in that language?

\end{exparts} 
\end{answer}
\end{exercise}

\recommended
\begin{exercise}
Is the set of decimal representations of real numbers
a language?
\begin{answer}\verified
No.
By definition, a language is a set of strings and also 
by definition, a string is of finite length.
For some real numbers the decimal representation does not make a finite string;
one is $\pi=3.14\ldots$ and another is $1/3=0.33\ldots$
\end{answer}
\end{exercise}

  or~\str{)(()}?
  \begin{exparts*}
  \item Only the first
  \item Only the second
  \item Both
  \item Neither
  \end{exparts*}
\begin{answer}
  It is both.
\end{answer}
\end{exercise}

\recommended
\begin{exercise}
  Show that if $\beta$ is a string then 
  $\beta\concat\reversal{\beta}$ is a palindrome.
  Do all palindromes have that form?  
\begin{answer}\verified
  If $\beta=\sequence{b_0,\ldots,b_{i-1}}$ is a string then 
  $\beta\concat\reversal{\beta}
  =\sequence{b_0,\ldots,b_{i-1}}\concat\sequence{b_{i-1},\ldots,b_0}$
  is clearly a palindrome.
  (This holds for the empty string also.)
  There are palindromes not of that form.
  One is $\gamma=\str{010}$, which
  cannot be decomposed into $\gamma=\beta\concat\reversal{\beta}$,
  since it has odd length.
\end{answer}
\end{exercise}

\begin{exercise}

\begin{exparts*}

\item List all the members of $\lang_1\concat\lang_0$.

\begin{exercise}
\begin{credit}
  F Stephan, \url{https://www.comp.nus.edu.sg/~fstephan/toc01slides.pdf}
\end{credit}
Suppose that the language $\lang_0$ has three elements and $\lang_1$ has two.
Knowing only that information, for each of these
find the least number of elements possible
and the greatest number possible?
\begin{exparts*}
\item $\lang_0\cup \lang_1$
\item $\lang_0\cap \lang_1$
\item $\lang_0\concat\lang_1$
\item $\lang_1^2$
\item $\reversal{\lang_1}$
\item $\kleenestar{\lang_0}\cap\kleenestar{\lang_1}$
\end{exparts*}
\begin{answer}\verified
\begin{exparts}
\item 
The minimum is three, which happens when the second is a subset of the first.
The maximum is five, which happens when the two are disjoint.
\item
The minimum is zero, which happens when the two are disjoint.
The maximum is two, which happens when the second is a subset of the first.
\item 
The maximum is six, as with
$\lang_0=\set{\str{a},\str{b},\str{c}}$ and $\lang_1=\set{\str{x},\str{y}}$,
which gives 
$\lang_0\concat\lang_1=\set{\str{ax},\str{ay},\str{bx},\str{by},\str{cx},\str{cy}}$.
The minimum is four, as with
$\lang_0=\set{\emptystring,\str{a},\str{aa}}$ and 
$\lang_1=\set{\emptystring,\str{a}}$, which gives
$\lang_0\concat\lang_1=\set{\emptystring,\str{a},\str{aa},\str{aaa}}$.
\item
The minimum is three, as when $\lang_1=\set{\emptystring,\str{a}}$
gives $\lang_1^2=\set{\emptystring,\str{a},\str{aa}}$.
The maximum is four, an example of which is 
$\lang_1=\set{\str{a},\str{b}}$ giving

\end{answer}

\begin{exercise}
Does $\kleenestar{\lang}$ differ from 
$\kleenestar{(\lang\cup\set{\emptystring})}$?
\begin{answer}\verified
  Yes, but only in an edge case.
  If $\lang=\emptyset$ then $\kleenestar{\lang}=\emptyset$ 
  while $\kleenestar{(\lang\cup\set{\emptystring})}=\set{\emptystring}$.

  We will show that if $\lang\neq\emptyset$ then the two sets are equal,
  $\kleenestar{\lang}=\kleenestar{(\lang\cup\set{\emptystring})}\!$.
  The containment 
  $\kleenestar{\lang}\subseteq\kleenestar{(\lang\cup\set{\emptystring})}$
  is clear.

  For the other direction, that 
  $\kleenestar{(\lang\cup\set{\emptystring})}\subseteq\kleenestar{\lang}$,
  assume that $\sigma\in\kleenestar{(\lang\cup\set{\emptystring})}\!$ where
  $\sigma=\sigma_0\concat\cdots\concat\sigma_{n-1}$ for some $n\in\N$ and
  all of the $\sigma_i$ are elements of $\lang\cup\set{\emptystring}$.

  equals~$\emptystring$ then $\sigma=\emptystring$, and is an element of 
  $\kleenestar{\lang}$ because $\lang\neq\emptyset$ and 
  $\emptystring=\rho^0$ for any $\rho\in\lang$.
  Otherwise there is at least one $i\in\set{0,\ldots n-1}$ 
  such that $\sigma_i\neq\emptystring$.
  In this case, omitting from the string~$\sigma$ those $\sigma_j$ that
  equal the empty string gives that $\sigma\in\lang^k$ for some~$k\leq n$, 
  and so $\sigma\in\kleenestar{\lang}\!$.  
\end{answer}

\begin{exercise}
We can ask how many elements are in the set $\lang^2\!$.
\begin{exparts}
\item Prove that if two strings are unequal then their squares are also
  unequal.  
  Conclude that if $\lang$ has $k$-many elements then 
  $\lang^2$ has at least $k$-many elements.
\item Provide an example of a nonempty language for which 
  this is the number. 
\item Prove that where $\lang$ has $k$-many elements, $\lang^2$ has at most
$k^2$-many.
\item Provide an example, for each $k\in\N$, of a language that 
achieves this upper bound. 
\end{exparts}
\begin{answer}\verified
  For any language we refer to its alphabet as $\Sigma$.
  \begin{exparts}
  \item Consider unequal strings $\sigma_0\neq\sigma_1$.
    They can't both be the empty string, 
    and if one of them is the empty string but the other is not
    then clearly $\sigma_0^2\neq\sigma_1^2$
    because one of those two is empty while the other is not.
    So now suppose that neither of the two strings $\sigma_0$ and~$\sigma_1$
    is empty.
    If they are different lengths then their squares are also different lengths.
    The case remaining is that they are nonempty equal-length strings,
    $\sigma_0=\sequence{s_{0,0},s_{0,1},\ldots\, s_{0,n}}$
    and
    $\sigma_1=\sequence{s_{1,0},s_{1,1},\ldots\, s_{1,n}}$ for some $n\in\N$.
    Fix the smallest index~$i$ where $s_{0,i}\neq s_{1,i}$.
    For that same~$i$ we have that $\sigma_0^2$ and $\sigma_1^2$ differ on
    index~$i$, and are therefore unequal.

    The prior paragraph implies that if $\lang$ has $k$-many different elements 
    $\lang=\set{\sigma_0,\ldots \sigma_{k-1}}$ then the strings
    $\sigma_0^2$,\ldots, $\sigma_{k-1}^2$ are different and so 
    $\lang^2$ has at least $k$-many different elements.
  \item The language $\lang=\set{\emptystring}$ has
    $\lang^2=\set{\emptystring}$.
  \item Let $\lang=\set{\sigma_0,\sigma_1,\ldots\, \sigma_{k-1}}$ for $k\in\N^+$ 
    (we take these strings to all be different from each other).
    Then the list
    $\sigma_0\concat\sigma_0$, $\sigma_0\concat\sigma_1$,
    \ldots{} $\sigma_{k-1}\concat\sigma_{k-1}$ has length~$k^2\!$.
    Hence the largest number of elements that $\lang^2$ can have is~$k^2\!$.
  \item Consider the language 
    $\lang=\set{\sigma_0, \sigma_1,\ldots\, \sigma_{k-1}}$ 
    where the $k$-many strings have length one and are unequal, 
    so each consists of a single symbol that is different from the symbols used
    in any of the others.
    Clearly all of the members of the list 
    $\sigma_0\concat\sigma_0$, $\sigma_0\concat\sigma_1$,
    \ldots{} $\sigma_{k-1}\concat\sigma_{k-1}$
    are unequal and so $\lang^2$ has $k^2$-many elements.
  \end{exparts}
\end{answer}
\end{exercise}

  and that 
  $\kleenestar{\lang}=\set{\sigma_0\concat\cdots\concat\sigma_{k-1}\suchthat \text{$k\in\N$ and $\sigma_0,\ldots,\sigma_{k-1}\in\lang$}}$.

\begin{exercise}
  The description of the powers of a language in \zcref{def:LangOps}
  writes $\sigma_0\concat\cdots\concat\sigma_{k-1}$, without
  parentheses, and so doesn't specify a construction for the set.
  For that construction the natural approach 
  is:~$\lang^0=\set{\emptystring}$,
  and $\lang^{k+1}=\lang^k\concat\lang$.

  concatenation yield the same string.
  To prevent confusion between the two forms, 
  for this argument only denote 
  $\set{\sigma_0\concat\cdots\concat\sigma_{k-1}\suchthat \sigma_i\in\lang}$

  $\lang^{k}\!$.

  $\sigma_0\concat\cdots\concat\sigma_{i-1}\in {}^i\!\lang$

  $\sigma_0\concat\cdots\concat\sigma_{i-1}\in\lang^i$, for

  concatenation of $j+1$-many strings, 
  $\sigma_0\concat\cdots\concat\sigma_{j-1}\concat\sigma_j\in{}^{j+1}\!\lang$.

  rewrite it as $(\sigma_0\concat\cdots\concat\sigma_{j-1})\concat\sigma_j$,

  $(\sigma_0\concat\cdots\concat\sigma_{j-1})\concat\sigma_j\in\lang^{j+1}\!$.

  $\set{\emptystring}$ by definition, and that 
  $\sigma_0\in\lang^1$  and $\sigma_0\in{}^1\!\lang$ for any $\sigma_0\in\lang$. 
  The inductive hypothesis is that if $\sigma\in\lang^{i}$ then
  $\sigma\in {}^{i}\!\lang$ for $i\in\set{0,\ldots\,k}$.

  $(\sigma_0\concat\cdots\concat\sigma_{j-1})\concat\sigma_j$.

  write it without the parentheses
  $\sigma_0\concat\cdots\concat\sigma_{j-1}\concat\sigma_j$

\begin{exercise}
The operations of languages form an algebraic system.

Show each.
\begin{exparts}

  $\lang_0\cup\lang_1=\lang_1\cup\lang_0$ and

concatenation, so $\lang\concat\set{\emptystring}=\lang$

there are languages such that 
$\lang_0\concat\lang_1\neq\lang_1\concat\lang_0$.

$(\lang_0\concat\lang_1)\concat\lang_2

    =\reversal{\lang_1}\concat\reversal{\lang_0}\!$.

 =(\lang_0\concat\lang_2)\,\cup\,(\lang_1\concat\lang_2)$,

concatenation, $\emptyset\concat\lang=\lang\concat\emptyset=\emptyset$.

  commutative.

  $\lang\concat\set{\emptystring}=\set{\sigma\concat\emptystring\suchthat \sigma\in\lang}=\set{\sigma\suchthat \sigma\in\lang}=\lang$.

  while
  $\lang_1\concat\lang_0=\set{\str{ba}}$.

  associative:~the $i$-th entry of $(\sigma_0\concat\sigma_1)\concat\sigma_2$
  is the same as the $i$-th entry of $\sigma_0\concat(\sigma_1\concat\sigma_2)$.
\item This is immediate from the fact that for strings
  $\reversal{(\sigma_0\concat\sigma_1)}$ equals
  $\reversal{\sigma_1}\concat\reversal{\sigma_0}\!$.
\item A string is an element of $(\lang_0\cup\lang_1)\concat\lang_2$
  if and only if it has the form $\sigma\concat\tau$ where
  $\tau\in\lang_2$, and $\sigma\in\lang_0$ or $\sigma\in\lang_1$.
  That's true if and only if both $\tau\in\lang_2$ and $\sigma\in\lang_0$,
  or both $\tau\in\lang_2$ and $\sigma\in\lang_1$.
  In turn that holds if and only if 
  $\sigma\in(\lang_0\concat\lang_2)\cup(\lang_1\concat\lang_2)$.
  The right-distributive argument goes the same way.
\item For any language~$\lang$ the definition gives
  $\emptyset\concat\lang=\set{\sigma_0\concat\sigma_1
    \suchthat \text{$\sigma_0\in\emptyset$ and $\sigma_1\in\lang$}}$.
  The condition `$\sigma_0\in\emptyset$' is never satisfied so this
  set is empty.
  The same goes for $\lang\concat\emptyset$.
\item For any strings, no matter how the concatenation is 
  parenthesized we can remove the parentheses.
  For instance, $((\sigma_0\concat\sigma_1)\concat\sigma_2)\concat\sigma_3$ 
  equals $((\sigma_0\concat(\sigma_1\concat\sigma_2))\concat\sigma_3$
  because the $i$-th elements of the two are equal.
  (We can easily show this statement by induction.)
  From this, the result is immediate.
\end{exparts}
\end{answer}
\end{exercise}

\section{Grammars}\index{grammar|(}  \label{sec:Grammars}
We have defined a language as a set of strings.
But this allows for any willy-nilly set. 
\citetext{In practice usually a language is governed by rules}{%
  Linguists started formalizing 
  the description of language, including phrase structure, at the start of the 
  1900's.
  Meanwhile, string rewriting rules as formal, abstract systems were introduced 
  and studied by mathematicians including Axel Thue in 1914, 
  Emil Post from the 1920's through the 1940's and Turing in 1936. 
  Noam Chomsky, while teaching linguistics to students of 
  information theory at MIT, combined linguistics and mathematics by 
  taking Thue's formalism as the basis for the description of the syntax of 
  natural language.  \autocite{wiki:Linguistics}}.

Here is an example.
Native English speakers will say that the noun phrase
``the big red barn'' sounds fine
but that \citetext{``the red big barn'' sounds wrong.}{%
  Experts 
  vary on the exact rules but one source gives the correct order as
  article + number + judgment/attitude + size, length, height + age + 
  color + origin + material + purpose + noun, so that
  ``big red barn'' is size + color + noun, as is
  ``little green men.'' 
  This is called the Royal Order of Adjectives; 
  see \protect\url{http://english.stackexchange.com/a/1159}.
  A person may object by citing ``big bad wolf'' but it turns out there is
  another, stronger, rule that if there are three words then they have to
  go I-A-O and if there are two words then the order has to
  be I followed by either A or O.
  Thus we have tick tock but not tock tick. 
  Similarly for tic-tac-toe, mishmash, King Kong, or dilly dally.}
That is, sentences in natural languages are constructed 
in patterns and the second of those does not follow the pattern for English.
Artificial languages such as programming languages
also have syntax rules, usually 
\citetext{very strict rules}{%
  Everyone who has programmed has had a compiler chide them about
  a syntax violation.}. 

A \definend{grammar}\index{grammar}\index{language!grammar} 
is a set of rules for the formation of strings in a language.
% That is, it is an analysis of the structure of its language.
In an aphorism, 
\citetext{grammars are the language of languages.}{%
  From Matt Swift,
  \protect\url{http://matt.might.net/articles/grammars-bnf-ebnf/}.} 


\subsection{Definition}
Before the definition we'll first see 
an example.

\begin{example}  \label{ex:TheYoungManCaughtABall}
A full set of rules for English would be
quite large.
Here is a subset:
\begin{parenum} 
%<*ex:RulesForEnglish>
\item~a sentence can be made from a noun phrase followed by a verb phrase,
\item~a noun phrase can be made from an article followed by a noun,
\item~a noun phrase can also be made from an article then an adjective then a 
  noun,
\item~a verb phrase can be made with a verb followed by a noun phrase,
\item~one article is `the',
\item~one adjective is `young',
\item~one verb is `caught',
\item~two nouns are `man' and `ball'.
%</ex:RulesForEnglish>
\end{parenum}

This is a convenient notation for those rules.
%<*ex:GrammarRulesForEnglish>
\begin{grammar}
\ntrm{sentence}  \produces{} \ntrm{noun phrase} \ntrm{verb phrase} 

\ntrm{noun phrase}  \produces{} \ntrm{article} \ntrm{noun}  

\ntrm{noun phrase}  \produces{} \ntrm{article} \ntrm{adjective} \ntrm{noun} 

\ntrm{verb phrase} \produces{} \ntrm{verb} \ntrm{noun phrase} 

\ntrm{article} \produces{} \trm{the}  

\ntrm{adjective} \produces{} \trm{young}  

\ntrm{verb} \produces{} \trm{caught}  

\ntrm{noun} \produces{} \trm{man} \syntaxor \trm{ball}
\end{grammar}
%</ex:GrammarRulesForEnglish>
\end{example}

%<*discussion:GrammarVocabulary>
The rules use two different kinds of components.
The ones written in typewriter type such as
`\trm{the}'
are elements of~$\Sigma$, the alphabet of the language.
These are 
\definend{terminals}.\footnote{%
  So in this example the alphabet $\Sigma$ is not the set of twenty six letters, 
  it is
  the dictionary of allowed English words.}\index{terminal}\index{grammar!terminal}  
The ones with angle brackets and italics such as `\ntrm{sentence}' 
are 
\definend{nonterminals}.\index{nonterminal}\index{grammar!nonterminal}
These are like variables for intermediate steps 
and do not appear in the language's strings.

The two symbols `\productionsymbol{}' and `\grammarorsymbol' are neither 
terminals nor nonterminals.
They are \definend{metacharacters},\index{metacharacter}
part of the syntax of the rules themselves.
%</discussion:GrammarVocabulary>

%<*def:Grammar>
\begin{definition}
A \definend{context-free grammar}\index{context free!grammar}\index{grammar!context free}\index{grammar}\index{language!grammar}
is a four-tuple $\sequence{\Sigma,N,S,P}$.
The set $\Sigma$ is an alphabet, whose elements are the
\definend{terminal symbols},\index{terminal}
and the elements of the set $N$ are the 
\definend{nonterminals}\index{nonterminal} 
or
\definend{syntactic categories}.\index{syntactic category}\index{grammar!syntactic category}
(We take $\Sigma$ and~$N$ to be disjoint, and that
neither contains metacharacters.)
The symbol $S\in N$ is the
\definend{start symbol}.\index{start symbol}\index{grammar!start symbol}

Finally, $P$ is a set of 
\definend{productions}\index{production}\index{grammar!production}
or \definend{rewrite rules}.\index{rewrite rule}\index{grammar!rewrite rule}
Each has one arrow, \productionsymbol{}.\footnotemark[2]
To the right of the arrow is 
the rule's \definend{body}\index{body of a production}\index{grammar!body of a production} 
or 
\definend{expansion},\index{expansion of a production}\index{grammar!expansion of a production}
a string of terminals and nonterminals.
To the left of the arrow is the rule's 
\definend{head},\index{head of a production}\index{grammar!head} 
which is a single nonterminal.\footnotemark[3]
\end{definition}\footnotetext[2]{%
  Read the arrow aloud
  as ``may produce,'' or ``may expand to,'' or ``may be constructed as.''
}\footnotetext[3]{These grammars are context free because
  each head consists of one nonterminal.
  \citetext{A grammar that does not follow this format is}{%
    Taken from \protect\url{https://en.wikipedia.org/wiki/Formal_grammar}.}:  
  % one that allows heads of the form
  % $\sigma_0$\ntrm{X}$\sigma_1$, where $\sigma_0$ and~$\sigma_1$ are 
  % strings of terminals and nonterminals.
  % % (They can be empty strings.)
  % \protect\label{ex:anbncnGrammar}
  % For example, 
  % \citetext{this grammar}{%

  (i)~\ntrm{S}\produces{} \str{a}\ntrm{B}\ntrm{S}\str{c} | \str{abc},
  (ii)~\ntrm{S}\produces{}\str{abc},

  (iv)~\ntrm{B}\str{b}\produces{}\str{bb}.

  % S

  are \protect\definend{context sensitive}\protect\index{grammar!context sensitive}
  because they only allow
  substitution for~\ntrm{X} in a context.
  % of $\sigma_0$ and~$\sigma_1$.

  the context free ones that
  we are using, and there are grammar classes even more general.

  % because it is a good balance of convenience and power.

Those rules for \ntrm{expr} and \ntrm{term} are recursive.
But we don't get stuck in an infinite regress because 
the question is not whether we could perversely 
keep expanding \synt{expr} forever.
Instead, we will be given a string such as \str{x*(y+z)}
and the question will be whether 
we can find a terminating derivation. 
\end{remark}

In the prior example the nonterminals such as \synt{expr} or \synt{term} 
describe the role of those components in the language, as did
the English grammar fragment's \synt{noun phrase} and \synt{article}.
That is why nonterminals are sometimes called `syntactic categories'.
But for examples and exercises we often use small grammars whose 
terminals and nonterminals do not have any particular meaning.
For these, a common convention is to
write productions using single letters, 
with nonterminals in upper case and terminals
in lower case.

\begin{example}  \label{ex:GrammarOfanbn}
This two-rule grammar has one nonterminal, S.
\begin{grammar}
  S \produces{} \trm{a}S\trm{b} \syntaxor \emptystring
\end{grammar}
Here is a derivation of
the string $\str{a}^2\str{b}^2=\str{aabb}$.
\begin{center}
  S
  \derives\trm{a}S\trm{b}
  \derives\trm{aa}S\trm{bb}            
  \derives\trm{aa}\emptystring\trm{bb}
  = \trm{aabb}  
\end{center}

  $S
  \derives\trm{a}S\trm{b}
  \derives\trm{aa}S\trm{bb}            
  \derives\trm{aaa}S\trm{bbb}            
  \derives\trm{aaa}\emptystring\trm{bbb}
  = \trm{aaabbb}$  
is a derivation of $\str{a}^3\str{b}^3\!$.
With this grammar, derivable strings have the form
$\str{a}^n\str{b}^n$ for $n\in\N$.
\end{example}

We now give a complete description of how the production rules 
govern the derivations.
Each rule in a context free grammar 
has the form \mbox{`head\produces{}body'} where
the head consists of a single nonterminal.
The body is a sequence of terminals and nonterminals.
% (such a string is a 
% \definend{sentential form}).\index{sentential form}
Each step of a derivation has the form below,
where $\tau_0$ and $\tau_1$ are strings of terminals and non-terminals.
\begin{center}
  $\tau_0\concat\text{head}\concat\tau_1$
  \quad\derives\quad
  $\tau_0\concat\text{body}\concat\tau_1$
\end{center}
That is, if there is a match for the rule's head
then we can replace it with the body.

Where $\sigma_0,\sigma_1$ are strings of terminals and nonterminals,
if they are related by a sequence of derivation steps then
we write $\sigma_0\;\kleenestar{\derivessymbol}\;\sigma_1$.\footnote{%
  Read `$\kleenestar{\derivessymbol}$' aloud as ``eventually expands to.''}
Where $\sigma_0=S$ is the start symbol, 
if there is a sequence $\sigma_0\;\kleenestar{\derivessymbol}\;\sigma_1$ that
finishes with 
a string of terminals $\sigma_1\in\kleenestar{\Sigma}$ then we say
that $\sigma_1$ \definend{has a derivation}\index{derivation}
from the grammar.

%<*def:LanguageOfGrammar>
\begin{definition}
The \definend{language derived from a grammar}\index{language!derived from a grammar} 
is the set of strings of terminals having derivations
that begin with the start symbol.
\end{definition}
%</def:LanguageOfGrammar>

\begin{example} \label{ex:grammarForNaturals}
This grammar's language is the set of representations of natural numbers. 

\begin{grammar}
  \ntrm{natural} \produces{} \ntrm{digit} 
        \syntaxor \ntrm{digit}\ntrm{natural}   
  
  \ntrm{digit} \produces{} \trm{0} \syntaxor $\ldots${} \trm{9}
\end{grammar}

\noindent This is a derivation for the string \str{321}, along with its
parse tree.

       &\derives\ntrm{digit}\ntrm{natural}     \\ 
       &\derives\trm{3}\ntrm{natural}           \\
       &\derives\trm{3}\ntrm{digit}\ntrm{natural}    \\  
       &\derives\trm{32}\ntrm{natural}          \\
       &\derives\trm{32}\ntrm{digit}            \\
       &\derives\trm{321}
  \end{tabular}
  \qquad     
  \vcenteredhbox{\includegraphics{languages/asy/parsetree/parsetree001.pdf}}
\end{center}

\begin{example}
This grammar gives the language of all length~$2$ bitstrings, using the brute 
force approach of just listing all the member strings.
Any finite language is derived from a grammar in this way.

\begin{grammar}
  S \produces{} 
   \trm{00} \syntaxor \trm{01} \syntaxor \trm{10} \syntaxor \trm{11}
\end{grammar}

\noindent This gives the length~$3$ bitstrings
by using the nonterminals to keep count.

\begin{grammar}
  A \produces{} \trm{0}B \syntaxor \trm{1}B

  B \produces{} \trm{0}C \syntaxor \trm{1}C

  C \produces{} \trm{0} | \trm{1}
\end{grammar}

\noindent A derivation of \str{101} is 
  A
  \derives\trm{1}B
  \derives\trm{10}C            
  \derives\trm{101}.            
\end{example}

\begin{example}
\begin{credit}
  SE user \href{https://cs.stackexchange.com/a/75423/67754}{Rick Decker}
\end{credit}
This grammar 
\begin{grammar}
S \produces{} \trm{a}S\trm{b} \syntaxor \trm{a}S 
         \syntaxor \trm{a} \syntaxor S\trm{b} \syntaxor \trm{b}
\end{grammar}
generates the language
$\lang=\set{\str{a}^i\str{b}^j\in\kleenestar{\set{\str{a},\str{b}}} \suchthat\text{$i\neq0$ or $j\neq 0$}}$.

This is the first grammar that we have seen
where the generated language is not immediately clear.
So we will verify, first that the generated language is a 
subset of~$\lang$ and then that it is also a superset.

The rules
show that any derivation step 
$\tau_0\concat\text{head}\concat\tau_1$
  \derives~$\tau_0\concat\text{body}\concat\tau_1$
only adds \trm{a}'s on the left and 
\trm{b}'s on the right, so every string in the language has the form
$\str{a}^i\str{b}^j\!$.
That same rules show that in any terminating derivation S 
must eventually be replaced by either \trm{a} or \trm{b}.
Together these two give that the generated language is a subset of~$\lang$.

For containment the other way, we will prove that every $\sigma\in\lang$ 
has a derivation.
We will use induction on the length $\lh{\sigma}$.
By the definition of~$\lang$ 
the base case is $\lh{\sigma}=1$.
In this case either $\sigma=\str{a}$ or~$\sigma=\str{b}$,
each of which obviously has a derivation.

For the inductive step, fix $n\geq 1$
and assume that every string from $\lang$ of length $k=1$, \ldots{} $k=n$ 
has a derivation.
Consider $\sigma\in\lang$ of length~$n+1$.
By the definition of~$\lang$ it has the form $\sigma =\str{a}^i\str{b}^j$.
There are three cases: either  or~$i=j=1$, or $i>1$, or $j>1$.
A derivation for $\sigma=\str{a}^1\str{b}^1$ is easy.
If $i>1$ then $\hat{\sigma} =\str{a}^{i-1}\str{b}^{j}$ is a string of
length~$n$, so by the inductive hypothesis it has a derivation
S\derives$\cdots$\derives{}~$\hat{\sigma}$.
Prefixing that derivation with
a S\derives{}\trm{a}S step will put an
additional \str{a} on the left.
Similar reasoning works when $j>1$.
\end{example}

The description of how rules govern derivations
is like the description in this book's first section
% from page~\pageref{text:DescriptionOfTMAction} 
of how
a Turing machine's instructions determine the evolution of the
sequence of configurations.
That is, production rules are like a program, directing a 
derivation.
However one difference is that for Turing machines,
from a given
input string there is a determined sequence of configurations.
But for grammars, from the start symbol a derivation can branch out in many
different ways.

\begin{grammar}
\ntrm{sentence} \produces{} \ntrm{subject} \ntrm{predicate}

\ntrm{subject} \produces{} \ntrm{article} \ntrm{noun1}

\ntrm{predicate} \produces{} \ntrm{verb} \ntrm{direct-object}

\ntrm{direct-object} \produces{} \ntrm{article} \ntrm{noun2}

\ntrm{article} \produces{} \trm{the} \syntaxor \trm{a} \syntaxor \emptystring

\ntrm{noun1} \produces{} \trm{dog} \syntaxor \trm{flea}

\ntrm{noun2} \produces{} \trm{man} \syntaxor \trm{dog}

\ntrm{verb} \produces{} \trm{bites} \syntaxor \trm{licks}  
\end{grammar}
\begin{exparts}
\item Give a derivation for \str{dog bites man}.  
\item Show that there is no derivation for \str{man bites dog}.  
\end{exparts}
\begin{answer}\verified
  \begin{exparts}
  \item This is a derivation for `\str{dog bites man}'.
  \begin{display}
  \begin{tabular}[t]{l}
    \ntrm{sentence} 
      \derives \ntrm{subject} \ntrm{predicate}
      \derives \ntrm{article} \ntrm{noun1} \ntrm{predicate}      
     \\ \quad
      \derives \ntrm{article} \ntrm{noun1} \ntrm{verb} \ntrm{direct object}
      \derives \ntrm{article} \ntrm{noun1} \ntrm{verb} \ntrm{article} \ntrm{noun2}
     \\ \quad
      \derives \emptystring{} \ntrm{noun1} \ntrm{verb} \ntrm{article} \ntrm{noun2}
      \derives \emptystring{} \trm{dog} \ntrm{verb} \ntrm{article} \ntrm{noun2}
     \\ \quad
      \derives \emptystring{} \trm{dog} \trm{bites} \ntrm{article} \ntrm{noun2}
      \derives \emptystring{} \trm{dog} \trm{bites} \emptystring{} \ntrm{noun2}
     \\ \quad
      \derives \emptystring{} \trm{dog} \trm{bites} \emptystring{} \trm{man}
      = \trm{dog bites man}
  \end{tabular}       
  \end{display}
  \item The start symbol \ntrm{sentence} expands to 
    \ntrm{subject}\ntrm{predicate}.
    As to the first of those, \ntrm{subject} expands to 
    \ntrm{article}~\ntrm{noun1},
    and \ntrm{noun1} must expand to either
    of the terminals \trm{dog} or \trm{flea}.
    However, \trm{man} is derived only from~\ntrm{noun2}, 
    which is derived only from \ntrm{direct-object},
    which in turn is derived only from \ntrm{predicate}.
    So \trm{man} cannot be the first word of the sentence,
    since it must be preceded by either \trm{dog} or \trm{flea}.
  \end{exparts}
\end{answer}

\begin{exercise}  \label{exer:VerifyAnbn}
Verify that the language derived from the 
grammar in \zcref{ex:GrammarOfanbn}
is $\lang=\set{\str{a}^n\str{b}^n\suchthat n\in\N}$.
\begin{answer}\verified
  We will use induction to show that 
  in the course of a derivation all of the results are of either the form
  \mbox{$\trm{a}^k$ S $\trm{b}^k$} or of the form
  \mbox{$\trm{a}^k\trm{b}^k\!$}.
  By the definition of the language generated by a grammar,
  only strings without any nonterminals are in the language so
  that will give the verification. 

  The induction is on the number of derivation steps, that is,
  on the number of rule applications.
  The base step is that there are zero-many rule applications.
  In this case the string is~`S', which is the $k=0$ instance of the 
  desired form.

  For the inductive step assume that the statement is true where the 
  number of rule applications is  $n=0$, $n=1$, \ldots{} $n=k$ and consider
  the $n=k+1$ case. 
  We get the string for the $k+1$ case by applying a rule to 
  a string after the~$k$ case.
  The inductive hypothesis is that such a string has one of two 
  forms, \mbox{$\trm{a}^k$ S $\trm{b}^k$} or
  \mbox{$\trm{a}^k \trm{b}^k$}.
  The rules don't apply to the latter string so consider the former one.

  Applied to \mbox{$\trm{a}^k$ S $\trm{b}^k$} the first rule gives
  \mbox{$\trm{a}^{k+1}$ S $\trm{b}^{k+1}$}, which has the right form.
  The second rule gives \mbox{$\trm{a}^{k+1}\trm{b}^{k+1}$}, again of the
  right form.
\end{answer}
\end{exercise}

\subsection{Definition}
We start with the basics.

%<*def:Graph>
\begin{definition}\index{graph} \label{def:SimpleGraph}
A \definend{simple graph}\index{simple graph}\index{graph!simple} 
is an ordered pair
$\mathcal{G}=\sequence{\mathcal{N},\mathcal{E}}$ where
$\mathcal{N}$ is a set of
\definend{vertices}\index{vertex}\index{graph!vertex} % \footnotemark[1] 
or \definend{nodes}\index{node}\index{graph!node}
and $\mathcal{E}$ is a set of \definend{edges}.\index{edge}\index{graph!edge}
Each edge is a set of two distinct vertices;
these vertices are 
\definend{adjacent}\index{adjacent vertices}\index{graph!adjacent vertices}
or \definend{neighbors}.\index{neighbor verticess}\index{graph!neighbor vertices}    
\end{definition}
% \footnotetext[1]{%
%   Graphs can have infinitely many vertices but
%   we won't ever need that. 
%   For convenience
%   we will stick to finite ones.}
%</def:Graph>

\noindent A graph is finite\index{graph!finite} if it has finitely many vertices
and infinite\index{graph!infinite} if it has infinitely many.
 
\begin{example} \label{ex:SimpleGraphFiveVert}
This simple graph~$\mathcal{G}$ 
has five vertices
and eight edges.

%<*discussion:EdgeNotation>
Instead of writing $e=\set{v,\hat{v}}$ we often write $e=v\hat{v}$. 
Since edges are sets and sets are unordered, in a simple graph 
we could write the same edge as $e=\hat{v}v$.
%</discussion:EdgeNotation>

%<*discussion:GraphVariantsi>
There are many extensions of that definition.
One is to allow some vertices to  
connect to themselves, forming a 
\definend{loop}.\index{loop}\index{graph!loop}\footnote{%
  Formally, we might extend the definition to allow some edges in
  $\mathcal{E}$ to be single-element sets.
  We will not specify how each variant is formalized.}
% (We might define this by extending \zcref{def:SimpleGraph} to also allow
% an edge to be a one-element set.
% In the rest of this section, instead of focusing on the formal details
% we will keep the discussion at an intuitive level.)
Another variant is a 
\definend{multigraph},\index{multigraph}\index{graph!multigraph}
which allows two vertices to share more than one edge. 
Still another is a 
\definend{weighted graph},\index{weighted graph}\index{graph!weighted} 
which gives
each edge a real number 
\definend{weight},\index{edge weight}\index{weight}\index{graph!edge weight} 
perhaps signifying the distance
or the cost in money or time to traverse that edge.
%</discussion:GraphVariantsi>

%<*discussion:GraphVariantsii>
A very often-used variation is a 
\definend{directed graph}\index{directed graph}\index{graph!directed} 
or \definend{digraph},\index{digraph}\index{graph!digraph} 
where 
edges have a direction, 
as in a road map that includes one-way streets.
If an edge is directed from $v$ to $\hat{v}$ then we 
can write it as $v\hat{v}$ but not in the other order.
%</discussion:GraphVariantsii>
The Turing machine graph above is a digraph
and also has loops.

%<*discussion:GraphVariantsiii>
Some important variations involve whether the graph has cycles.
A cycle is a closed path
around the graph; see the definition below.
A \definend{tree}\index{tree}\index{graph!tree} 
is an undirected connected graph with no cycles
(often one vertex is singled out as the tree's \definend{root}).\index{root}\index{tree!root}
% One of the two examples at the start of this section is a syntax tree.
A 
\definend{directed acyclic graph}\index{directed acyclic graph}\index{graph!directed acyclic}
or 
\definend{DAG}\index{directed acyclic graph DAG}\index{DAG|see{directed acyclic graph DAG}} 
is a directed graph with no directed cycles.
%</discussion:GraphVariantsiii>





\subsection{Paths}\index{graph!traversal|(}
Many problems that we shall consider involve moving through a graph.
%<*def:Adjacent>
\begin{definition} % https://faculty.math.illinois.edu/~west/openp/gloss.html
Two graph edges are 
\definend{incident}\index{incident}\index{graph!incident edges}
if they share a vertex, so that they have the form $e_0=uv$ and~$e_1=vw$.
A \definend{walk}\index{walk}\index{graph!walk} 
is a sequence of incident edges 
$\sequence{v_0v_1,\,v_1v_2,\ldots\,v_{n-1}v_n}$.
Its \definend{length}\index{length}\index{walk length}\index{graph!walk length} 
is the number of edges, $n$.
A vertex is \definend{contained}\index{vertex!contained in a walk}\index{walk!contained vertex} 
in a walk if it is shared by two incident edges in that walk.
or is the initial or final vertex.
If the initial vertex equals the final vertex then the walk is 
\definend{closed},\index{closed walk}\index{graph!closed walk} 
otherwise it is 
\definend{open}.\index{open walk}\index{graph!open walk}
A \definend{trail}\index{trail}\index{graph!trail}
is a walk where no edge occurs twice.
A \definend{circuit}\index{circuit}\index{graph!circuit}
is a closed trail.
A \definend{path}\index{path}\index{graph!path} 
is a walk with no repeated edges or vertices, 
except that it may be closed and so have equal
first and last vertices.
A closed path with at least one edge is a

\subsection{Graph representation}\index{graph!representation|(}
We can 
\citetext{represent graphs}{%
  \zcref{ex:SimpleGraphFiveVert} make the point that a graph 
  is about the connections between vertices, not about how it is drawn. 
  This graph representation via a matrix
  also illustrates that point because it is, after all, not drawn.} 
in a computer with reasonable efficiency.
A simple and common way
is with a matrix.
This example represents \zcref{ex:SimpleGraphFiveVert}'s graph:
it has a~$1$ in the $i,j$~entry if the graph has an edge from $v_i$ to~$v_j$
and a~$0$ if there is no such edge.
\begingroup\setlength{\abovedisplayskip}{4pt}
\setlength{\belowdisplayskip}{4pt}
\begin{equation*}
  \mathcal{M}(\mathcal{G})=
  \begin{blockarray}{*{6}{c}}
           &v_0 &v_1 &v_2 &v_3 &v_4    \\
    \begin{block}{c(*{5}{c})}
      v_0  &0   &1   &1  &0   &0  \\
      v_1  &1   &0   &1  &1   &1  \\
      v_2  &1   &1   &0  &1   &1  \\
      v_3  &0   &1   &1  &0   &1  \\
      v_4  &0   &1   &1  &1   &0  \\
    \end{block}
  \end{blockarray}
  % \tag{$*$}
\end{equation*}
\endgroup
% We can tell that this matrix represents  
% a simple graph because it has only $0$ and~$1$ entries,
% because all the diagonal entries are~$0$,
% and because the matrix is symmetric, meaning that the $i,j$ entry is~$1$ 
% if and only if the $j,i$ entry is also~$1$.

Matrix representation extends to cover other graph variants.
If a graph is directed and has a one-way edge from $v_i$ to~$v_j$
but none from $v_j$ to~$v_i$
then its matrix is not symmetric because
the $i,j$ entry will be~$1$ but the $j,i$ entry will be~$0$. 
For a multigraph, where there can be multiple edges from one vertex to 
another, the associated entry can be larger than~$1$.
And, if a graph has a loop then its matrix has 
a diagonal entry that is a natural number larger than zero.

%<*def:AdjacencyMatrix>
\begin{definition}
For a graph~$\mathcal{G}$, the
\definend{adjacency matrix}\index{adjacency matrix}\index{graph!matrix representation} 
$\mathcal{M}(\mathcal{G})$
has that the $i,j$ entry equals
the number of edges from $v_i$ to~$v_j$.
\end{definition}
%</def:AdjacencyMatrix>

%<*lem:MatrixPowersAdjacencyMatrix>
\begin{lemma} \label{lem:MatPowerPatahsLengthN}

the graph~$\mathcal{G}$.
Then in its matrix multiplicative $n$-th power,
the $i,j$ entry is the number of paths of length~$n$
from vertex~$v_i$ to vertex~$v_j$.
\end{lemma}
%</lem:MatrixPowersAdjacencyMatrix>

\subsection{Graph isomorphism}\index{graph!isomorphism|(}
We sometimes want to know when two graphs are essentially identical.
Consider these two.
\begin{center}
  \vcenteredhbox{\includegraphics{languages/asy/graphs/graphs11.pdf}}
  \hspace*{3em}
  \vcenteredhbox{\includegraphics{languages/asy/graphs/graphs12.pdf}}
\end{center}
They have the same number of vertices and the same number of edges.
Further, on the right as well as on the left
there are two classes of vertices where all the vertices in the first class
connect to all the vertices in the second class:~on the left the two classes 
are the top and bottom rows while on the right they
are the even-\hbox{} and odd-numbered vertices.
A person may suspect that, as in \zcref{fig:DrawTwoWays}, these are two
ways to draw the same graph, with the vertex names changed for further 
obfuscation.

That's true;~if we define this correspondence between
the vertices
\begin{center}  \small
  \begin{tabular}{r|cccccc}
    \tabulartext{Vertex on left} &$v_0$ &$v_1$ &$v_2$ &$v_3$ &$v_4$ &$v_5$ \\
    \cline{2-7}
    \tabulartext{Vertex on right} &$w_0$ &$w_2$ &$w_4$ &$w_1$ &$w_3$ &$w_5$ \\
  \end{tabular}
\end{center}
then as a consequence the edges also correspond.
\begin{center}  \small
  \begin{tabular}{@{}r|cccccc@{}}
    \tabulartext{Edge on left} 
      &$\set{v_0,v_3}$ &$\set{v_0,v_4}$ &$\set{v_0,v_5}$
      &$\set{v_1,v_3}$ &$\set{v_1,v_4}$ &$\set{v_1,v_5}$  \\
    \cline{2-7}
    \tabulartext{Edge on right} 
      &$\set{w_0,w_1}$ &$\set{w_0,w_3}$ &$\set{w_0,w_5}$
      &$\set{w_2,w_1}$ &$\set{w_2,w_3}$ &$\set{w_2,w_5}$  \\
  \end{tabular}                               \\[1ex]
  \hspace*{-8em}
  \begin{tabular}{r|ccc}
    \tabulartext{(Cont.) Edge on left} 
      &$\set{v_2,v_3}$ &$\set{v_2,v_4}$ &$\set{v_2,v_5}$  \\
    \cline{2-4}
    \tabulartext{Edge on right} 
      &$\set{w_2,w_1}$ &$\set{w_2,w_3}$ &$\set{w_2,w_5}$  \\
  \end{tabular}
\end{center}
% For instance, for the first edge on the left $\set{v_0,v_3}$, we are associating
% $v_0\leftrightarrow w_0$ and~$v_3\leftrightarrow w_1$ 
% so we look on the right for an edge
% $\set{w_0,w_1}$ and sure enough, it is there.

%<*def:GraphIsomorphism>
\begin{definition}  \label{def:GraphIsomorphism}
Two graphs $\mathcal{G}$ and $\hat{\mathcal{G}}$ are 
\definend{isomorphic}\index{isomorphism}\index{isomorphic graphs}\index{graph!isomorphism}
if there is a one-to-one and onto map $\map{f}{\mathcal{N}}{\hat{\mathcal{N}}}$
such that $\mathcal{G}$ has an edge $\set{v_i,v_j}\in\mathcal{E}$
if and only if $\hat{\mathcal{G}}$ has the associated edge 
$\set{f(v_i),f(v_j)}\in\hat{\mathcal{E}}$.
\end{definition}
%</def:GraphIsomorphism>

\ifbool{MakingPaperCopy}{%
  \relax
}{%
  \margingraphic{0.18\textwidth}{languages/pix/edgelord.png}{\label{fig:xkcdedgelord}\href{https://xkcd.com/2036/}{Courtesy \url{xkcd.com}}}
}
To verify that two graphs are isomorphic 
the most natural thing is to produce the map~$f$ and then verify that 
in consequence the edges also correspond. 
The exercises have examples.

%<*discussion:GraphIsomorphism>
Showing that graphs are not isomorphic usually entails finding some 
graph-theoretic way in which they differ. 
A useful such property to consider is 
the 
\definend{degree of a vertex},\index{degree!of a vertex}\index{graph!vertex degree} 
the total number of edges touching
that vertex, with the proviso that 
a loop from the vertex to itself counts as two.
The 
\definend{degree sequence}\index{degree!sequence}\index{graph!degree sequence} 
of a graph is the non-increasing sequence
of its vertex degrees.
%</discussion:GraphIsomorphism>
Thus, \zcref{ex:CommitteeColoring}'s graph has degree sequence
$\sequence{3,2,1,1,1}$.

\zcref{exer:DegreeSequenceMustMatch} shows that if graphs are isomorphic then
associated vertices have the same degree and 
thus graphs with different degree sequences are not isomorphic.
In addition, if we are given two graphs then 
we can use the degrees of the vertices to
help construct an isomorphism, if there is one;~examples 
are in the exercises.
(Note, though, that there are graphs with the same degree sequence 
that are not isomorphic.)

Determining whether two given graphs are isomorphic is in general 
a hard problem.
We could use brute force, checking every possible correspondence between
the two sets of vertices,
but that would be slow.
We do not currently know whether there is a quick way.
% we can quickly determine whether two graphs are isomorphic.
(There are algorithms that in practice do well for most
graphs but in the worst cases are quite slow.)
More on the speed of algorithms
is in the final chapter.
\index{graph!isomorphism|)}

\begin{exparts}
\item Show that if two graphs are isomorphic then they have the same number
of vertices.
Thus graphs with different numbers of vertices are not isomorphic.
\item Show that if two graphs are isomorphic then they have the same number
of edges.
Thus graphs with different numbers of edges are not isomorphic.
\item
Show that if two graphs are isomorphic and one has a vertex of degree~$k$
then so does the other.
Thus two graphs where one has a degree~$k$ vertex and the other does not
are not isomorphic.
\item 
Show that if two graphs are isomorphic then for each degree~$k$, the number
of vertices of the first graph having that degree equals the number of 
vertices of the second graph having that degree. 
Thus graphs with different degree sequences are not isomorphic.  
\item
Use the prior result to show that the two graphs of \zcref{ex:TwoWalkGraphs}
are not isomorphic.
\item
Verify that while these two graphs have the same degree sequence, they are
not isomorphic.
\hint~consider the paths starting at the degree~$3$ vertex.
\begin{center}
  \vcenteredhbox{\includegraphics{languages/asy/graphs/graphs21.pdf}}
  \hspace{2em}
  \vcenteredhbox{\includegraphics{languages/asy/graphs/graphs22.pdf}}
\end{center}
\end{exparts}
We often use these to show that graphs are not isomorphic, by taking
the contrapositive statements.
For instance, the first item that if graphs are isomorphic then they 
have the same number of vertices, is equivalent to the statement 
that if they do not have the same number of vertices then they are
not isomorphic.
\begin{answer}\verified
  \begin{exparts}
  \item By the definition of graph isomorphism, \zcref{def:GraphIsomorphism}, 
  if two graphs $\mathcal{G}$ and~$\hat{\mathcal{G}}$ are isomorphic
  then there is a correspondence between their vertices.
  They therefore have the same number of vertices. 
  \item The definition of graph isomorphism states
  that the edges correspond.
  So isomorphic graphs have the same number of edges.
  \item Suppose that $\mathcal{G}=\sequence{\mathcal{N},\mathcal{E}}$ 
  and~$\hat{\mathcal{G}}=\sequence{\hat{\mathcal{N}},\hat{\mathcal{E}}}$
  are isomorphic via the function~$f$\!.
  Let vertex $v\in\mathcal{N}$ have degree~$k$.
  Then in the set~$\mathcal{E}$
  the vertex~$v$ occurs~$k$ times (counting once for edges in which the
  vertex occurs once and twice for loops on~$v$).

  Now consider the vertex~$f(v)$ 
  and the set~$\hat{\mathcal{E}}\!$.
  Because $f$ gives a correspondence among edges, the vertex must occur~$k$ 
  times in the set (here also counting once for edges in which the
  vertex occurs once and twice for loops on~$v$).
  So $f(v)$ has degree~$k$.
  \item This is the same as the prior item, but instead of a single vertex~$v$
  we include all of the vertices $v_0,\ldots\, v_n$.
  \item There are a number of the prior items that we could apply.
    The simplest is that they have a different number of vertices.
    Another is that the degree sequences differ since
    on the left the degree sequence is $\sequence{3,3,3,3}$
    while on the right it is $\sequence{4,4,4,4,4,4,4,4}$. 
  \item Clearly they have the same degree sequence, 
   $\sequence{3,1,1,1,1,1}$.
   Suppose that the two are isomorphic via the correspondence~$f$.
   Then $f$ must associate the two degree-$3$ vertices.
   The graph on the left has two unequal length~$2$ paths that 
   start with its degree~$3$ vertex.
   The graph on the right does not have two, it only has one.
  \end{exparts}
\end{answer}
\end{exercise}

\begin{exercise} \label{exer:MatPowerPatahsLengthN}
We can prove \zcref{lem:MatPowerPatahsLengthN} by induction.
\begin{exparts}
\item As a warmup, 
  show that in the product of the matrix with itself
  $\big(\mathcal{M}(\mathcal{G})\big)^2$ the entry~$i,j$
  is the number of length-two walks.
\item Do the induction argument.
  The base step is $n=1$.
  The inductive step assumes the lemma for $n=1$, \ldots, $n=p$
  and then verifies that the $i,j$~entry
  of the power $\big(\mathcal{M}(\mathcal{G})\big)^{p+1}$ equals 
  the number of length~$p+1$ walks from $v_i$ to~$v_j$.
\end{exparts}
\begin{answer}\verified
  \begin{exparts}
  \item There is a length~$2$ walk from $v_i$ to~$v_j$ if and only if there
  is some~$v_k$ where both $v_iv_k$ and~$v_kv_j$ are edges.
  Thus the number of such walks is
  $m_{i,1}m_{1,j}+m_{i,2}m_{2,j}+\cdots m_{i,n}m_{n,j}$,
  where each $m_{a,b}$ is an entry from $\mathcal{M}(\mathcal{G})$.
  That sum is the the $i,j$ entry 
  of~$\big(\mathcal{M}(\mathcal{G})\big)^2\!$. 
  \item The base step holds by the definition of $\mathcal{M}(\mathcal{G})$.

  For the inductive step 
  assume the hypothesis that the statement is true for
  $n=2$, \ldots, $n=p$ and consider the statement for $n=p+1$.
  There is a length~$p+1$ walk from $v_i$ to~$v_j$ if and only if there
  is some~$v_k$ where there is a length~$p$ walk from 
  $v_i$ to~$v_k$, and also~$v_kv_j$ is an edge.
  By the inductive hypothesis the number of such walks is
  $q_{i,1}m_{1,j}+q_{i,2}m_{2,j}+\cdots+ q_{i,n}m_{n,j}$,
  where each $q_{i,b}$ is an entry from $\bigl(\mathcal{M}(\mathcal{G})\bigr)^p$
  and $m_{b,j}$ is an entry from $\mathcal{M}(\mathcal{G})$.
  That summation is the $i,j$ entry 
  of~$\big(\mathcal{M}(\mathcal{G})\big)^{p+1}\!$. 
  \end{exparts}
\end{answer}
\end{exercise}

\begin{exercise} \label{exer:KonigsLemmaProof}
Prove K\"{o}nig's lemma, \zcref{lem:KonigsLemma}.
\begin{answer}
Fix a vertex~$v_0$.
The graph is connected, so for every other vertex there is a path reaching it
that starts at $v_0$.

For each of $v_0$'s neighbors, there is a set of vertices
that can be reached from $v_0$ via a path through that neighbor.
There are infinitely many vertices so there must be 
a neighbor (unequal to~$v_0$) 
where the set of vertices that are reachable
in that way is infinite.
Pick such a neighbor and call it~$v_1$. 

Now iterate: by choice of $v_1$ there are infinitely many vertices reachable
by a path starting with the edge $v_0v_1$. 
Because $v_1$ has finitely many neighbors,
there is a $v_2$ adjacent to $v_1$ (and unequal to either $v_0$ or~$v_1$), 
through which there are paths to
infinitely many of the graph's vertices.
In this way we get a path containing infinitely many vertices    
\end{answer}
\end{exercise}

The study of grammar, the rules for phrase structure and forming sentences,
has a long history, dating back as early as the fifth century BC.
Mathematicians, including A~Thue and E~Post, began systematizing it as 
rewriting rules by the early 1900's.
The variant here 
was produced in the late 1950's 
by J~Backus with contributions from P~Naur as part of the
design of the early computer language ALGOL60. 
Since then these rules have become
\citetext{the most common way to express grammars}{%
  One factor influencing its adoption was a letter that D~Knuth
  wrote to the \textit{Communications of the ACM}
  \autocite{KnuthCACM}.
  He listed
  some advantages over the grammar-specification
  methods that were then widely used.
  Most importantly, he contrasted BNF's use of descriptive
  text such as `\texttt{<addition operator>}' for syntactic categories,
  instead of something like `\texttt{A}', 
  saying that the difference is a great addition
  to ``the \textit{explanatory power} of a syntax.''
  He also proposed the name `Backus Naur Form'.
  (Now a hyphen is most common.) 
}.\footnote{%
  BNF is only loosely defined.
  While there are standards,
  often materials do not conform exactly to any single standard.}

were at the time not typeable with a standard keyboard.

  The Earth is constantly undergoing deceleration caused by the 
  braking action of the tides. 
  The average deceleration of the Earth is roughly $1.4$ milliseconds per day 
  per century, although the exact number varies from year to year
  depending on many factors, including major earthquakes and volcanic
  eruptions. 
  To ensure that 
  atomic clocks and the Earth's rotational time do not differ  
  by more than $0.9$ seconds,
  occasionally an extra second is added to civil time. 
  This leap second can be either positive or negative depending on the Earth's 
  rotation\Dash on occasion there are minutes with only $58$ seconds, and on
  occasion minutes with~$60$.

  Adding to the confusion is that the changes in rotation are uneven and
  we cannot predict leap seconds far into the future.  
  The International Earth Rotation Service publishes bulletins that
  announce leap seconds with a few weeks warning. 
  Thus, there is no way to determine how many seconds there will be between 
  the current instant and, say, ten years from now.
  (This can cause trouble in area such as navigation and high-frequency trading
  and there are proposals to eliminate leap seconds or replace them with
  leap hours.)
  Since the first leap second in 1972, all leap seconds have been positive and 
  there were 23 leap seconds in the 34 years to January~2006.
  \autocite{web:USNO}}. 
One issue is representing times and one standard in that area is 
\citetext{RFC~3339}{\autocite{rfc3339}},
\textit{Date and Time on the Internet: Timestamps}.
It uses 
\citetext{strings such as \str{1958-10-12T23:20:50.52Z}}{%

  earlier,
  simplicity (there is only one format),
  and that they include the time zone information.}.

There are a number of extended BNF notations that that are more than simple
character substitutions.
One is shown above in the
\ntrm{partial-time} rule, which includes square brackets as metacharacters
to denote that \ntrm{time-secfrac} is optional.
This is a very common construct: another example of it is in this syntax
description  
for \str{if $\ldots$ then $\ldots$} with an optional
\str{else}.

\begin{grammar}
    \ntrm{if-stmt} \bnfproduces{}  \trm{if} \ntrm{boolean-expr} \trm{then}
                             \ntrm{stmt-sequence}\\*
                        \quad[ \trm{else}
                             \ntrm{stmt-sequence} ]
                        \ntrm{end-if} \trm{;}
\end{grammar}

To denote a repetition of zero or more, BNF uses a 
Kleene star,~$\kleenestar{}$\!.

\begin{grammar}
 \ntrm{string} \bnfproduces{} \ntrm{letter}\trm{*}
\end{grammar}
To express `one or more', BNF uses a plus sign,~\trm{+}.
 
\begin{example} \label{ex:PythonFloatingPoint}
This grammar for Python floating point numbers shows 
both square brackets and the
plus sign.

\begin{grammar}
\ntrm{floatnumber}   \bnfproduces{}  \ntrm{pointfloat} \syntaxor \ntrm{exponentfloat}

\ntrm{pointfloat}    \bnfproduces{}  [\ntrm{intpart}] \ntrm{fraction} \syntaxor \ntrm{intpart} \trm{.}

\ntrm{exponentfloat} \bnfproduces{}  (\ntrm{intpart} \syntaxor \ntrm{pointfloat}) \ntrm{exponent}

\ntrm{intpart}       \bnfproduces{}  \ntrm{digit}+

\ntrm{fraction}      \bnfproduces{}  \trm{.} \ntrm{digit}+

\ntrm{exponent}      \bnfproduces{}  (\trm{e}\syntaxor{}\trm{E}) [\trm{+}\syntaxor{}\trm{-}] \ntrm{digit}+
\end{grammar}

\noindent In the \ntrm{pointfloat} rule the first \ntrm{intpart}
is optional.
And, an \ntrm{intpart} consists of one or more digits.
\end{example}

Each of these extensions is not necessary in that 
we can express the grammars without the extensions.
For instance, we could replace the this use of Kleene star

\begin{grammar}
 \ntrm{string} \bnfproduces{} \ntrm{letter}\trm{*}
\end{grammar}

\noindent with this. 

\begin{grammar}
\ntrm{string} \bnfproduces{} \ntrm{letter}\ntrm{string} \syntaxor \emptystring 
\end{grammar}

\noindent But these constructs come up often enough
that adopting an abbreviation is a significant convenience.

Passing from the grammar to a parser for that grammar is mechanical.
There are programs that take as input a grammar,
often one in BNF, and give as output source code that will
parse files following that grammar's format.
Such a program is a \definend{parser-generator}\index{parser-generator} 
(sometimes instead called a 
\definend{compiler-compiler},\index{compiler-compiler}
which is a fun term but is misleading because a parser 
is only part of a compiler).

\medskip
In summary,
BNF can express the range of languages that
we ordinarily want to express (context free grammars) 
and it smoothly translates to a parser.
It has the advantage of conscision, while
not giving up clarity where that is helpful.
That is, BNF is an impedance match\Dash it fits with what
we want to do.

\extra{Lambda Calculus and Scheme}
% See http://matt.might.net/articles/compiling-up-to-lambda-calculus/

% Jim Larson
% 1996-07-26
% This talk was given at the JPL Section 312 Programming Lunchtime Seminar.

A function accepts input and produces an output. 
Suppose we have a ``chocolate-covering'' function that produces the 
following outputs for the corresponding inputs:
% \begin{grammar}
%   \str{peanuts} &\produces  \str{chocolate-covered peanuts} \\
%   \str{rasins}  &\produces  \str{chocolate-covered rasins} \\
%   \str{ants}    &\produces \str{chocolate-covered ants}
% \end{grammar}
We can use Lambda-calculus to describe such a function.
\begin{equation*}
	\lambda x.\str{chocolate-covered $x$}
\end{equation*}
This is a \definend{lambda-expression}.

To apply the function to an argument, use the following syntax.
% \begin{equation*}
%   (\lambda x.\str{chocolate-covered $x$})\,\str{peanuts} 
%     \produces \str{chocolate-covered peanuts}
% \end{equation*}
Functions can also be the result of applying a lambda-expression, as with this ``covering function maker.''
\begin{equation*}
  \lambda y.\lambda x.\str{$y$-covered $x$}
\end{equation*}
Use this to create a caramel-covering function.
% \begin{align*}
%   (\lambda y.\lambda x.\str{$y$-covered $x$})\,\str{caramel} 
%     &\produces \lambda x.\str{caramel-covered $x$}   \\
%   (\lambda x.\str{caramel-covered $x$})\,\str{peanuts} 
%     &\produces \str{caramel-covered peanuts}
% \end{align*}
Functions can also be the inputs to other functions, as with this 
``apply-to-ants'' function.
\begin{equation*}
	\lambda f.(f)\,\str{ants}
\end{equation*}
We can feed the chocolate-covering function to the "apply-to-ants" function:
% \begin{multline*}
% 	(\lambda f.\str{$(f)$ants})\lambda x.\str{chocolate-covered $x$}  \\
%       \begin{split}
%         \hspace*{3em}
% 	&\produces (\lambda x.\str{chocolate-covered $x$})\str{ants}  \\
% 	&\produces \str{chocolate-covered ants}
%       \end{split}
% \end{multline*}

Lambda-expressions have the following syntax.
\begin{lstlisting}
	lambda-expression \bnfproduces{}	variable
				| constant
				| application
				| abstraction
	application \bnfproduces{} (lambda-expression)lambda-expression
	abstraction \bnfproduces{} Lvariable.lambda-expression
\end{lstlisting}
The evaluation of lambda-expression is from the application of two reduction 
rules. 
The \definend{alpha-reduction} rule says that 
we can consistently rename bindings of variables
% \begin{equation*}
% 	\lambda x.E \produces \text{$\lambda z.\{z/x\}E$ 
%                         for any $z$ which is neither free nor bound in $E$}
% \end{equation*}
where $\{z/x\}E$ means the substitution of $z$ for $x$ for any free occurrence 
of $x$ in $E$. 
The \definend{beta reduction} rule says that application of a 
lambda-expression to an argument is the consistent replacement of the 
argument for the lambda-expression's bound variable in its body:
\begin{equation*}
	(\lambda x.P)Q -> [Q/x]P
\end{equation*}
where $[Q/x]P$ means the substitution of $Q$ for $x$ for any free occurrence 
of $x$ in $P$.

The Church-Rosser Theorem states that the final result of a chain of 
substitutions does not depend on the order in which the substitutions are 
performed.

\subsection{Universality of Lambda-calculus}
The Lambda-calculus is a universal model of computation, that is, 
any computation that can be expressed in a Turing machine can also be 
expressed in the lambda calculus.

To show this, here is the translation of a conditional control structure 
into lambda-calculus.
\begin{align*}
	\str{true} &= \lambda x.\lambda y.x  \\
	\str{false} &= \lambda x.\lambda y.y        \\
	\str{if-then-else} &= \lambda a.\lambda b.\lambda c.((a)b)c 
\end{align*}
Here is an application of those rules.
% \begin{multline*}
% 	(((\str{if-then-else})\str{false})\str{apple})\str{banana}  \\
%       \begin{split}
%         \qquad 
% 	&\produces (((\lambda a.\lambda b.\lambda c.((a)b)c)\lambda x.\lambda y.y)\str{apple})\str{banana}       \\
% 	&\produces ((\lambda b.\lambda c.((\lambda x.\lambda y.y)b)c)\str{apple})\str{banana}          \\
% 	&\produces (\lambda c.((\lambda x.\lambda y.y)\str{apple})c)\str{banana}  \\
% 	&\produces ((\lambda x.\lambda y.y)\str{apple})\str{banana}   \\
% 	&\produces (\lambda y.y)\str{banana}    \\
% 	&\produces \str{banana}
%      \end{split}
% \end{multline*}
Here is the translation of some data structure operations.
\begin{align*}
	\str{cons} &= \lambda a.\lambda b.\lambda c.((c)a)b   \\
	\str{head} &= \lambda x.(x)\str{true}                  \\
	\str{tail} &= \lambda x.(x)\str{false}               \\
          \\
	0 &= \lambda f.\lambda x.x    \\
	1 &= \lambda f.\lambda x.(f)x  \\
	2 &= \lambda f.\lambda x.(f)(f)x   \\
	3 &= \lambda f.\lambda x.(f)(f)(f)x    \\
        \\
	\str{succ} &= \lambda n.\lambda f.\lambda x.(f)((n)f)x  \\
	+ &= \lambda m.\lambda n.\lambda f.\lambda x.((m)f)((n)f)x   \\
	* &= \lambda m.\lambda n.\lambda f.(m)(n)f           \\
	\str{zero?} &= \lambda n.((n)(\str{true})\str{false})\str{true} \\
	\str{pred} &= \lambda n.(((n)\lambda p.\lambda z.((z)(\str{succ})(p)\str{true})(p)\str{true})Lz.((z)0)0)\str{false}
\end{align*}

Lastly, you can create recursive functions with the \definend{$Y$ combinator}.
\begin{gather*}
	Y = \lambda y.(\lambda x.(y)(x)x)\lambda x.(y)(x)x        \\
	(Y)E -> (E)(Y)E -> \cdots -> (E)\ldots (E)(Y)E
\end{gather*}
We need this to create recursive functions, such as the factorial function:
\begin{equation*}
	\str{fact} = \lambda n.(((\str{if-then-else})(\str{zero?})n)1)((*)n)(\str{fact})(\str{pred})n
\end{equation*}
As written, this doesn't work since \str{fact} is a free variable in its 
own definition! We need some way to bind \str{fact} to ``this function,'' 
which can be done with Y.
\begin{equation*}
	\str{fact} = (Y)\lambda f.\lambda n.(((\str{if-then-else})(\str{zero?})n)1)((*)n)(f)(\str{pred})n
        \end{equation*}

        

\subsection{From theory to programming language}
Although the lambda-calculus is powerful enough to express any program, 
this doesn't mean that you'd actually want to do so. 
After all, the Turing Machine offers an equally powerful computational basis.

The strength of the lambda-calculus is that it is easily used as a ``glue'' 
on top of a richer world of primitives. 
Its advantages as a glue are that it has a natural correspondence with the way 
that people program, and natural compilation techniques yield 
high-performance code. 
The latter comes through optimizations know as tail-call and 
continuation-passing, which are more advanced topics not covered here.

There are software engineering advantages to a language glued together 
with lambda-calculus. 
Lambda expressions can be understood locally\Dash their dependence on 
their environment is entirely through their free variables. 
Lambda expressions tend to have fewer free variables and more bound 
variables than comparable imperative code, since they do not rely as heavily 
on assignment to express the computation. 
An imperative program proceeds by altering some globally-accessible 
store of values. 
By contrast, a functional program proceeds by function application and 
the return of values. 
This eliminates large classes of errors associated with maintaining a global store of values.




\subsection{Scheme}
The Scheme programming language is essentially the lambda-calculus outlined 
above, plus these
\begin{itemize}
\item
    The ability for a lambda-expression to bind several arguments at once.
\item
    A rich set of constants, so numbers, arithmetic, data structures, etc., don't have to be built out of thin air.
\item
    Primitive control constructs, so control operations don't have to be built out of thin air.
\item
    An assignment operation, should it be necessary.
\item
    An environment of defined names, to allow for interactive use, redefinition, and recursive definitions without using the $Y$ combinator.
\item
    A library with I/O operations to connect programs to the outside world. 
\end{itemize}

In Scheme, programs look like data structures - both are built of lists. A list looks like:
\begin{equation*}
	(\str{elt1}\ \str{elt2}\ \ldots{}\ \str{eltn})
\end{equation*}
where each element is either an atom (number or symbol), or another list.

Expressions from the lambda-calculus are translated as follows:
% \begin{align*}
% 	\lambda x.M  &\becomes  \text{\codeinline!(lambda (x) M)!} \\
% 	(M)N  &\becomes  \text{\codeinline!(M N)!}
% \end{align*}
In addition, Scheme allows lambda expressions and function applications of 
more than one argument.
\begin{lstlisting}
(lambda (a b c) (+ a (* b c)))
\end{lstlisting}
The define syntax binds names to values within the local environment:
\begin{lstlisting}
(define pi 3.14159265)
(define fact
    (lambda (n)
        (if (zero? n)
        1
        (* n (fact (- n 1))))))
(define alpha (sin (/ pi 180)))
\end{lstlisting}
Some Scheme constructs are `syntactic sugar', that is, 
expressions that can be translated into expressions in terms of more 
primitive operators. 
The \codeinline!let! construct allows initialization and binding of 
local variables so that this
\begin{lstlisting}
(let ((x1 E1)
      (x2 E2)
      (x3 E3))
      \ldots{}body\ldots{} )
\end{lstlisting}
is equivalent to this.
\begin{lstlisting}
((lambda (x1 x2 x3) \ldots{}body\ldots{} )
E1
E2
E3)
\end{lstlisting}
% Definition of a function can be done without an explicit lambda-expression
% \begin{lstlisting}
% 	(define (f x y z)	=>	(define f
% 	  \ldots{}body\ldots{})			  (lambda (x y z)
% 					    \ldots{}body\ldots{}))
% \end{lstlisting}



\subsection{Standard idioms in Scheme}
Where a conventional block-structured imperative language like C or Pascal 
would write
\begin{lstlisting}
begin
    x := 1;
    y := 2 * some_global_var;
    z := some_function();
    \ldots{}body using x, y, and z\ldots{}
end
\end{lstlisting}
Scheme would instead use the let syntax to bind local variables.
\begin{lstlisting}
(let ((x 1)
    (y (* 2 some-global-var))
    (z (some-function)))
    ..body using x, y, and z\ldots{})
\end{lstlisting}
As we see above, the \codeinline!let! construct is just the stylized use of 
lambda and a function application to create an environment for the body 
where the local variables are bound to their values. 
Note that this style of programming requires the local variables to be 
initialized before use.

Scheme downplays iterative constructs such as \codeinline!do!, preferring 
recursive function calls. 
A special optimization called tail-recursion produces compiled code 
that is equivalent to a loop.
\begin{lstlisting}
(define (new-fact n)
    (define (iter n a)
    (if (zero? n)
        a
        (iter (- n 1) (* n a))))
    (iter n 1))
\end{lstlisting}
Compare this to the equivalent C function:
\begin{lstlisting}
int
new_fact(int n)
{
    int a = 1;
    while (n != 0)
        a *= n--;
    return a;
}
\end{lstlisting}
Note that the loop in the C version cannot be understood on its own\Dash in 
order to see what \codeinline!n! and \codeinline!a! are we have to 
see the entire function, while in the Scheme version, the 
\codeinline!iter! function can be lifted out of the \codeinline!new-fact! 
function and understood on its own\Dash it has no free variables! 
This may not seem too important for a toy example like this, but as the 
size of the function and the complexity of the loop scales up, 
this kind of modularity can be important.

Although it may seem unnecessary and clumsy to define a new function every 
time you need a loop, some common uses can be turned into functions 
themselves. 
For instance, a common operation in Scheme is the act of taking a 
list and applying a function to each of the elements, forming a new list of 
the results.
\begin{lstlisting}
(define (list-of-squares l)
    (define (iter l)
        (if (null? l)
            (quote ())
            (cons ((lambda (x) (* x x)) (car l)) (iter (cdr l)))))
    (iter l))
\end{lstlisting}
This kind of iteration is idiomatic, so we can capture it in a function:
\begin{lstlisting}
(define (map f l)
    (define (iter l)
        (if (null? l)
            (quote ())
            (cons (f (car l)) (iter (cdr l)))))
        (iter l))

(define (list-of-squares l)
    (map (lambda (x) (* x x)) l))
\end{lstlisting}
We could produce this program in C as well, using the technique of passing 
pointers to functions as arguments to other functions. 
However, there are some features of C that make this difficult. 
Suppose we want a function to do an affine transformation $Ax + B$ on a 
list of numbers, with A and B as parameters to the function. 
In C we have to write this.
\begin{lstlisting}
double A, B;	/* global variables */
static double
affine(double x)
{
    return A * x + B;
}

List *
affinelist(double a, double b, List *l)
{
    A = a;
    B = b;
    return map(&affine, l);
}
\end{lstlisting}
Since in C, the map function accepts only a function pointer, 
the transformation parameters have to be held in some static location for 
the affine function to find them. This prevents the code from being 
reentrant\Dash only one call to affinelist can be active at a time.

Pascal allows functions to be declared within a block, and to have access 
to all the variables visible within that block. 
In a `block-structured' variation of C would could do the following:
\begin{lstlisting}
List *
affinelist(double a, double b, List *l)
{
    double
    affine(double x)
    {
        return a * x + b;
    }
    return map(&affine, l);
}
\end{lstlisting}
This allows the function to be re-entrant. 
But Scheme allows us even more freedom in the use of these local 
functions\Dash they can persist even after the return of the parent function! 
The variables bound by the parent function are still accessible to the local 
functions, and only by them, in effect creating an opaque object with the 
local functions as the methods for accessing its state. 
This gives us a way to do object-oriented programming with higher-order 
functions in Scheme.

Suppose we want to create an object with state variables svN and methods 
methodN.
\begin{lstlisting}
(define (make-object sv1 sv2 ... svN)
    (lambda (mesg)
        (cond ((eq? mesg (quote method1)) (lambda args1 body1))
               ((eq? mesg (quote method2)) (lambda args2 body2))
                 ...
               ((eq? mesg (quote methodM)) (lambda argsM bodyM))
               (else (error "Unknown method for object")))))

(define (method1 obj args1) ((obj (quote method1)) args1))
    ...
\end{lstlisting}
So an object is a procedure which accepts a message and dynamically 
returns a procedure which will handle that message. 
Each procedure has access to the state variables which were used to create 
the object. 
Multiple instances are created through multiple invocations of the 
\codeinline!make-object! function. 
Class structure and inheritance can be accomplished through delegation. 
So use of higher-order functions can implement object-oriented code in a 
natural way.

Here are some advantages of a lambda-calculus-based programming language.
\begin{itemize}
\item
    A clean mathematical basis. The formal specification of the language doesn't need to refer to a machine or compiler.
\item
    Many common programming idioms have a natural representation.
\item
    Advanced programming through higher-order functions.
\item
    Direct correspondence with advanced mathematical objects such as functionals.
\item
    Efficient machine implementation.
\item
    Programs are more modular\Dash they can be understood and analyzed locally. 
\end{itemize}

There are some disadvantages too.
\begin{itemize}
\item
    Real-world implementations are not as good as they could be.
\item
    The model of computation provided by the language is far removed from the realities of the underlying machine. This can be both good and bad.
\item
    Things that are simple in other languages tend to be hard in Scheme, yet some simple Scheme tricks are hard to do in other languages.
\item
    Programming with full lambda-calculus requires a garbage collector in the runtime system. This entails
        a more complicated runtime system than Fortran or C, 
        difficulty in linking with code compiled from another language, and 
        complications for real-time or interactive use. 
\end{itemize}
