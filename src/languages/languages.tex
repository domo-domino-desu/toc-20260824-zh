Turing machines input strings and output strings, sequences of tape symbols.
So a natural way to work is to represent a problem as a string,
put it on the tape, run a computation, and end with
the solution as a string.

Everyday computers work the same way.
Consider a program that finds the shortest driving distance
between cities.   
% Perhaps it works with a map of the country idealized as a
% a collection of nodes and edges, intersections and the roads joining them.
Probably we work by inputting the map distances as a strings of symbols and
inputting the desired two cities as two strings,
and after running the program we have the output
directions as a string.
So strings, and collections of strings, are essential.

Recall that a \definend{symbol} (sometimes called a \definend{token}) 
is something that a machine can read and write,\footnote{%
  We can imagine Turing's clerk 
  doing a calculation without symbols, keeping track of information by 
  \protect\citetext{requiring elephants to move 
  to the left side of a road or to the right}{Less fancifully, we could be
  making
  a Turing machine out of Legos and want to keep track by sliding a block
  from one side of a column to the other.
  Or, we could use an abacus.}.
  But 
  \protect\citetext{we could translate any such procedure}{While a 
  person may quite sensibly worry that elephants could be not just on
  the left side or the right, but in any of the continuum of points
  in between, 
  we will make this 
  assertion without more philosophical analysis than by just referring
  to the discrete nature of our mechanisms
  (as Turing basically did).
  That is, we take it as an axiom.} 
  into one using marks that our mechanism's read/write head can handle with 
  a tape, such as \protect\str{0} and \protect\str{1}.
  So the restriction to readability and writeability is not essential.
  We include it in the definition of symbols because our mechanisms will
  need to manipulate them.
  For this purpose, elephants
  would be an inconvenience.}
and an \definend{alphabet} is a nonempty and finite set of symbols.

%<*def:String>
\begin{definition}
A \definend{string} or \definend{word}
over an alphabet is a finite sequence of elements from that alphabet.
The string with no elements is 
the \citetext{\definend{empty string}, denoted~$\emptystring$}{Possibly 
  $\emptystring$ came as an abbreviation for `empty'.   
  Some authors use $\lambda$, possibly from the German word for 
  `empty', \textit{leer}.  \autocite{csse:Siren}}.
\end{definition}
%</def:String>
We write symbols in a distinct typeface, as in \str{1} or \str{a},
because the alternative of quoting them would be 
clunky.\footnote{%
  We must give them a distinct look because 
  we must distinguish the symbol `\protect\str{a}'
  from the variable `$a$' 
  so that we can tell ``let $S=\protect\str{a}$'' 
  apart from 
  ``let $S=a$.'' 
  Symbols are not variables\Dash they don't hold a value,
  they are themselves a value.}
One potentially surprising aspect of the term `symbol' is that 
some symbols contain more than one character.
For instance, a programming language
may have \str{if} as a symbol, indecomposable
into separate letters.

%<*discussion:AlphSymbol>
Traditionally, we use the Greek letter $\Sigma$ to denote an alphabet.
We denote strings with lower case Greek letters 
and denote the string's 
elements with the associated lower case roman letter, as in
$\sigma=\sequence{s_0,\ldots,s_{i-1}}$%
%</discussion:AlphSymbol>
or $\tau=\sequence{t_0,\ldots,t_{j-1}}$.\footnote{%
  If $i=0$ or 
  $j=0$ then this gives the empty string, so we take $i,j\in\N$.}

%<*def:StringLength>
\begin{definition}  \label{def:StringLength}
Let $\sigma=\sequence{s_0,\ldots,s_{n-1}}$ be a string.
Its \definend{length $\lh{\sigma}$} 
is the number of symbols,~$n$. 
In particular, 
the length of the empty string is $\lh{\emptystring}=0$.
\end{definition}
%</def:StringLength>

We use strings a lot. 
The diamond brackets and commas are ungainly. 
%<*dis:OmitCommas>
We usually adopt a shortcut where
instead of $\sequence{\str{a},\str{b},\str{c}}$, we write \str{abc}.
%</dis:OmitCommas>
That is, we usually have
the alphabet consist of single-character symbols and then write strings
by omitting the brackets and commas.\footnote{%
  To see why when we drop the commas we want the alphabet to consist of 
  single-character symbols, consider
  $\Sigma=\set{\str{a}, \str{aa}}$ 
  and the string $\str{aaa}$.
  Without the commas this string is ambiguous:~it could
  mean $\sequence{\str{a},\str{aa}}$, or 
  $\sequence{\str{aa},\str{a}}$, or
  $\sequence{\str{a},\str{a}, \str{a}}$.} 
However, this convenience 
comes with the disadvantage that without the diamond brackets  
the empty string is just nothing, which is why 
we have the separate symbol~$\emptystring$.\footnote{%
  Omitting the 
  diamond brackets and commas blurs the distinction between a symbol 
  and a one-symbol string, between \str{a} and $\sequence{\str{a}}$.
  However, dropping the brackets it is so convenient that we accept this
  disadvantage.}

The Scheme alphabet contains the symbols \str{or} and \str{car}, and
allows variable names such as \str{a}, \str{x}, or \str{lastname}.
An example of a string is $\str{(or a ready)}$, which is 
a sequence of five alphabet elements
$\sequence{\str{(}, \str{or}, \str{a}, \str{ready},~\str{)}}$.
% Scheme writes the sequence by separating its elements with spaces

\end{example}

%<*def:Bitstrings>
\begin{definition}
The alphabet consisting of the zero and one characters is
\definend{$\B=\set{\str{0},\str{1}}$}.
Strings over this alphabet are  \definend{bitstrings} or \definend{bit strings}.
\end{definition}
%</def:Bitstrings>

%<*def:Kleenestar>
\begin{definition}
Let~$\Sigma$ be an alphabet.
For $k\in\N$, 
the set of length~$k$ strings over that alphabet is \definend{$\Sigma^k$}.  
The set of strings over $\Sigma$ of any (finite) length is 
\definend{$\kleenestar{\Sigma}=\cup_{k\in\N}\Sigma^k$}.
\end{definition}
%</def:Kleenestar>

%<*def:StringOps>
\begin{definition}[Operations on strings] \label{def:StringOps}
Let $\sigma=\sequence{s_0\ldots,s_{i-1}}$ and 
$\tau=\sequence{t_0,\ldots,t_{j-1}}$ be strings over an
alphabet~$\Sigma$.
The 
\definend{concatenation $\sigma\concat\tau$} or \definend{$\sigma\tau$}
appends the second sequence to the first
$\sigma\concat\tau=\sequence{s_0\ldots,s_{i-1},t_0,\ldots,t_{j-1}}$.
\label{def:substring}
If we can write 
$\sigma=\tau_0\concat \cdots \concat\tau_{k-1}$ then 
$\sigma$ \definend{decomposes} into the other strings.
Each $\tau_i$ is a \definend{substring} of $\sigma$.
The first, $\tau_0$, is a \definend{prefix} of~$\sigma$,
while the last, $\tau_{k-1}$, is a \definend{suffix}. 

The \definend{replication $\sigma^n$} or \definend{power} of a string is the 
iterated concatenation with itself, so that $\sigma^2=\sigma\concat\sigma$ 
and $\sigma^3=\sigma\concat\sigma\concat\sigma$, etc.
We write $\sigma^1=\sigma$ and $\sigma^0=\emptystring$.

The \definend{reversal $\reversal{\sigma}$} of a string takes the symbols 
in reverse order
$\reversal{\sigma}=\sequence{s_{i-1}, \ldots, s_0}$.
The reversal of the empty string is itself
$\reversal{\emptystring}=\emptystring$.
\end{definition}
%</def:StringOps>

\begin{example}
Let $\Sigma=\set{\str{a},\str{b}}$, and let
$\sigma=\str{abc}$ and $\tau=\str{bbaac}$.
Then the concatenation $\sigma\tau$ is \str{abcbbaac}.
The third power $\sigma^3$ is \str{abcabcabc},
and the reverse $\reversal{\tau}$ is \str{caabb}.
\end{example}

%<*def:Lang>
\begin{definition}
A \definend{language~$\lang$ over an alphabet~$\Sigma$}
is a set of strings drawn from that alphabet. 
That is, $\lang\subseteq\kleenestar{\Sigma}$.  
\end{definition}
%</def:Lang>

\begin{example}
The set of bit strings
that begin with \str{1} is 
$\lang=\set{\str{1},\,\str{10},\,\str{11},\,\str{100},\,\ldots}$.   
\end{example}

\begin{example}
Another language over $\B$
is the \citetext{finite set $\set{\str{1000001},\str{1100001}}$}{%
  Although it looks like two strings plucked from the air, the language is not 
  without sense since \str{1000001} represents capital A in the 
  ASCII encoding, while \str{1100001} is lower case a.
  The American Standard Code for Information Interchange, ASCII,
  is a widely used way of encoding character information in computers.  
  The most common modern character encoding is UTF-8, 
  which is a superset of ASCII.}.
\end{example}

\begin{example}
Let $\Sigma=\set{\str{a}, \str{b}}$.
The language consisting of strings where the number of \str{a}'s is twice 
the number of \str{b}'s is
$\lang=\set{\emptystring,\str{aab},\str{aba},\str{baa},
               \str{aaaabb}, \,\ldots}$.  
\end{example}

\begin{example}
Let $\Sigma=\set{\str{a},\, \str{b},\, \str{c}}$.
The language of length-two strings over that alphabet is
$\lang=\Sigma^2=\set{\str{aa},\,\str{ab},\,\str{ba}\,\dots,\,\str{cc}}$.
Over the same alphabet 
this is the language of length-three strings that are sorted in ascending order.
\begin{equation*}
  \set{\str{aaa},\, \str{aab},\, \str{aac},\, \str{abb},\, \str{abc},
    \str{acc},\,\str{bbb},\,\str{bbc},\, \str{bcc},\, \str{ccc}}
\end{equation*}
\end{example}

\begin{definition} \label{def:palindrome}
A
\citetext{\definend{palindrome}}{%
  Sometimes people poke fun at Psycology by labelling it
  the study of college freshmen because so many studies, paraphrased, start with
  ``we put a bunch of college freshmen in a room and lied to them
  about what we were doing and \ldots\@''
  Similarly, sometimes Theoretical Computer Science may seem like
  the study of palindromes.}
is a string that reads the same forwards as backwards.
\end{definition}

Some words from English that are plaindromes are 
`kayak', `noon', and~`racecar'.

\begin{example}  
The language of palindromes over $\Sigma=\set{\str{a},\str{b}}$ is
$\lang=\set{\sigma\in\kleenestar{\Sigma}\suchthat \sigma=\reversal{\sigma}}$.
A few members are \str{abba}, \str{aaabaaa}, and \str{a}.
\end{example}

\begin{example}
Let $\Sigma=\set{\str{a}, \str{b}, \str{c}}$.
Pythagorean triples $\sequence{i,j,k}\in\N^3$ 
are those where $i^2+j^2=k^2$.
A few such triples are $\sequence{3,4,5}$, $\sequence{5,12,13}$,
and $\sequence{8,15,17}$.
One way to describe Pythaorean triples
is with this language.
\begin{align*}
  \lang
   &= \set{\str{a}^i\str{b}^j\str{c}^k\in\kleenestar{\Sigma} 
            \suchthat \text{$i,j,k\in\N$ and $i^2+j^2=k^2$}}  \\
   &=\set{\str{aaabbbbccccc}=\str{a}^3\str{b}^4\str{c}^5,\,
            \str{a}^5\str{b}^{12}\str{c}^{13},\,
            \str{a}^8\str{b}^{15}\str{c}^{17},\,\ldots}
\end{align*}
\end{example}

\begin{example}
  The empty set is a language $\lang=\set{}$, over any alphabet.
  So is the set whose single element is the empty string
  $\hat{\lang}=\set{\emptystring}$.
\end{example}

The term ``language'' comes from that, for instance,
an English language sentence is a string made by concatenating words 
taken from a dictionary for English.
There, $\Sigma$ is the set of words in the dictionary.

Of course, the above definition
allows a `language' to be any set of strings at all, while
in a natural language
you can't form a sentence by just taking any crazy sequence of words; 
an sentence must be constructed according to rules.
We will study sets of rules, grammars, later in this chapter.

%<*def:class>
\begin{definition}
A collection of languages is a \definend{class}.
\end{definition}
%</def:class>

\begin{example}
Fix an alphabet~$\Sigma$.
The collection of all finite languages over
that alphabet is a class.
\end{example}

% \begin{example}
% Another class is the collection of all languages over
% $\B=\kleenestar{\set{\str{0},\str{1}}}$ containing only
% strings with more \str{0}'s than \str{1}'s.
% One member of this class is the finite language
% $\lang_0=\set{\str{0},\str{001},\str{0001}}$.
% Another is $\lang_1=\set{\str{0}^{k+1}\str{1}^k\suchthat k\in\N}$.
% \end{example}

\begin{example}
Let $\TM_e$ be a Turing machines, using the input alphabet
$\Sigma=\set{\str{B},\str{1}}$.
The set of strings
$
\lang_e=\set{\sigma\in\kleenestar{\Sigma}\suchthat
  \text{$\TM_e$ halts on input $\sigma$}}
$  is a language.
The collection of all such languages is a class.
\end{example}

After defining languages, we next consider 
their operations.
Because languages are sets, the operations of union, intersection, etc., work.
However, for instance the union of a 
language over~$\kleenestar{\set{\str{a}}}$ with
a language over~$\kleenestar{\set{\str{b}}}$ 
will be an awkward marriage, a combination of strings of \str{a}'s and 
strings of \str{b}'s.
That is, 
the union of a language over $\Sigma_0$ with 
a language over $\Sigma_1$ is a language over $\Sigma_0\cup\Sigma_1$.
Of course, if the two alphabets are the same then this accounting
nonsense goes away.
A similar thing happens for intersection; see 
\cref{exer:LanguageUnionIntersection}.

Other operations on languages are extensions of operations on strings.
We define the concatenation of languages 
to be the language of concatenations, etc.

%<*def:LangOps>
\begin{definition}[Operations on languages]  \label{def:LangOps}
The
\definend{concatenation of languages $\lang_0\concat\lang_1$ or $\lang_0\lang_1$}
is the set of concatenations,
$\set{\sigma_0\concat\sigma_1\suchthat \text{$\sigma_0\in\lang_0$ and $\sigma_1\in\lang_1$}}$.

For any language, the \definend{power $\lang^k$} 
is the language consisting of the
concatenation of $k$-many strings
$\lang^k=
\set{\sigma_0\concat\cdots\concat\sigma_{k-1}\suchthat \sigma_i\in\lang}$.
In particular, $\lang^1=\lang$ and $\lang^0=\set{\emptystring}$.
The \definend{Kleene star of a language $\kleenestar{\lang}$} is the 
language consisting of the concatenation of any number of strings.
\begin{equation*}
\kleenestar{\lang}=\set{\sigma_0\concat\cdots\concat\sigma_{k-1}\suchthat \text{$k\in\N$ and $\sigma_0,\ldots,\sigma_{k-1}\in\lang$}}
\end{equation*}
This includes the concatenation of $i=0$-many strings, 
so that $\emptystring\in\kleenestar{\lang}$. 

The \definend{reversal $\reversal{\lang}$} of a language~$\lang$ is 
the language of reversals,
$\reversal{\lang}=\set{\reversal{\sigma}\suchthat \sigma\in\lang}$.
\end{definition}
%</def:LangOps>

\begin{example}
Where the language 
is the set of bit strings $\lang=\set{\str{1000001},\str{1100001}}$ 
then the reversal is $\reversal{\lang}=\set{\str{1000001},\str{10000011}}$.
\end{example}

%<*ex:KleeneStar>
\begin{example}
If the language $\lang$ consists of two strings $\set{\str{a},\,\str{bc}}$
then the second power of that language is
$\lang^2=\set{\str{aa},\,\str{abc},\,\str{bca},\,\str{bcbc}}$.
Its Kleene star is this.
\begin{equation*}
  \kleenestar{\lang}=\set{\emptystring,\,\str{a},\,\str{bc},\,\str{aa},\,\str{abc},\,\str{bca},\,\str{bcbc},\,\str{aaa},\,\ldots}  
\end{equation*}
\end{example}
%</ex:KleeneStar>

Earlier we defined 
that the Kleene star of an alphabet~$\Sigma$ is the set of strings
over that alphabet, of any length.
The two definitions agree if 
we take each character in the alphabet as a length-one string. 

A final note about Kleene star.
We could define the operation of
repeatedly choosing strings from the language in two ways.
We could choose a string~$\sigma$ from the
language and then replicate,
getting the set of $\sigma^k$'s,
Or, we could repeat choosing strings from the language, getting
$\sigma_0\concat\sigma_i\concat\cdots\concat\sigma_{i-1}$'s.
The second case is more useful and that's the definition of
$\kleenestar{\lang}$.


\begin{exercises}
\begin{exercise}
Let $\sigma=\str{10110}$ and $\tau=\str{110111}$ be bit strings.
Find each.
\begin{exparts*}
\item $\sigma\concat \tau$
\item $\sigma\concat\tau\concat\sigma$
\item $\reversal{\sigma}$
\item $\sigma^3$
\item $\str{0}^3\concat\sigma$ 
\end{exparts*}
\begin{answer}
\begin{exparts}
\item $\sigma\concat \tau=\str{10110}\concat\str{110111}=\str{10110110111}$.
\item $\sigma\concat\tau\concat\sigma=
   \str{10110}\concat\str{110111}\concat\str{10110}=\str{1011011011110110}$
\item $\reversal{\sigma}=\reversal{\str{10110}}=\str{01101}$
\item $\sigma^3=\str{10110}\concat\str{10110}\concat\str{10110}
               =\str{101101011010110}$
\item $\str{0}^3\concat\sigma=\str{000}\concat\str{10110}=\str{00010110}$ 
\end{exparts}
\end{answer}
\end{exercise}

\begin{exercise}
Let the alphabet be $\Sigma=\set{\str{a},\,\str{b},\,\str{c}}$.
Suppose that $\sigma=\str{ab}$ and $\tau=\str{bca}$.
Find each.
\begin{exparts*}
\item $\sigma\concat\tau$
\item $\sigma^2\concat\tau^2$
\item $\reversal{\sigma}\concat\reversal{\tau}$  
\item $\sigma^3$
\end{exparts*}
\begin{answer}
\begin{exparts}
\item \str{abbca}    
\item \str{ababbcabca}
\item \str{baacb}
\item \str{ababab}
\end{exparts}
\end{answer}
\end{exercise}

\begin{exercise}
Let
$\lang=\set{\sigma\in\kleenestar{\B}\suchthat 
   \text{$\lh{\sigma}=4$ and $\sigma$ starts with \str{0}}}$.
How many elements are in that language?
\begin{answer}
There are $2^4=16$ bit strings of length~$4$ and half of them
start with \str{0}, so the answer is $8$.   
\end{answer}
\end{exercise}

\item Is \str{ba} a suffix?
\item Is \str{bab} a substring?
\item Is \emptystring{} a suffix?
\end{exparts*}

\begin{exparts}

\item Yes.

\end{exparts}
\end{answer}
\end{exercise}

\begin{exercise}
Is the set of real numbers a language?
More precisely, is the set of decimal representations of real numbers
a language?
\begin{answer}
No.
By definition, a language is a set of strings.
By definition, a string is of finite length.
For some real numbers the decimal representation does not make a finite string;
one is $\pi=3.14\ldots$ and another is $1/3=0.33\ldots$
\end{answer}
\end{exercise}

\begin{exercise}
Show that string concatenation is not commutative, that there are 
strings $\sigma$ and $\tau$ so that 
$\sigma\concat\tau\neq\tau\concat\sigma$.
\begin{answer}
One example using $\B$ is $\sigma=\sequence{0}$ and $\tau=\sequence{1}$.
Then $\sigma\concat\tau=\sequence{0,1}$ while
$\tau\concat\sigma=\sequence{1,0}$.  
\end{answer}
\end{exercise}

\begin{exercise}
Recall that a string 
is a palindrome if it equals its own reversal.
\begin{exparts}
\item
Of \str{()()} and \str{)(()},  
which is a palindrome?  Both? Neither?
\item
Show that if $\beta$ is a string then 
$\beta\concat\reversal{\beta}$ is a palindrome.
\item
Do all palindromes have that form?  
\end{exparts}
\begin{answer}
\begin{exparts}
\item
Both
\item
If $\beta=\sequence{b_0,\ldots,b_{i-1}}$ is a string then 
$\beta\concat\reversal{\beta}
  =\sequence{b_0,\ldots,b_{i-1}}\concat\sequence{b_{i-1},\ldots,b_0}$.
This is clearly a palindrome.
\item
There are palindromes not of that form.
One is $\gamma=\str{010}$, which
cannot be decomposed as $\gamma=\beta\concat\reversal{\beta}$.  
\end{exparts}
\end{answer}
\end{exercise}

\begin{exercise}
Is the $k$-th power of a language the same as the language of $k$-th powers?   
\begin{answer}
No.
Let $\lang=\set{\str{a}, \str{b}}$ and let $k=2$.
Then the $k$-th power of the language is
$\lang^k=\set{\str{aa},\,\str{ab},\,\str{ba},\,\str{bb}}$.  
The language of $k$-th powers is
$\set{\sigma^2\suchthat \sigma\in\lang}=\set{\str{aa},\,\str{bb}}$.
So the language of $k$-th powers does not contain \str{ab}, while
$\lang^k$ does.
\end{answer}
\end{exercise}

\begin{exercise}

without parentheses.

prove that concatenation is associative:
$\alpha\concat(\beta\concat\gamma)=(\alpha\concat\beta)\concat\gamma$.
\begin{answer}
Use induction on the length of $\alpha$.
\end{answer}
\end{exercise}

\begin{exercise}
What is the relation between $\lh{\sigma}$, $\lh{\tau}$, 
and $\lh{\sigma\concat\tau}$?
You must justify your answer.
\begin{answer}
Show that the length of a concatenation is the sum of the two lengths:
$\lh{\sigma\concat\tau}=
\lh{\sequence{s_0\ldots,s_{i-1},t_0,\ldots,t_{j-1}}}=i+j=\lh{\sigma}+\lh{\tau}$.
This is routine to prove by induction.
\end{answer}
\end{exercise}

\end{answer}
\end{exercise}

\begin{exercise} \label{exer:LanguageUnionIntersection}
We've observed that the union of a language over~$\Sigma_0$ with a
language over~$\Sigma_1$ is a language over~$\Sigma_0\cup\Sigma_1$.
\begin{exparts}
\item Prove this.
\item Formulate and prove the matching statement for intersection.    
\end{exparts}
\end{exercise}

\begin{exercise}
A language~$\lang$ over some $\Sigma$ is \definend{finite} if
$\lh{\lang}<\infty$, so that there is some
bound $B\in\N$ where $\lh{\sigma}\leq B$ for all $\sigma\in\lang$
\begin{exparts}
\item If the language is finite must the alphabet be finite?
\item Show that the class of finite languages is closed under
  finite union.
  That is, show that if $\lang_0,\ldots \lang_k$ are finite
  languages over a shared alphabet for some $k\in\N$ then their
  union is also finite.
\item Show that the class of finite languages is also closed under
  finite intersection and finite concatenation.
\item Show that the class of finite languages is not closed under
  complementation or Kleene star.  
\end{exparts}
\end{exercise}

\begin{exercise}
Prove that this constructive definition of string replication is equivalent
to the one from \cref{def:StringOps}.
\begin{equation*}
  \sigma^n =
    \begin{cases}
      \emptystring  &\case{if $n=0$}  \\
       \sigma^{n-1}\concat\sigma &\case{if $n>0$}
    \end{cases}
\end{equation*}
Use this definition to produce a Scheme function.  
\end{exercise}

\begin{exercise}
What is the difference between the languages
   $\lang 
      =\set{\sigma\in\kleenestar{\Sigma}\suchthat \sigma=\reversal{\sigma}}$ 
and
 $\hat{\lang} 
  =\set{\sigma\concat\reversal{\sigma}\suchthat \sigma\in\kleenestar{\Sigma}}$?
\end{exercise}

\begin{exercise} \index{Levi's lemma}
(Levi's lemma)
Prove that for all strings $\alpha,\beta,\gamma,\delta\in\kleenestar{\Sigma}$, 
if $\alpha\concat\beta=\gamma\concat\delta$
then there exists a string $\sigma$ such that either
(1)~$\alpha\concat\sigma=\gamma$ 
or (2)~$\alpha=\gamma\concat\sigma$.
That is, there is a string in the middle 
that can be grouped to one side or the other.
\hint{} case~(1) applies when $\lh{\alpha}\leq\lh{\gamma}$.
\end{exercise}


\begin{exercise}
For any language $\lang\subseteq\kleenestar{\Sigma}$ we can form the
set of prefixes.
\begin{equation*} 
  \operatorname{Pref}(\lang)
   =\set{\tau\in\kleenestar{\Sigma}
         \suchthat\text{$\sigma\in\lang$ and $\tau$ is a prefix of $\sigma$}}
\end{equation*} 
Where $\Sigma=\set{\str{a},\str{b}}$ and 
$\lang=\set{\str{abaaba},\str{bba}}$,
find $\operatorname{Pref}(\lang)$.
\end{exercise}

\begin{exercise}
Another way of defining the powers of a language is
$\lang^0=\set{\emptystring}$,
and $\lang^{k+1}=\lang^k\concat\lang$.
Show this is equivalent to the one given in \Cref{def:LangOps}.
\end{exercise}

\begin{exercise}
The operations of languages form an algebraic system.
Assume these languages are over the same alphabet.
\begin{exparts}
\item Show that language union and intersection are commmutative:
  $\lang_0\cup\lang_1=\lang_1\cup\lang_0$ and
  $\lang_0\cap\lang_1=\lang_1\cap\lang_0$.
\item
Show that the language consisting of the empty string
is the identity element with respect to language 
concatenation, so $\lang\concat\lang{\set{\emptystring}}=\lang$
and $\lang{\set{\emptystring}}\concat\lang=\lang$.  
\item
Give an example showing that language concatenation is not commutative,
that there are lanaguages such that 
$\lang_0\concat\lang_1\neq\lang_1\concat\lang_0$.
\item
Show that language concatenation is associative:
$(\lang_0\concat\lang_1)\concat\lang_2
  =\lang_0\concat(\lang_1\concat\lang_2)$.
\item 
Show that $\reversal{(\lang_0\concat\lang_1)}
    =\reversal{\lang_1}\concat\reversal{\lang_0}$.
\item 
Show that concatenation is left distributive over union:
$(\lang_0\cup\lang_1)\concat\lang_3
 =(\lang_0\concat\lang_3)\cup(\lang_2\concat\lang_3)$.
Show that it is also right distributive.
\item
Show that the empty language is an annihilator for 
concatenation: $\emptyset\concat\lang=\lang\concat\emptyset=\emptyset$.
\item
Show that $\kleenestar{\emptyset}=\set{\emptystring}$
and that $\kleenestar{\set{\emptystring}}=\set{\emptystring}$.
\item
Show that $\kleenestar{(\kleenestar{\lang})}=\kleenestar{\lang}$.
\end{exparts}
\end{exercise}
\end{exercises}




\section{Grammars}  \label{sec:Grammars}
Our formal definition of a language is that it is a set of strings.
This allows for any willy-nilly set.
But often 
\citetext{in practice a language is given by rules}{%
  Linguists started formalizing 
  the description of language, including phrase structure, at the start of the 
  1900's.
  Meanwhile, string rewriting rules as formal, abstract systems were introduced 
  and studied by mathematicians including Axel Thue in 1914, 
  Emil Post from the 1920's through the 1940's and Turing in 1936. 
  Noam Chomsky, while teaching linguistics to students of 
  information theory at MIT, combined linguistics and mathematics by 
  taking Thue's formalism as the basis for the description of the syntax of 
  natural language.  \autocite{wiki:Linguistics}}.

Here is an example.
To a native English speaker the noun phrase ``the big red barn'' sounds fine
but \citetext{``the red big barn'' sounds wrong.}{%
  Experts 
  vary on the exact rules but one source gives 
  (article) + number + judgement/attitude + size, length, height + age + 
  color + origin + material + purpose + (noun), so that
  ``big red barn'' is size + color + noun, as is
  Another example is ``little green men.'' 
  This is the Royal Order of Adjectives; 
  see \protect\url{http://english.stackexchange.com/a/1159}.
  A person may object by citing ``big bad wolf'' but it turns out there is
  another, stronger, rule that if there are three words then they have to
  go I-A-O and if there are two words then the order has to
  be I followed by either A or O.
  Thus we have tick tock but not tock tick. 
  Similarly for tic-tac-toe, mishmash, King Kong, or dilly dally.}
That is, sentences in natural languages are constructed 
in patterns.
A grammar is an analysis of the structure of a language, a set of rules.

An artificial language can have a grammar also.
For instance, programming languages have very strict syntax rules, 
and the languages we use to express problems will also follow patterns.

In a phrase, 
\citetext{grammars are the language of languages.}{%
  Aphorism from Matt Swift,
  \protect\url{http://matt.might.net/articles/grammars-bnf-ebnf/}.} 


\subsection{Definition}
We'll first see an example and then the formal definition.

\begin{example}
This is a subset of the rules for for English:
\begin{parenum} 
%<*ex:RulesForEnglish>
\item~a sentence can be made from a noun phrase followed by a verb phrase,
\item~a noun phrase can be made from an article followed by a noun,
\item~a noun phrase can also be made from an article then an adjective then a 
  noun,
\item~a verb phrase can be made with a verb followed by a noun phrase,
\item~one article is `the',
\item~one adjective is `young',
\item~one verb is `caught',
\item~two nouns are `man' and `ball'.
%</ex:RulesForEnglish>
\end{parenum}

This is a convenient notation.

%<*ex:GrammarRulesForEnglish>
\begin{grammar}
\ntrm{sentence}  \produces{} \ntrm{noun phrase} \ntrm{verb phrase} 

\ntrm{noun phrase}  \produces{} \ntrm{article} \ntrm{noun}  

\ntrm{noun phrase}  \produces{} \ntrm{article} \ntrm{adjective} \ntrm{noun} 

\ntrm{verb phrase} \produces{} \ntrm{verb} \ntrm{noun phrase} 

\ntrm{article} \produces{} \trm{the}  

\ntrm{adjective} \produces{} \trm{young}  

\ntrm{verb} \produces{} \trm{caught}  

\ntrm{noun} \produces{} \trm{man} \syntaxor \trm{ball}  
\end{grammar}
%</ex:GrammarRulesForEnglish>
\end{example}

%<*discussion:GrammarVocabulary>
Each line is a \definend{production} or \definend{rewrite rule}.
Each has an arrow, \productionsymbol{}, 
in the middle.
Read it aloud
as ``may produce,'' or ``may expand to,'' or ``may be constructed as.''
On the left of the arrow is a \definend{head} and on the right is 
a \definend{body} or \definend{expansion}.

Sometimes two rules have the same head,
as with 
\synt{noun phrase}. 
There are also two rules for \synt{noun} but 
we have abbreviated by combining 
the bodies using the `\syntaxor'~pipe symbol, read aloud as ``or.''

We make rules using two different kinds of components.
The  kind written in typewriter type, such as
\trm{young},
are what will make up the elements of the alphabet~$\Sigma$ of the language.
They are \definend{terminals}.  
The kind written like `\ntrm{article}', with angle brackets and in italics,
are \definend{nonterminals}.
These act as variables and are
used for intermediate steps in the construction of strings.

The two symbols \productionsymbol{} and \grammarorsymbol are neither 
terminals nor nonterminals.
They are \definend{metacharacters},
part of the syntax of the rules themselves.
%</discussion:GrammarVocabulary>

%<*discussion:DerivationVocabulary>
The rewrite rules govern the \definend{derivation} of strings in the language.
Under the English grammar 
every derivation starts with \ntrm{sentence}.
Along the way, intermediate string contain a mix of nonterminals and 
terminals.
The rules all have a head with a single nonterminal so to derive the 
next string,
pick a nonterminal in the present string and substitute an associated rule body.
\begin{center}
  \begin{tabular}{r@{}l}
  \synt{sentence} &\derives \synt{noun phrase} \synt{verb phrase}  \\
    &\derives \synt{article} \synt{adjective} \synt{noun} \synt{verb phrase}  \\
    &\derives \str{the} \synt{adjective} \synt{noun} \synt{verb phrase}  \\
    &\derives \str{the} \str{young} \synt{noun} \synt{verb phrase}  \\
    &\derives \str{the} \str{young} \str{man} \synt{verb phrase}  \\
    &\derives \str{the} \str{young} \str{man} \synt{verb} \synt{noun phrase}  \\
    &\derives \str{the} \str{young} \str{man} \str{caught} \synt{noun phrase}  \\
    &\derives \str{the} \str{young} \str{man} \str{caught} \synt{article} \synt{noun}  \\
    &\derives \str{the} \str{young} \str{man} \str{caught} \str{the} \synt{noun}  \\
    &\derives \str{the} \str{young} \str{man} \str{caught} \str{the} \str{ball}  
  \end{tabular}
\end{center}
Note that the single line arrow \productionsymbol{} is for  rules 
while the double line \derivessymbol{} is for derivations.
Read \derivessymbol{} aloud as ``derives'' or ``expands to.'' 

The above derivation always substitutes for the leftmost nonterminal, 
so it is a \definend{leftmost derivation}.
However, in general we could substitute for any nonterminal.
%</discussion:DerivationVocabulary>

%<*discussion:DerivationTree>
The \definend{derivation tree}
or \definend{parse tree} is an alternative representation of the
derivation.
(The words 
`terminal' and `nonterminal' come where the components lie in this tree.)
%</discussion:DerivationTree>
\begin{center}
  \includegraphics{languages/asy/parsetree/parsetree000.pdf}
\end{center}

%<*def:Grammar>
\begin{definition}
A \definend{context-free grammar}, which in this book we will just call 
a \definend{grammar},
is a four-tuple $\mathcal{G}=\sequence{\Sigma,N,S,P}$.
First, $\Sigma$ is an alphabet, whose elements are the
\definend{terminal symbols}.
Second, $N$ is a set of \definend{nonterminals} 
or \definend{syntactic categories}.
(We assume that $\Sigma$ and~$N$ are disjoint and that
neither contains metacharacters.)
Third, $S\in N$ is the \definend{start symbol}. 
Fourth, $P$ is a set of \definend{productions} or \definend{rewrite rules}.
\end{definition}

\noindent We will usually not explicitly name the start symbol, but instead
take the convention that it is 
the head of the first rule.
%</def:Grammar>

\begin{example} \label{ex:GrammarOfTerms}
This grammar describes algebraic expressions that involve only addition,
multiplication, and parentheses.
\begin{grammar}
\ntrm{expr} \produces{} \ntrm{term} \trm{+} \ntrm{expr} \syntaxor \ntrm{term}

\ntrm{term} \produces{} \ntrm{term} \trm{*} \ntrm{factor} \syntaxor \ntrm{factor}

\ntrm{factor} \produces \trm{(} \ntrm{expr} \trm{)} \syntaxor 
  \trm{a} \syntaxor \trm{b} \syntaxor \ldots{} \syntaxor \trm{z}
\end{grammar}
Here is a derivation of the string \str{x*(y+z)}. 
\begin{center}
  \begin{tabular}{r@{}l}
    \ntrm{expr}
    &\derives\ntrm{term}              \\
    &\derives\ntrm{term} \trm{*} \ntrm{factor} \\           
    &\derives\ntrm{factor} \trm{*} \ntrm{factor}  \\
    &\derives\trm{x} \trm{*} \ntrm{factor}       \\
    &\derives\trm{x} \trm{*} \trm{(} \ntrm{expr} \trm{)}  \\  
    &\derives\trm{x} \trm{*} \trm{(} \ntrm{term} \trm{+} \ntrm{expr} \trm{)}  \\  
    &\derives\trm{x} \trm{*} \trm{(} \ntrm{term} \trm{+} \ntrm{term} \trm{)}  \\
    &\derives\trm{x} \trm{*} \trm{(} \ntrm{factor} \trm{+} \ntrm{term} \trm{)} \\ 
    &\derives\trm{x} \trm{*} \trm{(} \ntrm{factor} \trm{+} \ntrm{factor} \trm{)} \\ 
    &\derives\trm{x} \trm{*} \trm{(} \trm{y} \trm{+} \ntrm{factor} \trm{)}  \\
    &\derives\trm{x} \trm{*} \trm{(} \trm{y} \trm{+} \trm{z} \trm{)} 
  \end{tabular} 
  \qquad
  \vcenteredhbox{\includegraphics{languages/asy/parsetree/parsetree004.pdf}}
\end{center}
\end{example}

In that example the rules for \ntrm{expr} and \ntrm{term} are recursive.
This doesn't mean that we get stuck in infinite regress.
The question is not whether you could perversely 
keep expanding \synt{expr};
the question is whether, given a string such as \str{x*(y+z)}, 
you can find a terminating derivation. 

In examples and exercises we often use small grammars whose 
terminals and nonterminals do not have any particular meaning.
For this, we move from the verbose notation like
`\ntrm{sentence} \produces{} \ntrm{noun phrase} \ntrm{verb phrase}'
used above to 
writing single letters, with nonterminals in upper case and terminals
in lower case.

\begin{example}  \label{ex:GrammarOfanbn}
This two-rule grammar has one nonterminal, S.
\begin{grammar}
  S \produces{} \trm{a}S\trm{b} \syntaxor \emptystring
\end{grammar}
Here is a derivation of
the string $\str{a}^2\str{b}^2$.
\begin{center}
  S
  \derives\trm{a}S\trm{b}
  \derives\trm{aa}S\trm{bb}            
  \derives\trm{aa}\emptystring\trm{bb}
  \derives\trm{aabb}  
\end{center}
Similarly, 
  S
  \derives\trm{a}S\trm{b}
  \derives\trm{aa}S\trm{bb}            
  \derives\trm{aaa}S\trm{bbb}            
  \derives\trm{aaa}\emptystring\trm{bbb}
  \derives\trm{aaabbb}  
is a derivation of $\str{a}^3\str{b}^3$.
For this grammar, derivable strings have the form
$\str{a}^n\str{b}^n$ for $n\in\N$.
\end{example}

We next give a complete description of how the production rules
govern the derivations.
Each rule has the form \mbox{`head\produces{}body'}, where
the head consists of a single nonterminal.
The body is a sequence of terminals and nonterminals,
(such a string is a \definend{sentential form}).
Each step of a derivation has the form below,
where $\tau_0$ and $\tau_1$ are sequences of terminals and non-terminals.
\begin{center}
  $\tau_0\concat\text{head}\concat\tau_1$
  \quad\derives\quad
  $\tau_0\concat\text{body}\concat\tau_1$
\end{center}
That is, if there is a match for the rule's head
then we can replace it with the body.

Where $\sigma_0,\sigma_1$ are sequences of terminals and nonterminals,
if they are related by a sequence of derivation steps then
we may write $\sigma_0\kleenestar{\derivessymbol}\;\sigma_1$.
If we have a derivation $\sigma_0\kleenestar{\derivessymbol}\;\sigma_1$ that
starts with the start symbol $\sigma_0=S$ and finishes with 
a string of terminals $\sigma_1\in\kleenestar{\Sigma}$ then we say
that $\sigma_1$ \definend{has a derivation} from the grammar.\footnote{%
  This definition of a rule suffices for our purposes but it is not the
  most general definition.
  % as with \str{a}S\str{b}\produces\str{c}.
  % With that, as one step in a derivation we could get
  % \str{bb}T\str{a}S\str{ba}\derives\str{bb}T\str{ca}.
  % This definition allows rule heads of the form
  One more general definition allows heads of the form
  $\sigma_0X\sigma_1$, where $\sigma_0$ and~$\sigma_1$ are 
  strings of terminals.
  % In that ruls
  % that provide a context
  % for the nonterminal~$S$, and substitutions for $S$ are only allowed in context.
  (The $\sigma_i$'s can be empty.)
  \protect\label{ex:anbncnGrammar}
  For example, consider
  \citetext{this grammar}{%
  Taken from \protect\url{https://en.wikipedia.org/wiki/Formal_grammar}.}:  
  (i)~S\produces{} \str{a}BS\str{c} | \str{abc},
  (ii)~B\str{a}\produces{}\str{a}B,
  (iii)~B\str{b}\produces{}\str{bb}.
  In the derivation
  S 
  \derives\str{a}BS\str{c}
  \derives\str{a}B\str{abcc}
  \derives\str{aa}B\str{bcc}
  \derives\str{aabbcc}
  the third step uses~(ii)
  and the fourth step uses~(iii).
  Grammars with heads of the form
  $\sigma_0X\sigma_1$  are \protect\definend{context sensitive}
  because we can only
  substitute for~X in the context of $\sigma_0$ and~$\sigma_1$.
  These grammars describe more languages than the context free ones that
  we are using.
  But our definition satisfies our needs and is
  the class of grammars that appear most often in practice, 
  because it is a good balance of convenience and power. 
  } 

This description is reminiscient of the one on 
page~\pageref{text:DescriptionOfTMAction}
detailing how 
a Turing machine's instructions determine the evolution of the
sequence of configurations that is a computation.
That is, production rules are like a program, shaping a 
derivation.
However, one difference is that 
we have defined Turing machines as deterministic, so that from a given
input string there is a determined sequence of configurations.
Here, from a given start symbol a derivation can branch out to 
go to many different ending strings. % ,

\begin{remark}  \label{rem:AmbiguousGrammar}
%<*rem:AmbiguousGrammar>
An important problem with grammars relates to 
the following bit of C language-like code that shows nested
\codeinline{if} statements. 
\begin{lstlisting}
  if ... then ... if ... then ... else ...
\end{lstlisting}
This is a \definend{dangling else}.
As written, we cannot tell whether the \codeinline{else} is associated
with the first \codeinline{if} or the second; as illustrated below.
\begin{center}
  \begin{minipage}{0.4\linewidth}
    \begin{lstlisting}
 if ... 
 then ...
     if ...
     then ... 
 else ...
\end{lstlisting}
  \end{minipage}
  \quad
  \begin{minipage}{0.4\linewidth}
    \begin{lstlisting}
 if ... 
 then ...
     if ...
     then ... 
     else ...
\end{lstlisting}
  \end{minipage}
\end{center}
An \definend{ambiguous grammar}
is one where some strings
have two different leftmost derivations. 
%</rem:AmbiguousGrammar>

This grammar for elementary algebra expressions
\begin{grammar}
\ntrm{expr} \produces{} \ntrm{expr} \trm{+} \ntrm{expr}
        \othersyntax  \ntrm{expr} \trm{*} \ntrm{expr>}
        \othersyntax  \trm{(} \ntrm{expr} \trm{)} \
               \syntaxor  \trm{a}  \syntaxor  \trm{b}  \syntaxor \ldots{} 
               \trm{z}
\end{grammar}
is ambiguous because \str{a+b*c} has two
leftmost derivations.
\begin{center}
\hspace{1em}\begin{tabular}{l}
  \ntrm{expr}\derives\ntrm{expr}\trm{+}\ntrm{expr}
  \derives\trm{a} \trm{+} \ntrm{expr}                 \\ \quad
  \derives\trm{a} \trm{+} \ntrm{expr} \trm{*} \ntrm{expr}          
  \derives\trm{a} \trm{+} \trm{b} \trm{*} \ntrm{expr}          
  \derives\trm{a} \trm{+} \trm{b} \trm{*} \trm{c}          
\end{tabular}        \\[1ex]
\hspace{1em}\begin{tabular}{l}
  \ntrm{expr}\derives\ntrm{expr} \trm{*} \ntrm{expr}
  \derives\ntrm{expr} \trm{+} \ntrm{expr} \trm{*} \ntrm{expr}    \\ \quad 
  \derives\trm{a} \trm{+} \ntrm{expr} \trm{*} \ntrm{expr}  
  \derives\trm{a} \trm{+} \trm{b} \trm{*} \ntrm{expr}  
  \derives\trm{a} \trm{+} \trm{b} \trm{*} \trm{c}          
\end{tabular}
\end{center}
The two give different parse trees.
\begin{center}
  \includegraphics{languages/asy/parsetree/parsetree002.pdf}
  \hspace{2.5em}
  \includegraphics{languages/asy/parsetree/parsetree003.pdf}
\end{center}
The problem 
comes if we substitute $1$ for~\str{a}, and $2$ for~\str{b},
and $3$ for~\str{c}.
Using the left tree,
we first multiply $2$ by~$3$ and then add~$1$ to get a total of~$7$.
But using the right tree we get $1$ plus~$2$, which we multiply by~$3$,
giving~$9$.

In contrast, this grammar has the same language but is unambiguous.
\begin{grammar}
\ntrm{expr} \produces{} \ntrm{expr} \trm{+} \ntrm{term}  
       \othersyntax  \ntrm{term}

\ntrm{term} \produces{} \ntrm{term} \trm{*} \ntrm{factor} 
         \othersyntax  \ntrm{factor}

\ntrm{factor} \produces{} \trm{(} \ntrm{expr} \trm{)}    
        \othersyntax  \trm{a}  \syntaxor  \trm{b}  \syntaxor \ldots{} 
         \syntaxor \trm{z}
\end{grammar}
See \Cref{exer:AmbiguousGrammar}.
\end{remark}


%<*def:LanguageOfGrammar>
\begin{definition}
The \definend{language derived from a grammar} 
is the set of strings of terminals having derivations
beginning with the start symbol.
\end{definition}
%</def:LanguageOfGrammar>

\begin{example} \label{ex:grammarForNaturals}
This grammar's language is the set of strings representing natural numbers.
\begin{grammar}
  \ntrm{natural} \produces{} \ntrm{digit} 
        \syntaxor \ntrm{digit}\ntrm{natural}   
  
  \ntrm{digit} \produces{} \trm{0} \syntaxor \ldots{} \syntaxor \trm{9}
\end{grammar}
This is a derivation for the string \str{321}, along with its
parse tree.
\begin{center}
  \begin{tabular}{r@{}l}
    \ntrm{natural}
       &\derives\ntrm{digit}\ntrm{natural}     \\ 
       &\derives\trm{3}\ntrm{natural}           \\
       &\derives\trm{3}\ntrm{digit}\ntrm{natural}    \\  
       &\derives\trm{32}\ntrm{natural}          \\
       &\derives\trm{32}\ntrm{digit}            \\
       &\derives\trm{321}
  \end{tabular}
  \qquad     
  \vcenteredhbox{\includegraphics{languages/asy/parsetree/parsetree001.pdf}}
\end{center}
% We can also derive \str{0321}, \str{00321}, etc., so this grammar is
% perhaps too simple-minded for practice.   
\end{example}

This grammar's language is the set of strings representing

  \ntrm{natural} \produces{} $\emptystring$  
        \syntaxor \trm{1}\ntrm{natural}

\begin{example}
Any finite language is derived from a grammar.
This one gives the language of all length~$2$ bit strings, using the brute 
force approach of just listing all the member strings.
\begin{grammar}
  S \produces{} 
   \trm{00} \syntaxor \trm{01} \syntaxor \trm{10} \syntaxor \trm{11}
\end{grammar}
This grammar gives the length~$3$ bit strings, using a somewhat more 
refined approach than force.
\begin{grammar}
  A \produces{} \trm{0}B \syntaxor \trm{1}B

  B \produces{} \trm{0}C \syntaxor \trm{1}C

  C \produces{} \trm{0} | \trm{1}
\end{grammar}
\end{example}

\begin{example}
For this grammar 
\begin{grammar}
  S \produces{} \trm{a}S\trm{b} \syntaxor T \syntaxor U
 
  T \produces{} \trm{a}S \syntaxor \trm{a}

  U \produces{} S\trm{b} \syntaxor \trm{b} 
\end{grammar}
the generated language is
$\lang{L}=\set{\str{a}^i\str{b}^j\in\kleenestar{\set{\str{a},\str{b}}} \suchthat\text{$i\neq0$ or $j\neq 0$}}$.
% https://cs.stackexchange.com/a/75423/67754
One way to see that is to replace 
T and U by their
expansions to get this.
\begin{grammar}
S \produces{} \trm{a}S\trm{b} \syntaxor \trm{a}S 
         \syntaxor \trm{a} \syntaxor S\trm{b} \syntaxor \trm{b}
\end{grammar}

This is the first example where the generated language is not clear
so we will do a formal verification. 
We will show mutual containment, that the generated language is a 
subset of~$\lang$ and that it is also a superset.
The rule that eliminates T and~U 
shows that any derivation step 
$\tau_0\concat\text{head}\concat\tau_1$
  \derives~$\tau_0\concat\text{body}\concat\tau_1$
only adds \trm{a}'s on the left and 
\trm{b}'s on the right, so every string in the language has the form
$\str{a}^i\str{b}^j$.
That same rule shows that in any terminating derivation S 
must eventually be replaced by either \trm{a} or \trm{b}.
Together these two give that the generated language is a subset of~$\lang$.

For containment the other way, we will prove that every $\sigma\in\lang$ 
has a derivation.
We will use induction on the length $\lh{\sigma}$.
The smallest case, the base case, is $\lh{\sigma}=1$
by the definition of~$\lang$.
In this case either $\sigma=\str{a}$ or~$\sigma=\str{b}$,
each of which obviously has a derivation.

For the inductive step, 
suppose that every string from $\lang$ of length $k=1$, \ldots, $k=n$ 
has a derivation (where $n\geq 1$)
and let $\sigma$ have length $n+1$.
Write $\sigma =\str{a}^i\str{b}^j$.
There are three cases: either $i>1$, or $j>1$, or~$i=j=1$.
If $i>1$ then $\hat{\sigma} =\str{a}^{i-1}\str{b}^{j}$ is a string of
length~$n$, so by the inductive hypothesis it has a derivation
S\derives$\cdots$\derives{}~$\hat{\sigma}$.
Prefixing that derivation with
a S\derives{}\trm{a}S step will put an
addional \str{a} on the left,
as required: 
S\derives\trm{a}S\derives$\cdots$\derives{}~$\sigma$.
The $j>1$~case is similar,
and the case of $\sigma=\str{a}^1\str{b}^1$ is easy.
\end{example}

\section{Graphs}
This chapter's goal is to describe how we state problems and 
solutions.
As the \citetext{blogfeed for Theoretical Computer Science}{%
\autocite{blog:TOC}} \url{http://cstheory-feed.org/} shows,
people working in this field often state their results in terms of 
graphs, so we will now review the basics of Graph Theory.

\subsection{Definition}
Graphs are so natural in this area that we have already used them. 
Here are two examples.
\begin{center}
  \vcenteredhbox{\includegraphics{prologue/asy/circlediagram/circlediagram00.pdf}}
  \hspace*{3em}
  \vcenteredhbox{\includegraphics{languages/asy/parsetree/parsetree004.pdf}}
\end{center}
Both examples have vertices, the circles and the symbols,
that are connected by edges.
The edges represent a relationship between the vertices.

%<*def:Graph>
\begin{definition} \label{def:SimpleGraph}
A \definend{simple graph} is an ordered pair
$\mathcal{G}=\sequence{\mathcal{V},\mathcal{E}}$ where
$\mathcal{V}$ is a set of
\definend{vertices} or \definend{nodes}
and $\mathcal{E}$ is a set of \definend{edges}.
Each edge is a set of two distinct vertices.    
\end{definition}
%</def:Graph>

\begin{example} \label{ex:SimpleGraphFiveVert}
This simple graph has five vertices $\mathcal{V}=\set{v_0,\ldots,v_4}$ 
and eight edges.
\begin{center}
  \vcenteredhbox{\includegraphics{languages/asy/graphs/graphs00.pdf}}
  \qquad
  $\mathcal{E}=\set{\set{v_0,v_1},\set{v_0,v_2},\,\ldots\,\set{v_3,v_4}}$
\end{center}
The most important thing to note is that the graph is not its picture.
A graph is about how the vertices are connected.
Both of the pictures below
show the same graph as above
because they show the same vertices and the same connections 
between them.
\begin{fig}[fig:DrawTwoWays]{The same graph, laid out in two additional ways.}
  \vcenteredhbox{\includegraphics{languages/asy/graphs/graphs01.pdf}}
  \hspace*{3em}
  \vcenteredhbox{\includegraphics{languages/asy/graphs/graphs02.pdf}}
\end{fig}
\end{example}

%<*discussion:EdgeNotation>
Instead of the set $e=\set{v,\hat{v}}$ we often use a string $e=v\hat{v}$. 
Since sets are unordered we could also write $e=\hat{v}v$.
%</discussion:EdgeNotation>

\margingraphic{0.18\textwidth}{languages/pix/edgelord.png}{\label{fig:xkcdedgelord}\href{https://xkcd.com/2036/}{Courtesy \url{xkcd.com}}}
%<*discussion:GraphVariants>
There are many variations of \cref{def:SimpleGraph}.
One allows a vertex to  
connect to itself, forming a \definend{loop}.
% (We might define this by extending \cref{def:SimpleGraph} to also allow
% an edge to be a one-element set.
% In the rest of this section, instead of focusing on the formal details
% we will keep the discussion at an intuitive level.)
Another is a \definend{multigraph},
which allows two vertices to have more than one edge between them. 
Another is a \definend{directed graph} or
\definend{digraph}, where 
edges have a direction, 
as in a road map that includes one-way streets.
% In a digraph, if an edge is directed from $v$ to $\hat{v}$ then we 
% can write it as $v\hat{v}$ but not in the other order.
% The Turing machine at the start of this section is a digraph
% and also has loops.
Still another extension is
a \definend{weighted graph}, which gives
each edge a real number \definend{weight}, perhaps signifying the distance
or the cost in money or in time to traverse that edge.
%</discussion:GraphVariants>

%<*def:Subgraph>
\begin{definition}
Where $\mathcal{G}=\sequence{\mathcal{V},\mathcal{E}}$ is a graph,
a \definend{subgraph}
$\hat{\mathcal{G}}=\sequence{\hat{\mathcal{V}},\hat{\mathcal{E}}}$
satisfies
$\hat{\mathcal{V}}\subseteq\mathcal{V}$ and
$\hat{\mathcal{E}}\subseteq\mathcal{E}$.
A subgraph with every possible edge, with the property that
for every $e=v_iv_j\in\mathcal{E}$ such that $v_i,v_j\in\hat{\mathcal{V}}$
then $e\in\hat{\mathcal{E}}$, is an \definend{induced subgraph}.
\end{definition}
%</def:Subgraph>

\begin{example}
For the graph from the prior example, the induced subgraph involving
vertices $\hat{\mathcal{V}}=\set{v_1,v_2,v_3}$ is a triangle.
\end{example}





\subsection{Traversal}
We often want to describe problems that involve
moving through a graph, from vertex to vertex.

%<*def:Adjacent>
\begin{definition}
Two graph edges are \definend{adjacent}
if they share a vertex, so that the first edge is $uv$ and
the second is~$vw$.
A \definend{walk} is a sequence of adjacent edges 
$\sequence{v_0v_1,\,v_1v_2,\,\ldots,\,v_{n-1}v_n}$.
Its \definend{length} is the number of edges, $n$.
% Its \definend{initial vertex} is~$v_0$ and its \definend{final vertex} is~$v_n$.
If the initial vertex~$v_0$ equals the final vertex~$v_n$ then it is a 
\definend{closed} walk, otherwise it is \definend{open}.

If no edge occurs twice then it is a \definend{trail}.
If a trail's vertices are distinct, 
except possibly that the initial vertex equals the final vertex,
then it is a \definend{path}.
A closed path that has at least one edge is a \definend{cycle}. 
A \definend{circuit} is a closed walk that either contains all of the edges,
in which case it is an \definend{Euler circuit}, or all of the vertices,
making it a \definend{Hamiltonian circuit}.

A graph is \definend{connected} if there is a path between any two vertices.
\end{definition}
%</def:Adjacent>

\subsection{Graph representation}
A common way to represent a graph in a computer
is with a matrix.
This example represents \cref{ex:SimpleGraphFiveVert}'s graph:
it has a~$1$ in the $i,j$~entry if the graph has an edge from $v_i$ to~$v_j$
and a~$0$ otherwise.
\begin{equation*}
  \mathcal{M}(\mathcal{G})=
  \begin{blockarray}{*{6}{c}}
           &v_0 &v_1 &v_2 &v_3 &v_4    \\
    \begin{block}{c(*{5}{c})}
      v_0  &0   &1   &1  &0   &0  \\
      v_1  &1   &0   &1  &1   &1  \\
      v_2  &1   &1   &0  &1   &1  \\
      v_3  &0   &1   &1  &0   &1  \\
      v_4  &0   &1   &1  &1   &0  \\
    \end{block}
  \end{blockarray}
  \tag{$*$}
\end{equation*}
% \Cref{ex:SimpleGraphFiveVert} make the point that a graph 
% is about the connections between vertices, not about how it is drawn. 
% This representation
% underlines that because it is, after all, not drawn.

%<*def:AdjacencyMatrix>
\begin{definition}
For a graph~$\mathcal{G}$, the
\definend{adjacency matrix} $\mathcal{M}(\mathcal{G})$
representing the graph has $i,j$ entries equal to
the number of edges from $v_i$ to~$v_j$.
\end{definition}
%</def:AdjacencyMatrix>

This covers the graph variants listed earlier.
For instance, as in ($*$), a simple graph has only $0$ and~$1$ entries.
A loop makes a diagonal entry be nonzero.
And if there are multiple edges from one vertex to another then
the associated entry will be larger than~$1$.

%<*lem:MatrixPowersAdjacencyMatrix>
\begin{lemma} \label{lem:MatPowerPatahsLengthN}
Let the matrix $\mathcal{M}(\mathcal{G})$ represent
the graph~$\mathcal{G}$.
Then in its matrix multiplicative $n$-th power
the $i,j$ entry is the number of paths of length~$n$
from vertex~$v_i$ to vertex~$v_j$.
\end{lemma}
%</lem:MatrixPowersAdjacencyMatrix>

\begin{proof}
\Cref{exer:MatPowerPatahsLengthN}.
\end{proof}

\begin{definition}
A \definend{$k$-coloring} of a graph, for $k\in\N$, is a partition of

The final  
topic is to decide when two graphs are essentially identical.
Consider these two.

  \hspace*{3em}

They have the same number of vertices and the same number of edges.
Further, on the right as well as on the left
there are two classes of vertices where all the vertices in the first class
connect to all the vertices in the second class (on the left the two classes 
are the top and bottom rows while on the right they
are $\set{w_0,w_2,w_4}$ and $\set{w_1,w_3,w_5}$).
A person may suspect that as in \cref{fig:DrawTwoWays} these are two
ways to draw the same graph, with the vertex names changed for further 
obfuscation.

That's true:~if we associate
the vertices in this way
\begin{center}  \small
  \begin{tabular}{r|cccccc}
    \tabulartext{Vertex on left} &$v_0$ &$v_1$ &$v_2$ &$v_3$ &$v_4$ &$v_5$ \\
    \cline{2-7}
    \tabulartext{Vertex on right} &$w_0$ &$w_2$ &$w_4$ &$w_1$ &$w_3$ &$w_5$ \\
  \end{tabular}
\end{center}
then as a consequence the edges associate also.
\begin{center}  \small
  \begin{tabular}{@{}r|cccccc@{}}
    \tabulartext{Edge on left} 
      &$\set{v_0,v_3}$ &$\set{v_0,v_4}$ &$\set{v_0,v_5}$
      &$\set{v_1,v_3}$ &$\set{v_1,v_4}$ &$\set{v_1,v_5}$  \\
    \cline{2-7}
    \tabulartext{Edge on right} 
      &$\set{w_0,w_1}$ &$\set{w_0,w_3}$ &$\set{w_0,w_5}$
      &$\set{w_2,w_1}$ &$\set{w_2,w_3}$ &$\set{w_2,w_5}$  \\
  \end{tabular}                               \\[1ex]
  \hspace*{-8em}
  \begin{tabular}{r|ccc}
    \tabulartext{Edge on left (cont)} 
      &$\set{v_2,v_3}$ &$\set{v_2,v_4}$ &$\set{v_2,v_5}$  \\
    \cline{2-4}
    \tabulartext{Edge on right} 
      &$\set{w_2,w_1}$ &$\set{w_2,w_3}$ &$\set{w_2,w_5}$  \\
  \end{tabular}
\end{center}
% For instance, for the first edge on the left $\set{v_0,v_3}$, we are associating
% $v_0\leftrightarrow w_0$ and~$v_3\leftrightarrow w_1$ 
% so we look on the right for an edge
% $\set{w_0,w_1}$ and sure enough, it is there.

%<*def:GraphIsomorphism>
\begin{definition}
Two graphs $\mathcal{G}$ and $\hat{\mathcal{G}}$ are \definend{isomorphic}
if there is a one-to-one and onto map $\map{f}{\mathcal{V}}{\hat{\mathcal{V}}}$
such that $\mathcal{G}$ has an edge $\set{v_i,v_j}\in\mathcal{E}$
if and only if $\hat{\mathcal{G}}$ has the associated edge 
$\set{f(v_i),f(v_j)}\in\hat{\mathcal{E}}$.
\end{definition}
%</def:GraphIsomorphism>

To show graphs are isomorphic the most natural thing is to produce the map~$f$.
Examples are in the exercises.

%<*discussion:GraphIsomorphism>
The \definend{degree of a vertex} is the total number of edges touching
on that vertex (that is, where that vertex is an element of the set
that defines the edge) except that 
a loop from the vertex to itself counts as two.
The \definend{degree sequence} is the non-increasing sequence
of its vertex degrees.
%</discussion:GraphIsomorphism>
Thus, the graph in \cref{ex:CommitteeColoring} has degree sequence
$\sequence{3,2,1,1,1}$.

\Cref{exer:DegreeSequenceMustMatch} shows that if graphs are isomorphic then
associated vertices have the same degree.
Thus graphs with different degree sequences are not isomorphic.
And, if the the degree sequences are equal then they
help us construct an isomorphisms, if there is one.
(There are graphs with the same degree sequence that are not isomorphic.)
Examples of this also are in the exercises.

\section{Problems} 
We have already discussed some problems, notably the \HP{}
and ones related to it.
Before going further
we will pause to discuss what we mean by a problem,
and by a solution.
We will discuss this on an intuitive level only\Dash indeed, 
some of these things have no widely accepted
precise definition, but the discussion is nonetheless useful.



\subsection{Problems, algorithms, and programs}
A problem is a job, a task that we want done.
Because this is the Theory of Computing we are most interested in
problems that can be done with 
a mechanism.

Often a problem encompasses a family of tasks.
Consider the problem of taking as input a weighted graph
and two vertices, and returning as output the path between them that is
of least cost.
Contrast that with the problem of taking as input a road map of the
United States and returning the path between Los Angeles and New York that
is cheapest. 
Seeing a problem like the second one would be unusual
since it is a special case of the first, which 
feels more natural.\footnote{There are interesting problems
  that are only one task.
  One is the problem of computing the digits of $\pi$.
  We could also view theo Halting Problem as a single task,
  that of finding a single Turing machine that inputs~$e\in\N$ 
  and determines whether $\TMfcn_e(e)\converges$.}

An algorithm describes at a high level a way to solve the problem
that is effective,
that is
computable on a mechanism.\footnote{% https://cs.stackexchange.com/a/31953
  \citetext{There is no widely-accepted formal definition of `algorithm'}{%
    This discussion derives from  \autocite{pseudonym}.}.
  Whatever it is, it sits between `mathematical function'
  and `computer program'.

  For example, `sort' is a function mapping sequences of orderable items
  to sequences of orderable items,
  which takes each sequence to the ordered version of itself.
  This function could be implemented using different algorithms,
  including merge sort, heap sort, etc.\@
  Each algorithm, in turn, could be implemented using different programs.
  So the best handle that we have is that an `algorithm' is
  an equivalence class of programs (i.e., Turing machines),
  where two programs are equivalent
  if they do essentially the same thing.
  Any two programs which implement the same algorithm must compute the same
  function, but the converse is not true.
  Similarly, there is an equivalence class between algorithms, where two
  algorithms are equivalent if they compute the same mathematical function.
  
  The hard part in all this is trying to capture what we mean by
  ``essentially the same thing.''
  There are some things that we obviously should include.
  For example, fix a program that does a merge sort on sequences of strings
  and that uses \str{x} for a variable but not \str{y}.
  The program that you get by simultaneously replacing all the
  \str{x}'s with \str{y}'s is essentially the same.
  And, there are some things that we may want not to include; an
  operating system kernel is a single program but implements many
  algorithms.
  But in any event, giving a completely satisfactory
  definition of `algorithm' is an open problem.}
An algorithm is not an implementation,
although it should be described in a way that is 
detailed enough that implementing it is
routine for an experienced professional.
(Often we look for an algorithm to be efficient in its use of time or space
or some other resource.
But an algorithm that is poor is still an algorithm.)

A program is an implementation of an algorithm,
typically expressed in a formal computer language.
It is designed to be executed on a particular computing platform.

One subtle point about algorithms 
is that while they are abstractions, they nonetheless are based on
an underlying computing model.
An algorithm that is based on a Turing machine model
for adding one to an input 
might be to move right until the head reaches a blank, then add a \str{1},
and then move back to the left.
Of course, an algorithm to do the same task on a model that is like
a desktop computer would be very different; those
computers have adding one as a primitive operation.

\margingraphic*{0.20\textwidth}{languages/pix/sah.jpg}
A very different computing model that an algorithm could target
is distributed computation.
For example, the SETI@home project is a scientific experiment, based at the
University of California Berkeley, that uses Internet-connected
computers in the search for extraterrestrial intelligence.
Many volunteer users participate.
Each installs on their computer a program that only runs when the CPU
is idle, which 
downloads and analyzes blocks of data from a radio telescope.
This is massively parallel computation and many blocks get
analyzed simultaneously.\footnote{%
  You can easily run it on your computer.
  It is Free;
  visit \protect\url{http://setiathome.berkeley.edu/}.
  For more, see also \url{https://en.wikipedia.org/wiki/List_of_distributed_computing_projects}.}
Obviously, an algorithm aimed at this model could be very different than
one aimed at a serial computer.

\subsection{Statements}
Strictly speaking,
a complete description of a problem should include the form of the
inputs and outputs.
For instance, if we state a problem as, `to input a sequence of natural numbers
and return their product'
then we have not fully specified the input.
We might take the input to be 
a list of strings representing decimal numbers
or
we might take it as a single bit string
\citetext{where each number $n$ is represented with $n$-many \str{1}'s
and numbers are separated by \str{0}'s}{%
  An experienced programmer may have the reaction that unary is rediculous
  because it is wasteful\Dash
  if the input
  is one thousand then this representation would require the 
  machine to take a thousand steps just to read the input, 
  while in binary notation the input is $\str{1111101000}$, which 
  takes only ten steps to read.
  But we have found representing the number~$n$ with $n$-many strokes
  suited our purpose in the past, when we simply wanted to illustrate the
  Turing machines that we had introduced.
  Besides, at this moment we are not concerned with efficiency but 
  instead with what can be computed in principle.},
so that the sequence $\sequence{2,1,3}$ becomes \str{11010111}.
Or we could specify something more exotic
such as putting the sequence numbers as 
powers of primes, so that~$\sequence{2,1,3}$ becomes 
the single number $2^23^15^3=1500$ and then we represent that in a string of
decimal digits.

This matters because the form of the input and output can change the algorithm
or our analysis of its behavior.
Consider the problem of determining whether an input number is
divisible by four.
A number in binary is divisible by four if and only if the final two bits
are \str{00}, so this input form
\citetext{makes the job trivial}{Decimal is not much harder since
  a decimal number is divisible by four if and only if the final two digits
  are in the set $\set{\str{00},\str{04}, \,\ldots\,\str{96}}$.}.

Nevertheless, most of the time for our purposes specifying the input in great
detail is going into the weeds.
At this time we only want to know in principle whether we can 
solve the problems with mechanical computation and
by Church's Thesis that is not 
affected by the exact form of the input and output representations.
Consequently, we will usually leave
\citetext{exact specifications for the programmer}{%
  \autocite{article:MarsOrbiter}},
and instead typically take the input
to be bit strings since
this is convenient, straightforward, and widely used in practice.
(In the book's last part we will be more concerned with algorithm performance
but even there we will downplay the details to the extent possible.)



\subsection{Problem types}
So the basic work is that we state problems and look for
algorithms.
For instance, the problem statement ``Given a graph whose edges are
labeled with costs, and two vertices, produce a path between those two
of least cost'' asks for an algorithm to go from the specified inputs
to the output.
As we do that we notice that the problems that come up in Theory of Computation
fall into a number of types.

One problem type that we have already seen
is a \definend{function problem}.
This asks that our algorithm have a single output for each input. 
Two examples are: 
``Given a natural number, return its prime factorization''
and
``Given two natural numbers, return their greatest common divisor.'' 

A second type 
is the \definend{optimization problem}, which look for the 
best solution according to some metric.
The shortest path problem described above is of this type.

Another type is a \definend{search problem}.
Here we are looking for an instance of a solution and while there may be many
instances in the search space, we stop when we have found any one.
An example is the problem
``Given a weighted graph, and two vertices, and a bound $B\in\N$,
find a path between the vertices that costs less than the bound.'' 
For instance, we can look for a flight between New York and
San Francisco that costs less than \$800
and if we find any one then we stop.

% \begin{TODO}
% Another example is a $k$-coloring
% \end{TODO}

A \definend{decision problem} has an answer of `Yes' or `No'.
The first problem we saw, the 
\protect\textit{Entscheidungsproblem},
is a decision problem.\footnote{%
  Recall that the word is German for ``decision problem''
  and that it asks for an algorithm to decide, given a mathematical statement,
  whether the statement is true or false.}
Another is
`Given a natural number, decide if it is prime'.
We have seen many more decision problems 
in conjunction with the \HP{}, such as the problem of
determining, given an index~$e$, whether $\TMfcn_e$ will for any input
output a seven.
\citetext{In short, Decision:~Is there a needle in the haystack? Search:~Find it.}{%
  \autocite{blog:ComputationalComplexityDecisionVsSearch}}

Although a decision problem calls for producing a function of a kind,
a Boolean function,
they have a different feel so we consider them separately.

This problem type may be less familiar than
other types, 
perhaps because they don't appear much in programming classes.
However we will work with them often.
One reason is that in the next chapter we will 
study machines that cannot write so we need a simple 
way for these machines to do something with the input and a 
`Yes' or `No' output suits the circumstance.
Another reason is that in many contexts stating a problem in this
way is natural, as we saw with the \HP.

Often a decision problem is expressed as a
\definend{language recognition problem},
where we are given some $\lang$ and asked for an algorithm to
decide if the given input is a member of the language.
An example is the problem, given an input string,
of determining membership in 
$\lang=\set{\sigma\in\kleenestar{\set{\str{a},\str{b}}}\suchthat \text{$\sigma$ starts with \str{a} and contains at least two \str{b}'s}}$.
Another example is that we can express the problem of determining
whether~$d$ divides~$n$
by asking about membership of the pair $\sequence{d,n}$ in the language
$\lang=\set{\sequence{a,b}\in\N^2\suchthat \text{$a$ divides $b$}}$.
Part of our interest in problems of language membership
arises from practice; for instance, a language complier must recognize whether
a given source file is a member of the language.

Search problems and decision problems are related.
For one, if you can solve a search problem then you can solve the
associated decision problem quickly.
For instance, consider 
the search problem that takes in a string~$\sigma$ and a substring~$\tau$,
returns the starting index of $\tau$ in~$\sigma$ if it is there, 
and returns $0$ if not.
The associated decision problem just asks if $\tau$ is a substring of~$\sigma$,
yes or no.
Well, if you can solve the first then you can use it to instantly 
solve the second.

What about the other direction?
Suppose that you could quickly solve the decision problem.
Then to solve the search problem you could look at the initial segments
of~$\sigma$: the initial substring of length~$0$, the initial substring
of length~$1$, etc., and apply the decision problem to each in turn.
That is, if we can solve the decision problem quickly then
we can use it to solve the search problem, but with some overhead.

But while the differences between two categories of problems can seem small,
they are subtle.
Here is an example:~we can quickly determine whether a number has
nontrivial factors, which is  a decision problem,
but we don't know at this time how to quickly solve the search
problem of finding any factors.

We shall introduce some notation conveniences for grammars that are
widely used.
This is a loose collection, meaning that you may see a grammar describe 
with some of these conveniences but not others. 
Together they are called \definend{Backus-Naur form, BNF}.

\margingraphic[l]{1.75cm}{languages/pix/backus.jpg}{\href{https://en.wikipedia.org/wiki/John_Backus}{John Backus 1924--2007}}
The study of grammar, the rules for phrase structure and forming sentences,
has a long history.
In the 1900's it began to be systematized as rewriting rules by
mathematicians including A~Thue and E~Post.
The BNF variant was produced by J~Backus in the late 1950's as part of the
effort to systematize the early computer language ALGOL60. 
Since then it has become
\citetext{the most-often used way to express grammars}{%
  One factor influencing its adoption was a letter that D~Knuth
  wrote to the \textit{Communications of the ACM}
  \autocite{KnuthCACM}.
  He proposed the name Bacus Naur Form and listed
  some advantages over the grammar-specification
  methods that were then widely used.
  Most importantly, he contrasted BNF's `\texttt{<addition operator>}'
  with `\texttt{A}', saying that the difference is a great addition
  to ``the \textit{explanatory power} of a syntax.''
}.

One difference from the prior subsection is a minor typographical 
change (these adjustments were made by P~Naur:~originally the metacharacters
were not typeable using characters from a standard keyboard.
The advantage of having metacharacters not from a keyboard is that
most likely all of the language characters are typeable.
So there is no need to distinguish, say, between the pipe character $\str{|}$
when used as a part of a language and when used as a metacharacter.
But the disadvantage is in the typing.
In the end the convenience of having typeable characters 
won over the technical gain of having to typographically distinguish 
metacharacters. 

For instance, for a long time there were not arrows on a standard keyboard
so in place of the arrow symbol `\produces{}',
BNF substitutes
`\bnfsymbol'.

There are other typographical issues that arise with grammars.
While many authors write 
nonterminals with diamond brackets, as we do,
you can see other conventions such as italic type or a different color.

BNF is both clear and concise, it can express the range of languages that
we ordinarily want to express and it smoothly translates to 
a parser.
That is, BNF is an impedance match\Dash it fits with what
we typically want to do.
Here we will incorporate some extensions for
grouping and replication that is like what you will see 
in the wild.\footnote{%
  There is no standard for BNF.
  Several variants do have standards, including one called Extended BNF, but 
  these are not necessarily what you will see.}

\begin{example}
This is a grammar for real numbers having a finite decimal part.
Take the rules for \ntrm{natural} from \cref{ex:grammarForNaturals}.
\begin{grammar}
\ntrm{start} \bnfproduces{}  \trm{-}\ntrm{fraction}
        \syntaxor \trm{+}\ntrm{fraction} 
        \syntaxor \ntrm{fraction}                

\ntrm{fraction} 
     \bnfproduces{} \ntrm{natural} 
       \syntaxor \ntrm{natural}\trm{.}\ntrm{natural}     
\end{grammar}
This derivation for \str{2.718} is rightmost.
\begin{displayedsteps}
  \initialstep\ntrm{start}
  \derives\ntrm{fraction}
  \derives\ntrm{natural}\trm{.}\ntrm{natural}            
  \derives\ntrm{natural}\trm{.}\ntrm{digit}\ntrm{natural}
  \derives\ntrm{natural}\trm{.}\ntrm{digit}\ntrm{digit}\ntrm{natural}  
  \derives\ntrm{natural}\trm{.}\ntrm{digit}\ntrm{digit}\ntrm{digit}
  \derives\ntrm{natural}\trm{.}\ntrm{digit}\ntrm{digit}\trm{8}  
  \derives\ntrm{natural}\trm{.}\ntrm{digit}\trm{18}
  \derives\ntrm{natural}\trm{.718} 
  \derives\trm{2.718}
\end{displayedsteps}
Here is a derivation for \trm{0.577} that is neither 
leftmost nor rightmost.
\begin{displayedsteps}
  \initialstep\ntrm{start}
  \derives\ntrm{fraction}
  \derives\ntrm{natural}\trm{.}\ntrm{natural}            
  \derives\ntrm{natural}\trm{.}\ntrm{digit}\ntrm{natural}
  \derives\ntrm{natural}\trm{.5}\ntrm{natural}  
  \derives\ntrm{natural}\trm{.5}\ntrm{digit}\ntrm{natural}
  \derives\ntrm{digit}\trm{.5}\ntrm{digit}\ntrm{natural} 
  \derives\ntrm{digit}\trm{.5}\ntrm{digit}\ntrm{digit}  
  \derives\ntrm{digit}\trm{.5}\ntrm{digit}\trm{7}
  \derives\trm{0.5}\ntrm{digit}\trm{7} 
  \derives\trm{0.577}
\end{displayedsteps}
\end{example}

\begin{example}
\citetext{Time is a complicated engineering problem}{% 
  %see https://zachholman.com/talk/utc-is-enough-for-everyone-right
  One example of a complication of time, among many, is leap seconds.
  The Earth is constantly undergoing a deceleration caused by the 
  braking action of the tides. 
  The average deceleration of the Earth is roughly $1.4$ milliseconds per day 
  per century, although the exact number varies from year to year. 
  To ensure that 
  atomic clocks and the Earth's rotational time do not differ  
  by more than $0.9$ seconds,
  occasionally an extra second is added to civil time. 
  This leap second can be either positive or negative depending on the Earth's 
  rotation\Dash on occasion there are minutes with only $58$ seconds, and on
  occasion minutes with~$60$.

  Adding to the confusion is that the changes in rotation are uneven and
  leap seconds cannot be predicted far into the future.  
  The International Earth Rotation Service publishes bulletins that
  announce leap seconds with a few weeks warning. 
  Thus, there is no way to determine how many seconds there will be between 
  the current instant and ten years from now.
  Since the first leap second in 1972, all leap seconds have been positive and 
  there were 23 leap seconds in the 34 years to January, 2006.
  \autocite{web:USNO}}. 
One issue is representing times and one solution in that area is 
\citetext{RFC~3339}{\autocite{rfc3339}},
\textit{Date and Time on the Internet: Timestamps}.
It uses 
\citetext{strings such as \str{1958-10-12T23:20:50.52Z}}{%
  This format has a number of advantages including human readability,
  that if you sort a collection of these strings then earlier times will come
  earlier,
  simplicity (there is only one format),
  and that they include the time zone information.}.
Here is \citetext{a BNF grammar}{%
Some notes: 
(1)~Coordinated Universal Time, the basis for civil time, is
often called UTC, but is sometimes abbreviated Z,
(2)~years are four digits to prevent the Y2K problem \autocite{y2k},
(3)~the only month numbers allowed are $01$--$12$ and in each month
only some day numbers are allowed,
and (4)~the only time hours allowed are $00$--$23$, minutes must 
be in the range $00$--$59$, etc. \autocite{rfc3339}}
Some nonterminals are from \cref{exer:GrammarsForSmallLangs},
This grammar includes some metacharacter extensions that we will 
discuss below.
% % https://www.ietf.org/rfc/rfc3339.txt
   % date-month      = 2DIGIT  ; 01-12
   % date-mday       = 2DIGIT  ; 01-28, 01-29, 01-30, 01-31 based on
   %                           ; month/year
   % time-hour       = 2DIGIT  ; 00-23
   % time-minute     = 2DIGIT  ; 00-59
   % time-second     = 2DIGIT  ; 00-58, 00-59, 00-60 based on leap second
   %                           ; rules
   % time-secfrac    = "." 1*DIGIT
   % time-numoffset  = ("+" / "-") time-hour ":" time-minute
   % time-offset     = "Z" / time-numoffset

   % partial-time    = time-hour ":" time-minute ":" time-second
   %                   [time-secfrac]
   % full-date       = date-fullyear "-" date-month "-" date-mday
   % full-time       = partial-time time-offset

   % date-time       = full-date "T" full-time
\begin{grammar}
\ntrm{date-fullyear} \bnfproduces{} \ntrm{4-digits}

\ntrm{date-month} \bnfproduces{} \ntrm{2-digits}

\ntrm{date-mday} \bnfproduces{} \ntrm{2-digits} 

\ntrm{time-hour} \bnfproduces{} \ntrm{2-digits}

\ntrm{time-minute} \bnfproduces{} \ntrm{2-digits}  

\ntrm{time-second} \bnfproduces{} \ntrm{2-digits} 

\ntrm{time-secfrac} \bnfproduces{} \trm{.} \ntrm{1-or-more-digits}

\ntrm{time-numoffset} \bnfproduces{} (\trm{+} \syntaxor \trm{-}) \ntrm{time-hour} \trm{:} \ntrm{time-minute}

\ntrm{time-offset} \bnfproduces{} \trm{Z} \syntaxor \ntrm{time-numoffset}

\ntrm{partial-time} \bnfproduces{} \ntrm{time-hour} \trm{:} \ntrm{time-minute} \trm{:} \ntrm{time-second} [\ntrm{time-secfrac}]

\ntrm{full-date} \bnfproduces{} \ntrm{date-fullyear} \trm{-} \ntrm{date-month} \trm{-} \ntrm{date-mday}

\ntrm{full-time} \bnfproduces{} \ntrm{partial-time} \ntrm{time-offset}

\ntrm{date-time} \bnfproduces{} \ntrm{full-date} \trm{T} \ntrm{full-time}
\end{grammar}
\end{example}

One common BNF notation extension is shown in that grammar's
\ntrm{time-numoffset} rule, where the
parentheses are used as metacharacters to group
a choice between the terminals \trm{+} and~\trm{-}.

The \ntrm{partial-time} rule includes square brackets as metacharacters.
They deonte that the \ntrm{time-secfrac} is optional.
This is a common construct: another example shows 
a negation sign as optional in 
the rule \mbox{\ntrm{term} \bnfproduces{} [ \trm{-} ] \ntrm{factor}}.
Still another example is this syntax for \str{if ... then ...} with an optional
\str{else ...}.
\begin{grammar}
    \ntrm{if-stmt} \bnfproduces{}  \trm{if} \ntrm{boolean-expr} \trm{then}
                             \ntrm{stmt-sequence}\\*
                        \quad[ \trm{else}
                             \ntrm{stmt-sequence} ]
                        \ntrm{end if} \trm{;}
\end{grammar}

To show repetition we may use a Kleene star~* 
to mean `zero or more', 
or a~+ to mean `one or more'.
This shows parentheses and repetition.
\begin{grammar}
 \ntrm{identifier} \bnfproduces{} \ntrm{letter} ( \ntrm{letter} \syntaxor \ntrm{digit} )*
\end{grammar}
It is equivalent to this.
\begin{grammar}
\ntrm{identifier} \bnfproduces{} \ntrm{letter} \syntaxor \ntrm{letter} \ntrm{atoms}

\ntrm{atoms} \bnfproduces{} \ntrm{letter} \ntrm{atoms} \syntaxor \ntrm{digit} \ntrm{atoms} \syntaxor \emptystring
\end{grammar}
 
\begin{example} \label{ex:PythonFloatingPoint}
This grammar for floating point numbers shows all three 
abbreviations.
\begin{grammar}
\ntrm{floatnumber}   \bnfproduces{}  \ntrm{pointfloat} \syntaxor \ntrm{exponentfloat}

\ntrm{pointfloat}    \bnfproduces{}  [\ntrm{intpart}] \ntrm{fraction} \syntaxor \ntrm{intpart} \trm{.}

\ntrm{exponentfloat} \bnfproduces{}  (\ntrm{intpart} \syntaxor \ntrm{pointfloat}) \ntrm{exponent}

\ntrm{intpart}       \bnfproduces{}  \ntrm{digit}+

\ntrm{fraction}      \bnfproduces{}  \trm{.} \ntrm{digit}+

\ntrm{exponent}      \bnfproduces{}  (\trm{e} \syntaxor \trm{E}) [\trm{+} \syntaxor \trm{-}] \ntrm{digit}+
\end{grammar}
As part of the \ntrm{pointfloat} rule, the first \ntrm{intpart}
is optional.
An \ntrm{intpart}, what we have earlier called a \ntrm{natural},
consists of one or more digits.
And an expansion of \ntrm{exponent} must start with a choice between 
\str{e} or \str{E}.
\end{example}

Each of these extension constructs is not necessary
since we can express them in plain BNF.
For instance, we could replace the \ntrm{pointfloat} rule with this. 
\begin{grammar}
\ntrm{pointfloat} \bnfproduces{} \ntrm{intpart} \ntrm{fraction} 
    \syntaxor \ntrm{fraction} 
    \syntaxor \ntrm{intpart} \trm{.}
\end{grammar}
But these constructs come up often enough
that adopting an abbreviation is worthwhile.

\begin{remark}
Passing from the grammar to a parser for that grammar is mechanical.
That is, it is natural to write a program that takes as input a grammar
in BNF and gives as output the source code of a program that will
parse files following that grammar's format.
Such a program is a \definend{compiler-compiler}.

At one point there were many compiler-compiler available, with a variety
of different features.
They were amalgamated into one with the production of
YACC, Yet Another Compiler Compiler.
In recent years, YACC has itself been supplanted with a version that is
Free from the GNU project, obviously called Bison.
\end{remark}

\extra{Lambda Calculus and Scheme}
% See http://matt.might.net/articles/compiling-up-to-lambda-calculus/

% Jim Larson
% 1996-07-26
% This talk was given at the JPL Section 312 Programming Lunchtime Seminar.

A function accepts input and produces an output. 
Suppose we have a ``chocolate-covering'' function that produces the 
following outputs for the corresponding inputs:
% \begin{grammar}
%   \str{peanuts} &\produces  \str{chocolate-covered peanuts} \\
%   \str{rasins}  &\produces  \str{chocolate-covered rasins} \\
%   \str{ants}    &\produces \str{chocolate-covered ants}
% \end{grammar}
We can use Lambda-calculus to describe such a function.
\begin{equation*}
	\lambda x.\str{chocolate-covered $x$}
\end{equation*}
This is a \definend{lambda-expression}.

To apply the function to an argument, use the following syntax.
% \begin{equation*}
%   (\lambda x.\str{chocolate-covered $x$})\,\str{peanuts} 
%     \produces \str{chocolate-covered peanuts}
% \end{equation*}
Functions can also be the result of applying a lambda-expression, as with this ``covering function maker.''
\begin{equation*}
  \lambda y.\lambda x.\str{$y$-covered $x$}
\end{equation*}
Use this to create a caramel-covering function.
% \begin{align*}
%   (\lambda y.\lambda x.\str{$y$-covered $x$})\,\str{caramel} 
%     &\produces \lambda x.\str{caramel-covered $x$}   \\
%   (\lambda x.\str{caramel-covered $x$})\,\str{peanuts} 
%     &\produces \str{caramel-covered peanuts}
% \end{align*}
Functions can also be the inputs to other functions, as with this 
``apply-to-ants'' function.
\begin{equation*}
	\lambda f.(f)\,\str{ants}
\end{equation*}
We can feed the chocolate-covering function to the "apply-to-ants" function:
% \begin{multline*}
% 	(\lambda f.\str{$(f)$ants})\lambda x.\str{chocolate-covered $x$}  \\
%       \begin{split}
%         \hspace*{3em}
% 	&\produces (\lambda x.\str{chocolate-covered $x$})\str{ants}  \\
% 	&\produces \str{chocolate-covered ants}
%       \end{split}
% \end{multline*}

Lambda-expressions have the following syntax.
\begin{lstlisting}
	lambda-expression \bnfproduces{}	variable
				| constant
				| application
				| abstraction
	application \bnfproduces{} (lambda-expression)lambda-expression
	abstraction \bnfproduces{} Lvariable.lambda-expression
\end{lstlisting}
The evaluation of lambda-expression is from the application of two reduction 
rules. 
The \definend{alpha-reduction} rule says that 
we can consistantly rename bindings of variables
% \begin{equation*}
% 	\lambda x.E \produces \text{$\lambda z.\{z/x\}E$ 
%                         for any $z$ which is neither free nor bound in $E$}
% \end{equation*}
where $\{z/x\}E$ means the substitution of $z$ for $x$ for any free occurance 
of $x$ in $E$. 
The \definend{beta reduction} rule says that application of a 
lambda-expression to an argument is the consistent replacement of the 
argument for the lambda-expression's bound variable in its body:
\begin{equation*}
	(\lambda x.P)Q -> [Q/x]P
\end{equation*}
where $[Q/x]P$ means the substitution of $Q$ for $x$ for any free occurrance 
of $x$ in $P$.

The Church-Rosser Theorem states that the final result of a chain of 
substitutions does not depend on the order in which the substitutions are 
performed.

\subsection{Universality of Lambda-calculus}
The Lambda-calculus is a universal model of computation, that is, 
any computation that can be expressed in a Turing machine can also be 
expressed in the lambda calculus.

To show this, here is the translation of a conditional control structure 
into lambda-calculus.
\begin{align*}
	\str{true} &= \lambda x.\lambda y.x  \\
	\str{false} &= \lambda x.\lambda y.y        \\
	\str{if-then-else} &= \lambda a.\lambda b.\lambda c.((a)b)c 
\end{align*}
Here is an application of those rules.
% \begin{multline*}
% 	(((\str{if-then-else})\str{false})\str{apple})\str{banana}  \\
%       \begin{split}
%         \qquad 
% 	&\produces (((\lambda a.\lambda b.\lambda c.((a)b)c)\lambda x.\lambda y.y)\str{apple})\str{banana}       \\
% 	&\produces ((\lambda b.\lambda c.((\lambda x.\lambda y.y)b)c)\str{apple})\str{banana}          \\
% 	&\produces (\lambda c.((\lambda x.\lambda y.y)\str{apple})c)\str{banana}  \\
% 	&\produces ((\lambda x.\lambda y.y)\str{apple})\str{banana}   \\
% 	&\produces (\lambda y.y)\str{banana}    \\
% 	&\produces \str{banana}
%      \end{split}
% \end{multline*}
Here is the translation of some data structure operations.
\begin{align*}
	\str{cons} &= \lambda a.\lambda b.\lambda c.((c)a)b   \\
	\str{head} &= \lambda x.(x)\str{true}                  \\
	\str{tail} &= \lambda x.(x)\str{false}               \\
          \\
	0 &= \lambda f.\lambda x.x    \\
	1 &= \lambda f.\lambda x.(f)x  \\
	2 &= \lambda f.\lambda x.(f)(f)x   \\
	3 &= \lambda f.\lambda x.(f)(f)(f)x    \\
        \\
	\str{succ} &= \lambda n.\lambda f.\lambda x.(f)((n)f)x  \\
	+ &= \lambda m.\lambda n.\lambda f.\lambda x.((m)f)((n)f)x   \\
	* &= \lambda m.\lambda n.\lambda f.(m)(n)f           \\
	\str{zero?} &= \lambda n.((n)(\str{true})\str{false})\str{true} \\
	\str{pred} &= \lambda n.(((n)\lambda p.\lambda z.((z)(\str{succ})(p)\str{true})(p)\str{true})Lz.((z)0)0)\str{false}
\end{align*}

Lastly, you can create recursive functions with the \definend{$Y$ combinator}.
\begin{gather*}
	Y = \lambda y.(\lambda x.(y)(x)x)\lambda x.(y)(x)x        \\
	(Y)E -> (E)(Y)E -> \cdots -> (E)\ldots (E)(Y)E
\end{gather*}
We need this to create recursive functions, such as the factorial funtion:
\begin{equation*}
	\str{fact} = \lambda n.(((\str{if-then-else})(\str{zero?})n)1)((*)n)(\str{fact})(\str{pred})n
\end{equation*}
As written, this doesn't work since \str{fact} is a free variable in its 
own definition! We need some way to bind \str{fact} to ``this function,'' 
which can be done with Y.
\begin{equation*}
	\str{fact} = (Y)\lambda f.\lambda n.(((\str{if-then-else})(\str{zero?})n)1)((*)n)(f)(\str{pred})n
        \end{equation*}

        

\subsection{From theory to programming language}
Although the lambda-calculus is powerful enough to express any program, 
this doesn't mean that you'd actually want to do so. 
After all, the Turing Machine offers an equally powerful computational basis.

The strength of the lambda-calculus is that it is easily used as a ``glue'' 
on top of a richer world of primitives. 
Its advantages as a glue are that it has a natural correspondence with the way 
that people program, and natural compilation techniques yield 
high-performance code. 
The latter comes through optimizations know as tail-call and 
continuation-passing, which are more advanced topics not covered here.

There are software engineering advantages to a language glued together 
with lambda-calculus. 
Lambda expressions can be understood locally\Dash their dependence on 
their environment is entirely through their free variables. 
Lambda expressions tend to have fewer free variables and more bound 
variables than comparable imperative code, since they do not rely as heavily 
on assignment to express the computation. 
An imperative program proceeds by altering some globally-accessible 
store of values. 
By contrast, a functional program proceeds by function application and 
the return of values. 
This eliminates large classes of errors associated with maintinaing a global store of values.




\subsection{Scheme}
The Scheme programming language is essentially the lambda-calculus outlined 
above, plus these
\begin{itemize}
\item
    The ability for a lambda-expression to bind several arguments at once.
\item
    A rich set of constants, so numbers, arithmetic, data structures, etc., don't have to be built out of thin air.
\item
    Primitive control constructs, so control operations don't have to be built out of thin air.
\item
    An assignment operation, should it be necessary.
\item
    An environment of defined names, to allow for interactive use, redefinition, and recursive definitions without using the $Y$ combinator.
\item
    A library with I/O operations to connect programs to the outside world. 
\end{itemize}

In Scheme, programs look like data structures - both are built of lists. A list looks like:
\begin{equation*}
	(\str{elt1}\ \str{elt2}\ \ldots{}\ \str{eltn})
\end{equation*}
where each element is either an atom (number or symbol), or another list.

Expressions from the lambda-calculus are translated as follows:
% \begin{align*}
% 	\lambda x.M  &\becomes  \text{\codeinline!(lambda (x) M)!} \\
% 	(M)N  &\becomes  \text{\codeinline!(M N)!}
% \end{align*}
In addition, Scheme allows lambda expressions and function applications of 
more than one argument.
\begin{lstlisting}
(lambda (a b c) (+ a (* b c)))
\end{lstlisting}
The define syntax binds names to values within the local environment:
\begin{lstlisting}
(define pi 3.14159265)
(define fact
    (lambda (n)
        (if (zero? n)
        1
        (* n (fact (- n 1))))))
(define alpha (sin (/ pi 180)))
\end{lstlisting}
Some Scheme constructs are `syntactic sugar', that is, 
expressions that can be translated into expressions in terms of more 
primitive operators. 
The \codeinline!let! construct allows initialization and binding of 
local variables so that this
\begin{lstlisting}
(let ((x1 E1)
      (x2 E2)
      (x3 E3))
      \ldots{}body\ldots{} )
\end{lstlisting}
is equivalent to this.
\begin{lstlisting}
((lambda (x1 x2 x3) \ldots{}body\ldots{} )
E1
E2
E3)
\end{lstlisting}
% Definition of a function can be done without an explicit lambda-expression
% \begin{lstlisting}
% 	(define (f x y z)	=>	(define f
% 	  \ldots{}body\ldots{})			  (lambda (x y z)
% 					    \ldots{}body\ldots{}))
% \end{lstlisting}



\subsection{Standard idioms in Scheme}
Where a conventional block-structured imperative language like C or Pascal 
would write
\begin{lstlisting}
begin
    x := 1;
    y := 2 * some_global_var;
    z := some_function();
    \ldots{}body using x, y, and z\ldots{}
end
\end{lstlisting}
Scheme would instead use the let syntax to bind local variables.
\begin{lstlisting}
(let ((x 1)
    (y (* 2 some-global-var))
    (z (some-function)))
    ..body using x, y, and z\ldots{})
\end{lstlisting}
As we see above, the \codeinline!let! construct is just the stylized use of 
lambda and a function application to create an environment for the body 
where the local variables are bound to their values. 
Note that this style of programming requires the local variables to be 
initialized before use.

Scheme downplays iterative constructs such as \codeinline!do!, preferring 
recursive function calls. 
A special optimization called tail-recursion produces compiled code 
that is equivalent to a loop.
\begin{lstlisting}
(define (new-fact n)
    (define (iter n a)
    (if (zero? n)
        a
        (iter (- n 1) (* n a))))
    (iter n 1))
\end{lstlisting}
Compare this to the equivalent C function:
\begin{lstlisting}
int
new_fact(int n)
{
    int a = 1;
    while (n != 0)
        a *= n--;
    return a;
}
\end{lstlisting}
Note that the loop in the C version cannot be understood on its own\Dash in 
order to see what \codeinline!n! and \codeinline!a! are we have to 
see the entire function, while in the Scheme version, the 
\codeinline!iter! function can be lifted out of the \codeinline!new-fact! 
function and understood on its own\Dash it has no free variables! 
This may not seem too important for a toy example like this, but as the 
size of the function and the complexity of the loop scales up, 
this kind of modularity can be important.

Although it may seem unnecessary and clumsy to define a new function every 
time you need a loop, some common uses can be turned into functions 
themselves. 
For instance, a common operation in Scheme is the act of taking a 
list and applying a function to each of the elements, forming a new list of 
the results.
\begin{lstlisting}
(define (list-of-squares l)
    (define (iter l)
        (if (null? l)
            (quote ())
            (cons ((lambda (x) (* x x)) (car l)) (iter (cdr l)))))
    (iter l))
\end{lstlisting}
This kind of iteration is idiomatic, so we can capture it in a function:
\begin{lstlisting}
(define (map f l)
    (define (iter l)
        (if (null? l)
            (quote ())
            (cons (f (car l)) (iter (cdr l)))))
        (iter l))

(define (list-of-squares l)
    (map (lambda (x) (* x x)) l))
\end{lstlisting}
We could produce this program in C as well, using the technique of passing 
pointers to functions as arguments to other functions. 
However, there are some features of C that make this difficult. 
Suppose we want a function to do an affine transformation $Ax + B$ on a 
list of numbers, with A and B as parameters to the function. 
In C we have to write this.
\begin{lstlisting}
double A, B;	/* global variables */
static double
affine(double x)
{
    return A * x + B;
}

List *
affinelist(double a, double b, List *l)
{
    A = a;
    B = b;
    return map(&affine, l);
}
\end{lstlisting}
Since in C, the map function accepts only a function pointer, 
the transformation parameters have to be held in some static location for 
the affine function to find them. This prevents the code from being 
reentrant\Dash only one call to affinelist can be active at a time.

Pascal allows functions to be declared within a block, and to have access 
to all the variables visible within that block. 
In a `block-structured' variation of C would could do the following:
\begin{lstlisting}
List *
affinelist(double a, double b, List *l)
{
    double
    affine(double x)
    {
        return a * x + b;
    }
    return map(&affine, l);
}
\end{lstlisting}
This allows the function to be re-entrant. 
But Scheme allows us even more freedom in the use of these local 
functions\Dash they can persist even after the return of the parent function! 
The variables bound by the parent function are still accessible to the local 
functions, and only by them, in effect creating an opaque object with the 
local functions as the methods for accessing its state. 
This gives us a way to do object-oriented programming with higher-order 
functions in Scheme.

Suppose we want to create an object with state variables svN and methods 
methodN.
\begin{lstlisting}
(define (make-object sv1 sv2 ... svN)
    (lambda (mesg)
        (cond ((eq? mesg (quote method1)) (lambda args1 body1))
               ((eq? mesg (quote method2)) (lambda args2 body2))
                 ...
               ((eq? mesg (quote methodM)) (lambda argsM bodyM))
               (else (error "Unknown method for object")))))

(define (method1 obj args1) ((obj (quote method1)) args1))
    ...
\end{lstlisting}
So an object is a procedure which accepts a message and dynamically 
returns a procedure which will handle that message. 
Each procedure has access to the state variables which were used to create 
the object. 
Multiple instances are created through multiple invocations of the 
\codeinline!make-object! function. 
Class structure and inheritance can be accomplished through delegation. 
So use of higher-order functions can implement object-oriented code in a 
natural way.

Here are some advantages of a lambda-calculus-based programming language.
\begin{itemize}
\item
    A clean mathematical basis. The formal specification of the language doesn't need to refer to a machine or compiler.
\item
    Many common programming idioms have a natural representation.
\item
    Advanced programming through higher-order functions.
\item
    Direct correspondence with advanced mathematical objects such as functionals.
\item
    Efficient machine implementation.
\item
    Programs are more modular\Dash they can be understood and analyzed locally. 
\end{itemize}

There are some disadvantages too.
\begin{itemize}
\item
    Real-world implementations are not as good as they could be.
\item
    The model of computation provided by the language is far removed from the realities of the underlying machine. This can be both good and bad.
\item
    Things that are simple in other languages tend to be hard in Scheme, yet some simple Scheme tricks are hard to do in other languages.
\item
    Programming with full lambda-calculus requires a garbage collector in the runtime system. This entails
        a more complicated runtime system than Fortran or C, 
        difficulty in linking with code compiled from another language, and 
        complications for real-time or interactive use. 
\end{itemize}
