Turing machines input strings and output strings, sequences of tape symbols.
So a natural way to work is to represent a problem as a string,
put it on the tape, run a computation, and end with
the solution as a string.

Everyday computers work the same way.
Consider a program that finds the shortest driving distance
between cities.   
% Perhaps it works with a map of the country idealized as a
% a collection of nodes and edges, intersections and the roads joining them.
Probably we work by inputting the map distances as a strings of symbols and
inputting the desired two cities as two strings,
and after running the program we have the output
directions as a string.
So strings, and collections of strings, are essential.

\section{Languages}\index{language|(} % see for more: http://jeffe.cs.illinois.edu/teaching/algorithms/all-models.pdf
Our machines input and output strings of symbols.
In this book we take 
a \definend{symbol}\index{symbol} 
(sometimes called a \definend{token})\index{token} 
to be an atomic unit that a machine can read and write.\footnote{%
  We can imagine Turing's clerk 
  calculating without reading and writing symbols, 
  keeping track of information by 
  \protect\citetext{having elephants move 
  to the left side of a road or to the right}{% 
    Less fancifully, we could be making
    a Turing machine out of Legos and want to keep track by sliding a block
    from one side of a column to the other.
    Or, we could use an abacus.}.
  But 
  \protect\citetext{we could translate any such procedure}{%
    While a 
    person may quite sensibly worry that elephants could be not just on
    the left side or the right, but in any of the continuum of points
    in between, we will make this 
    assertion without more philosophical analysis than by just referring
    to the discrete nature of our mechanisms
    (as Turing basically did).
    That is, we take it as an axiom.} 
  into one using marks that our mechanism's read/write head can handle.
  So the restriction to readability and writeability is not essential.
  We include it in the definition of symbols because our mechanisms will
  use them.
  For this purpose, elephants
  would be an inconvenience.}
An \definend{alphabet}\index{alphabet} 
is a nonempty and finite set of symbols.
A \definend{string}\index{string} 
over an alphabet 
is a sequence of symbols from that alphabet.
We usually denote an alphabet with the upper case greek letter $\Sigma$
although an exception is $\B=\set{\str{0},\str{1}}$,
the alphabet from which we make bit strings.
We use lower case greek letters such as $\sigma$ and~$\tau$ to denote
strings.  
We use $\emptystring$ to denote the empty string, the length zero sequence
of symbols.
The set of all strings over $\Sigma$ is 
\index{Kleene star}$\kleenestar{\Sigma}$.\footnote{%
  For more on strings see the Appendix on page~\pageref{sec:Strings}.}

%<*def:Lang>
\begin{definition}
A \definend{language~$\lang$ over an alphabet~$\Sigma$}\index{language}
is a set of strings drawn from that alphabet. 
That is, $\lang\subseteq\kleenestar{\Sigma}$.  
\end{definition}
%</def:Lang>

\begin{example}
The set of bit strings
that begin with \str{1} is 
$\lang=\set{\str{1},\,\str{10},\,\str{11},\,\str{100},\,\ldots}$.   
\end{example}

\begin{example}
Another language over $\B$
is the \citetext{finite set $\set{\str{1000001},\str{1100001}}$}{%
  Although it looks like two strings plucked from the air, the language is not 
  without sense since \str{1000001} represents capital A in the 
  ASCII encoding, while \str{1100001} is lower case a.
  The American Standard Code for Information Interchange, ASCII,
  is a widely used way of encoding character information in computers.  
  The most common modern character encoding is UTF-8, 
  which is a superset of ASCII.}.
\end{example}

\begin{example}
Let $\Sigma=\set{\str{a}, \str{b}}$.
The language consisting of strings where the number of \str{a}'s is twice 
the number of \str{b}'s is
$\lang=\set{\emptystring,\str{aab},\str{aba},\str{baa},
               \str{aaaabb}, \,\ldots}$.  
\end{example}

\begin{example}
Let $\Sigma=\set{\str{a},\, \str{b},\, \str{c}}$.
The language of length-two strings over that alphabet is
$\lang=\Sigma^2=\set{\str{aa},\,\str{ab},\,\str{ba}\,\dots,\,\str{cc}}$.
Over the same alphabet 
this is the language of length-three strings that are sorted in ascending order.
\begin{equation*}
  \set{\str{aaa},\, \str{aab},\, \str{aac},\, \str{abb},\, \str{abc},
    \str{acc},\,\str{bbb},\,\str{bbc},\, \str{bcc},\, \str{ccc}}
\end{equation*}
(It is not that the set is sorted in ascending order since sets don't have
an order.
Instead, each string has its characters come in ascending order.)
\end{example}

\begin{definition}\index{palindrome} \label{def:palindrome}
A
\citetext{\definend{palindrome}}{%
  Sometimes people tease Psychology by labelling it
  the study of college freshmen because so many studies start, roughly,
  ``we put a bunch of college freshmen in a room, lied to them
  about what we were doing, and \ldots\sentencespace''
  In the same way, Theory of Computing sometimes seems like
  the study of palindromes.}
is a string that reads the same forwards as backwards.
\end{definition}

Some 
\citetext{words from English that are plaindromes}{%
  Some people like to move beyond single word palindromes to 
  make sentence-length palindromes that make some sense.
  Some of the more famous are:~(1)~supposedly the first sentence ever uttered, 
  ``Madam, I'm Adam''
  (2)~Napoleon's lament, ``Able was I ere I saw Elba''
  and (3)~``A man, a plan, a canal: Panama'', about Theodore Roosevelt.}
are `kayak', `noon', and~`racecar'.

\begin{example}  
The language of palindromes over $\Sigma=\set{\str{a},\str{b}}$ is
$\lang=\set{\sigma\in\kleenestar{\Sigma}\suchthat \sigma=\reversal{\sigma}}$.
A few members are \str{abba}, \str{aaabaaa}, and \str{a}.
\end{example}

\begin{example}
Let $\Sigma=\set{\str{a}, \str{b}, \str{c}}$.
Pythagorean triples $\sequence{i,j,k}\in\N^3$ 
are those where $i^2+j^2=k^2$.
A few such triples are $\sequence{3,4,5}$, $\sequence{5,12,13}$,
and $\sequence{8,15,17}$.
One way to describe Pythaorean triples
is with this language.
\begin{align*}
  \lang
   &= \set{\str{a}^i\str{b}^j\str{c}^k\in\kleenestar{\Sigma} 
            \suchthat \text{$i,j,k\in\N$ and $i^2+j^2=k^2$}}  \\
   &=\set{\str{aaabbbbccccc}=\str{a}^3\str{b}^4\str{c}^5,\,
            \str{a}^5\str{b}^{12}\str{c}^{13},\,
            \str{a}^8\str{b}^{15}\str{c}^{17},\,\ldots}
\end{align*}
\end{example}

\begin{example}
  The empty set is a language $\lang=\set{}$ over any alphabet.
  So is the set whose single element is the empty string
  $\hat{\lang}=\set{\emptystring}$.
  These two languages are different, because the first has no members.
\end{example}

We can think that a natural language such as English consists of 
sentences, which are strings of words from a dictionary.
Here $\Sigma$ is the set of dictionary words and $\sigma$ is a sentence.
This explains the definition of ``language'' as a set of strings.
Of course, our definition
allows a language to be any set of strings at all, while
in English
you can't form a sentence by just taking any crazy sequence of words; 
an sentence must be constructed according to rules.
We will study sets of rules, grammars, later in this chapter.

A collection of languages is a \definend{class}.\index{class}\index{language!class}
\end{definition}

\begin{example}
Fix an alphabet~$\Sigma$.
The collection of all finite languages over
that alphabet is a class.
\end{example}

\begin{example}
Let $\TM_e$ be a Turing machines, using the input alphabet
$\Sigma=\set{\str{B},\str{1}}$.
The set of strings
$
\lang_e=\set{\sigma\in\kleenestar{\Sigma}\suchthat
  \text{$\TM_e$ halts on input $\sigma$}}
$  is a language.
The collection of all such languages, of the $\lang_e$ for all~$e\in\N$,
is the class of computably enumerable languages over~$\Sigma$.
\end{example}

We next consider operations on languages.
They are sets so the operations of union, intersection, etc., apply.
However, for instance the union of a 
language over~$\kleenestar{\set{\str{a}}}$ with
a language over~$\kleenestar{\set{\str{b}}}$ 
is an awkward marriage, a combination of strings of \str{a}'s with
strings of \str{b}'s.
That is, 
the union of a language over $\Sigma_0$ with 
a language over $\Sigma_1$ is a language over $\Sigma_0\cup\Sigma_1$.
% Of course, if the two alphabets are the same then this accounting
% nonsense goes away.
The same thing happens for intersection.
% ; see 
% \cref{exer:LanguageUnionIntersection}.

Other operations on languages are extensions of operations on strings.
We define the concatenation of languages 
to be the language of concatenations, etc.

%<*def:LangOps>
\begin{definition}[Operations on languages]\index{language!operations on}  \label{def:LangOps}
The
\definend{concatenation of languages, $\lang_0\concat\lang_1$ or $\lang_0\lang_1$},\index{concatenation of languages}\index{language!concatenation}
is the set of concatenations,
$\set{\sigma_0\concat\sigma_1\suchthat \text{$\sigma_0\in\lang_0$ and $\sigma_1\in\lang_1$}}$.

For any language, the 
\definend{power, $\lang^k$},\index{power of a language}\index{language!power} 
is the language consisting of the
concatenation of $k$-many strings
$\lang^k=
\set{\sigma_0\concat\cdots\concat\sigma_{k-1}\suchthat \sigma_i\in\lang}$
when $k>0$.
In particular, $\lang^1=\lang$.
For $k=0$ we take $\lang^0=\set{\emptystring}$.\footnotemark[1]
The 
\definend{Kleene star of a language, $\kleenestar{\lang}$},\index{Kleene star}\index{language!Kleene star} 
is the 
language consisting of the concatenation of any number of strings.
\begin{equation*}
\kleenestar{\lang}=\set{\sigma_0\concat\cdots\concat\sigma_{k-1}\suchthat \text{$k\in\N$ and $\sigma_0,\ldots,\sigma_{k-1}\in\lang$}}
\end{equation*}
This includes the concatenation of $0$-many strings, 
so that $\emptystring\in\kleenestar{\lang}$ if $\lang\neq \emptyset$. 

The 
\definend{reversal, $\reversal{\lang}$},\index{reversal of a language}\index{language!reversal} 
of a language~$\lang$ is 
the language of reversals,
$\reversal{\lang}=\set{\reversal{\sigma}\suchthat \sigma\in\lang}$.
\end{definition}\footnotetext[1]{%
  For technical convenience we take $\lang^0=\set{\emptystring}$ even when
  $\lang=\emptyset$; see \cref{exer:WhyEmptysetZeroPowerNotEmpty}.
}
%</def:LangOps>

\begin{example}
Where the language 
is the set of bit strings $\lang=\set{\str{1000001},\str{1100001}}$ 
then the reversal is $\reversal{\lang}=\set{\str{1000001},\str{10000011}}$.
\end{example}

%<*ex:KleeneStar>
\begin{example}
If the language $\lang$ consists of two strings $\set{\str{a},\,\str{bc}}$
then the second power of that language is
$\lang^2=\set{\str{aa},\,\str{abc},\,\str{bca},\,\str{bcbc}}$.
Its Kleene star is this.
\begin{equation*}
  \kleenestar{\lang}=\set{\emptystring,\,\str{a},\,\str{bc},\,\str{aa},\,\str{abc},\,\str{bca},\,\str{bcbc},\,\str{aaa},\,\ldots}  
\end{equation*}
\end{example}
%</ex:KleeneStar>

Earlier for an alphabet~$\Sigma$ we defined 
$\kleenestar{\Sigma}$ to be the set of strings
over that alphabet, of any length.
The two definitions agree if 
we take each character in the alphabet to be a length-one string. 

A final comment about Kleene star.
We could define the operation of
repeatedly choosing strings from the language in two ways.
We could choose a string~$\sigma$ from the
language and then replicate,
getting the set of $\sigma^k$'s,
Or, we could repeat choosing strings from the language, getting
$\sigma_0\concat\sigma_1\concat\cdots\concat\sigma_{k-1}$'s.
The second case is more useful and that's the definition of
$\kleenestar{\lang}$.

\end{answer}

\begin{exercise}
  Show that if $\beta$ is a string then 
  $\beta\concat\reversal{\beta}$ is a palindrome.
  Do all palindromes have that form?  
\begin{answer}\verified
  If $\beta=\sequence{b_0,\ldots,b_{i-1}}$ is a string then 
  $\beta\concat\reversal{\beta}
  =\sequence{b_0,\ldots,b_{i-1}}\concat\sequence{b_{i-1},\ldots,b_0}$
  is clearly a palindrome.

  There are palindromes not of that form.
  One is $\gamma=\str{010}$, which
  cannot be decomposed into $\gamma=\beta\concat\reversal{\beta}$.  
\end{answer}
\end{exercise}

\begin{exercise}
Does $\kleenestar{\lang}$ differ from 
$\kleenestar{(\lang\cup\set{\emptystring})}$?
\begin{answer}
  Yes, but only in an edge case.
  If $\lang=\emptyset$ then $\kleenestar{\lang}=\emptyset$ 
  while $\kleenestar{(\lang\cup\set{\emptystring})}=\set{\emptystring}$.

  We will show that if $\lang\neq\emptyset$ then the two sets are equal,
  $\kleenestar{\lang}=\kleenestar{(\lang\cup\set{\emptystring})}$.
  The containment 
  $\kleenestar{\lang}\subseteq\kleenestar{(\lang\cup\set{\emptystring})}$
  is clear.

  For the other direction, 
  $\kleenestar{(\lang\cup\set{\emptystring})}\subseteq\kleenestar{\lang}$,
  assume that $\sigma\in\kleenestar{(\lang\cup\set{\emptystring})}$.
  Then $\sigma=\sigma_0\concat\cdots\concat\sigma_{n-1}$ for some $n\in\N$ and
  $\sigma_i\in\lang\cup\set{\emptystring}$.
  If for all~$i\in\set{0,\ldots n-1}$ the string~$\sigma_i$ 
  equals~$\emptystring$ then $\sigma=\emptystring$, and is an element of 
  $\kleenestar{\lang}$ because $\lang\neq\emptyset$ and 
  $\emptystring=\rho^0$ for any $\rho\in\lang$.
  Otherwise there is at least one $i\in\set{0,\ldots n-1}$ 
  such that $\sigma_i\neq\emptystring$.
  In this case, omitting from the string~$\sigma$ those $\sigma_j$ that
  equal the empty string gives that $\sigma\in\lang^k$ for some~$k\leq n$, 
  and so $\sigma\in\kleenestar{\lang}$.  
\end{answer}

\begin{exercise}
We can ask how many elements are in the set $\lang^2$.
\begin{exparts}
\item Prove that if two strings are unequal then their squares are also
  unequal.  
  Conclude that if $\lang$ has $k$-many elements then 
  $\lang^2$ has at least $k$-many elements.
\item Provide an example of a nonempty language that 
achieves this lower bound. 
\item Prove that where $\lang$ has $k$-many elements, $\lang^2$ has at most
$k^2$-many.
\item Provide an example, for each $k\in\N$, of a language that 
achieves this upper bound. 
\end{exparts}
\begin{answer}
  Let the alphabet be $\Sigma$.
  \begin{exparts}
  \item Consider unequal strings $\sigma_0\neq\sigma_1$.
    They can't both be the empty string, 
    and if one of them is the empty string but the other is not
    then clearly $\sigma_0^2\neq\sigma_1^2$
    because one of those two is empty while the other is not.
    So now suppose that neither of the two strings $\sigma_0$ and~$\sigma_1$
    is empty.
    If they are different lengths then their squares are also different lengths.
    The case remaining is that they are nonempty equal-length strings,
    $\sigma_0=\sequence{s_{0,0},s_{0,1},\ldots s_{0,n}}$
    and
    $\sigma_1=\sequence{s_{1,0},s_{1,1},\ldots s_{1,n}}$ for some $n\in\N$.
    Fix the smallest index~$i$ where $s_{0,i}\neq s_{1,i}$.
    For that same~$i$ we have that $\sigma_0^2$ and $\sigma_1^2$ differ on
    index~$i$, and are therefore unequal.

    The prior paragraph implies that if $\lang$ has $k$-many different elements 
    $\lang=\set{\sigma_0,\ldots \sigma_{k-1}}$ then the elements of the set
    $\set{\sigma_0^2,\ldots \sigma_{k-1}^2}\subseteq \lang^2$ are different.
  \item The language $\lang=\set{\emptystring}$ has
    $\lang^2=\set{\emptystring}$.
  \item Let $\lang=\set{\sigma_0,\sigma_1,\ldots \sigma_{k-1}}$ for $k\in\N^+$ 
    (we take these strings to all be different from each other).
    Then the list
    $\sigma_0\concat\sigma_0$, $\sigma_0\concat\sigma_1$,
    \ldots{} $\sigma_{k-1}\concat\sigma_{k-1}$ has length~$k^2$.
    Hence the largest number of elements that $\lang^2$ can have is~$k^2$.
  \item Consider the language 
    $\lang=\set{\sigma_0, \sigma_1,\ldots \sigma_{k-1}}$ 
    where the $k$-many strings have length one and are unequal, 
    so each consists of a single symbol that is different from the symbols used
    in any of the others.
    Clearly all of the members of the list 
    $\sigma_0\concat\sigma_0$, $\sigma_0\concat\sigma_1$,
    \ldots{} $\sigma_{k-1}\concat\sigma_{k-1}$
    are unequal, and so $\lang^2$ has $k^2$-many elements.
  \end{exparts}
\end{answer}
\end{exercise}

\begin{exercise}
Another way of defining the powers of a language 
is:~$\lang^0=\set{\emptystring}$,
and $\lang^{k+1}=\lang^k\concat\lang$.

\begin{answer}
  To prevent confusion between the two forms, denote 
  $\set{\sigma_0\concat\cdots\concat\sigma_{k-1}\suchthat \sigma_i\in\lang}$
  as ${}^k\!\lang$, for the purpose of this argument.

  We first show that any element of ${}^k\!\lang$ is an element of 
  $\lang^{k}$.
  % so fix $\sigma=\sigma_0\concat\cdots\concat\sigma_{k-1}\in {}^k\lang$.

  $\sigma_0\concat\cdots\concat\sigma_{i-1}\in {}^1\!\lang$

  $\sigma_0\concat\cdots\concat\sigma_{i-1}\in\lang^1$

  any element of any $\lang^k$ is an element of 
  ${}^k\!\lang$.

  $\sigma\in {}^{i}\!\lang$ and so

  Then $\sigma\concat\tau$ has the form

\begin{exercise}
The operations of languages form an algebraic system.
Assume these languages are over the same alphabet.
Show each.
\begin{exparts}
\item Language union and intersection are commmutative,
  $\lang_0\cup\lang_1=\lang_1\cup\lang_0$ and
  $\lang_0\cap\lang_1=\lang_1\cap\lang_0$.
\item
The language consisting of the empty string
is the identity element with respect to language 
concatenation, so $\lang\concat\set{\emptystring}=\lang$
and $\set{\emptystring}\concat\lang=\lang$.  
\item
Language concatenation need not be commutative;
there are lanaguages such that 
$\lang_0\concat\lang_1\neq\lang_1\concat\lang_0$.
\item
Language concatenation is associative,
$(\lang_0\concat\lang_1)\concat\lang_2
  =\lang_0\concat(\lang_1\concat\lang_2)$.
\item 
$\reversal{(\lang_0\concat\lang_1)}
    =\reversal{\lang_1}\concat\reversal{\lang_0}$.
\item 
Concatenation is left distributive over union, 
$(\lang_0\cup\lang_1)\concat\lang_2
 =(\lang_0\concat\lang_2)\,\cup\,(\lang_1\concat\lang_2)$,
and also right distributive.
\item
The empty language is an annihilator for 
concatenation, $\emptyset\concat\lang=\lang\concat\emptyset=\emptyset$.
\item The Kleene star operation is idempotent,
$\kleenestar{(\kleenestar{\lang})}=\kleenestar{\lang}$.
\end{exparts}
\begin{answer}
\begin{exparts}
\item For any sets, languages or not, union and intersection are 
  commutative.
\item We have 
  $\lang\concat\set{\emptystring}=\set{\sigma\concat\emptystring\suchthat \sigma\in\lang}=\set{\sigma\suchthat \sigma\in\lang}=\lang$.
\item Where $\Sigma=\set{\str{a},\str{b}}$
  take $\lang_0=\set{\str{a}}$ and $\lang_1=\set{\str{b}}$.
  Then $\lang_0\concat\lang_1=\set{\str{ab}}$ while
  $\lang_1\concat\lang_0=\set{\str{ba}}$.
\item This is immediate from the fact that string concatenation is
  associative:~the $i$-th entry of $(\sigma_0\concat\sigma_1)\concat\sigma_2$
  is the same as the $i$-th entry of $\sigma_0\concat(\sigma_1\concat\sigma_2)$.
\item This is immediate from the fact that for strings
  $\reversal{(\sigma_0\concat\string_1)}$ equals
  $\reversal{\sigma_1}\concat\reversal{\sigma_0}$.
\item A string is an element of $(\lang_0\cup\lang_1)\concat\lang_2$
  if and only if it has the form $\sigma\concat\tau$ where
  $\tau\in\lang_2$, and $\sigma\in\lang_0$ or $\sigma\in\lang_1$.
  That's true if and only if both $\tau\in\lang_2$ and $\sigma\in\lang_0$,
  or both $\tau\in\lang_2$ and $\sigma\in\lang_1$.
  In turn that holds if and only if 
  $\sigma\in(\lang_0\concat\lang_2)\cup(\lang_1\concat\lang_2)$.
  The right-distributive argument goes the same way.
\item For any language~$\lang$ the definition gives
  $\emptyset\concat\lang=\set{\sigma_0\concat\sigma_1
    \suchthat \text{$\sigma_0\in\emptyset$ and $\sigma_1\in\lang$}}$.
  The condition `$\sigma_0\in\emptyset$' is never satisfied so this
  set is empty.
  The same goes for $\lang\concat\emptyset$.
\item For any strings, no matter how the concatenation is 
  parenthesized we can remove the parentheses.
  For instance, $((\sigma_0\concat\sigma_1)\concat\sigma_2)\concat\sigma_3$ 
  equals $((\sigma_0\concat(\sigma_1\concat\sigma_2))\concat\sigma_3$
  becuase the $i$-th elements of the two are equal.
  (We can easily show this statement by induction.)
  From this, the result is immediate.
\end{exparts}
\end{answer}
\end{exercise}

\section{Grammars}\index{grammar|(}  \label{sec:Grammars}
We have defined that a language is a set of strings.
But this allows for any willy-nilly set. 
\citetext{In practice a language is usually given by rules}{%
  Linguists started formalizing 
  the description of language, including phrase structure, at the start of the 
  1900's.
  Meanwhile, string rewriting rules as formal, abstract systems were introduced 
  and studied by mathematicians including Axel Thue in 1914, 
  Emil Post from the 1920's through the 1940's and Turing in 1936. 
  Noam Chomsky, while teaching linguistics to students of 
  information theory at MIT, combined linguistics and mathematics by 
  taking Thue's formalism as the basis for the description of the syntax of 
  natural language.  \autocite{wiki:Linguistics}}.

Here is an example.
Native English speakers will say that the noun phrase
``the big red barn'' sounds fine
but that \citetext{``the red big barn'' sounds wrong.}{%
  Experts 
  vary on the exact rules but one source gives 
  (article) + number + judgement/attitude + size, length, height + age + 
  color + origin + material + purpose + (noun), so that
  ``big red barn'' is size + color + noun, as is
  Another example is ``little green men.'' 
  This is the Royal Order of Adjectives; 
  see \protect\url{http://english.stackexchange.com/a/1159}.
  A person may object by citing ``big bad wolf'' but it turns out there is
  another, stronger, rule that if there are three words then they have to
  go I-A-O and if there are two words then the order has to
  be I followed by either A or O.
  Thus we have tick tock but not tock tick. 
  Similarly for tic-tac-toe, mishmash, King Kong, or dilly dally.}
That is, sentences in natural languages are constructed 
in patterns and the second of those does not follow the English pattern.
Artificial languages such as programming languages
also have syntax rules, usually 
\citetext{very strict rules}{%
  Everyone who has programmed has had a compiler chide them about
  a syntax violation.}. 

A grammar a set of rules for the formation of strings in a language,
that is, it is an analysis of the structure of a language.
In an aphorism, 
\citetext{grammars are the language of languages.}{%
  From Matt Swift,
  \protect\url{http://matt.might.net/articles/grammars-bnf-ebnf/}.} 


\subsection{Definition}
Before the formal definition we'll first see 
an example.

\begin{example}
This is a subset of the rules for for English:
\begin{parenum} 
%<*ex:RulesForEnglish>
\item~a sentence can be made from a noun phrase followed by a verb phrase,
\item~a noun phrase can be made from an article followed by a noun,
\item~a noun phrase can also be made from an article then an adjective then a 
  noun,
\item~a verb phrase can be made with a verb followed by a noun phrase,
\item~one article is `the',
\item~one adjective is `young',
\item~one verb is `caught',
\item~two nouns are `man' and `ball'.
%</ex:RulesForEnglish>
\end{parenum}

This is a convenient notation for the rules just listed.
%<*ex:GrammarRulesForEnglish>
\begin{grammar}
\ntrm{sentence}  \produces{} \ntrm{noun phrase} \ntrm{verb phrase} 

\ntrm{noun phrase}  \produces{} \ntrm{article} \ntrm{noun}  

\ntrm{noun phrase}  \produces{} \ntrm{article} \ntrm{adjective} \ntrm{noun} 

\ntrm{verb phrase} \produces{} \ntrm{verb} \ntrm{noun phrase} 

\ntrm{article} \produces{} \trm{the}  

\ntrm{adjective} \produces{} \trm{young}  

\ntrm{verb} \produces{} \trm{caught}  

\ntrm{noun} \produces{} \trm{man} \syntaxor \trm{ball}
\end{grammar}
%</ex:GrammarRulesForEnglish>
\end{example}

%<*discussion:GrammarVocabulary>
Each line is a \definend{production}\index{production in a grammar}\index{grammar!production} 
or \definend{rewrite rule}.\index{rewrite rule in a grammar}\index{grammar!rewrite rule}
Each has one arrow, \productionsymbol{}.\footnote{%
  Read the arrow aloud
  as ``may produce,'' or ``may expand to,'' or ``may be constructed as.''}
To the left of each arrow is a 
\definend{head}\index{head of a production}\index{grammar!head} 
and to the right is 
a \definend{body}\index{body of a production}\index{grammar!body of a production} 
or 
\definend{expansion}.\index{expansion of a production}\index{grammar!expansion of a production}
Sometimes two rules have the same head,
as with 
\synt{noun phrase}. 
There are also two rules for \synt{noun} but 
we have abbreviated by combining 
the bodies using the 
\index{pipe symbol@pipe symbol, \syntaxor}`\syntaxor'~pipe symbol.\footnote{%
 Read aloud as ``or.''}

We make rules using two different kinds of components.
The  kind written in typewriter type, such as
\trm{young},
are from the alphabet~$\Sigma$ of the language.
These are 
\definend{terminals}.\index{terminal}\index{grammar!terminal}  
The kind written with angle brackets and in italics, such as \ntrm{article}, 
are 
\definend{nonterminals}.\index{nonterminal}\index{grammar!nonterminal}
These are like variables, and are
used for intermediate steps.

The two symbols `\productionsymbol{}' and `\grammarorsymbol' are neither 
terminals nor nonterminals.
They are \definend{metacharacters},\index{metacharacter}
part of the syntax of the rules themselves.
%</discussion:GrammarVocabulary>

%<*discussion:DerivationVocabulary>
These rewrite rules govern the 
\definend{derivation}\index{derivation}\index{grammar!derivation} 
of strings in the language.
Under the English grammar 
every derivation starts with \ntrm{sentence}.
Along the way, intermediate strings contain a mix of nonterminals and 
terminals.
The rules all have a head with a single nonterminal. 
So to derive the 
next string,
pick a nonterminal in the present string and substitute an associated rule body.
\begin{center}
  \begin{tabular}{r@{}l}
  \synt{sentence} &\derives \synt{noun phrase} \synt{verb phrase}  \\
    &\derives \synt{article} \synt{adjective} \synt{noun} \synt{verb phrase}  \\
    &\derives \str{the} \synt{adjective} \synt{noun} \synt{verb phrase}  \\
    &\derives \str{the} \str{young} \synt{noun} \synt{verb phrase}  \\
    &\derives \str{the} \str{young} \str{man} \synt{verb phrase}  \\
    &\derives \str{the} \str{young} \str{man} \synt{verb} \synt{noun phrase}  \\
    &\derives \str{the} \str{young} \str{man} \str{caught} \synt{noun phrase}  \\
    &\derives \str{the} \str{young} \str{man} \str{caught} \synt{article} \synt{noun}  \\
    &\derives \str{the} \str{young} \str{man} \str{caught} \str{the} \synt{noun}  \\
    &\derives \str{the} \str{young} \str{man} \str{caught} \str{the} \str{ball}  
  \end{tabular}
\end{center}
Note that the single line arrow \productionsymbol{} is for  rules 
while the double line arrow \derivessymbol{} is for derivations.\footnote{%
  Read `\derivessymbol{}' aloud as ``derives'' or ``expands to.''}

That derivation always substitutes for the leftmost nonterminal
so it is a \definend{leftmost derivation}.\index{derivation}\index{leftmost derivation}
However, in general 
we could substitute for any nonterminal.
%</discussion:DerivationVocabulary>

%<*discussion:DerivationTree>
The \definend{derivation tree}\index{derivation tree}
or \definend{parse tree}\index{parse tree} is an alternative representation.\footnote{%
  The terms
  `terminal' and `nonterminal' come from where the components lie in this tree.}
%</discussion:DerivationTree>
\begin{center}

\end{center}

%<*def:Grammar>
\begin{definition}
A \definend{context-free grammar},\index{context free!grammar}\index{grammar!context free}\index{grammar}\index{language!grammar}
is a four-tuple $\mathcal{G}=\sequence{\Sigma,N,S,P}$.
First, $\Sigma$ is an alphabet, whose elements are the
\definend{terminal symbols}.\index{terminal}
Second, $N$ is a set of \definend{nonterminals}\index{nonterminal} 
or \definend{syntactic categories}.\index{syntactic category}\index{grammar!syntactic category}
(We assume that $\Sigma$ and~$N$ are disjoint and that
neither contains metacharacters.)
Third, $S\in N$ is the \definend{start symbol}.\index{start symbol}\index{grammar!start symbol} 
Fourth, $P$ is a set of 
\definend{productions}\index{production}\index{grammar!production}
or \definend{rewrite rules}.\index{rewrite rule}\index{grammar!rewrite rule}
\end{definition}

\noindent We will take the start symbol to be 
the head of the first rule.
%</def:Grammar>

\begin{example} \label{ex:GrammarOfTerms}
This context free grammar describes algebraic expressions that 
involve only addition, multiplication, and parentheses.
\begin{grammar}
\ntrm{expr} \produces{} \ntrm{term} \trm{+} \ntrm{expr} \syntaxor \ntrm{term}

\ntrm{term} \produces{} \ntrm{term} \trm{*} \ntrm{factor} \syntaxor \ntrm{factor}

\ntrm{factor} \produces \trm{(} \ntrm{expr} \trm{)} \syntaxor 
  \trm{a} \syntaxor \trm{b} \syntaxor \ldots{} \syntaxor \trm{z}
\end{grammar}

\begin{center}
  \begin{tabular}{r@{}l}
    \ntrm{expr}
    &\derives\ntrm{term}              \\
    &\derives\ntrm{term} \trm{*} \ntrm{factor} \\           
    &\derives\ntrm{factor} \trm{*} \ntrm{factor}  \\
    &\derives\trm{x} \trm{*} \ntrm{factor}       \\
    &\derives\trm{x} \trm{*} \trm{(} \ntrm{expr} \trm{)}  \\  
    &\derives\trm{x} \trm{*} \trm{(} \ntrm{term} \trm{+} \ntrm{expr} \trm{)}  \\  
    &\derives\trm{x} \trm{*} \trm{(} \ntrm{term} \trm{+} \ntrm{term} \trm{)}  \\

We next give a complete description of how the production rules
govern the derivations.
Each rule in a context free grammar 
has the form \mbox{`head\produces{}body'} where
the head consists of a single nonterminal.
The body is a sequence of terminals and nonterminals.
% (such a string is a 
% \definend{sentential form}).\index{sentential form}
Each step of a derivation has the form below,
where $\tau_0$ and $\tau_1$ are sequences of terminals and non-terminals.
\begin{center}
  $\tau_0\concat\text{head}\concat\tau_1$
  \quad\derives\quad
  $\tau_0\concat\text{body}\concat\tau_1$
\end{center}
That is, if there is a match for the rule's head
then we can replace it with the body.

Where $\sigma_0,\sigma_1$ are sequences of terminals and nonterminals,
if they are related by a sequence of derivation steps then
we may write $\sigma_0\kleenestar{\derivessymbol}\,\sigma_1$.
Where $\sigma_0=S$ is the start symbol, 
if there is a derivation $\sigma_0\;\kleenestar{\derivessymbol}\;\sigma_1$ that
finishes with 
a string of terminals $\sigma_1\in\kleenestar{\Sigma}$ then we say
that $\sigma_1$ \definend{has a derivation}\index{derivation}
 from the grammar.\footnote{%
  This definition of rules, grammars, and derivations suffices for us
  but it is not the most general one.
  One more general definition allows heads of the form
  $\sigma_0X\sigma_1$, where $\sigma_0$ and~$\sigma_1$ are 
  strings of terminals.
  % In that ruls
  % that provide a context
  % for the nonterminal~$S$, and substitutions for $S$ are only allowed in context.
  (The $\sigma_i$'s can be empty.)
  \protect\label{ex:anbncnGrammar}
  For example, consider
  \citetext{this grammar}{%
  Taken from \protect\url{https://en.wikipedia.org/wiki/Formal_grammar}.}:  
  (i)~S\produces{} \str{a}BS\str{c} | \str{abc},
  (ii)~B\str{a}\produces{}\str{a}B,
  (iii)~B\str{b}\produces{}\str{bb}.
  Rule~(ii) says that if you see a string 
  with something followed by \str{a} then you
  can replace that string with \str{a} followed by that thing.
  For instance, in the derivation
  S 
  \derives\str{a}BS\str{c}
  \derives\str{a}B\str{abcc}
  \derives\str{aa}B\str{bcc}
  \derives\str{aabbcc}
  the third step uses~(ii)
  and the fourth step uses~(iii).
  Grammars with heads of the form
  $\sigma_0X\sigma_1$  are \protect\definend{context sensitive}
  because we can only
  substitute for~X in the context of $\sigma_0$ and~$\sigma_1$.
  These grammars describe more languages than the context free ones that
  we are using.
  But our definition satisfies our needs and is
  the class of grammars that you will see in practice. 
  % because it is a good balance of convenience and power. 
  } 

This description is like the one on 
page~\pageref{text:DescriptionOfTMAction}
detailing how 
a Turing machine's instructions determine the evolution of the
sequence of configurations that is a computation.
That is, production rules are like a program, directing a 
derivation.
However, one difference from that page's description is that there
Turing machines are deterministic, so that from a given
input string there is a determined sequence of configurations.
Here, from a given start symbol a derivation can branch out to 
go to many different ending strings.

\end{definition}

\begin{example}
Any finite language is derived from a grammar.
This one gives the language of all length~$2$ bit strings, using the brute 
force approach of just listing all the member strings.

\begin{grammar}
  S \produces{} 
   \trm{00} \syntaxor \trm{01} \syntaxor \trm{10} \syntaxor \trm{11}
\end{grammar}

\noindent This gives the length~$3$ bit strings
by using the nonterminals to keep count.

\begin{grammar}
  A \produces{} \trm{0}B \syntaxor \trm{1}B

  B \produces{} \trm{0}C \syntaxor \trm{1}C

  C \produces{} \trm{0} | \trm{1}
\end{grammar}
\end{example}

\begin{example}
\begin{credit}
  SE user \href{https://cs.stackexchange.com/a/75423/67754}{Rick Decker}
\end{credit}
For this grammar 
\begin{grammar}
  S \produces{} \trm{a}S\trm{b} \syntaxor T \syntaxor U
 
  T \produces{} \trm{a}S \syntaxor \trm{a}

  U \produces{} S\trm{b} \syntaxor \trm{b} 
\end{grammar}
an alternative is to replace 
T and U by their
expansions to get this.

\begin{grammar}
S \produces{} \trm{a}S\trm{b} \syntaxor \trm{a}S 
         \syntaxor \trm{a} \syntaxor S\trm{b} \syntaxor \trm{b}
\end{grammar}

\noindent It generates the language
$\lang=\set{\str{a}^i\str{b}^j\in\kleenestar{\set{\str{a},\str{b}}} \suchthat\text{$i\neq0$ or $j\neq 0$}}$.

The prior example is the first one where the generated language is not clear
so we will do a formal verification. 
We will show mutual containment, that the generated language is a 
subset of~$\lang$ and that it is also a superset.
The rule that eliminates T and~U 
shows that any derivation step 
$\tau_0\concat\text{head}\concat\tau_1$
  \derives~$\tau_0\concat\text{body}\concat\tau_1$
only adds \trm{a}'s on the left and 
\trm{b}'s on the right, so every string in the language has the form
$\str{a}^i\str{b}^j$.
That same rule shows that in any terminating derivation S 
must eventually be replaced by either \trm{a} or \trm{b}.
Together these two give that the generated language is a subset of~$\lang$.

For containment the other way, we will prove that every $\sigma\in\lang$ 
has a derivation.
We will use induction on the length $\lh{\sigma}$.
By the definition of~$\lang$ 
the base case is $\lh{\sigma}=1$.
In this case either $\sigma=\str{a}$ or~$\sigma=\str{b}$,
each of which obviously has a derivation.

For the inductive step, 
suppose that every string from $\lang$ of length $k=1$, \ldots, $k=n$ 
has a derivation for $n\geq 1$
and let $\sigma$ have length $n+1$.
Write $\sigma =\str{a}^i\str{b}^j$.
There are three cases: either $i>1$, or $j>1$, or~$i=j=1$.
If $i>1$ then $\hat{\sigma} =\str{a}^{i-1}\str{b}^{j}$ is a string of
length~$n$, so by the inductive hypothesis it has a derivation
S\derives$\cdots$\derives{}~$\hat{\sigma}$.
Prefixing that derivation with
a S\derives{}\trm{a}S step will put an
addional \str{a} on the left.
The $j>1$~case works the same way,
and $\sigma=\str{a}^1\str{b}^1$ is easy.
\end{example}

  \ntrm{expr}\derives\ntrm{expr}\trm{+}\ntrm{expr}
  \derives\trm{a} \trm{+} \ntrm{expr}                 \\ \quad
  \derives\trm{a} \trm{+} \ntrm{expr} \trm{*} \ntrm{expr}          
  \derives\trm{a} \trm{+} \trm{b} \trm{*} \ntrm{expr}          
  \derives\trm{a} \trm{+} \trm{b} \trm{*} \trm{c}          
\end{tabular}        \\[1ex]
\hspace{1em}\begin{tabular}{l}
  \ntrm{expr}\derives\ntrm{expr} \trm{*} \ntrm{expr}
  \derives\ntrm{expr} \trm{+} \ntrm{expr} \trm{*} \ntrm{expr}    \\ \quad 
  \derives\trm{a} \trm{+} \ntrm{expr} \trm{*} \ntrm{expr}  
  \derives\trm{a} \trm{+} \trm{b} \trm{*} \ntrm{expr}  
  \derives\trm{a} \trm{+} \trm{b} \trm{*} \trm{c}          
\end{tabular}
\end{center}
The two give different parse trees.
\begin{center}
  \includegraphics{languages/asy/parsetree/parsetree002.pdf}
  \hspace{2.5em}
  \includegraphics{languages/asy/parsetree/parsetree003.pdf}
\end{center}
Again, the issue is that we get two different behaviors. 
For instance, substitute
$1$ for~\str{a}, and $2$ for~\str{b}, and $3$ for~\str{c}.
The left tree gives $1+(2\cdot 3)=7$ while the right tree
gives $(1+2)\cdot 3=9$.

In contrast, this grammar for elementary algebra expressions  
is unambiguous.

\begin{grammar}
\ntrm{expr} \produces{} \ntrm{expr} \trm{+} \ntrm{term}  
       \othersyntax  \ntrm{term}

\ntrm{term} \produces{} \ntrm{term} \trm{*} \ntrm{factor} 
         \othersyntax  \ntrm{factor}

\ntrm{factor} \produces{} \trm{(} \ntrm{expr} \trm{)}    
        \othersyntax  \trm{a}  \syntaxor  \trm{b}  \syntaxor \ldots{} 
         \syntaxor \trm{z}
\end{grammar}

\noindent Chooosing grammars that are not ambiguous is important in practice.
\end{example}

\begin{exercise}  \label{exer:VerifyAnbn}
Verify that the language derived from the 
grammar in \cref{ex:GrammarOfanbn}
is $\lang=\set{\str{a}^n\str{b}^n\suchthat n\in\N}$.
\begin{answer}
  We will use induction to show that 
  in the course of a derivation all of the results are of either the form
  either \mbox{$\trm{a}^k$ S $\trm{b}^k$} or of the form
  \mbox{$\trm{a}^k\trm{b}^k$}.
  By the definition of the language generated by a grammar,
  only strings without any nonterminals are in the language so
  that will give the verification. 

  The induction is on the number of derivation steps, that is,
  on the number of rule applications.
  The base step is that there are zero-many rule applications.
  In this case the string is~`S', which is the $k=0$ instance of the 
  desired form.

  For the inductive step assume that the statement is true where the 
  number of rule applications is  $n=0$, $n=1$, \ldots $n=k$ and consider
  the $n=k+1$ case. 
  We get the string for the $k+1$ case by applying a rule to 
  a string after the~$k$ case.
  The inductive hypothesis is that such a string has one of two 
  forms, \mbox{$\trm{a}^k$ S $\trm{b}^k$} or
  \mbox{$\trm{a}^k \trm{b}^k$}.
  The rules don't apply to the latter string so consider the former one.

  Applied to \mbox{$\trm{a}^k$ S $\trm{b}^k$} the first rule gives
  \mbox{$\trm{a}^{k+1}$ S $\trm{b}^{k+1}$}, which has the right form.
  The second rule gives \mbox{$\trm{a}^{k+1}\trm{b}^{k+1}$}, again of the
  right form.
\end{answer}
\end{exercise}

%<*def:Graph>
\begin{definition}\index{graph} \label{def:SimpleGraph}
A \definend{simple graph}\index{simple graph}\index{graph!simple} 
is an ordered pair
$\mathcal{G}=\sequence{\mathcal{V},\mathcal{E}}$ where
$\mathcal{V}$ is a finite set of
\definend{vertices}\footnotemark[1]\index{vertex}\index{graph!vertex} 
or \definend{nodes}\index{node}\index{graph!node}
and $\mathcal{E}$ is a set of \definend{edges}.\index{edge}\index{graph!edge}

%<*def:Adjacent>
\begin{definition}
Two graph edges are 
\definend{adjacent}\index{adjacent}\index{graph!adjacent edges}
if they share a vertex, so that they are $uv$ and~$vw$.
A \definend{walk}\index{walk}\index{graph!walk} 
is a sequence of adjacent edges 
$\sequence{v_0v_1,\,v_1v_2,\,\ldots,\,v_{n-1}v_n}$.
Its \definend{length}\index{length}\index{walk length}\index{graph!walk length} 
is the number of edges, $n$.
% Its \definend{initial vertex} is~$v_0$ and its \definend{final vertex} is~$v_n$.
If the initial vertex~$v_0$ equals the final vertex~$v_n$ then is 
\definend{closed}\index{closed walk}\index{graph!closed walk} 
walk, otherwise it is 
\definend{open}.\index{open walk}\index{graph!open walk}
If no edge occurs twice then it is a 
\definend{trail}.\index{trail}\index{graph!trail}
If a trail's vertices are distinct, 
except possibly that the initial vertex equals the final vertex,
then it is a \definend{path}.\index{path}\index{graph!path}
A closed path with at least one edge is a 
\definend{cycle}.\index{cycle}\index{graph!cycle} 
A graph is 
\definend{connected}\index{connected graph}\index{graph!connected} 
if between any two vertices there is a path.
\end{definition}
%</def:Adjacent>

There are many variations of \cref{def:SimpleGraph}, used for
modeling circumstances that a simple graph cannot model.
One variant allows that some vertices to  
connect to themselves, forming a 
\definend{loop}.\index{loop}\index{graph!loop}

% an edge to be a one-element set.

Another is a 
\definend{multigraph},\index{multigraph}\index{graph!multigraph}
which allows two vertices to have more than one edge between them. 
Still another is
a 
\definend{weighted graph},\index{weighted graph}\index{graph!weighted} 
which gives
each edge a real number 
\definend{weight},\index{edge weight}\index{weight}\index{graph!edge weight} 
perhaps signifying the distance
or the cost in money or in time to traverse that edge.

A very common variation is a 
\definend{directed graph}\index{directed graph}\index{graph!directed} 
or \definend{digraph},\index{digraph}\index{graph!digraph} 
where 
edges have a direction, 
as in a road map that includes one-way streets.

and also has loops.

Some important graph variations involve the nature of the connections.

is an undirected connected graph with no cycles.
At the start of this section is a syntax tree.

\definend{directed acyclic graph}\index{directed acyclic graph}\index{graph!directed acyclic}

\definend{DAG}\index{DAG}

\begin{definition}

\definend{Euler circuit},\index{circuit!Euler}\index{Euler circuit}\index{graph!Euler circuit}

%<*def:Subgraph>
\begin{definition}
Where $\mathcal{G}=\sequence{\mathcal{V},\mathcal{E}}$ is a graph,
a \definend{subgraph}\index{subgraph}\index{graph!subgraph}
$\hat{\mathcal{G}}=\sequence{\hat{\mathcal{V}},\hat{\mathcal{E}}}$
satisfies
$\hat{\mathcal{V}}\subseteq\mathcal{V}$ and
$\hat{\mathcal{E}}\subseteq\mathcal{E}$.

for every $e=v_iv_j\in\mathcal{E}$ such that $v_i,v_j\in\hat{\mathcal{V}}$

\definend{induced subgraph}.\index{induced subgraph}\index{subgraph!induced}\index{graph!induced subgraph}

\subsection{Graph representation}\index{graph!representation|(}
A common way to 
\citetext{represent a graph in a computer}{%
  \Cref{ex:SimpleGraphFiveVert} make the point that a graph 
  is about the connections between vertices, not about how it is drawn. 
  This graph representation via a matrix
  also illustrates that point because it is, after all, not drawn.} 
is with a matrix.
This example represents \cref{ex:SimpleGraphFiveVert}'s graph:
it has a~$1$ in the $i,j$~entry if the graph has an edge from $v_i$ to~$v_j$
and a~$0$ otherwise.
\begin{equation*}
  \mathcal{M}(\mathcal{G})=
  \begin{blockarray}{*{6}{c}}
           &v_0 &v_1 &v_2 &v_3 &v_4    \\
    \begin{block}{c(*{5}{c})}
      v_0  &0   &1   &1  &0   &0  \\
      v_1  &1   &0   &1  &1   &1  \\
      v_2  &1   &1   &0  &1   &1  \\
      v_3  &0   &1   &1  &0   &1  \\
      v_4  &0   &1   &1  &1   &0  \\
    \end{block}
  \end{blockarray}
  \tag{$*$}
\end{equation*}

%<*def:AdjacencyMatrix>
\begin{definition}
For a graph~$\mathcal{G}$, the
\definend{adjacency matrix}\index{adjacency matrix}\index{graph!matrix representation} 
$\mathcal{M}(\mathcal{G})$
representing the graph has $i,j$ entries equal to
the number of edges from $v_i$ to~$v_j$.
\end{definition}
%</def:AdjacencyMatrix>

This definition covers graph variants that were listed earlier.
For instance, the graph represented in ($*$)
is a simple graph because the matrix has only $0$ and~$1$ entries,
because all the diagonal entries are~$0$,
and because the matrix is symmetric, meaning that the $i,j$ entry has 
a~$1$ if and only if the $j,i$ entry is also~$1$.
If a graph has a loop then the matrix has 
a diagonal entry that is a positive integer.
If the graph is directed and has a one-way edge from $v_i$ to~$v_j$
then the $i,j$ entry records that edge but the $j,i$ entry does not. 
And for a multigraph, where there are multiple edges from one vertex to 
another, the associated entry will be larger than~$1$.

\begin{lemma} \label{lem:MatPowerPatahsLengthN}
Let the matrix $\mathcal{M}(\mathcal{G})$ represent
the graph~$\mathcal{G}$.
Then in its matrix multiplicative $n$-th power
the $i,j$ entry is the number of paths of length~$n$
from vertex~$v_i$ to vertex~$v_j$.
\end{lemma}
%</lem:MatrixPowersAdjacencyMatrix>

\begin{proof}
\Cref{exer:MatPowerPatahsLengthN}.
\end{proof}

\subsection{Graph isomorphism}\index{graph!isomorphism|(}
We sometimes want to know when two graphs are essentially identical.
Consider these two.
\begin{center}
  \vcenteredhbox{\includegraphics{languages/asy/graphs/graphs11.pdf}}
  \hspace*{3em}
  \vcenteredhbox{\includegraphics{languages/asy/graphs/graphs12.pdf}}
\end{center}
They have the same number of vertices and the same number of edges.
Further, on the right as well as on the left
there are two classes of vertices where all the vertices in the first class
connect to all the vertices in the second class (on the left the two classes 
are the top and bottom rows while on the right they
are $\set{w_0,w_2,w_4}$ and $\set{w_1,w_3,w_5}$).
A person may suspect that as in \cref{fig:DrawTwoWays} these are two
ways to draw the same graph, with the vertex names changed for further 
obfuscation.

That's true:~if we make a correspondence between
the vertices in this way
\begin{center}  \small
  \begin{tabular}{r|cccccc}
    \tabulartext{Vertex on left} &$v_0$ &$v_1$ &$v_2$ &$v_3$ &$v_4$ &$v_5$ \\
    \cline{2-7}
    \tabulartext{Vertex on right} &$w_0$ &$w_2$ &$w_4$ &$w_1$ &$w_3$ &$w_5$ \\
  \end{tabular}
\end{center}
then as a consequence the edges also correspond.
\begin{center}  \small
  \begin{tabular}{@{}r|cccccc@{}}
    \tabulartext{Edge on left} 
      &$\set{v_0,v_3}$ &$\set{v_0,v_4}$ &$\set{v_0,v_5}$
      &$\set{v_1,v_3}$ &$\set{v_1,v_4}$ &$\set{v_1,v_5}$  \\
    \cline{2-7}
    \tabulartext{Edge on right} 
      &$\set{w_0,w_1}$ &$\set{w_0,w_3}$ &$\set{w_0,w_5}$
      &$\set{w_2,w_1}$ &$\set{w_2,w_3}$ &$\set{w_2,w_5}$  \\
  \end{tabular}                               \\[1ex]
  \hspace*{-8em}
  \begin{tabular}{r|ccc}
    \tabulartext{Edge on left (cont)} 
      &$\set{v_2,v_3}$ &$\set{v_2,v_4}$ &$\set{v_2,v_5}$  \\
    \cline{2-4}
    \tabulartext{Edge on right} 
      &$\set{w_2,w_1}$ &$\set{w_2,w_3}$ &$\set{w_2,w_5}$  \\
  \end{tabular}
\end{center}
% For instance, for the first edge on the left $\set{v_0,v_3}$, we are associating
% $v_0\leftrightarrow w_0$ and~$v_3\leftrightarrow w_1$ 
% so we look on the right for an edge
% $\set{w_0,w_1}$ and sure enough, it is there.

%<*def:GraphIsomorphism>
\begin{definition}  \label{def:GraphIsomorphism}
Two graphs $\mathcal{G}$ and $\hat{\mathcal{G}}$ are 
\definend{isomorphic}\index{isomorphism}\index{isomorphic}\index{graph!isomorphism}
if there is a one-to-one and onto map $\map{f}{\mathcal{V}}{\hat{\mathcal{V}}}$
such that $\mathcal{G}$ has an edge $\set{v_i,v_j}\in\mathcal{E}$
if and only if $\hat{\mathcal{G}}$ has the associated edge 
$\set{f(v_i),f(v_j)}\in\hat{\mathcal{E}}$.
\end{definition}
%</def:GraphIsomorphism>

To verify that two graphs are isomorphic 
the most natural thing is to produce the map~$f$ and then verify that 
in consequence the edges also correspond. 
The exercises have examples.

%<*discussion:GraphIsomorphism>
Showing that graphs are not isomorphic usually entails finding some 
graph-theoretic way in which they differ. 
A common and useful such property is to consider 
the 
\definend{degree of a vertex},\index{degree of a vertex}\index{graph!vertex degree} 
the total number of edges touching
that vertex with the proviso that 
a loop from the vertex to itself counts as two.
The 
\definend{degree sequence}\index{degree sequence}\index{graph!degree sequence} 
of a graph is the non-increasing sequence
of its vertex degrees.
%</discussion:GraphIsomorphism>
Thus, the graph in \cref{ex:CommitteeColoring} has degree sequence
$\sequence{3,2,1,1,1}$.
\Cref{exer:DegreeSequenceMustMatch} shows that if graphs are isomorphic then
associated vertices have the same degree and 
thus graphs with different degree sequences are not isomorphic.
Also, if the the degree sequences are equal then they
help us construct an isomorphisms, if there is one;~examples 
of this are in the exercises.
(There are graphs with the same degree sequence that are not isomorphic.)
\index{graph!isomorphism|)}

\begin{exercise}  \label{exer:DegreeSequenceMustMatch}
We can use degrees and degree sequences to help find isomorphisms, or
to show that graphs are not isomorphic.
(Here we allow graphs to have loops and to have multiple edges between
vertices, but we do not make the extension to directed edges or edges with
weights.)
\begin{exparts}
\item Show that if two graphs are isomorphic then they have the same number
of vertices.
\item Show that if two graphs are isomorphic then they have the same number
of edges.
\item
Show that if two graphs are isomorphic and one has a vertex of degree~$k$
then so does the other.
\item 
Show that if two graphs are isomorphic then for each degree~$k$, the number
of vertices of the first graph having that degree equals the number of 
vertices of the second graph having that degree. 
Thus, isomorphic graphs have degree sequences that  
are equal.    
\item
Use the prior result to show that the two graphs of \cref{ex:TwoWalkGraphs}
are not isomorphic.
\end{exparts}
As in the final item, 
in arguments we often use the contrapositive of these statements.
For instance, the first item
implies that if they do not have the same number of vertices then they are
not isomorphic.
\begin{answer}
  \begin{exparts}
  \item By the definition of graph isomorphism, \cref{def:GraphIsomorphism}, 
  if two graphs $\mathcal{G}$ and~$\hat{\mathcal{G}}$ are isomorphic
  then there is a correspondence between their vertices.
  They therefore have the same number of vertices. 
  \item As in the prior item, the definition of graph isomorphism states
  that the edges correspond.
  \item Suppose that $\mathcal{G}=\sequence{\mathcal{V},\mathcal{E}}$ 
  and~$\hat{\mathcal{G}}=\sequence{\hat{\mathcal{V}},\hat{\mathcal{E}}}$
  are isomorphic via the function~$f$\!.
  Let vertex $v\in\mathcal{V}$ have degree~$k$.
  Then in the set~$\mathcal{E}$
  the vertex~$v$ occurs~$k$ times (counting once for edges in which the
  vertex occurs once, and twice for loops on~$v$).

  Apply the correspondence.
  That is, consider the vertex~$f(v)$ 
  and the set~$\hat{\mathcal{E}}$.
  Because $f$ gives a correspondence among edges, the vertex must occur~$k$ 
  times in the set.
  So $f(v)$ has degree~$k$.
  \item This is the same as the prior item, but instead of a single vertex~$v$
  there is a sequence of vertices $v_0,\ldots v_n$.
  \item The degree sequences differ.
    On the left the degree sequence is $\sequence{3,3,3,3}$
    while on the right it is $\sequence{4,4,4,4,4,4,4,4}$. 
  \end{exparts}
\end{answer}
\end{exercise}

\extra{BNF}\index{BNF|(}  % http://www.bottlecaps.de/rr/ui
We shall introduce some widely used notation conveniences for grammars.
Together they are called 
\definend{Backus-Naur form, BNF}.\index{Backus-Naur form, BNF}\index{grammar!Backus-Naur form, BNF}\index{grammar!BNF, Backus-Naur form}

\margingraphic[l]{1.75cm}{languages/pix/backus.jpg}{\href{https://en.wikipedia.org/wiki/John_Backus}{John Backus 1924--2007}}\index{Backus, J!picture}
The study of grammar, the rules for phrase structure and forming sentences,
has a long history, dating back as early as the fifth century BC.
Mathematicians, including A~Thue and E~Post, began put their
stamp on it by systematizing it as 
rewriting rules in the early 1900's.
The BNF variant was produced by J~Backus in the late 1950's as part of the
effort to systematize the early computer language ALGOL60. 
Since then these rules have become
\citetext{a widely used way to express grammars}{%
  One factor influencing its adoption was a letter that D~Knuth
  wrote to the \textit{Communications of the ACM}
  \autocite{KnuthCACM}.
  He proposed the name Bacus Naur Form and listed
  some advantages over the grammar-specification
  methods that were then widely used.
  Most importantly, he contrasted BNF's `\texttt{<addition operator>}'
  with `\texttt{A}', saying that the difference is a great addition
  to ``the \textit{explanatory power} of a syntax.''
}.

\margingraphic[r]{0.15\textwidth}{languages/pix/naur.jpg}{\label{fig:naur}\href{https://en.wikipedia.org/wiki/Peter_Naur}{Peter Naur 1928--2016}}\index{Naur, P!picture}
One difference from the prior subsection is a minor typographical 
change. 
(These adjustments were made by P~Naur;~originally the metacharacters
were not typeable with a standard keyboard.
The advantage of having metacharacters not on a keyboard is that
most likely all of the language characters are typeable.
So there is no need to distinguish, say, between the pipe character $\str{|}$
when used as a part of a language and when used as a metacharacter.
But the disadvantage lies in having to type the untypeable.
In the end the convenience of having typeable characters 
won over the technical gain of having to typographically distinguish 
metacharacters.)\index{metacharacter}
For instance, for a long time there were not arrows on a standard keyboard
so in place of the arrow symbol `$\rightarrow$',
BNF uses
`\bnfsymbol'.

There are other typographical issues that arise with grammars.
While many authors write 
nonterminals with diamond brackets, as we do,
others use other conventions such as italic type or a different 
color.\footnote{%
  For example, syntax coloring is a common feature of programming editors.}

BNF is both clear and concise, it can express the range of languages that
we ordinarily want to express and it smoothly translates to 
a parser.\footnote{%
  BNF is only loosely defined.
  Several variants do have standards
  but what you see often does not conform to any published standard.}
That is, BNF is an impedance match\Dash it fits with what
we typically want to do.
Here we will incorporate 
\citetext{some extensions for grouping and replication}{%
  The best current standard is 
  \protect\url{https://www.w3.org/TR/xml/}.}
that is like what you will see in the wild.

\begin{example}
\citetext{Time is a complicated engineering problem}{% 
  %see https://zachholman.com/talk/utc-is-enough-for-everyone-right
  One example of a complication of time, among many, is leap seconds.
  The Earth is constantly undergoing a deceleration caused by the 
  braking action of the tides. 
  The average deceleration of the Earth is roughly $1.4$ milliseconds per day 
  per century, although the exact number varies from year to year. 
  To ensure that 
  atomic clocks and the Earth's rotational time do not differ  
  by more than $0.9$ seconds,
  occasionally an extra second is added to civil time. 
  This leap second can be either positive or negative depending on the Earth's 
  rotation\Dash on occasion there are minutes with only $58$ seconds, and on
  occasion minutes with~$60$.

  Adding to the confusion is that the changes in rotation are uneven and
  leap seconds cannot be predicted far into the future.  
  The International Earth Rotation Service publishes bulletins that
  announce leap seconds with a few weeks warning. 
  Thus, there is no way to determine how many seconds there will be between 
  the current instant and ten years from now.
  Since the first leap second in 1972, all leap seconds have been positive and 
  there were 23 leap seconds in the 34 years to January, 2006.
  \autocite{web:USNO}}. 
One issue is representing times and one solution in that area is 
\citetext{RFC~3339}{\autocite{rfc3339}},
\textit{Date and Time on the Internet: Timestamps}.
It uses 
\citetext{strings such as \str{1958-10-12T23:20:50.52Z}}{%
  This format has a number of advantages including human readability,
  that if you sort a collection of these strings then earlier times will come
  earlier,
  simplicity (there is only one format),
  and that they include the time zone information.}.
Here is \citetext{a BNF grammar}{%
  Some notes: 
  (1)~Coordinated Universal Time, the basis for civil time, is
  often called UTC, but is sometimes abbreviated Z,
  (2)~years are four digits to prevent the Y2K problem \autocite{y2k},
  (3)~the only month numbers allowed are $01$--$12$ and in each month
  only some day numbers are allowed,
  and (4)~the only time hours allowed are $00$--$23$, minutes must 
  be in the range $00$--$59$, etc. \autocite{rfc3339}}.
Some nonterminals are from \cref{exer:GrammarsForSmallLangs}.
This grammar includes some metacharacter extensions that we will 
discuss below.

   % date-month      = 2DIGIT  ; 01-12
   % date-mday       = 2DIGIT  ; 01-28, 01-29, 01-30, 01-31 based on
   %                           ; month/year
   % time-hour       = 2DIGIT  ; 00-23
   % time-minute     = 2DIGIT  ; 00-59
   % time-second     = 2DIGIT  ; 00-58, 00-59, 00-60 based on leap second
   %                           ; rules
   % time-secfrac    = "." 1*DIGIT
   % time-numoffset  = ("+" / "-") time-hour ":" time-minute
   % time-offset     = "Z" / time-numoffset

   % partial-time    = time-hour ":" time-minute ":" time-second
   %                   [time-secfrac]
   % full-date       = date-fullyear "-" date-month "-" date-mday
   % full-time       = partial-time time-offset

   % date-time       = full-date "T" full-time

One common BNF notation extension is in that grammar's
\ntrm{time-numoffset} rule, where the
parentheses are used as metacharacters to group
a choice between the terminals \trm{+} and~\trm{-}.

The \ntrm{partial-time} rule includes square brackets as metacharacters.
They deonte that the \ntrm{time-secfrac} is optional.
This is a common construct: another exampleis this syntax 
for \str{if ... then ...} with an optional
\str{else ...}.

\begin{grammar}
    \ntrm{if-stmt} \bnfproduces{}  \trm{if} \ntrm{boolean-expr} \trm{then}
                             \ntrm{stmt-sequence}\\*
                        \quad[ \trm{else}
                             \ntrm{stmt-sequence} ]
                        \ntrm{end if} \trm{;}
\end{grammar}

To show repetition BNF may use a superscript Kleene star~$\kleenestar{}$ 
to mean `zero or more'
or a~$\hbox{}^+$ to mean `one or more'.
This shows parentheses and repetition.
\begin{grammar}
 \ntrm{identifier} \bnfproduces{} \ntrm{letter} ( \ntrm{letter} \syntaxor \ntrm{digit} )*
\end{grammar}

Each of these extension constructs is not necessary
since we can express them in plain BNF.
For instance, we could replace the prior rule with this. 

\begin{grammar}
\ntrm{identifier} \bnfproduces{} \ntrm{letter} \syntaxor \ntrm{letter} \ntrm{atoms}

\ntrm{atoms} \bnfproduces{} \ntrm{letter} \ntrm{atoms} \syntaxor \ntrm{digit} \ntrm{atoms} \syntaxor \emptystring
\end{grammar}

\noindent But these constructs come up often enough
that adopting an abbreviation is convenient.
 
\begin{example} \label{ex:PythonFloatingPoint}
This grammar for floating point numbers shows all three 
abbreviations.

\begin{grammar}
\ntrm{floatnumber}   \bnfproduces{}  \ntrm{pointfloat} \syntaxor \ntrm{exponentfloat}

\ntrm{pointfloat}    \bnfproduces{}  [\ntrm{intpart}] \ntrm{fraction} \syntaxor \ntrm{intpart} \trm{.}

\ntrm{exponentfloat} \bnfproduces{}  (\ntrm{intpart} \syntaxor \ntrm{pointfloat}) \ntrm{exponent}

\ntrm{intpart}       \bnfproduces{}  \ntrm{digit}+

\ntrm{fraction}      \bnfproduces{}  \trm{.} \ntrm{digit}+

\ntrm{exponent}      \bnfproduces{}  (\trm{e} \syntaxor \trm{E}) [\trm{+} \syntaxor \trm{-}] \ntrm{digit}+
\end{grammar}

\noindent As part of the \ntrm{pointfloat} rule, the first \ntrm{intpart}
is optional.
An \ntrm{intpart}, what we have earlier called a \ntrm{natural},
consists of one or more digits.
And an expansion of \ntrm{exponent} must start with a choice between 
\str{e} or \str{E}.
\end{example}

Each of these extension constructs is not necessary
since we can express them in plain BNF.
For instance, we could replace the \ntrm{pointfloat} rule with this. 
\begin{grammar}
\ntrm{pointfloat} \bnfproduces{} \ntrm{intpart} \ntrm{fraction} 
    \syntaxor \ntrm{fraction} 
    \syntaxor \ntrm{intpart} \trm{.}
\end{grammar}
But these constructs come up often enough
that adopting an abbreviation is worthwhile.

\begin{remark}
Passing from the grammar to a parser for that grammar is mechanical.
That is, it is natural to write a program that takes as input a grammar
in BNF and gives as output the source code of a program that will
parse files following that grammar's format.
Such a program is a \definend{compiler-compiler}.

At one point there were many compiler-compiler available, with a variety
of different features.
They were amalgamated into one with the production of
YACC, Yet Another Compiler Compiler.
In recent years, YACC has itself been supplanted with a version that is
Free from the GNU project, obviously called Bison.
\end{remark}

\extra{Lambda Calculus and Scheme}
% See http://matt.might.net/articles/compiling-up-to-lambda-calculus/

% Jim Larson
% 1996-07-26
% This talk was given at the JPL Section 312 Programming Lunchtime Seminar.

A function accepts input and produces an output. 
Suppose we have a ``chocolate-covering'' function that produces the 
following outputs for the corresponding inputs:
% \begin{grammar}
%   \str{peanuts} &\produces  \str{chocolate-covered peanuts} \\
%   \str{rasins}  &\produces  \str{chocolate-covered rasins} \\
%   \str{ants}    &\produces \str{chocolate-covered ants}
% \end{grammar}
We can use Lambda-calculus to describe such a function.
\begin{equation*}
	\lambda x.\str{chocolate-covered $x$}
\end{equation*}
This is a \definend{lambda-expression}.

To apply the function to an argument, use the following syntax.
% \begin{equation*}
%   (\lambda x.\str{chocolate-covered $x$})\,\str{peanuts} 
%     \produces \str{chocolate-covered peanuts}
% \end{equation*}
Functions can also be the result of applying a lambda-expression, as with this ``covering function maker.''
\begin{equation*}
  \lambda y.\lambda x.\str{$y$-covered $x$}
\end{equation*}
Use this to create a caramel-covering function.
% \begin{align*}
%   (\lambda y.\lambda x.\str{$y$-covered $x$})\,\str{caramel} 
%     &\produces \lambda x.\str{caramel-covered $x$}   \\
%   (\lambda x.\str{caramel-covered $x$})\,\str{peanuts} 
%     &\produces \str{caramel-covered peanuts}
% \end{align*}
Functions can also be the inputs to other functions, as with this 
``apply-to-ants'' function.
\begin{equation*}
	\lambda f.(f)\,\str{ants}
\end{equation*}
We can feed the chocolate-covering function to the "apply-to-ants" function:
% \begin{multline*}
% 	(\lambda f.\str{$(f)$ants})\lambda x.\str{chocolate-covered $x$}  \\
%       \begin{split}
%         \hspace*{3em}
% 	&\produces (\lambda x.\str{chocolate-covered $x$})\str{ants}  \\
% 	&\produces \str{chocolate-covered ants}
%       \end{split}
% \end{multline*}

Lambda-expressions have the following syntax.
\begin{lstlisting}
	lambda-expression \bnfproduces{}	variable
				| constant
				| application
				| abstraction
	application \bnfproduces{} (lambda-expression)lambda-expression
	abstraction \bnfproduces{} Lvariable.lambda-expression
\end{lstlisting}
The evaluation of lambda-expression is from the application of two reduction 
rules. 
The \definend{alpha-reduction} rule says that 
we can consistantly rename bindings of variables
% \begin{equation*}
% 	\lambda x.E \produces \text{$\lambda z.\{z/x\}E$ 
%                         for any $z$ which is neither free nor bound in $E$}
% \end{equation*}
where $\{z/x\}E$ means the substitution of $z$ for $x$ for any free occurance 
of $x$ in $E$. 
The \definend{beta reduction} rule says that application of a 
lambda-expression to an argument is the consistent replacement of the 
argument for the lambda-expression's bound variable in its body:
\begin{equation*}
	(\lambda x.P)Q -> [Q/x]P
\end{equation*}
where $[Q/x]P$ means the substitution of $Q$ for $x$ for any free occurrance 
of $x$ in $P$.

The Church-Rosser Theorem states that the final result of a chain of 
substitutions does not depend on the order in which the substitutions are 
performed.

\subsection{Universality of Lambda-calculus}
The Lambda-calculus is a universal model of computation, that is, 
any computation that can be expressed in a Turing machine can also be 
expressed in the lambda calculus.

To show this, here is the translation of a conditional control structure 
into lambda-calculus.
\begin{align*}
	\str{true} &= \lambda x.\lambda y.x  \\
	\str{false} &= \lambda x.\lambda y.y        \\
	\str{if-then-else} &= \lambda a.\lambda b.\lambda c.((a)b)c 
\end{align*}
Here is an application of those rules.
% \begin{multline*}
% 	(((\str{if-then-else})\str{false})\str{apple})\str{banana}  \\
%       \begin{split}
%         \qquad 
% 	&\produces (((\lambda a.\lambda b.\lambda c.((a)b)c)\lambda x.\lambda y.y)\str{apple})\str{banana}       \\
% 	&\produces ((\lambda b.\lambda c.((\lambda x.\lambda y.y)b)c)\str{apple})\str{banana}          \\
% 	&\produces (\lambda c.((\lambda x.\lambda y.y)\str{apple})c)\str{banana}  \\
% 	&\produces ((\lambda x.\lambda y.y)\str{apple})\str{banana}   \\
% 	&\produces (\lambda y.y)\str{banana}    \\
% 	&\produces \str{banana}
%      \end{split}
% \end{multline*}
Here is the translation of some data structure operations.
\begin{align*}
	\str{cons} &= \lambda a.\lambda b.\lambda c.((c)a)b   \\
	\str{head} &= \lambda x.(x)\str{true}                  \\
	\str{tail} &= \lambda x.(x)\str{false}               \\
          \\
	0 &= \lambda f.\lambda x.x    \\
	1 &= \lambda f.\lambda x.(f)x  \\
	2 &= \lambda f.\lambda x.(f)(f)x   \\
	3 &= \lambda f.\lambda x.(f)(f)(f)x    \\
        \\
	\str{succ} &= \lambda n.\lambda f.\lambda x.(f)((n)f)x  \\
	+ &= \lambda m.\lambda n.\lambda f.\lambda x.((m)f)((n)f)x   \\
	* &= \lambda m.\lambda n.\lambda f.(m)(n)f           \\
	\str{zero?} &= \lambda n.((n)(\str{true})\str{false})\str{true} \\
	\str{pred} &= \lambda n.(((n)\lambda p.\lambda z.((z)(\str{succ})(p)\str{true})(p)\str{true})Lz.((z)0)0)\str{false}
\end{align*}

Lastly, you can create recursive functions with the \definend{$Y$ combinator}.
\begin{gather*}
	Y = \lambda y.(\lambda x.(y)(x)x)\lambda x.(y)(x)x        \\
	(Y)E -> (E)(Y)E -> \cdots -> (E)\ldots (E)(Y)E
\end{gather*}
We need this to create recursive functions, such as the factorial funtion:
\begin{equation*}
	\str{fact} = \lambda n.(((\str{if-then-else})(\str{zero?})n)1)((*)n)(\str{fact})(\str{pred})n
\end{equation*}
As written, this doesn't work since \str{fact} is a free variable in its 
own definition! We need some way to bind \str{fact} to ``this function,'' 
which can be done with Y.
\begin{equation*}
	\str{fact} = (Y)\lambda f.\lambda n.(((\str{if-then-else})(\str{zero?})n)1)((*)n)(f)(\str{pred})n
        \end{equation*}

        

\subsection{From theory to programming language}
Although the lambda-calculus is powerful enough to express any program, 
this doesn't mean that you'd actually want to do so. 
After all, the Turing Machine offers an equally powerful computational basis.

The strength of the lambda-calculus is that it is easily used as a ``glue'' 
on top of a richer world of primitives. 
Its advantages as a glue are that it has a natural correspondence with the way 
that people program, and natural compilation techniques yield 
high-performance code. 
The latter comes through optimizations know as tail-call and 
continuation-passing, which are more advanced topics not covered here.

There are software engineering advantages to a language glued together 
with lambda-calculus. 
Lambda expressions can be understood locally\Dash their dependence on 
their environment is entirely through their free variables. 
Lambda expressions tend to have fewer free variables and more bound 
variables than comparable imperative code, since they do not rely as heavily 
on assignment to express the computation. 
An imperative program proceeds by altering some globally-accessible 
store of values. 
By contrast, a functional program proceeds by function application and 
the return of values. 
This eliminates large classes of errors associated with maintinaing a global store of values.




\subsection{Scheme}
The Scheme programming language is essentially the lambda-calculus outlined 
above, plus these
\begin{itemize}
\item
    The ability for a lambda-expression to bind several arguments at once.
\item
    A rich set of constants, so numbers, arithmetic, data structures, etc., don't have to be built out of thin air.
\item
    Primitive control constructs, so control operations don't have to be built out of thin air.
\item
    An assignment operation, should it be necessary.
\item
    An environment of defined names, to allow for interactive use, redefinition, and recursive definitions without using the $Y$ combinator.
\item
    A library with I/O operations to connect programs to the outside world. 
\end{itemize}

In Scheme, programs look like data structures - both are built of lists. A list looks like:
\begin{equation*}
	(\str{elt1}\ \str{elt2}\ \ldots{}\ \str{eltn})
\end{equation*}
where each element is either an atom (number or symbol), or another list.

Expressions from the lambda-calculus are translated as follows:
% \begin{align*}
% 	\lambda x.M  &\becomes  \text{\codeinline!(lambda (x) M)!} \\
% 	(M)N  &\becomes  \text{\codeinline!(M N)!}
% \end{align*}
In addition, Scheme allows lambda expressions and function applications of 
more than one argument.
\begin{lstlisting}
(lambda (a b c) (+ a (* b c)))
\end{lstlisting}
The define syntax binds names to values within the local environment:
\begin{lstlisting}
(define pi 3.14159265)
(define fact
    (lambda (n)
        (if (zero? n)
        1
        (* n (fact (- n 1))))))
(define alpha (sin (/ pi 180)))
\end{lstlisting}
Some Scheme constructs are `syntactic sugar', that is, 
expressions that can be translated into expressions in terms of more 
primitive operators. 
The \codeinline!let! construct allows initialization and binding of 
local variables so that this
\begin{lstlisting}
(let ((x1 E1)
      (x2 E2)
      (x3 E3))
      \ldots{}body\ldots{} )
\end{lstlisting}
is equivalent to this.
\begin{lstlisting}
((lambda (x1 x2 x3) \ldots{}body\ldots{} )
E1
E2
E3)
\end{lstlisting}
% Definition of a function can be done without an explicit lambda-expression
% \begin{lstlisting}
% 	(define (f x y z)	=>	(define f
% 	  \ldots{}body\ldots{})			  (lambda (x y z)
% 					    \ldots{}body\ldots{}))
% \end{lstlisting}



\subsection{Standard idioms in Scheme}
Where a conventional block-structured imperative language like C or Pascal 
would write
\begin{lstlisting}
begin
    x := 1;
    y := 2 * some_global_var;
    z := some_function();
    \ldots{}body using x, y, and z\ldots{}
end
\end{lstlisting}
Scheme would instead use the let syntax to bind local variables.
\begin{lstlisting}
(let ((x 1)
    (y (* 2 some-global-var))
    (z (some-function)))
    ..body using x, y, and z\ldots{})
\end{lstlisting}
As we see above, the \codeinline!let! construct is just the stylized use of 
lambda and a function application to create an environment for the body 
where the local variables are bound to their values. 
Note that this style of programming requires the local variables to be 
initialized before use.

Scheme downplays iterative constructs such as \codeinline!do!, preferring 
recursive function calls. 
A special optimization called tail-recursion produces compiled code 
that is equivalent to a loop.
\begin{lstlisting}
(define (new-fact n)
    (define (iter n a)
    (if (zero? n)
        a
        (iter (- n 1) (* n a))))
    (iter n 1))
\end{lstlisting}
Compare this to the equivalent C function:
\begin{lstlisting}
int
new_fact(int n)
{
    int a = 1;
    while (n != 0)
        a *= n--;
    return a;
}
\end{lstlisting}
Note that the loop in the C version cannot be understood on its own\Dash in 
order to see what \codeinline!n! and \codeinline!a! are we have to 
see the entire function, while in the Scheme version, the 
\codeinline!iter! function can be lifted out of the \codeinline!new-fact! 
function and understood on its own\Dash it has no free variables! 
This may not seem too important for a toy example like this, but as the 
size of the function and the complexity of the loop scales up, 
this kind of modularity can be important.

Although it may seem unnecessary and clumsy to define a new function every 
time you need a loop, some common uses can be turned into functions 
themselves. 
For instance, a common operation in Scheme is the act of taking a 
list and applying a function to each of the elements, forming a new list of 
the results.
\begin{lstlisting}
(define (list-of-squares l)
    (define (iter l)
        (if (null? l)
            (quote ())
            (cons ((lambda (x) (* x x)) (car l)) (iter (cdr l)))))
    (iter l))
\end{lstlisting}
This kind of iteration is idiomatic, so we can capture it in a function:
\begin{lstlisting}
(define (map f l)
    (define (iter l)
        (if (null? l)
            (quote ())
            (cons (f (car l)) (iter (cdr l)))))
        (iter l))

(define (list-of-squares l)
    (map (lambda (x) (* x x)) l))
\end{lstlisting}
We could produce this program in C as well, using the technique of passing 
pointers to functions as arguments to other functions. 
However, there are some features of C that make this difficult. 
Suppose we want a function to do an affine transformation $Ax + B$ on a 
list of numbers, with A and B as parameters to the function. 
In C we have to write this.
\begin{lstlisting}
double A, B;	/* global variables */
static double
affine(double x)
{
    return A * x + B;
}

List *
affinelist(double a, double b, List *l)
{
    A = a;
    B = b;
    return map(&affine, l);
}
\end{lstlisting}
Since in C, the map function accepts only a function pointer, 
the transformation parameters have to be held in some static location for 
the affine function to find them. This prevents the code from being 
reentrant\Dash only one call to affinelist can be active at a time.

Pascal allows functions to be declared within a block, and to have access 
to all the variables visible within that block. 
In a `block-structured' variation of C would could do the following:
\begin{lstlisting}
List *
affinelist(double a, double b, List *l)
{
    double
    affine(double x)
    {
        return a * x + b;
    }
    return map(&affine, l);
}
\end{lstlisting}
This allows the function to be re-entrant. 
But Scheme allows us even more freedom in the use of these local 
functions\Dash they can persist even after the return of the parent function! 
The variables bound by the parent function are still accessible to the local 
functions, and only by them, in effect creating an opaque object with the 
local functions as the methods for accessing its state. 
This gives us a way to do object-oriented programming with higher-order 
functions in Scheme.

Suppose we want to create an object with state variables svN and methods 
methodN.
\begin{lstlisting}
(define (make-object sv1 sv2 ... svN)
    (lambda (mesg)
        (cond ((eq? mesg (quote method1)) (lambda args1 body1))
               ((eq? mesg (quote method2)) (lambda args2 body2))
                 ...
               ((eq? mesg (quote methodM)) (lambda argsM bodyM))
               (else (error "Unknown method for object")))))

(define (method1 obj args1) ((obj (quote method1)) args1))
    ...
\end{lstlisting}
So an object is a procedure which accepts a message and dynamically 
returns a procedure which will handle that message. 
Each procedure has access to the state variables which were used to create 
the object. 
Multiple instances are created through multiple invocations of the 
\codeinline!make-object! function. 
Class structure and inheritance can be accomplished through delegation. 
So use of higher-order functions can implement object-oriented code in a 
natural way.

Here are some advantages of a lambda-calculus-based programming language.
\begin{itemize}
\item
    A clean mathematical basis. The formal specification of the language doesn't need to refer to a machine or compiler.
\item
    Many common programming idioms have a natural representation.
\item
    Advanced programming through higher-order functions.
\item
    Direct correspondence with advanced mathematical objects such as functionals.
\item
    Efficient machine implementation.
\item
    Programs are more modular\Dash they can be understood and analyzed locally. 
\end{itemize}

There are some disadvantages too.
\begin{itemize}
\item
    Real-world implementations are not as good as they could be.
\item
    The model of computation provided by the language is far removed from the realities of the underlying machine. This can be both good and bad.
\item
    Things that are simple in other languages tend to be hard in Scheme, yet some simple Scheme tricks are hard to do in other languages.
\item
    Programming with full lambda-calculus requires a garbage collector in the runtime system. This entails
        a more complicated runtime system than Fortran or C, 
        difficulty in linking with code compiled from another language, and 
        complications for real-time or interactive use. 
\end{itemize}
