What can be mechanically computed, at least in principle?
For instance, the function that doubles its input, that
takes in~$x$ and outputs~$2x$, is intuitively mechanically computable.
We shall call such things \definend{effective}.

The question asks for the things that can be computed more than  
it asks for how to compute them. 
So in this chapter
we tend to be more interested in the function,
in the input-output behavior,
than we are in
the details of coding it.

\section{Turing machines}
Despite that general tendency to downplay implementation details, 
we follow the approach of Alan Turing so that 
our 
first step toward 
defining the set of computable 
\margingraphic{0.23\textwidth}{prologue/turing.jpg}{\label{fig:turing}\href{http://en.wikipedia.org/wiki/Alan_Turing}{Alan Turing 1912--1954}}
functions 
is to reflect on the details of doing things with a mechanism.

% \begin{wrapfigure}{R}{0.3\textwidth}
% \centering
% \includegraphics[width=0.25\textwidth]{prologue/turing.jpg}
% \caption{\label{fig:turing}\href{http://en.wikipedia.org/wiki/Alan_Turing}{Alan Turing 1912--1954}}
% \end{wrapfigure}
Turing was considering the kind of symbol-manipulating computation that
a person uses in mathematics when they factor polynomials 
or verify a step in a plane geometry proof.
The context of his thinking was the 
\textit{Entscheidungsproblem},\footnote{German for ``decision problem.''} 
proposed in 1928 by 
David Hilbert and Wilhelm Ackermann, which 
asks for an algorithm that decides the truth or falsity of
mathematical statements.
This algorithm should take 
as input a statement in an appropriate formal language 
and output `Yes' or `No', giving 
\citetext{whether or not the statement is true}{Hilbert was a very prominent 
mathematician and Ackermann was his student so they made an impression when 
they wrote, ``[This] must be considered the
main problem of mathematical logic'' \autocite{HilbertAckermann}, p 73.}.

After reflecting on the issue for some time, one day 
\citetext{after a run}{\autocite{Hodges}, p 96.}\footnote{He was a 
serious candidate for the 
1948 British Olympic marathon team.} Turing laid down in the grass and
imagined a
clerk doing by-hand multiplication with a 
sheet of paper that gradually becomes covered with columns of numbers.
With this simple case of symbol-pushing computing as a model, 
Turing posited requirements for the computing agent. 

First, it (or he, or she) has a memory facility, like the 
clerk's paper, 
for storage and retrieval of information.
The clerk's paper is two-dimensional but that is  
is not essential, since we could stretch out the work 
into a one-dimensional strip.

Second,  
the computing agent must follow a definite procedure, 
a precise set of instructions,
with no room for creative leaps.
Part of what makes the procedure definite is that 
the instructions don't involve 
random methods such as counting clicks from radioactive decay
to determine which of two possibilities to perform.
But another part is that the agent works in a discrete fashion, stepwise, 
without continuous methods or analog devices such as a slide rule.
If a time comes for a break then the agent could pause, noting where they are
in the procedure (``about to carry a $1$''), so that they could
resume later.
We say that the clerk has a finite set of possible \definend{states},
which we denote $q_0$, $q_1$, etc.

The third requirement is that Turing wanted what is computable in principle.
Therefore he imposed
\citetext{no upper bound}{This explication is derived 
  from \autocite{Rogers},  p 1--5.} 
on the size of the 
inputs. 
More precisely, he imposed no finite upper bound, so that 
should a calculation need more room on the tape then more is 
provided, perhaps by an operator.
He similarly put no upper bound on the number of instructions.
He put no upper bound on the amount of extra 
storage, scratch memory, needed in addition to the memory for the inputs and
instructions.
And he put no upper bound on the number of steps that a 
computation performs before it finishes.\footnote{Some authors
  describe the availablity of resources such as
  the amount of memory as `infinite'.
  Turing himself does this.
  A reader may object that this violates the goal of the definition, to 
  model physically-realizable computations, and
  so the development here instead says that 
  the resources have no finite upper bound.
  But really, it doesn't matter.
  The point is that if we show that something cannot be computed
  when there are no bounds then we have shown that 
  it cannot be computed on any physical device.}

The final question Turing faced is:
how smart should the computing agent be?
For instance, should we require that it can multiply?
We don't need multiplication because we can do
that with repeated addition.
We don't even need addition because we can do that by 
repeating the successor operation, the add-one operation.
In this way we can boil the computing agent down until it is  
quite basic, quite easy to understand,
until the operations \citetext{are so elementary that it is not easy
to imagine them further divided}{\autocite{Turing}},
while still keeping the agent powerful enough to do anything that can, 
in principle, be done. 


\subsection{Definition}
Based on these reflections, Turing imagines a box containing a
mechanism 
and fitted with a tape.
\begin{center}
   \includegraphics{asy/share/tm.pdf}
\end{center}

The tape is the memory.
The box can read from and write to this tape, one character at a time,
as well as move the read/write head relative to the tape, in either direction.
For instance, to do the multiplication problem, 
the computing agent can get the two input multiplicands from the tape 
(the picture above shows 
$74$ and~$72$ in binary), 
can use the tape for scratch work, and can write the
output to the tape.

The box is the computing agent, the CPU.
The \texttt{Start} button sets the computation going and 
the \texttt{Halt} light flags when the computation is finished.
How the mechanism inside the box is engineered is not 
important\Dash perhaps it has gears and levers,
or perhaps integrated circuits\Dash what
matters is that each of its finitely many parts 
can be in only finitely many states.
For instance, if it is made with gears then each gear settles in only 
a finite number of possible positions
and if it has chips then each 
register has a finite number of possible values.
Thus, however it is engineered, 
in total the box has only finitely many states.

While executing a calculation, the mechanism passes stepwise 
from state to state.
For instance, 
an agent doing multiplication may find, because
of what state it is in now and because of what it is now reading on the tape,
that it next needs to carry a~$1$.
The agent then passes to a new state, one whose intuitive meaning
is that carries take place there, possibly at the same time
also shifting the tape or writing to it.

Consequently, machine steps involve four pieces of information,
We denote the present state as $q_p$ and the next state as $q_n$.
The other two, $T_p$ and~$T_n$, 
describe what is presently being read on the tape
and what happens next with the tape.
The things that can happen next to the tape 
includes moving the tape head left or right without writing,
which we denote by setting $T_n=\str{L}$ or~$T_n=\str{R}$,
or writing a character to the tape without moving the head.
As to the set of characters that we can read from or write to the tape, 
we can choose whatever is convenient
but for the moment we restrict ourselves to 
$\str{1}$ and~blank (which we write as $\str{B}$ when just leaving an empty
space could cause confusion).

The four-tuple $q_pT_pT_nq_n$ is an \definend{instruction}.
For example, the instruction
$\texttt{q}_3%
 \texttt{1}%
 \texttt{B}%
  \texttt{q}_5$
is executed only if the machine is now in state~$q_3$
and is reading a \str{1} on the tape.
If so then the machine
writes a blank to the tape, replacing the \str{1},
and passes into state~$q_5$.

A Turing machine is a set of instructions (the full definition is below).
We use the symbol $\TM$, because the thing from our present-day experience 
that a Turing machine is most like is  
a computer program.

\begin{definition} \label{def:TuringMachine}
A \definend{Turing machine}~$\TM$ is a finite set of four-tuple 
\definend{instructions} $q_pT_pT_nq_n$,
where $q_p$ and~$q_n$ are elements of the set of \definend{states},
where $T_p$ is an element of the \definend{tape alphabet} set
(which must contain a symbol for blank),
and where the \definend{tape action}~$T_j$ 
is either of the symbols $\texttt{L}$ or~$\texttt{R}$,
or an element of the tape alphabet (which cannot contain
$\texttt{L}$ or~$\texttt{R}$).
The set of instructions~$\TM$ is subject to the restriction of being 
\definend{deterministic}: no two four-tuples can begin with 
the same $q_pT_p$.
\end{definition}

Here is a formal description of the action of Turing machine.
For a Turing machine $\TM$, a \definend{configuration}
is a four-tuple
$\sequence{q,s,\tau_L,\tau_R}$
where $q$ is a state, 
where $s$ is a character from the tape alphabet,
and where $\tau_L$ and~$\tau_R$ are strings of elements from the tape alphabet,
or possibly the empty string~$\emptystring$.
Using \cref{ex:MAdd} for illustration, each line in the
trace table pictures a configuration.
Thus, 
on line~$2$ 
the configuration has 
the state $q=q_0$, 
the character under the head $s$ is the blank,
the tape to the left of the head is $\tau_L=\str{11}$,
and the tape to the right of the head is $\tau_R=\str{111}$.

What remains is to describe a \definend{step},
the movement of $\TM$ from a configuration to its next configuration.
Suppose that after step~$i$ the machine $\TM$ is in configuration
$\mathcal{C}_i=\sequence{q,s,\tau_L,\tau_R}$.
We look for an instruction $q_pT_pT_nq_n\in\TM$ with
$q_p=q$ and~$T_p=s$.
If there is no such instruction then we say that $\TM$ \definend{halts} at 
step~$i+1$.

Otherwise, because of nondeterminism, there is one such instruction.
What happens next depends on~$T_n$.
(1)~If $T_n$ is a symbol in the tape alphabet set then we write that
symbol to the tape, so that the 
next configuration is 
$\mathcal{C}_{i+1}=\sequence{q_n,T_n,\tau_L,\tau_R}$.
(2)~If $T_n$ is the symbol~\str{L} then we move the tape head one to the left.
That is, the next configuration is  
$\mathcal{C}_{i+1}=\sequence{q_n,\hat{s},\hat{\tau}_L,\hat{\tau}_R}$,
where $\hat{s}$ is the rightmost character of the string~$\tau_L$ (if
$\tau_L=\emptystring$ then $\hat{s}$ is the blank character),
where $\hat{\tau}_L$ is $\tau_L$ with its rightmost character omitted
(if $\tau_L=\emptystring$ then $\hat{\tau}_L=\emptystring$ also),
and where $\hat{\tau}_R$ is the concatenation of $s$ and $\tau_R$.
(3)~If $T_N$ is the symbol~\str{R} then we move the tape head to the right.
This is so similar to possibility~(2) that we omit the details.

If two configuration are related in this way then we write
$\mathcal{C}_i \yields \mathcal{C}_{i+1}$, read ``yields in 
one step.''
A \definend{computation} is a sequence of steps.
\begin{equation*}
  \mathcal{C}_0 \yields \mathcal{C}_1 \yields \mathcal{C}_2
   \yields \cdots \yields \mathcal{C}_n 
\end{equation*}
where $\mathcal{C}_o$ is the machine's initial configuration
and where the machine has halted at $\mathcal{C}_n$.
We abbreviate such a sequence with 
$\mathcal{C}_0\kleenestar{\yields}\mathcal{C}_n$, where 
$\kleenestar{\yields}$ is read ``yields.'' 

That description highlights that the core idea of a Turing machine is
the transitions.
Each instruction~$q_pT_pT_nq_n$
tells us how, from the current state and tape symbol $q_pT_p$,
we transition to the next tape action and state~$T_nq_n$.
The requirement of determinism says that this
action is a function, the \definend{transition function} 
$\map{\delta}{Q\times \Sigma}{\Sigma\cup\set{\str{L},\str{R}}\times \hat{Q}}$
(the set~$\hat{Q}$ differs from $Q$ in that it may have a few extra states used
as halting states).

We close this section with two points.
The first point is that some Turing machines, for at least some
starting configurations, do not halt.

\begin{example}
The machine
$
  \TM_{\text{inf loop}}=\set{
        \tminstruction{0}{B}{B}{0},\,
        \tminstruction{0}{1}{1}{0}
      }
$
never halts, regardless of the input.
\begin{center}
  \vcenteredhbox{\includegraphics{prologue/asy/circlediagram/infloop.pdf}}
\end{center}
\end{example}

If a machine~$\TM$ fails to halt on an input~$n$ then we 
say that the function computed by the machine \definend{diverges}, written
$\phi_{\TM}(n)\mathord{\uparrow}$.
We then call~$\phi$ a \definend{partial function}, emphasizing
that for some inputs there is no associated output.
In contrast, a function that has an output for each input is a 
\definend{total function}.

% The second point is that 
% the example machines above cannot be made to do arbitrary things, 
% they each do just one thing.
% The right first take is not that a Turing machine is what 
% we today call a computer,
% a general-purpose device. 
% Instead, the right first take is that a Turing machine is a program.

The second point brings us back to the start of this section.
At the end of the paper in which he introduced his definition of 
machine models, Turing showed that there is no machine that 
solves the 
\textit{Entscheidungsproblem}.
% In the next chapter we will discuss the significance of this at length
% but for now we note it as an example of  
% something that we cannot do with 
% mechanical computation.
To a person with computer programming training, 
where the all of the conversation naturally is on doing things,
the existence of jobs that cannot be done may be a surprise, perhaps
even a shock.
One thing that it shows is that the topics introduced 
here are nontrivial\Dash formalizing
the definition of mechanical computation leads to interesting results.

\subsection{History}
From the start of mathematics, algorithms have played a central part.
The most familiar example is a formula, such as 
the one for the height of a body dropped from the Leaning Tower of Pisa, 
$h(t)=-4.9t^2+56$.
A formula is a compact instruction list:
to compute~$h$,
given an input time, square it, then multiply
by~$-4.9$, and finally add~$56$.
The resulting output is the distance in meters 
of that object above the ground at the given time.

Another example of an early algorithm is
Euclid's Algorithm for finding the
greatest common divisor of two numbers.
Because it is iterative,
this fits well with the sense that a programmer has of what 
constitutes an algorithm.

\margingraphic{0.35\textwidth}{prologue/steppedreckoner.jpg}{\label{fig:turing}\href{http://en.wikipedia.org/wiki/Stepped_Reckoner}{Replica of Leibnitz's computer, the Stepped Reckoner}}
% \begin{wrapfigure}{L}{0.4\textwidth}
% \centering
% \includegraphics[width=0.35\textwidth]{prologue/steppedreckoner.jpg} % http://www.computerhistory.org/revolution/calculators/1/49/198
% \caption{\label{fig:turing}\href{http://en.wikipedia.org/wiki/Stepped_Reckoner}{Replica of Leibnitz's computer, the Stepped Reckoner}}
% \end{wrapfigure}
In the 1670's 
Gottfried Wilhelm von Leibniz, the co-creator of Calculus, 
constructed the first machine
that could do addition, subtraction, multiplication, division, 
and square roots as well.
This led him to speculate on the possibility of
a machine that could manipulate
symbols, not just numbers, and could
determine the truth of scientific statements. 
% (stated in some appropriate language).
To settle any dispute, Leibnitz wrote, 
two scholars could just say,
``Calculemus!'' (Latin for ``Let us calculate!''). 
This is an early version of the 
\textit{Entscheidungsproblem}.

The need for a fuller understanding of what
things are mechanically computable was made pressing by
the appearance in 1927 of the Incompleteness Theorem by Kurt G\"odel.
This result says that for any (sufficiently powerful) axiom system there
are statements that, while they are true, are not provable from those axioms. 
The intuition behind G\"odel's proof is that it gives an algorithm, a mechanical
computation, that takes as input
the axiom statements 
and produces as output the undecidable statement.
So understanding what can be done with the techniques in G\"odel's proof 
involves understanding what is intuitively mechanically computable.

\margingraphic{0.23\textwidth}{prologue/church.jpg}{\label{fig:church}\href{http://en.wikipedia.org/wiki/Alonzo_Church}{Alonzo Church 1903--1995}}
A number of mathematicians proposed formalizations 
of `intuitively mechanically computable'.
One was 
Alonzo Church\footnote{After producing his machine model, 
  Turing became a PhD student of Church at Princeton.}, 
who defined the $\lambda$-calculus, 
which, like Turing's scheme, also produces a set of functions.
Work with the $\lambda$-calculus showed that it can compute
large numbers of functions that
are intuitively computable, and also
found no intuitively computable function that could not be
computed under this system.  
\citetext{Church privately suggested}{\autocite{Soare99}} 
to G\"odel, the most prominent expert in the area,
that the set of $\lambda$-computable functions is the same
as the set of intuitively-computable functions.
But G\"odel was unconvinced.

That changed when G\"odel read 
Turing masterful analysis outlined in the prior section.
He subsequently wrote,
``That this really is the correct definition of mechanical computability  
was  \citetext{established  beyond  any  doubt}{\autocite{Godel95}}  
by  Turing.''

\begin{churchsthesis}
The set of things that are intuitively 
computable by a discrete deterministic mechanism 
is the same as the set of things that are computable by
a Turing machine.\footnotemark
\end{churchsthesis}
\footnotetext{Many authors
call this the Church-Turing Thesis.  
In this book, because Turing gets the 
machine, we give Church the thesis.}

Neither Church nor Turing stated anything as strong as
is given here; they proposed that the set of things 
that can be done by a Turing machine is the same as the set of things
that are intuitively computable by a
human computer, that is, they addressed the
\textit{Entscheidungsproblem}. 
The thesis given here, that what can be done by a Turing machine
is what can be done by any physical mechanism 
that is discrete and deterministic, is the thesis as it is 
taken in the field today, based both on the 
work of these two and on the work done since.
As developed at the start of this chapter, 
we take ``physical mechanism'' 
to go beyond people and to require only that the machine conforms to
the laws of the universe, somewhat idealized 
in that, for instance, we put no bound on the
number of steps in a computation.

Of course,
one reason for our interest in Church's Thesis is that it speaks to
the devices that we have on our desks and in our pockets.



\subsection{Evidence}
We cannot prove Church's Thesis.
As \citetext{Turing noted}{\autocite{Turing}}, 
``All arguments which can be given are bound to be, 
fundamentally, appeals to intuition, and for this reason rather 
unsatisfactory mathematically. 
The real question at issue is, `What are the possible processes which can 
be carried out in computing \ldots{}\,?' ''
Nonetheless, Church's Thesis is widely accepted. 
We will outline the arguments in its favor.

The first argument is coverage:~everything that people think of as 
intuitively computable has, on close analysis, proved to be
computable by a Turing machine.
This includes not just the number theory functions investigated by 
researchers in the 1930's but also all of the things computed by
all of the programs in all
of the computer languages written since, for they can all be 
compiled to run on a Turing machine.

Despite the weight of evidence, 
this argument would collapse with one 
counterexample, one operation that can be done in finite time 
on a physically-realizable discrete and deterministic 
device but that cannot be done on a 
Turing machine.
So this argument is strong but at least conceivably not decisive.

The second argument is convergence:~all of the models of computation that 
were proposed, by all of the researchers then and since,
yield the same set of computable functions.
For instance, Turing showed that the set of functions computable with
his machine model is equal to the set of functions computable
with Church's $\lambda$-calculus.

Now, everyone could be wrong. 
There could be some
\citetext{systematic error}{\autocite{DershowitzGurevich} p 304.} 
in the thinking around this point.
Before the advent of non-Euclidean geometry, researchers
seem not to have imagined the possibility that the Parallel Postulate
is neither true nor false, and perhaps some similar 
cultural blindness is happening here.
Nonetheless, when you have a question and you ask a group of very smart people
who go off and work independently,
and when they come back they all give you the
same answer,
then you think it is likely the right answer.
At the very least, convergence says that there is something natural 
and compelling about this set of functions.

An argument not available to G\"odel and others in the 1930's, 
since it depends on work done since, 
is consistency:~the details of the definition of a 
Turing machine are not essential to what can be computed.
For any way in which the Turing machine definition given above seems to 
take an arbitrary choice, 
altering that way will still lead to
the same set of computable functions.
% (of course, it is this set that we want).

For example,   
the number of tapes does not matter:
a machine with only one tape can compute the same functions as a machine 
with two or more.
(One way to simulate a two-tape machine~$\TM_2$ on
a one-tape machine~$\TM_1$ is
by having~$\TM_1$ use its
even-numbered tape positions for~$\TM_2$'s first tape and
using its odd tape positions for~$\TM_2$'s second tape.)
Thus, the fact that \cref{def:TuringMachine}'s machines have only one tape
is not an essential point.

Similarly, machines whose tape is unbounded in one direction only can 
compute all the functions that can be computed by
machines with a tape unbounded in both directions.
Machines with more than one read/write head compute the same
functions as those with only one head.

Although restricting to machines having only one state does not suffice
to compute all intuitively computable functions, allowing
two does\Dash
two-state machines are equipowerful with 
the unboundedly-many-states machines given in \cref{def:TuringMachine}.

Two symbols, such as blank and stroke, are enough
to compute any Turing-computable function.
Likewise, 
restricting to write-only machines, ones that cannot change marks once they 
have been put on the tape, suffices to compute the same set of functions.

There is one more condition that does not change the set of computable 
functions, determinism.
Recall that 
the definition of Turing machine given above does not allow, say, 
$\tminstruction{5}{1}{R}{6}$
and 
$\tminstruction{5}{1}{L}{4}$
in the same machine because they both begin with $q_5\texttt{1}$.
If we drop this restriction then the class of machines that we get are called
nondeterministic.
We will have much more to say on this later but 
the collection of nondeterministic Turing machines computes the same 
set of functions as does the collection of deterministic machines.

The fact that the details of the Turing machine definition are not essential 
is persuasive in that any proper definition of what is 
computable should posses this property.
% If two-tape machines computed more functions than one-tape machines, 
% and three-tape machines more than those, then identifying 
% the set of computable functions with those computable by single-tape machines
% would be foolish. 
But as with the prior argument, while
this means that the Turing machine notion is natural and wide-ranging, 
it still
seems to leave open a small crack of a possibility that the notion is not 
exhaustive.

The most persuasive single argument for Church's Thesis\Dash
what caused G\"odel to change his mind and what convinces scholars
still today\Dash
is clarity:~Turing's analysis itself is compelling.
G\"odel said this in the quote given earlier and 
Church felt the same way, writing that Turing machines have, 
``the advantage of making the
identification with effectiveness \ldots{} 
%in the ordinary (not explicitly defined) sense 
\citetext{evident immediately}{\autocite{Church36}}.''
% That is, when you read Turing's analysis you say to yourself, 
% ``Yes, this is exactly what can be done operating without limits
% by a discrete, deterministic, Newtonian mechanism.''


\subsection{What Church's Thesis does not say}
Turing's analysis, and that of Church and others, 
aims to understand 
what can and cannot be done in the course of a particular type of 
computation,
a discrete and deterministic manipulation of symbols that is 
without creative leaps.   

Church's Thesis does not say that in all circumstances the best way to
understand a computation is via the Turing machine model.
% While a security researcher studying 
% how operating systems could be more resilient to attacks 
% could conceivably model them as bit streams coming into a Turing machine,
% because including interactivity in the model would require  
% varying the bit streams, which is ungainly, they may 
% make more progress with some other model.
A numerical analyst investigating a floating point algorithm 
will want to use a computer model that has registers. 
Church's Thesis asserts  
that the discrete logic in the register machine 
model could in principle be done by a Turing machine, but for this
application the most felicitous thing is
a model with registers.

\citetext{Church's Thesis also does not assert that a Turing machine is 
every possible computing device}{One point that has caused confusion concerns processes with unbounded extent.  We look for our Turing machines to halt.  But some computations, such as an operating system, are designed to not stop.  Is the Turing machine model is inadequate for these?  The correct answer is given by Lance Fortnow \autocite{Fortnow10}. ``Computation is about process, about the transitions made from one state of the machine to another. Computation is not about the input and the output, point A and point B, but the journey. \ldots{} You can feed a Turing machine an infinite digits of a real number (Siegelmann), have computers interact with each other (Wegner-Goldin), or have a computer that perform an infinite series of tasks (Denning) but in all these cases the process remains the same, each step following Turing's model.''} 
in the sense that, say, if you are
using an automobile antilock braking system that includes logic circuits
but also includes various sensors then the Turing machine
only models the logical and arithmetic computations, not
the entire system. 
\citetext{Scott Aaronson has made this point}{From his blog \textit{Shtetl-Optimized}.  \autocite{Aaronson12}}, ``Suppose I \ldots{}
[argued] that \ldots{} [Church's] Thesis fails to capture all 
of computation, because Turing machines can't toast bread. 
\ldots{}
% Therefore, you need my revolutionary new model, the 
% Toaster-Enhanced Turing Machine (TETM), which allows bread as a possible input and includes toasting it as a primitive operation.
You might say: sure, I have a `point', but it's a totally uninteresting one. 
No one ever claimed that a Turing machine could handle every possible 
interaction with the external world, without first hooking it up to 
suitable peripherals. 
If you want a Turing machine to toast bread, you need to connect it 
to a toaster; then the TM can easily handle the toaster's internal logic 
\ldots\,.
% (unless this particular toaster requires solving the halting problem or something like that to determine how brown the bread should be!). 
In exactly the same way, if you want a TM to handle interactive communication, 
then you need to hook it up to suitable communication devices.''

In the same vein, we can get physical devices, for instance that plug into a 
computer's USB port, that 
\citetext{supply a stream of random bits}{Some CPU's come with that capability built in; see for instance \protect\url{https://en.wikipedia.org/wiki/RdRand}.}.
These are not pseudorandom bits that are computed by a method that 
is deterministic but which causes them to pass statistical tests.
These devices provide a stream of bits that well-established 
physics tells us are truly random.  
We will later discuss this case at greater length but its relevance here is
that Church's Thesis 
only asserts that Turing machines model the discrete and deterministic
computations that we can do after we are given input bits from such a device.


\subsection{An empirical question}
We have described that Turings's analysis of what can be done by a human 
computer was widely accepted.
We have also described that in the community of researchers
the contention known as Church's Thesis has strengthened over time from the
assertion that a Turing machine can do anything that can be done during human 
computation, 
to the assertion that a Turing machine can do anything that can be done by
any physically-realizable mechanism that is discrete and deterministic.
We have seen the arguments for that contention.

That raises the big question: can we do more, by
going beyond discrete and deterministic?
Are Turing machines an ultimate in all physically-possible computations?
For instance,
would analog methods\Dash passing lasers through
some gas, say, or some kind of quantum magic\Dash allow us to 
compute things that no Turing 
machine can compute?
Or did Turing, on that day, lying on that grassy river bank, 
delimit everything that 
experiments with reality would ever find to be possible?

This big question is open\Dash we have no final answer.
For a taste of the conversation:~in 
a \citetext{pail of water}{This is \protect\textit{Hinck's pail}, after Ian Hinckfuss, described in \autocite{Lycan}.} left for a time
there are a fantastically large number of molecules having 
an unbelievably large number of interactions, and those large numbers
essentially ensure that there is in the pail a configuration
of molecules that we can view as having gone through the steps
from \cref{ex:MPred}, our first example of a computation; 
can this bucket be said to compute?
In a perhaps more satisfactorily mathematical example,
we can prove that there is a case where the wave equation
has computable initial
conditions (for the initial real numbers~$x$ there is a program that 
inputs~$i\in\N$ and outputs the $i$-th decimal place of~$x$), 
but the unique solution is not computable. % Pour-El M. B., Richards I.
% The wave equation with computable initial data such that its unique solution is not computable. Adv. in Math 1981;39:215-239.
So does the experimental setup modelled by this equation 
compute something that Turing machines cannot?
Stated dramatically, 
do the planets in their orbits compute a solution to Kepler's laws?

Again,
\citetext{the question remains open}{A sample of readings: \autocite{Copeland96}, \autocite{Copeland99}, and \autocite{Copeland02} argue that computations can be done that are beyond the capabilities of Turing machines, while \autocite{Davis04}, \autocite{Davis06}, and \autocite{Gandy80} represent what is the more common view among Theory of Computing researchers.}. 
There 
is as yet no analysis of this wider notion of computation 
with the general support that Turing's analysis has garnered in its 
more narrow case.
In particular, no one has yet produced a generally accepted case of a 
physically possible mechanism that computes a function that no
Turing machine computes.

We will not persue this question, instead only 
observing that 
the community of researchers in the Theory of Computation has weighed in
by taking Church's Thesis as the basis for their work.
In this book we will stick to mechanisms that
are discrete and deterministic and `computation' will refer to the
kind of work that Turing analyzed.

Specifically, inside of the class of models that give the set of 
effective functions 
we will take Turing machines as our touchstone, because
we want to think about symbol-pushing computations, not numerical 
analysis, and not toast.




\subsection{How we use Church's Thesis} 
We are interested, at least in the first part of this book,
in what can and cannot be computed in principle,
and we will
not focus on the details of exactly how those things are computed.
For instance, we may describe sorting a list but not say whether
it is via a quicksort or shell sort.

As well, doing sophisticated tasks with Turing machines is hard and 
handling the needed details can blind us to larger points. 

Consequently, when we are showing that a certain
behavior is computable, if we can be clear and
rigorous without actually having to implement it on a Turing machine
then we will be delighted.
Church's Thesis helps us get away with this.
Many of our arguments will start with 
a sketch that something is intuitively computable.
We will then invoke
Church's Thesis to assert that it is therefore
computable by some Turing machine, 
and the argument proceeds with, ``Letting $\TM$ be a machine that \ldots{}\,.''
This
is just a question of wanting to move through the material,
to get things done.

In particular, Church's Thesis implies that we can show
that something is computable by producing a program for it; 
for this we use the language Scheme.

Having been a key person in the development of the atomic bomb,

He thought that to colonize Mars we should first send robots.
Mars is red because it is full of iron oxide, rust.
Robots could mine the rust, breaking it into iron and oxygen, which 
puts oxygen in the atmosphere, which is what we want. 
With all the iron, von Neumann thought,
the robots could make more robots to mine even more iron.
So he was thinking about making machines that are capable of self-reproduction.
(We will study more about self-reproduction later.)

His thinking, along with a suggestion from Stanis\l{}aw Ulam, who was studying
crystal growth, led him to use a cell-based approach.
So von Neumann laid out some computational devices in a grid of 
interconnections, making a \definend{cellular automaton}.

Interest in cellular automata greatly increased  when John Conway invented 
one called Life.
It was featured in an 
October~1970 magazine column
in the popular magazine \textit{Scientific American}.
The rules of the game 
are simple enough that a person could immediately take out a pencil
and start experimenting.
Lots of people did.
Then, when personal computers came out, 
Life became one of the \citetext{earliest computer crazes}{\autocite{Bellos}},
since it is easy for a beginner to program.

To start, draw a two-dimensional grid of square cells, like
graph paper or a big chess board.
The game proceeds in stages, or generations.
At each generation each cell is either alive or dead. 
Each cell has eight neighbours, the ones that are 
horizontally, vertically, or diagonally adjacent. 
The state of a cell in the next generation is determined by: 
(i)~a live cell with two or three live neighbours will again be live at
the next generation but any other live cell dies,
(ii)~a dead cell with exactly three live neighbours becomes alive at the
next generation but other dead cells stay dead.
(The backstory goes that live cells will die if they are either isolated 
or overcrowded, while if the environment is just right then life can spread.)
To begin, we seed the board with some initial pattern.

As Gardner noted, Conway, with help from others, developed the rules
of the game to balance tedious simplicity against 
inpenetrable complexity.

\begin{quotation}  % Gardner; Topsep issue because of the wrapfigure?
 The basic idea is to start with a simple configuration of counters 
(organisms), one to a cell, then observe how it changes as you apply 
Conway's ``genetic laws'' for births, deaths, and survivals. 
Conway chose his rules carefully, after a long period of experimentation, 
to meet three desiderata:
\begin{enumerate}[topsep=0ex,noitemsep]
\item
    There should be no initial pattern for which there is a simple proof that 
  the population can grow without limit.
\item
    There should be initial patterns that apparently do grow without limit.
\item
    There should be simple initial patterns that grow and change for a 
considerable period of time before coming to end in three possible 
ways:~fading away completely (from overcrowding or becoming too sparse), 
settling into a stable configuration that remains unchanged thereafter, 
or entering an oscillating phase in which they repeat an endless cycle of 
two or more periods. 
\end{enumerate}
In brief, the rules should be such as to make the behavior of the 
population unpredictable. 
\end{quotation}

The result is, as Conway says, a ``zero-player game.''
It is a  mathematical recreation in which patterns evolve in 
fascinating ways.

How powerful is the game, as a computational system?
Although it is beyond our scope, you can run Turing machines in the game
and
so it is able to compute anything that can be mechanically computed
\autocite{Rendell}.
