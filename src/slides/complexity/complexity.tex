\ExecuteMetaData[\catchfilefn]{def:BigO}

Think of `$f$ is $\bigOh(g)$' as meaning that
$f$'s growth rate is less than or equal to $g$'s rate.

\pause
\begin{itemize}
    \item Although Turing machines are discrete devices, we find the 
      real number functions convenient, 
      in particular when we do L'H\^{o}pital's Rule. 
    \item  The term `complexity function' is not standard.
      We shall find it convenient for stating the results below.
    \item
      We use the letter `$\bigOh$' because this is about the order of growth.
    \item
      The `$f=\bigOh(g)$' notation is awkward but 
      standard.
      The notation `$f\in\bigOh(g)$' is better but not as common.
\end{itemize}
\end{frame}

\begin{frame}{Computing $\bigOh$}

For many familiar functions these are more convenient ways to compute
orders of growth comparisons.

\ExecuteMetaData[\catchfilefn]{lem:LHBigO}

\pause
To compute the limits we usually can apply this theorem from 
Calculus~I.

\ExecuteMetaData[\catchfilefn]{th:LHopital}

\begin{example}
Consider $f(x)=3x^2-2x+4$ and $g(x)=(1/2)x^5-6$.
Take derivatives twice to conclude that $f$ is~$\bigOh(g)$
but $g$ is not~$\bigOh(f)$.
\begin{equation*}
  \lim_{x\to\infty}\frac{6x-2}{(5/2)x^4}
  \qquad
  \lim_{x\to\infty}\frac{6}{10x^3}=0
\end{equation*}
\end{example}
\end{frame}


\begin{frame}{The Hardy Hierarchy}
\ExecuteMetaData[\catchfilefn]{lem:PolySlowerThanExp}

\begin{example}
This shows that $f(x)=\lg(x)=\log_2(x)$ is $\bigOh(g)$ where
$g$~is the polynomial $g(x)=x^2$.
\begin{equation*}
  \lim_{x\to\infty}\frac{1/(x\cdot \ln(2))}{2x}
  =\lim_{x\to\infty}\frac{1}{x^2\cdot 2\ln(2)}
  =0
\end{equation*}
\end{example}

\begin{example}
This shows that the polynomial $f(x)=x^2$ is $\bigOh(g)$ where
$g$~is the exponential $g(x)=2^x$.
\begin{equation*}
  \lim_{x\to\infty}\frac{2x}{2^x\cdot \ln(2)}
 \qquad
  =\lim_{x\to\infty}\frac{2}{2^x\cdot \ln(2)^2}
  =0
\end{equation*}
\end{example}
\end{frame}

\begin{frame}{Tractable and intractable}
We often split that hierarchy between polynomial functions
and exponential functions.

A modern computer runs at about 10~GHz,
$10\,000$ million ticks per second,
and there are about $\scinot{3.16}{7}$~seconds in a year.
The chart shows how long a job will take if we use an algorithm
that runs in time $\lg n$, or time~$n$, etc.
\begin{center}\small
\ExecuteMetaData[\catchfilefn]{table:TractibleAndIntractible}
\end{center}
Consider the final column, and its final line.
It says $10^{12}$~years.
The universe is about $14$~billion years old and a billion is $10^{9}$ years,
so this exponential computation, even with input size only $100$,
would take longer than the age of the universe.

\pause
\alert{Cobham's thesis} is that 
the \alert{tractable}
problems\Dash those that are at least conceivably solvable in practice\Dash are
those for which there is an algorithm whose resource
consumption is polynomial.

\section{Polynomial time}

\begin{frame}{$\P$}
\ExecuteMetaData[\catchfilefn]{def:P}

Here are some languages whose decision problems are in~$\P$:\begin{parenum}
\item the language of correct sums
$\lang_1=\set{\sequence{a,b,c}\in\N^3\suchthat a+b=c}$,
\item the language of sorted strings
$\lang_2=\set{\sigma\in\kleenestar{\str{a},\ldots \str{z}}\suchthat \text{$\sigma$ is in alphabetical order}}$,
\item the language of correct matrix multiplication
$\lang_3=\set{\sequence{A,B,C}\suchthat\text{the matrices are such that $AB=C$}}$,
\item the language of primes
$\lang_4=\set{\str{1}^k\suchthat\text{$k$ is prime}}$,
\item the language of reachable nodes
$\lang_5=\set{\sequence{\mathcal{G},v,\hat{v}}\suchthat\text{graph $\mathcal{G}$ has a path from $v\hat{v}$}}$.  
\end{parenum}

\pause
In this illustration, the bean encloses all 
all decision problems, for $\lang\subseteq\kleenestar{\B}$.
Shaded is the class~$\P$.
The shading is in layers because
$\P$ contains problems such that there is a solution algorithm  
that is $\bigOh(1)$,
problems for which there is an algorithm that is $\bigOh(n)$,
problems that are $\bigOh(n^2)$, etc.

\begin{frame}{Effect of the model of computation}
Different models of computation work at different speeds.
In particular, we perceive that Turing machines are slow;
does that affect which problems go in which classes?

Close analysis shows that
Turing machines are typically slower than other natural models
by a factor of $n^2$ or $n^3$.
(We take a model to be `natural' if it
  was not invented just to be a counterexample to this.)
Thus, if we have a problem for which there is a
$\bigOh(n)$ algorithm on
another model then when translated to a Turing machine
algorithm it may be $\bigOh(n^4)$.
An extended version of Church's thesis posits that any
reasonable model of computation can be simulated on a
(probabilistic) Turing machine in polytime.
This thesis controversial and does not enjoy anything like
the support of the original.
But under it a problem that falls in the class~$\P$ using Turing machines
also falls there using other natural models.

\pause
\begin{remark}  
  There in the air is a possible exception to the extended thesis. 
  Under the Quantum Computing model
  there are several problems with polytime solutions,
  including integer factorization,
  for which we do not know of any polytime solution in a natural
  non-quantum model.
  Whether quantum computers will ever be practical physical devices is not
  at this moment perfectly clear but scientists and engineers seem to be making
  progress developing them.
\end{remark}
\end{frame}


\begin{frame}{Naturalness of the class $\P$}
There are several reasons why the class~$\P$ is natural to
study.

\begin{itemize}
\item It is invariant under the choice of
computing model.

If a problem is in $P$ based on any familiar model
including Turing machines, Integer RAM, and Scheme programs, then
it is in~$P$ for all of them.

\item It has a number of appealing closure properties.

\ExecuteMetaData[\catchfilefn]{discussion:PClosure}
\end{itemize}
\end{frame}

\section{Nondeterministic polynomial time}

\begin{frame}{$\NP$}
Recall that a machine is nondeterminstic if
from a present configuration and input
it may pass to a next configuration where the number of next states
is zero, or one, or more.

Recall also that we have two models of how these devices operate.
In the first, the machine's computation history is a tree and it
simultaneously computes all branches.
That is, we can picture the machine as unboundedly parallel.

In the second model the machine guesses which next state to follow,
or is told which next state to follow by a demon, and
then deterministically computes a check of that branch of the computation tree.
With the first model we say an input string is accepted if one of the 
branchs on the tree is an accepting branch.

\pause
With the first model we say an input string is accepted if one of the 
branchs on the tree is an accepting branch.
With the second model we say the input
is accepted if there is a sequences of guesses that the machine could
make, or if there exists a sequence of
branching hints that the demon could produce,
that leads to an accepting state.
With those definitions, the two models are logically equivalent in that
they accept the same languages.
\end{frame}

\begin{example}
\alert{Linear programming} is to optimize some objective function
$f(x_0,\ldots x_n)$ subject to constraints
$a_{i,0}x_0+\cdots+a_{i,n}x_n\leq d_i$ and $x_i\geq 0$.
Recast that as a decision problem for this language.
\begin{equation*}
  \lang_B=\set{\sequence{x_0,\ldots x_n}\suchthat\text{the $x_i$'s meet the constraints and the objective is at least~$B$}}
\end{equation*}

that works, a witness~$\omega$ is such a sequence.
\end{example}
